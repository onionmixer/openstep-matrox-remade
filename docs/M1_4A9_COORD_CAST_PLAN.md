# §3-12 의 나머지 절반 — 훅의 좌표 캐스트 (계획, 2026-08-21)

`M1_4A8` §9 가 이것을 지목했다. **부분 화소 문제가 아니었다** — 정점 하나를
통째로 한 행 옮기고 삼각형을 83 화소 크게 만들었다.

## 1. 잰 것 (모델이 아니라 계기로)

훅이 `(long)` 을 하기 **전의** 부동소수 창 좌표를 기록하게 하고
(`OSMGAMesaHookLastWin`), 모든 정수 위치를 훑었다:

```
   x: 320 개 중 20 개를 캐스트가 잃는다   2 4 7 9 12 14 17 19 22 24 27 29 32 34 39 44 49 54 59 64
   y: 240 개 중 10 개                     1 2 3 8 9 10 16 17 24 32
   어긋난 양: 4.8e-7 ~ 3.8e-6   (100 근처의 float ULP 는 1.19e-5)
```

`y = 10` 이 목록에 있다 — 도형 4 를 망친 바로 그 값이고, 이제 추론이 아니라
관측이다. **6.25% 와 4.2% 다. 드물지 않다.**

그리고 **반올림하면 이 30 개가 전부 고쳐진다**(확인함).

## 2. 서로 다른 두 가지를 구분한다

| | 무엇 | 크기 | 고치는 법 |
|---|---|---|---|
| **A** | 정수를 의도한 좌표에 붙는 **부동소수 잡음** | 한 행/열 통째 | 반올림이면 **전부** |
| **B** | 진짜 **부분 화소** 기하 | 최대 반 화소 | 소수부를 살려야 함 |

지금까지 §3-12 는 B 만 적어 뒀다. **A 가 훨씬 크고, A 는 지금 고칠 수 있다.**

## 3. 처음 쓴 것 — 무조건 반올림 — 은 **틀렸다**

"`floor(v + 0.5)` 로 바꾼다. 최근접이 정점 변위를 줄이니 B 도 좋아질
것이다" 라고 적었다. **그건 논증이었고, 재 보니 경우별로는 성립하지
않는다.**

python, 소수 좌표 삼각형 280 개, **정확한 소수 정점으로 계산한 규칙**과 다른
화소 수:

```
   정점을 절단   : 삼각형당 139.2
   정점을 반올림 : 삼각형당  81.0
   반올림이 나은 경우 230,  나쁜 경우 43,  같음 7
```

**평균은 좋아지고 15% 는 나빠진다.** 래스터화는 불연속이라 정점을 조금 덜
움직이는 것이 마스크를 덜 바꾼다는 보장이 없다 — 얇은 삼각형에서는 정점
하나가 긴 스팬의 소유를 통째로 뒤집는다.

교차검토의 중심 지적도 같다:

> unconditional nearest rounding is a behavioral change to B, not merely an
> implementation of A.

**맞다.** A 를 고치겠다면서 B 의 의미를 말없이 바꾸는 것이고, 그 대가가
15% 의 경우별 퇴행이다.

## 4. 그래서: **경계를 둔 스냅**

정수에서 **`eps` 안에 있을 때만** 정수로 맞추고, 그 밖에는 **지금 동작을
그대로 둔다**(절단).

```c
static long
osmgaSnap(double v)                 /* eps 안이면 정수로, 아니면 지금대로 */
{
    double n = floor(v + 0.5);

    return (fabs(v - n) <= OSMGA_COORD_EPS) ? (long)n : (long)floor(v);
}
```

- A 는 **완전히** 고쳐진다: 관측된 어긋남이 최대 `3.8e-6` 이고 `eps` 는 그보다
  훨씬 크다.
- B 는 **건드리지 않는다.** 10.6 은 계속 10 이다 — 옳아서가 아니라,
  **알려진 상태**이고 B 는 자기 계획을 가질 것이기 때문이다.
- `floor` 를 쓴다. `(long)` 캐스트는 0 쪽으로 자르므로 음수에서 틀린다.
  창 좌표가 음수일 일이 없어야 하지만 **없어야 한다에 기대지 않는다** —
  §M1_4A8 이 그렇게 틀렸다.

`eps` 는 측정에서 고른다: 관측 잡음 `≤ 3.8e-6`, 가장 큰 좌표에서의 float
ULP `≈ 3.8e-5`. **`eps = 1/4096 ≈ 2.4e-4`** 로 둔다 — 잡음의 60 배이고,
기하적으로는 밀리 화소의 4 분의 1 이라 아무 의미가 없다. 2 의 거듭제곱이라
정확히 표현된다.

### 4-1. 유한하지 않은 값

`osmgaCoordOK` 는 **캐스트 뒤에** 범위를 본다. NaN·무한대를 `long` 으로
캐스트하는 것은 정의되지 않는다. **스냅 앞에서** 유한성을 확인한다
(교차검토 지적).

## 5. `z` 도 같은 줄에 있다

`(dst).z = (unsigned long)VB->Win.data[idx][2];` 도 같은 캐스트다.
깊이 측정(`M1_4A7` §10)에서 이 절단은 **−0.43 코드**로 재어 놨다.
반올림하면 평균 0 근처로 가야 한다.

**z 도 같은 스냅을 쓰되, `eps` 는 따로 잰다** — 깊이는 값이 65535 까지 가고
ULP 도 그만큼 크다. x·y 의 `eps` 를 그대로 쓰면 안 된다. 계기가 `win[2]` 도
기록하므로 **먼저 z 의 잡음을 재고** 고른다.

그리고 교차검토가 이 방향의 위험을 짚었다: 정점 z 를 최근접으로 바꾸면
오차가 `[-0.5,+0.5]` 가 되는데, **출력 절단이 불연속**이라 양의 오차가
코드 경계를 넘으면 지금보다 한 코드 높아질 수 있다. 예: 정확한 깊이가
100.51 인 화소는 지금 100(맞음), 정점을 올리면 101(틀림).

**그러므로 깊이는 평균 잔차로 판정하지 않는다** — 화소별 코드와 **가시성**
(두 층, 코드 경계와 클램프 경계 양쪽)으로 본다. 스냅이 경계 안에서만
움직이므로 이 위험은 작아야 하지만, **작아야 한다에 기대지 않는다.**

## 6. 성공/실패 기준 (숫자를 미리 적는다)

- **좌표 탐침**: **인코딩된 좌표가 요청한 정수와 같을 것** — 양방향 모두.
  "잃는 위치 0" 만 보면 `N+ε → N+1` 이 안 잡힌다(교차검토). 그리고 뷰포트
  원점·홀짝 크기를 바꿔 가며 훑는다. 한 설정의 320x240 스윕은 근거가 얇다.
- **커버리지**: 도형 4 가 규칙과 **11546 = 11546** 으로 맞아야 한다
  (지금 11629, 초과 83).
- **회귀 없음**: 도형 1·2·3·5·6·7 의 커버리지가 계속 규칙과 일치.
  `coverage-compare.py` 가 「nothing to report」.
- **깊이**: 도형 1·2 의 중심 잔차 −0.92 → **−0.5 근처**, 도형 3 은 −0.53
  그대로(그 정점은 이미 정수라 바뀔 것이 없다 — 이건 **대조군**이다).
- **소수 좌표**: 경계를 둔 스냅은 B 를 **바꾸지 않으므로**, 소수 기하의
  결과가 **한 화소도 변하지 않아야** 한다. 변하면 `eps` 가 너무 크다.
  이게 무조건 반올림보다 훨씬 강한 기준이다 — "덜 벗어난다"는 총합 기준은
  경우별 퇴행을 숨긴다(교차검토).
- **마스크로 본다**: `11546 = 11546` 같은 개수 일치는 옮겨진 영역을 숨긴다.
  대칭차로 본다.

## 7. 안 하는 것

- **B 를 제대로 고치는 것**(소수부를 살려 AR 인코딩에 싣기). 크고, 커버리지
  규칙을 다시 세워야 하며, 별도 계획이 필요하다. 이번은 A 다.
- 클램프(`M1_4A7` §10-3). 별건.

## 8. 결과 (2026-08-21) — 기준을 전부 충족

`eps` 는 각 범위의 ULP 에서 골랐다. 깊이 잡음을 **먼저 재고** 정한 것이
값을 했다 — x·y 의 최악은 `1.5e-5` 인데 깊이는 `9.8e-4` 로, 처음 제안한
`1/4096` 을 **넘는다.**

```
   좌표  1/512  = 8192 에서의 ULP 의 2 배,  반 화소보다 256 배 작다
   깊이  1/32   = 65535 에서의 ULP 의 4 배, 반 코드보다  16 배 작다
```

| 기준 | 결과 |
|---|---|
| 83 화소짜리 도형이 규칙과 맞을 것 | **11629 → 11546 = 11546** |
| 다른 도형에 회귀 없을 것 | 도형 1·2·3 그대로 규칙과 일치, 7 도형 스윕 깨끗 |
| 깊이 −0.92 → −0.5 근처 | **−0.921 → −0.504, −0.937 → −0.518** |
| 정점 깊이가 이미 정수인 도형은 **안 움직일 것** | **−0.525 → −0.525** (대조군) |
| 소수 기하가 **한 화소도 안 변할 것** | **`hardware(8) == hardware(1)`, 0 화소** |

마지막 줄이 이 회차의 요점이다. 무조건 반올림이었다면 소수 기하가 움직였을
것이고, 재 보니 그 움직임은 **15% 의 경우에서 더 나빠지는** 것이었다.
경계를 둔 스냅은 A 를 완전히 고치고 B 를 **손대지 않는다.**

### 8-1. 보고에 드러난 것 — 회귀가 아니다

`coverage-compare.py` 가 도형 8(소수 좌표)의 179 행을 짚는다. 그건 스냅이
만든 것이 아니라 **B 그 자체**다: 하드웨어는 180.5 를 180 으로 바닥내려
삼각형이 짧아지고, 소프트웨어는 소수부를 유지한다. 스냅 전에도 있었고
스냅이 건드리지 않았다(위 표의 마지막 줄).

정확한 소수 정점으로 계산한 규칙에 대면 하드웨어는 누락 100·초과 180,
소프트웨어는 누락 0·초과 179 다. **소프트웨어의 초과 179 는 따로 볼 일이다**
— 꼭짓점이 정확히 반 화소에 있어 변이 화소 중심을 지나므로 동률 규칙이
집중적으로 걸리고, 내 신탁의 동률 처리가 Mesa 와 다를 수 있다. 결론이
아니라 **미확인**으로 적어 둔다.

### 8-2. 남은 것

- **B**: 소수부를 AR 인코딩에 싣기. 이제 A 가 빠져서 순수하게 남았다.
- **클램프**(`M1_4A7` §10-3): 도형 4 의 −5.2 코드.
- **Z3**: 출력 절단 −0.5 코드.

## 9. §8-1 의 미확인 항목을 닫았다 (2026-08-21)

"소프트웨어도 정확한 소수 규칙 대비 179 화소 초과 — 내 신탁의 동률 처리가
Mesa 와 다를 수 있다" 고 적어 뒀다. **신탁은 멀쩡했고, 도형이 나빴다.**

도형 8 은 꼭짓점을 정확히 **반 화소**에 둔다. 그러면 변이 화소 중심을
지나고, **화소 중심 200 개가 변 위에 정확히 놓인다.** 거기서는 추상 규칙이
아니라 각 구현의 동률 규약이 결정하고, Mesa 의 규약은 top-left 규칙이
아니라 **자기 11 비트 고정소수점**이다 — "변 위 표본을 전부 포함" 과
2 화소 차이로 맞았다.

오프셋별 동률 수를 세어 확인했다:

```
   +0 (정수) 0,   +1/2 → 200,   +1/4 → 0,   +1/3 → 0,   +37/128 → 0
```

**반 화소만 동률을 부른다.** 그래서 도형 9 를 넣었다 — 같은 삼각형을
`37/128` 만큼 옮긴 것, 큰 소수부인데 동률은 0.

### 9-1. 그러면 B 는 얼마짜리인가

```
   규칙        11240 화소
   소프트웨어  누락    0, 초과   0        <- 정확하다. 신탁도 Mesa 도 맞다.
   하드웨어    누락   60, 초과  20 = 80   (0.7%)
```

**B 는 이 도형에서 0.7% 다.** 도형 8 이 보여준 "누락 100·초과 180" 은
동률 스트레스가 부풀린 값이었다.

그리고 `hardware(9) == hardware(1)` — 절단이 40.289 를 40 으로 보내므로
정수 도형과 같은 그림을 그린다. A 를 고친 지금도 그렇다. **B 는 그대로
남아 있고, 이제 크기를 안다.**

### 9-2. 방법론으로 남길 것

**시험 도형은 조사 대상이 아닌 축에서 극단이면 안 된다.** 반 화소는 절단을
드러내기에 최적이었고 바로 그 이유로 동률에도 최적이었다. 하나를 재려고
고른 극단이 다른 하나를 망친다.
