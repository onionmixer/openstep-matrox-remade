# D2-2e — 배치 (2026-08-28, 코딩 전)

D2-2c/d 가 **삼각형 하나**를 그렸다. 생산으로 가려면 두 가지가 더 필요하다.

## 1. 두 질문 — 그리고 둘뿐이다

**Q1. 한 번의 VERTEX 제출이 프리미티브 여러 개를 나르는가?**
**Q2. run 1 을 다시 내지 않고 파이프에 또 먹일 수 있는가?**

이 둘이 답해지면 배치의 뼈대는 끝난다. 나머지(버퍼 재사용·인터럽트 완료·상태
전이)는 별개 문제이고 §6 에 남긴다.

## 2. 참조는 둘 다 그렇게 한다

**Q1**: Mesa 는 `vertex_dma_buffer` 에 정점을 **누적**하고(`used += bytes`,
`mgaioctl.h:112-115`) 가득 차야 flush 한다. DRM 은 그 버퍼를
`SECADDRESS/SECEND` **한 쌍**으로 통째 제출한다(`mga_state.c:679`,
`length = buf->used`). 즉 **한 제출에 프리미티브 다수가 참조의 정상 동작이다.**

**Q2**: `mga_g400_emit_state` 는 `dirty` 일 때만 상태를 내고,
`emit_pipe` 는 `warp_pipe` 가 **바뀔 때만** 낸다(`mga_state.c:380`).
정상 프레임은 파이프를 켠 채 정점만 반복 제출한다.

**그러므로 이 시험은 새 능력을 묻는 게 아니라 우리 구현이 참조와 같은지 묻는다.**

## 3. 설계

`D2-2c` 구조를 그대로 쓴다. run 1(GENERAL: 파이프 7 + 컨텍스트 + tex0 + 전역 +
클립 + SOFTRAP)은 **한 번만** 낸다. 그 다음:

```
B1   VERTEX  72 dword = 삼각형 3       -> fence(DWGSYNC) -> 검증
B2   VERTEX  48 dword = 삼각형 2       -> fence(DWGSYNC) -> 검증
     (run 1 을 다시 내지 않는다. 파이프는 켜진 채, 상태는 그대로)
suspend + quiesce
```

B1 과 B2 는 할당 안의 **다른 오프셋**을 쓴다 — 버퍼 재사용은 §6 의 별개 질문이고,
여기서 변수를 하나 줄인다.

## 4. 기하 — 색으로 구분한다 (python 확인)

64×64 블록, 클립 4..59. 반개 직각삼각형, 다리 `L` 이면 `L(L+1)/2` 픽셀.

개수만 맞고 자리가 틀린 경우를 잡기 위해서다.

## 6. 범위 밖 (이번에 답하지 않는다)

- **버퍼 재사용/aging** — 같은 메모리를 다시 쓰려면 카드가 다 읽었음을 알아야 한다.
  `DWGSYNC` 펜스가 답이지만 매번 펜스는 생산에서 비싸다.
- **인터럽트 기반 완료** — 지금은 폴링. `IEN` 을 켜려면 핸들러가 필요하다.
- **배치 사이 상태 변경** — `DWGCTL`·텍스처가 바뀌면 무엇을 다시 내야 하는가.
- **펜스 없이 연속 제출** — B1·B2 사이에 일부러 펜스를 둔다. 한 번에 한 변수.
- Mesa 연결.

## 7. 위험 — D2-2c 보다 낮다

새 레지스터 없음, 새 모드 없음, 새 수송 없음. **이미 통과한 경로에 데이터가 더
많이 갈 뿐이다.** 그래도 실패 정책은 §8 그대로 — 아무 레지스터도 더 쓰지 않고,
링·마이크로코드 보유, `stormBusy` 유지, 판정 로그를 스캔보다 먼저, 재부팅 요청.

## 8. codex 에 물을 것

1. Q1/Q2 를 이 형태로 묻는 것이 맞나. 참조 독해(§2)가 정확한가.
2. 한 VERTEX 제출 안에서 프리미티브 사이에 **구분자나 재프로그래밍**이 필요한가.
   특히 `WACCEPTSEQ` 를 프리미티브마다 다시 써야 하나(3-260 의 `seqptr` 서술이
   `seqoff=1` 에서 무관한지).
3. `wvrtxsz=7` 의 **뱅크 회전**이 프리미티브 3 개(72 dword)에 걸쳐 올바른가.
4. B2 를 run 1 없이 내도 되나 — 클립(`CXBNDRY/YTOP/YBOT`)을 다시 내야 하나.
   DRM 은 clip box 마다 다시 내지만 여기선 box 가 안 바뀐다.
5. **warpfifo 깊이**나 1 차 VERTEX 전송 길이에 삼각형 3 개가 넘을 한계가 있나.
6. 부분 그리기가 hang 으로 갈 경로가 있나.
7. 빠진 것.

### 9.1 §2 를 정정한다

참조가 증명하는 것은 **"WARP 파이프를 다시 켤 필요가 없다"** 까지다.
**"컨텍스트도 다시 안 내도 된다" 는 참조가 증명하지 않는다** — 오히려 참조는
버그 우회로 **매번 낸다.** 그리고 참조의 수송은 *1 차 GENERAL 안의 2 차 VERTEX*
인데 B1/B2 는 **1 차 VERTEX 직접**이다. D2-2c 가 그것을 한 번 증명했을 뿐이다.

**그러므로 Q2 는 참조보다 강한 주장이고, 그게 이 시험의 가치다.**
그리고 B2 가 실패하면 처방이 이미 있다 — **배치마다 컨텍스트를 다시 내면 된다.**
참조가 하는 그대로. 실패도 막다른 길이 아니다.

### 9.2 검증을 강화한다

- **정확한 픽셀 맵**과 대조한다. 개수·bbox 가 아니라 **모든 픽셀**을,
  삼각형 밖은 sentinel 인지까지.
- **색 비교는 `& 0x00ffffff`**. 실측이 근거다.
- **B1 통과가 B2 의 전제**. 안 맞으면 거기서 멈춘다.
- **B2 뒤 B1 재검증**.

### 9.3 주소 불변식을 명시한다 (시작 전 assert)

```
B1 시작·끝, B2 시작·끝이 모두 dword 정렬
각 배치 길이가 24 dword 의 배수
시작 != 끝
끝이 물리 연속 64 KiB 할당 안
B1 과 B2 가 겹치지 않는다
B1 끝 != B2 끝            <- 낡은 포인터가 완료로 오독되는 것을 막는다
run 1 목록이 어느 쪽에도 닿지 않는다
```

`PRIMEND` 가 시작보다 앞이거나 할당 밖이면 **카드가 무관한 물리 메모리를
bus-master 한다** — codex 가 지목한 가장 위험한 실패다. 위 불변식이 그것을 막는다.
