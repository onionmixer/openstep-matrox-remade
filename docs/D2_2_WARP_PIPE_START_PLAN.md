# D2-2 — WARP 파이프 기동

기준일: 2026-08-19
상태: 계획. **codex 교차검토 1회 완료(2026-08-19)** 후 개정판.
초판의 봉쇄 주장이 과했고(§3-1), 음성 대조가 빠져 있었다(§3-0).

D2-1에서 마이크로코드가 연속 물리 메모리에 자리를 잡고 주소표가 만들어졌다.
아직 **카드가 그것을 읽은 적은 없다.** 이 단계가 처음으로 `WIADDR2`에 주소를
준다.

## 0. 범위 — 두 개로 쪼갠다

지금까지와 성격이 다르다. 삼각형 하나를 그리려면 파이프 기동 + 컨텍스트 상태
+ 텍스처 상태 + 정점 버퍼(2차 DMA)가 전부 필요하고, 그것을 한 번에 하면
실패했을 때 **어디가 틀렸는지 알 수 없다.**

| 단계 | 묻는 것 | 그리는가 |
| --- | --- | --- |
| **D2-2a** | 파이프를 기동해도 엔진이 살아 있는가 | 아니오 |
| **D2-2b** | 삼각형이 나오는가 | 예 |

**이 문서는 D2-2a만 확정한다.** D2-2b는 D2-2a 결과를 보고 별도 계획서로 쓴다.

## 1. 확인된 사실

### 1-1. 파이프 emit은 전부 primary DMA로 보낼 수 있다

`mga_g400_emit_pipe`(`mga_state.c:272-352`)가 쓰는 레지스터를 전부 DMA 창에
대조했다:

| 레지스터 | 오프셋 | 그룹/인덱스 |
| --- | --- | --- |
| `WVRTXSZ` | 0x1dcc | 0 / 0x73 |
| `WACCEPTSEQ` | 0x1dd4 | 0 / 0x75 |
| `WIADDR2` | 0x1dd8 | 0 / 0x76 |
| `WFLAG` | 0x1dc4 | 0 / 0x71 |
| `WFLAG1` | 0x1de0 | 0 / 0x78 |
| `WR49/52/53/54/56/57/60/61/62` | 0x2dc4~0x2df8 | 1 / 0xf1~0xfe |

**하나도 빠짐없이 주소지정 가능하다.** 즉 D1에서 만든 링과 조립기를 그대로
쓴다. `OPMODE`처럼 MMIO로 빼야 하는 것이 없다.

### 1-2. 단일 텍스처 파이프(TGZ=0)의 emit 순서

이전 파이프가 T2가 아니면 플러시 분기를 타지 않으므로 7블록이다:

```
1  WIADDR2=SUSPEND,          DMAPAD ×3
2  WVRTXSZ=0x00001807,       DMAPAD ×3
3  WACCEPTSEQ=0 ×3,          WACCEPTSEQ=0x18000000
4  WFLAG=0, WFLAG1=0, WR56=0x46480000, DMAPAD
5  WR49=0, WR57=0, WR53=0, WR61=0
6  WR54=0x40, WR62=0x40, WR52=0x40, WR60=0x40      (MGA_G400_WR_MAGIC = 1<<6)
7  DMAPAD=0xffffffff ×3,     WIADDR2 = pipe0_phys | WMODE_START
```

7번 블록의 `DMAPAD 0xffffffff` 3개는 DRM이
*"Padding required to to hardware bug"* 라고 적어둔 회피책이며
(`mga_state.c:343`), **D1의 tail 패딩과는 별개다.** 값도 0이 아니라
`0xffffffff`다.

우리는 파이프를 처음 설정하므로 T2 플러시 분기(`mga_state.c:298-315`)를 타지
않는다. 근거: 분기 조건은 **이전** 파이프(`dev_priv->warp_pipe`)의 T2 비트인데,
`dev_priv`는 할당 직후 `memset(dev_priv, 0, ...)`으로 0이 된다
(`mga_dma.c:409`). `0 & MGA_T2 == 0`이므로 플러시가 없다.

### 1-2-1. DRM의 캐싱을 그대로 따르지 않는다 (의도적)

`mga_g400_emit_state`는 **요청 파이프가 이전 파이프와 다를 때만**
`mga_g400_emit_pipe`를 부른다(`mga_state.c:380`). 그런데 `dev_priv->warp_pipe`
초기값이 0이므로, **파이프 0을 처음 요청하면 `0 != 0`이 거짓이라 emit 자체가
건너뛰어진다** — 즉 그 경로에서는 `WIADDR2`에 `WMODE_START`가 영영 쓰이지
않는다.

DRM에서 이것이 문제가 되지 않는 이유는 우리가 확인할 수 없다(Mesa가 어떤
파이프를 먼저 요청하는지에 달렸다). **우리는 캐싱을 흉내내지 않고 무조건
emit한다.** 조건부 생략은 "왜 안 그려지지"를 만드는 종류의 최적화이고, 지금
단계에서 얻을 것이 없다.

### 1-3. `wagp_enable`은 PCI에서 0

`WIADDR2 = warp_pipe_phys[pipe] | WMODE_START | dev_priv->wagp_enable`인데
PCI bootstrap 경로는 `dma_access = 0`과 `wagp_enable = 0`을 함께 설정한다
(`mga_dma.c:699`). 즉 **`phys | WMODE_START(3)`만 쓴다.**

주의: **구형/비-bootstrap init 경로는 AGP 비트를 설정한다**(`mga_dma.c:842`).
우리는 PCI bootstrap 쪽 값에 묶여 있어야 하며, 두 경로를 섞어 읽으면 안 된다.

### 1-4. 정점 없는 기동은 **DRM이 만들어내지 않는 구성**이다

실제 그리기는 `SECADDRESS`/`SECEND`(둘 다 그룹1)에 정점 버퍼를 실어야
일어난다(`mga_state.c:675`). D2-2a는 그것을 하지 않는다.

**다만 이것을 "DRM 경로의 부분집합"으로 오해하면 안 된다.** DRM에서 파이프
emit은 오직 정점 dispatch 안에서, `buf->used`가 0이 아닐 때만 도달하며
(`mga_state.c:653`, `:667`), 같은 DMA 스트림에서 곧바로 `SECADDRESS`/`SECEND`가
뒤따른다(`:675`). 즉 **정점 없이 파이프만 기동된 상태는 원본 스택이 한 번도
만들지 않는 구성**이다.

우리가 그렇게 하는 이유는 위험 분리다 — 실패했을 때 파이프 기동과 정점 처리
중 어느 쪽인지 구분하기 위해서다. 그 대가로 **선례 없는 상태에 들어간다는
것**을 알고 들어간다.

## 2. 가장 큰 미지수

**파이프를 기동하면 엔진이 살아 있는가.** 부수 미지수:

- 마이크로코드가 이 칩에서 유효한가. 바이트가 그대로 있다는 것과 칩이
  그것을 실행한다는 것은 다른 이야기다(D2-1 §7-2).
- 정점 없이 기동된 WARP가 무엇을 하는가. **문서화된 바 없다.**
  대기할 것으로 보지만 근거는 없다.

## 3. 단계

### 3-0. D2-2a-neg — 음성 대조 (마이크로코드를 가리키지 않음)

codex 제안을 채택한다. **같은 링을 조립하되 마지막 `WIADDR2`에
`WMODE_SUSPEND`를 쓴다.** 그러면 WARP 레지스터 쓰기의 인코딩과 순서가
DMA로 제대로 전달되는지를 **파이프를 기동하지 않고** 확인할 수 있다.

그 다음 진짜 프로브는 **값 하나만 바뀐다** — 마지막 `WIADDR2`가
`pipe0_phys | WMODE_START`가 된다. D1의 음성 대조(`PRIMEND`만 보류)와 같은
구조이며, 같은 이유로 두 경로는 같은 조립 코드를 써야 한다.

**검증**: 링 완료(`PRIMADDRESS`가 tail 도달, `SOFTRAP` 발화), `WMISC` 유지,
2D 회귀 없음. 여기서 실패하면 **마이크로코드를 가리키기 전에** 인코딩 문제를
잡은 것이다.

### 3-1. D2-2a — 파이프 기동, 정점 없음

D1의 링 조립기·기동 경로를 재사용한다. 링 내용만 §1-2의 7블록 + `SOFTRAP` +
tail 패딩으로 바꾼다.

절차:
1. 마이크로코드 배치(D2-1b와 동일) — **버퍼를 해제하지 않는다**
2. `warp_init` 재실행, `WMISC == 0x3` 확인
3. 2D 엔진 idle 대기, stale `SOFTRAP` 정리
4. 링 조립 → 스토어 가시성 배리어 → `PRIMADDRESS`/`PRIMEND` 기동
5. bounded 폴링으로 완료 대기(D1과 같은 3조건)
6. `WIADDR2 = WMODE_SUSPEND`를 **MMIO로** 써서 파이프를 세운다
7. 마이크로코드 버퍼는 **부팅 동안 보유**한다

**검증 방법**
- V2a-1: 링이 완료되는가 — `PRIMADDRESS`가 tail 도달, `SOFTRAP` 발화,
  드로잉 엔진 idle. 이것이 증명하는 것은 **primary 명령 파서가 우리 패킷을
  소비하고 끝까지 갔다**는 것뿐이다. **WARP가 유효한 마이크로코드를
  가져왔다거나 안전하게 대기 중이라는 증거가 아니다.**
- V2a-2: `WMISC`가 기동 후에도 `0x3`인가 — WARP 설정이 무너지지 않았다는
  **표시**이지 파이프가 정상이라는 증명은 아니다. 소스에 읽을 수 있는 WARP
  상태는 이것뿐이다(`STATUS`는 SOFTRAP/DWG/primary-DMA 비트만 노출).
- V2a-3: 기동 직후와 suspend 후의 `WIADDR2` 되읽기를 각각 기록. 되읽기
  의미론이 증명된 바 없으므로 **판정 기준으로 쓰지 않고 관찰만 한다.**
- V2a-4: 2D 회귀 — S1/S2/S3/D1-2가 같은 부팅에서 전부 통과하는가.
  **WARP 기동이 2D 엔진을 망가뜨리지 않았다는 증거.**
- V2a-5: 화면 무변화, `revertToVGAMode` 정상, telnet 생존.

### 3-2. 봉쇄 — 초판보다 약하게 서술한다

초판은 "정점을 주지 않으므로 프레임버퍼에 쓸 경로가 열리지 않는다"고 적었다.
**증명되지 않은 주장이다.** 정확히 말하면:

- **성립하는 것**: `SECADDRESS`/`SECEND`(및 `SETUPADDRESS`/`SETUPEND`)가 없으면
  DRM이 쓰는 **정상 정점 제출 경로**는 없다.
- **성립하지 않는 것**: "따라서 카드가 아무 데도 쓸 수 없다." 이 단계는
  **불투명한 마이크로코드를 카드가 보이는 메모리에서 처음 실행**시키는
  것이고, 칩과 마이크로코드 조합이 틀렸을 때 내부적으로 무엇을 하는지는
  소스가 답해주지 않는다.

실제로 기대는 봉쇄는 다음 셋이다:
- 조립기 화이트리스트 — `PRIMADDRESS`/`PRIMEND`/`OPMODE`/`WMISC`는 링에
  인코딩 자체가 불가능하다.
- 음성 대조(§3-0)가 먼저 돌아 인코딩 문제를 걸러낸다.
- 실패 시 재시도하지 않고, 마이크로코드 버퍼를 **해제하지 않는다**.

추가로, `WIADDR2 = WMODE_START` 블록 **뒤에** `WIADDR2 = WMODE_SUSPEND`
블록을 하나 더 넣어 `SOFTRAP` 앞에 둔다. 이는 wedge된 WARP를 구해준다는
보장이 아니라, primary 파서가 계속 진행되는 경우 **의도한 실행 구간을
짧게 만드는** 조치다(codex 제안).

### 3-3. G450 위험을 명시해 둔다

legacy UAPI에 `MGA_CARD_TYPE_G450`이 있으나 **"not currently used"**로
표시돼 있고(`mga_drm.h:77`), WARP 설치·초기화는 G400/G550만 분기한다
(`mga_warp.c:85`, `:174`). X.Org는 `0x0525` rev ≥ 0x80을 G450이라 부르면서도
DRI에 chipset 2(G400)를 넘긴다(`mga_driver.c:285`, `mga_dri.c:570`).
**당대 스택이 G400 마이크로코드로 G450을 돌린 근거는 되지만, 보장은 아니다.**

## 4. 중단 조건

- 링이 완료되지 않음(폴링 타임아웃) → WARP 기동이 DMA를 막은 것
- `WMISC`가 `0x3`이 아니게 됨
- 2D self-test 회귀
- 화면 이상

어느 것이든 **D2-2b로 가지 않는다.**

## 5. D2-2b 스케치 (이 문서의 범위 밖)

필요한 것: G400 컨텍스트 emit(`DSTORG`/`MACCESS`/`PLNWT`/`DWGCTL`/`ZORG`/
`ALPHACTRL`/`FOGCOL`/`WFLAG`/`TDUALSTAGE0/1`/`FCOL`/`STENCIL`/`STENCILCTL`,
그리고 G400 전용 **DWGCTL 강제 리셋 쌍**(`MGA_LEN+MGA_EXEC = 0x80000000`,
`mga_state.c:60-64` — clip disable 비트를 지우기 위한 것)), 텍스처 emit,
클립 사각형, 그리고 `SECADDRESS`/`SECEND`로 실을 정점 버퍼. 정점 형식은
`WVRTXSZ=0x1807`이 규정한다.

## 6. 이 계획이 결정하지 않은 것

- D2-2a가 통과했을 때 D2-2b를 바로 할지, 아니면 컨텍스트 emit만 먼저
  검증할지.
- 마이크로코드 버퍼를 부팅 동안 보유하는 것이 다른 ISA DMA 사용자에게
  주는 영향. 24 KiB이고 아레나 크기는 여전히 측정된 바 없다.
