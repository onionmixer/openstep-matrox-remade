# W7 — 남은 항목에 대한 참조 증거

W6 §9.6 이 남긴 여섯 항목을 참조 소스로 조사한 기록이다. **하드웨어를 전혀
건드리지 않았다.** 항목 2 는 W6 §9 에서 이미 끝났으므로 나머지 다섯이다.

---

## 1. SEC 트리거 의미론 — **강한 정황이지 답이 아니다**

> **이 절의 초판은 "레지스터 레이아웃이 답을 준다" 는 제목이었고, 그 표현이
> 위험했다.** codex 의 지적이 정확하다: 그렇게 적어 두면 **나중에 이 문서를
> 읽는 사람(나 포함)이 §7 이 금지한 `SECADDRESS` 실험을 여는 근거로 쓸 수
> 있다.** 계획서 §4 가 처방하고 §7 이 금지해서 일곱 번째 프리즈를 만든 것과
> **똑같은 모양**이다. 그래서 제목과 결론을 모두 약화한다.

W6 §2 가 "미지이며 현재 시험 불가" 로 남긴 것이다. 레지스터 레이아웃과 참조의
관행이 **한 방향을 강하게 가리키지만, 그것으로 금지가 풀리지는 않는다.**

### 1.1 세 END 레지스터

| 레지스터 | 비트 0 | 비트 1 | 비트 2-31 |
| --- | --- | --- | --- |
| `PRIMEND` 0x1e5c | **`primnostart`** | `pagpxfer` | 주소 |
| `SECEND` 0x2c44 | *(없음)* | `sagpxfer` | 주소 |
| `SETUPEND` 0x2cd4 | *(없음)* | `agpxfer` | 주소 |

`nostart` 를 전수 검색하면 **`primnostart` 만 나오고 `secnostart` 도
`setupnostart` 도 없다.**

> **초판은 이것을 "두 헤더가 독립적으로 같은 것을 적는다" 고 썼다. 틀렸다.**
> 두 파일 모두 첫 줄이 `/* author: stephen crowley, crow@debian.org */` 이고
> 자동 생성 레지스터 파일이다. **같은 출처의 두 스냅샷이지 독립 확인이
> 아니다.** 확인은 하나뿐이다.

### 1.2 그리고 ADDRESS 쪽에는 모드가 있다

| 레지스터 | 비트 0-1 |
| --- | --- |
| `PRIMADDRESS` | `primod` (general/blit/vector/vertex) |
| `SECADDRESS` | `secmod` (같은 넷) |
| `SETUPADDRESS` | `mode` |

**ADDRESS = 설정(어디를, 어떤 형식으로). END = 방아쇠(어디까지, 그리고 출발).**

### 1.3 추론, 그리고 그것을 뒷받침하는 둘

**`PRIMEND` 에 "출발하지 말 것" 비트가 있다는 사실은, 그 레지스터를 쓰는 것이
평소에는 출발시킨다는 뜻이다.** 그렇지 않으면 그 비트가 존재할 이유가 없다.

뒷받침 1: DRM 의 IRQ 핸들러가 DMA 를 **재출발시킬 때 `PRIMEND` 를 다시 쓴다**
(`mga_irq.c:81`). `PRIMADDRESS` 가 아니다. ADDRESS 가 방아쇠라면 END 재기록은
아무것도 재출발시키지 못한다.

뒷받침 2 — **초판이 여기서 틀렸고, 틀린 방향이 나쁘다.** 초판은 *"그 사이
창에서 아무 일도 안 일어나는 것을 A0 만 세어도 86,554 회 관측했다"* 고 썼다.
**A0 는 그것을 관측하지 않는다.** A0 는 완료 예측이 성립한 **뒤에만**
`PRIMADDRESS` 를 읽는다(`:5911` 의 `if (spins3 < limit3)`). 두 쓰기 사이 창은
본 적이 없다.

**실제 증거는 D1-2 의 음성 대조 하나다**(`:6739`):

```c
/* Negative control.  PRIMADDRESS on its own selects the list and the
 * transfer mode; it does not start anything ... */
osmgaW32(base, MGA_PRIMADDRESS, phys | MGA_DMA_GENERAL);
for (spins = 0; spins < LIMIT/10; spins++) (void)osmgaR32(base, MGA_ENGSTATUS);
/* 블록이 여전히 sentinel 이어야 한다 */
```

**통과했다**(`D1_PRIMARY_DMA_RING_PLAN.md` §7). 즉 **1 차 채널에서, 한 번,
ADDRESS 단독이 아무것도 시작하지 않음을 실측했다.** 86,554 이 아니라 1 이고,
2 차가 아니라 1 차다. **초판은 증거를 8 만 배 부풀렸다.**

**그래서 말할 수 있는 것은 여기까지다**: 참조는 `PRIMEND` 를 1 차의
시작·재시작 발행 레지스터로 다루고, `SECADDRESS` 를 항상 `SECEND` 보다 먼저
쓰며, SEC 쪽에 알려진 "출발 금지" 인코딩은 없다.

**말할 수 없는 것**: "`SECEND` 를 쓰면 반드시 발사된다" 도, "`SECADDRESS` 가
낡은 END 와 상호작용하지 않는다" 도 **증명되지 않았다.** 1 차에는 wrap·트랩
재시작·포인터 기계가 있고 SEC 레이아웃에는 없다 — **대칭이 완전하지 않으므로
`secnostart` 의 부재가 대칭 증명이 되지 못한다.**

### 1.5 세 번째 구현 — 출하 Windows 드라이버 (2026-08-28)

`scratch/matrox-win/G400DD32.dll` 를 정적으로 봤다. **검색법을 먼저 검증했다** —
`89 ?? 00 1D 00 00`(= `mov [reg+0x1d00], reg`)이 W1 §V-5 가 나열한
`DWGCTL` 열한 곳을 **주소까지 그대로** 재현한다(`baa156ca`, `baa184db`,
`baa1ab4d`, `baa25f1d`, `baa28836`, `baa41e3a`, …).

> **첫 시도는 틀렸고 대조가 잡았다.** `op_any` 로 변위를 찾으려 했더니 0x1d00
> 조차 0 이 나왔다 — 그 도구는 변위를 매칭하지 않는다. 그다음 `40 2C 00 00`
> 바이트 검색은 12 곳을 냈는데 **전부 거짓 양성**이었다: `[eax+0x2c]` 변위
> 뒤에 `00 00` 으로 시작하는 즉시값이 온 것이지 0x2c40 이 아니었다.
> **대조 없이 그 12 나 그 0 을 믿었으면 둘 다 틀렸다.**

검증된 검색법으로 센 결과:

| 레지스터 | MMIO 쓰기 |
| --- | --- |
| `PRIMADDRESS` 0x1e58 | **2** |
| `PRIMEND` 0x1e5c | **4** |
| `OPMODE` 0x1e54 | 0 |
| **`SECADDRESS` 0x2c40** | **0** |
| **`SECEND` 0x2c44** | **0** |
| `WIADDR2` 0x1dd8 | 1 |

그리고 디코딩하면 그 여섯이 이렇게 갈린다:

```
baa3fb5d   mov [eax+1E58h], ecx    ; PRIMADDRESS
           or  edx, ecx            ; 끝값에 모드 비트를 얹는다
           mov [eax+1E5Ch], edx    ; PRIMEND        <- 쌍으로
baa3ffca   같은 모양 (PRIMADDRESS -> PRIMEND, 11 바이트)

baa3fd3f   mov [eax+1E5Ch], edx    ; PRIMEND 단독
baa3feda   mov [eax+1E5Ch], edx    ; PRIMEND 단독
```

**PRIMADDRESS 는 스트림을 (재)설정할 때만, PRIMEND 는 일을 더 낼 때마다.**
DRM 의 IRQ 가 `PRIMEND` 재기록으로 재출발시키는 것과 같은 그림이고,
**독립적인 세 번째 구현이다.**

### 1.6 그리고 새 사실 하나 — 아무도 SEC 를 MMIO 로 쓰지 않는다

| 구현 | `SECADDRESS`/`SECEND` 를 MMIO 로 쓰는가 |
| --- | --- |
| DRM | **아니다** — 1 차 목록 안에서 쓴다 |
| XFree86 DRI / DDX | **아니다** — 아예 안 쓴다 |
| Windows G400DD32 | **아니다** — 직접 쓰기 0 |

**우리 구조는 `PRIMADDRESS`/`PRIMEND` 를 MMIO 로 쓰므로, 2 차도 같은 방식으로
쓰고 싶어진다. 그러면 어느 구현도 해 본 적 없는 일을 하는 것이다.**

> **그러므로 설계 규칙 하나가 참조로 뒷받침된다: `SECADDRESS`/`SECEND` 는
> 1 차 목록 안에서만 낸다.** W6 §3.2 가 그렇게 적었고, 근거가 "DRM 이
> 그러니까" 에서 "**세 구현 중 아무도 다르게 하지 않았으니까**" 로 강해졌다.

### 1.4 W6 §2 의 위험 가설이 어떻게 되는가

W6 은 이렇게 적었다:

> `SECADDRESS` 가 **이전 `SECEND` 값에 대해** 시작할 수 있다면 →
> 모든 실제 제출에 stale-end 창이 있다

**§1.3 이 그 가설을 약화하지만 반박하지는 못한다.** 근거는 레지스터
레이아웃(출처 하나) + IRQ 의 재출발 방식 + **1 차 채널의 음성 대조 한 번**이다.
셋 다 1 차에 대한 것이고, **2 차에 대한 직접 증거는 여전히 없다.**

> **금지는 유지된다.** W6 §2 가 요구한 "문서·더 강한 참조 증거·안전한 유계
> 실험" 중 **두 번째에 부분적으로만** 해당한다. 이 절을 근거로
> `SECADDRESS` 실험을 열면 안 된다.

## 3. WARP 정지 — **정상 경로의 일부이고, 우리는 이미 써 봤다**

### 3.1 네 가지 모드

```
WIADDR2 (0x1dd8) 비트 0-1:
  WMODE_SUSPEND 0   WMODE_RESUME 1   WMODE_JUMP 2   WMODE_START 3
```

### 3.2 DRM 은 파이프를 바꿀 때마다 이 순서를 낸다

`mga_g400_emit_pipe`, **1 차 DMA 스트림 안에서**:

```
1  WIADDR2 = WMODE_SUSPEND                     <- 세운다
2  WVRTXSZ, WACCEPTSEQ, WR* 레지스터 재프로그래밍
3  DMAPAD 0xffffffff x3                        <- "Padding required to to hardware bug"
4  WIADDR2 = warp_pipe_phys[pipe] | WMODE_START <- 출발
```

**초기화가 아니라 렌더링 중 정상 경로다.** SUSPEND 는 재프로그래밍의 전제
상태이지 예외 처리가 아니다.

### 3.3 우리 기계에서 이미 쓴 적이 있다

`OpenStepMGAReplacementDisplay.m:6886,6889` 이 WMISC 프로브 전후로
`WIADDR2 = WMODE_SUSPEND` 를 **MMIO 로** 쓴다. D2-0a 가 실기 PASS 했다.

**그러므로 이 쓰기 자체는 이 카드에서 안전한 것으로 실측됐다** — 적어도 WARP 가
이미 서 있을 때는.

### 3.4 그러나 무장 해제로는 검증되지 않았다

- DRM 은 SUSPEND 를 **정상 상태 전이**로만 쓴다. **오류 경로에서 쓰는 곳이
  없다.**
- 그 순간 **앞선 2 차 전송의 입력은 배수됐다**(파서가 그 블록에 도달했으므로,
  W6 §9.2). **초판은 이것을 "스트림이 정숙하다" 로 적었는데 과했다** —
  W6 §9.3 이 이미 적었듯 2 차 읽기 완료와 WARP·래스터 완료는 다른 것이고,
  SUSPEND 시점에 하류가 서 있다는 증거는 없다.
- START 직전의 `0xffffffff` 패딩 세 개에 *"Padding required to to hardware
  bug"* 가 붙어 있다. **무엇을 막는 것인지는 어느 참조에도 없다** — 파서의
  패킹 동작인지, WARP 설정과 START 사이 지연인지, 주소 래치인지, START 전이
  자체인지. `mga_dma.c:132` 의 0 패딩(G400 매뉴얼 4-16 인용)은 **다른
  회피책**이고 이것의 설명이 아니다. 아는 것은 "저자가 이 자리에 회피책이
  필요하다고 여겼다" 까지다.

### 3.5 Windows 드라이버도 MMIO 로는 세우지 않는다 (2026-08-28)

같은 검증된 검색법으로(§1.5) `G400DD32.dll` 의 WARP 레지스터를 셌다:

| 레지스터 | MMIO 쓰기 |
| --- | --- |
| `WVRTXSZ` 0x1dcc | 2 |
| `WGETMSB` 0x1dc8 | 2 |
| **`WIADDR2` 0x1dd8** | **1** |

그 하나를 디코딩하면 `baa35700` 부근이 이렇다:

```
mov ecx, [eax+1E10h]   ; FIFOSTATUS
and ecx, 1Fh
cmp cl, 1
jb  -14                ; FIFO 자리가 날 때까지 돈다
mov ecx, 3             ; 모드 3 = WMODE_START
mov [eax+1DD8h], ecx   ; WIADDR2
```

**FIFO 를 기다린 뒤 START 를 쓴다. SUSPEND(0)를 MMIO 로 쓰는 곳은 없다.**

> 값이 `3` 이라 주소 비트가 0 인 것은 이 정적 판독으로 설명하지 못한다.
> 마이크로코드가 어디에 놓이는지, WIADDR2 가 어떤 기준의 주소를 받는지
> 안 봤다. **모드 필드가 3(START)이라는 것까지만 말한다.**

### 3.6 판정

| 구현 | WARP SUSPEND 를 어디서 내는가 |
| --- | --- |
| DRM | **1 차 DMA 스트림 안**, 파이프 변경 시 |
| XFree86 DRI | 같음(같은 코드 계열) |
| Windows G400DD32 | **내지 않는다.** MMIO WIADDR2 쓰기는 START 하나뿐 |
| 우리 | MMIO 로 SUSPEND, **단 WARP 가 이미 서 있을 때**(D2-0a) |

**달리는 WARP 를 MMIO 로 세우는 것은 어느 구현도 하지 않는다.** W6 §1.4 가
이것을 "리셋보다 좁은 무장 해제 후보" 로 지목했는데, **좁은 것은 맞지만
전례가 없는 것도 마찬가지다.** 쓰기 자체가 우리 카드에서 통과한 것
(D2-0a)은 **WARP 가 서 있을 때의 사실**이지 달릴 때의 사실이 아니다.

## 4. WARP 봉쇄 — **클립은 WARP 경로에도 쓰인다**

W6 §4 는 "클립 측정이 WARP 까지 일반화되지 않는다" 로 축소했다. **참조가
그 간극을 좁혀 준다.**

`mga_emit_clip_rect` 는 `CXBNDRY`/`YTOP`/`YBOT` 를 1 차 스트림으로 쓰고,
**정점 디스패치(`:671`)와 인덱스 디스패치(`:718`) 둘 다 그것을 호출한다.**
그 둘이 곧 WARP 를 먹이는 경로다.

G400 에서는 `DWGCTL` 을 다시 써서 `CLIPDIS` 를 지우기까지 한다
(`mga_state.c:58`) — **클립이 듣게 만들려는 의도가 명시적이다.**

**그러나 이것이 증명하는 것은 의도와 정상 동작이지 봉쇄가 아니다.**

- 인덱스 경로는 `SECADDRESS` 가 아니라 **`SETUPADDRESS`/`SETUPEND`** 를 쓴다.
  둘 다 "WARP 를 먹인다" 는 것은 그럴듯한 구조 추론이지 문서화된 계약이 아니다.
  **W6 §9.1 이 "2 차 레지스터가 디스패치 두 곳에 나온다" 고 쓴 것도 이 점에서
  틀렸다** — 정점 하나뿐이다. (W6 §9 의 aging 논증 자체는 정점 루프만으로
  성립하므로 결론은 유지된다.)
- 커널의 검증은 `nbox` 를 배열 크기로 clamp 할 뿐 **각 클립 사각형의 좌표를
  검증하지 않는다**(`mga_state.c:443`). 즉 참조의 클립은 **적대적 클라이언트에
  대한 봉쇄 증명이 아니다.**
- 잘못된 WARP 레코드·NaN·셋업 오버플로·깨진 마이크로코드가 래스터 클립을
  우회할 수 없다는 것은 **아무 데도 없다.**

**남는 것은 그대로 남는다**: 클립은 **목적지 쓰기**를 묶지, 2 차 DMA 의 시스템
메모리 읽기·마이크로코드 읽기·텍스처 읽기를 묶지 않는다.

| 읽기 경로 | 무엇이 묶는가 |
| --- | --- |
| 2 차 정점 전송 | `SECADDRESS`/`SECEND` — **연속 범위 하나** |
| setup 요소 목록 | `SETUPADDRESS`/`SETUPEND` |
| WARP 마이크로코드 | `WIADDR2` 는 **시작 주소일 뿐 끝이 없다** |
| 텍스처 | `TEXORG`/`TEXWIDTH`/`TEXHEIGHT`/`TEXCTL` — 논리 치수 제어이지 **할당 한계 레지스터가 아니다** |

**WARP 가 닿을 수 있는 메모리 전체를 묶는 레지스터는 소스에서 찾지 못했다.**
커널은 `TEXORG` 의 `SYSMEM|PCI` 조합 하나만 거부하고, 원점과 치수를 할당된
텍스처 객체와 대조하지 않는다.

### 4.1 Windows 드라이버도 같은 레지스터를 쓴다 (2026-08-28)

| 레지스터 | MMIO 쓰기 |
| --- | --- |
| `CXBNDRY` 0x1c80 | 1 (`baa61e24`) |
| `YTOP` 0x1c98 | 1 |
| `YBOT` 0x1c9c | 6 |
| `TEXORG` 0x2c24 | 1 (`baa61eff`) |

`baa61e24`(CXBNDRY) · `baa61e2e`(YBOT) · `baa61ec3`(0x2c00) · `baa61eff`
(TEXORG)가 **한 함수 안에 몰려 있다** — 클립과 텍스처를 함께 세우는 상태
설정 경로로 보인다.

**즉 출하 Windows 드라이버도 3D 상태에 같은 클립 레지스터를 쓴다.** 이것은
§4 의 "참조가 정상 3D 경로에 래스터 클립을 프로그래밍한다" 를 **세 번째
구현으로** 뒷받침한다. **여전히 의도의 증거이지 잘못된 WARP 입력에 대한 봉쇄
증명은 아니다.**

## 5. 수명·모드·클라이언트 — **참조에 구멍이 여럿이다. 베끼면 안 된다.**

### 5.1 정리 경로가 엔진 정지를 증명하지 않는다 — 다만 조건이 붙는다

`mga_do_cleanup_dma`(`mga_dma.c:942`)는 인터럽트를 끄고 곧바로 해제로 간다.
**idle 대기도, DMA 정지도, WARP SUSPEND 도, 인플라이트 검사도 없다.**

> **초판은 "곧바로 WARP 와 1 차 영역을 `drm_core_ioremapfree` 한다" 고 썼다.
> 조건을 빠뜨렸다** — 그 호출은 `type != _DRM_CONSISTENT` 일 때만 일어난다
> (`:958`, `:962`). PCI 경로는 둘 다 `_DRM_CONSISTENT` 로 잡으므로(§6.1)
> **그 unmap 은 건너뛴다.** 실제로 해제·unbind 까지 가는 것은 **AGP 경로**다.

**결함 자체는 남는다**: 어느 경로에서도 **엔진이 멈췄다는 증명이 없고**,
인터럽트 전달을 끄는 것은 엔진을 세우는 것이 아니다. AGP 경로에서는 카드가
아직 읽을 수 있는 메모리를 unmap·unbind·free 한다.

`mga_do_wait_for_idle` 은 소스에 있지만 호출부는 **초기화**(`:907`)와 다른
곳들이지 정리 경로가 아니다. `MGA_CLEANUP_DMA` ioctl 은 곧장
`mga_do_cleanup_dma(FULL_CLEANUP)` 로 간다(`:1029`).

`LOCK_TEST_WITH_RETURN` 이 있지만 그것은 **클라이언트끼리의 직렬화**이지
하드웨어가 멈췄다는 증명이 아니다.

> **W6 §3.3 의 "해제하지 않는다" 는 편집증이 아니라 참조의 정정이다.**

### 5.2 정점 제출의 길이가 검증되지 않는다

`mga_dma_vertex`(`mga_state.c:925`):

```c
buf->used = vertex->used;          /* 유저랜드 값, 그대로 */
```

그리고 `mga_dma_dispatch_vertex`(`:659`):

```c
u32 length = (u32) buf->used;
...  MGA_SECEND, ((address + length) | dev_priv->dma_access)
```

**`used <= buf->total` 검사가 어디에도 없다.** 인증된 DRI 클라이언트가
카드의 2 차 DMA 를 버퍼 끝 너머로 보낼 수 있다.

### 5.3 그리고 인덱스 검사에 off-by-one 이 있다 — **세 곳**

```c
if (vertex->idx < 0 || vertex->idx > dma->buf_count)   /* :920 */
    return -EINVAL;
buf = dma->buflist[vertex->idx];
```

`buflist` 는 `buf_count` 개다(`mga_dma.c:267`, `:324` 가 `i < buf_count` 로
돈다). `idx == buf_count` 는 **한 칸 밖**이고 이 검사는 그것을 통과시킨다.
`>=` 여야 한다.

**같은 실수가 셋이다**: `:920` 정점, `:955` 인덱스, `:998` iload.
바로 옆 `mga_dma.c:1132` 의 `request_count > buf_count` 는 **개수** 비교라
옳다 — 즉 저자가 문맥을 혼동한 것이지 관례가 그런 것이 아니다.

### 5.3a 그리고 셋이 전부가 아니다

codex 가 더 찾았고 확인했다:

- 인덱스 경로의 `start`/`end` 도 검증 없이 `SETUPADDRESS`/`SETUPEND` 로 간다.
- 버퍼를 내줄 때 `buf->file_priv` 를 기록하지만 **정점·인덱스 제출이 소유권을
  대조하지 않는다.**
- WARP 파이프 검증이 `> MGA_MAX_G400_PIPES` 다. 물리 주소 배열은 정확히
  `MGA_MAX_G400_PIPES` 개이므로 **파이프 16 이 통과해 한 칸 밖을 인덱싱한다** —
  §5.3 과 같은 종류의 off-by-one 이 넷째로 있는 셈이다.

**"구멍 셋" 이라고 세면 참조를 과소평가하는 것이다.** 세어 본 것이 셋이지
전수가 아니다.

### 5.4 그래서 우리 규칙

**참조의 정점 경로에서 검증을 베끼면 안 된다 — 검증이 없다.** W6 §7-5 가
요구한 것(오버플로 없는 `start + length`, 0 아닌 유계 길이, 장치 주소 가능성,
정렬, 레코드 배수, `end <= 할당 끝`)은 **참조에 없는 것을 새로 만드는 일**이지
옮겨 오는 일이 아니다.

## 6. 가시성 장벽 — 참조는 **코히런트 할당 + 순서 배리어**로 한다

```c
#define mga_flush_write_combine()   DRM_WRITEMEMORYBARRIER()    mga_drv.h:200
```

호출부 셋, **발행 직전**이다 — 둘은 `PRIMEND` 앞, 하나는 wrap 의
`PRIMADDRESS` 앞이다:

```
mga_dma.c:158   배리어 -> MGA_WRITE(PRIMEND, ...)
mga_dma.c:198   배리어 -> MGA_WRITE(PRIMEND, ...)
mga_dma.c:215   배리어 -> MGA_WRITE(PRIMADDRESS, ...)   (wrap 완료)
```

(초판은 셋 다 "도어벨" 이라고 썼다. 셋째는 wrap 의 포인터 되돌리기다.)

**우리는 같은 자리에서 148.7 KiB 짜리 체크섬 되읽기를 한다**(`:5752`).

> **초판은 그것이 §22 의 0.35 ms 의 "대부분" 이라고 썼다. 근거가 없다.**
> §22 는 그 0.35 를 **체크섬 + MMIO 상태 쓰기 12 개 + 도어벨 + 정착 읽기를
> 전부 합친 것**으로 적었고, 그 안의 배분은 재지 않았다. 어느 측정도 체크섬에
> 과반을 배정하지 않는다.

### 6.1 초안이 비교를 불공정하게 세웠다 — 자기 검토로 잡았다

초안은 *"참조는 배리어 하나로 하고 우리는 148.7 KiB 를 읽는다"* 고 썼다.
**참조가 가진 것을 축소해서 적은 것이다.**

PCI 경로에서 DRM 은 1 차 버퍼와 WARP 마이크로코드를 **`_DRM_CONSISTENT`** 로
할당한다:

```
mga_dma.c:641   drm_addmap(dev, 0, warp_size,    _DRM_CONSISTENT, ...)
mga_dma.c:657   drm_addmap(dev, 0, primary_size, _DRM_CONSISTENT, ...)
```

리눅스에서 그것은 **CPU 와 장치 사이가 구성상 코히런트한 메모리**다. 그러므로
`DRM_WRITEMEMORYBARRIER` 는 **가시성을 만드는 것이 아니라 순서를 정하는 것**
이다. 가시성은 할당자가 준다.

**정확한 비교는 이렇다:**

| | 가시성 | 순서 |
| --- | --- | --- |
| DRM (PCI) | **코히런트 할당** | 쓰기 배리어 하나 |
| 우리 | **미증명** (`IOMallocLow`) | 체크섬 되읽기 148.7 KiB 가 둘 다 겸함 |

**격차는 "148.7 KiB 대 명령 하나" 가 아니라 "코히런트 할당자가 있느냐 없느냐"
다.** 우리에게 정착 읽기(`:5928`)가 존재하는 이유도 같은 뿌리다.

> **그러므로 §6 은 최적화 후보가 아니라 질문이다**: OPENSTEP 에 코히런트
> 할당자가 있는가, 혹은 `IOMallocLow` 메모리가 이미 코히런트인가.
> S4a 가 VRAM 매핑에 대해 "stale-cache 게이트 COHERENT" 를 실측했지만
> **그것은 VRAM 이지 conventional memory 가 아니다.** 답이 "코히런트다" 이면
> 되읽기를 배리어로 바꿀 수 있고, 아니면 되읽기가 옳다.

## 7. 이 조사가 바꾼 것 — 그리고 **바꾸지 않은 것**

| 항목 | 후 |
| --- | --- |
| 1. SEC 트리거 | **여전히 미해결.** 정황은 넷으로 늘었다 — 레지스터 레이아웃, DRM 의 END 재기록, **Windows 드라이버의 PRIMEND 단독 쓰기 2 회**, 1 차의 음성 대조 1 회. **그러나 전부 1 차에 대한 것이고 2 차의 하드웨어 계약은 여전히 문서화되지 않았다** |
| 1b. (새로 나온 것) SEC 를 MMIO 로 쓰는 구현 | **없다 — 셋 중 아무도.** 설계 규칙 "1 차 목록 안에서만" 이 참조로 뒷받침된다(§1.6) |
| 2. 2 차 완료·회수 | 재사용에 충분(W6 §9), 실증만 남음 |
| 3. WARP 정지 | 파이프 변경의 **정상 경로**이고 쓰기 자체는 우리 카드에서 PASS. **비동기 MMIO 중단으로는 미검증**, 패딩이 무엇을 막는지도 미상 |
| 4. WARP 봉쇄 | 참조가 정상 3D 경로에 래스터 클립을 **프로그래밍한다**. 의도의 증거이지 **잘못된 WARP 입력·마이크로코드에 대한 봉쇄 증명이 아니다** |
| 5. 수명·모드·클라이언트 | **참조에 결함이 여럿.** 베끼지 말 것 (전수 아님) |
| 6. 가시성 장벽 | 참조는 **코히런트 할당**(`_DRM_CONSISTENT`)으로 가시성을 얻고 배리어는 순서용. 우리 질문은 "OPENSTEP 에 그런 할당자가 있는가" |

### 7.1 이 문서를 근거로 해서는 안 되는 일

**`SECADDRESS` 를 쓰는 실험을 여는 것.** §7 의 금지는 그대로다.

이 경고를 절 하나로 세워 두는 이유가 있다. **일곱 번째 프리즈는 계획서 §4 가
처방하고 같은 계획서 §7 이 금지해서 났다.** 문서 안에서 한 절이 다른 절을
뒤집으면, 나중에 읽는 사람은 자기에게 유리한 쪽을 먼저 찾는다 — 내가 그랬다.

**이 문서의 §1 은 "강한 정황" 이고 §7 의 금지를 이기지 못한다.** 초판의 §1 은
제목이 "레지스터 레이아웃이 답을 준다" 였고, 그대로 두었으면 정확히 그 함정을
다시 팠을 것이다.

### 7.2 착수 판정

**바뀌지 않는다.** 안전 blocker 는 여전히 하드웨어 실증을 요구하고, 이 문서는
**무엇을 실증해야 하는지를 좁혔을 뿐**이다.
