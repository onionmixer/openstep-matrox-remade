# M1-4 4d — 선택기가 텍스처를 받아들인다

2026-08-22.  **유저랜드만 바뀐다.**

## 1. 지금 없는 것 셋

1. 선택기가 `TEXTURE_BIT` 를 거절한다 — `Hook.c` 의 RasterMask 검사.
2. 아핀 판정이 없다.
3. 텍스처 삼각형은 **사다리꼴마다 배치 하나**로 내야 하는데(`M1_4C3` §7-2:
   `tmr[]` 이 배치 전역이고 엔진은 프리미티브마다 u 를 다시 심는다) 지금
   훅은 한 배치에 다 넣고 한 번 제출한다.

## 2. 받아들일 조건 (전부 확인해야 하고, 하나라도 모르면 거절)

| 조건 | 근거 |
|---|---|
| 한 유닛만, 그것도 `TEXTURE0_2D` | `types.h:733`.  1D·3D·큐브는 안 다룬다 |
| `EnvMode == GL_REPLACE` | 엔진이 하는 것이 그것이다 — 측정함 (`M1_4_TEXTURE_PLAN` 4a) |
| `WrapS == WrapT == GL_CLAMP` | 커널이 `CLAMPUV` 를 고정한다 |
| `MinFilter == MagFilter == GL_NEAREST` | bilinear 은 승인만 봤지 그림은 안 봤다 |
| 텍스처가 상주 가능 | `OSMGAMesaTexResidentCurrent` 가 판단 (2D·레벨0·테두리0·비압축·`GL_RGBA`·크기) |
| **아핀** | 아래 |
| `TexGenEnabled == 0` | 생성 좌표는 안 다룬다 |

### 2-1 아핀 판정

`VB->Win.data[v][3]` 은 **역 W** 다.  셋이 **정확히 같으면** 원근 나눗셈이
상수이므로 `s`, `t` 를 그대로 선형 보간하는 것이 맞다.  엡실론은 쓰지 않는다 —
맞는 것을 거절할 수는 있어도 틀린 것을 들여서는 안 된다.

`q` 는 `VB->TexCoordPtr[0]->size` 가 4 일 때만 있다.  4 미만이면 암묵적으로
1 이고, 4 면 세 꼭짓점 모두 `data[v][3] == 1.0` 이어야 한다.

`tritemp.h:403` 이 `TexCoordPtr[0]->data[v][0]` 을 그대로 읽으므로, 그 값은
나누기 전의 `s` 다.  아핀이면 그것을 선형으로 쓰는 것이 소프트웨어와 같은
답을 준다.

## 3. 제출

훅의 지금 모양은 "빌더가 `n` 개를 채우고 한 번 제출"이다.  텍스처가 있으면
**`n` 번 제출**한다 — 배치마다 삼각형 하나와 그 사다리꼴의 `tmr[]`.

* 실패하면(거절되면) **그 삼각형 전체를 소프트웨어로** 넘긴다.  절반만
  그리고 마는 것보다 낫다 — 다만 첫 사다리꼴이 이미 그려졌을 수 있으므로,
  그 경우 소프트웨어가 그 위에 다시 그린다.  `GL_REPLACE` 이고 깊이 시험이
  같은 값이면 결과는 같다.  **이 논거가 약하면 첫 제출 전에 전부 검사한다.**
* 비용: 쪼개지는 삼각형은 제출이 두 번이다.  제출은 동기이므로 실재하는
  비용이고, 재는 것은 4d 의 일이다.

## 4. 무엇을 재나

1. **선택 계기** — 텍스처 상태에서 `hookHardState` 가 오르는지, 조건을 하나씩
   깨뜨리면 `hookSoftState` 로 가는지.  일곱 조건 각각에 사례 하나.
2. **그림** — 텍셀이 자기 좌표를 담은 텍스처를 사각형에 씌우고, 화소가
   오라클과 맞는지.  **소프트웨어와도 비교한다** — 두 경로가 같은 그림을
   그려야 한다(엔진의 +511 만큼 텍셀 경계에서 어긋나는 것은 알려진 값).
3. **원근** — `glFrustum` 으로 기울인 사각형이 **소프트웨어로 가는지**.
   가속되면 아핀 게이트가 새는 것이다.
4. **쪼개진 삼각형** — 두 사다리꼴이 이음매에서 텍스처가 끊기지 않는지.
   이것이 §3 의 제출 방식을 가르는 시험이다.
5. **되돌림** — 아레나가 없을 때(1024×768) 텍스처 삼각형이 소프트웨어로
   가는지, 그리고 화소가 온전한지.

## 5. 안 하는 것

* 원근 보정.  아핀만.
* `GL_MODULATE`, `GL_DECAL`, `GL_BLEND` 환경.
* bilinear.
* 여러 유닛, 밉맵, `GL_REPEAT`.

### 6-1 내가 참고 코드에서 먼저 본 것

Mesa 자신의 빠른 2D 텍스처 경로 조건(`triangle.c:1568-1578`)과 대조하니 둘이
더 빠져 있었다: **`BaseLevel`**(codex 도 지적했다)과
**`Light.Model.ColorControl == GL_SINGLE_COLOR`** — 분리 스페큘러가 켜지면
색이 하나 더 붙는다.

### 6-2 고친 조건

* **`GL_RGB` 만 받는다.**  그러면 `Av = Af` — 정점 알파이고, 그것은 빌더가
  이미 넣는 값이다.  **측정 없이 구성상 옳다.**  `GL_RGBA` 는 엔진의 텍스처
  알파가 목적지에 닿는지 재고 나서 연다.
* **혼합은 꺼져 있어야 한다.**  그래야 (a) 알파 질문이 아예 안 생기고,
  (b) 아래의 재그리기가 멱등이다.
* `ctx->Texture.ReallyEnabled == TEXTURE0_2D` (전역 마스크).
* `tObj->BaseLevel == 0`, 그리고 이미지는 `Image[BaseLevel]`.
* `Light.Model.ColorControl == GL_SINGLE_COLOR`.
* 유닛 0 의 객체를 쓴다 — 활성 유닛이 아니라.

### 6-3 쪼개진 삼각형

혼합이 꺼져 있으면 재그리기가 안전하다:

* 깊이 없음 — `GL_REPLACE` 로 같은 화소에 같은 텍셀을 두 번 쓴다.  **멱등.**
* 깊이 `GL_LESS` — 두 번째로 같은 깊이를 쓰면 시험이 **떨어진다**.  첫
  사다리꼴은 하드웨어가 그린 채로 남고 둘째만 소프트웨어가 그린다.

혼합이 켜져 있으면 둘 다 아니므로, 혼합을 조건에서 뺀 것이 이 문제도 닫는다.

### 6-4 측정을 실패 가능하게

* 이음매 시험은 `n == 2`, **하드웨어 제출 두 번**, 그리고 두 사다리꼴의
  `tmr[6..7]` 이 **서로 다름**을 단언한다.
* 원근 시험은 다른 조건이 아니라 **아핀 게이트가** 거절했음을 계기로 본다.
* 아레나 없음 시험은 **아레나 거절 계기**가 올랐고 제출이 없었음을 본다.
* 그림 시험은 텍셀에 네 채널을 다르게 두고, 알파도 함께 본다.

## 7. 결과 (2026-08-22) — GL 프로그램이 텍스처를 가속한다

`test/openstep-mga-mesa-texdraw-test.c` 는 `glTexImage2D` 와 `glTexCoord2f`
로 그린다.  백엔드를 직접 부르지 않는다.

```
# ordinary: drawn 2 software 0 persp 0 absent 0 uploads 1 painted 16384
  a textured quad reaches the engine             ok
  and nothing fell back                          ok
  and it covered the quad                        ok
  every pixel is a texel of this texture         ok
  GL_MODULATE instead of GL_REPLACE              ok
  GL_LINEAR instead of GL_NEAREST                ok
  GL_REPEAT instead of GL_CLAMP                  ok
  blending on                                    ok
  acceleration returns when the state does       ok
  a perspective triangle is refused              ok
  and by the affine gate, not by something else  ok
```

* **그림**: 텍셀마다 세 채널을 다르게 두고, 그려진 화소에서 **텍셀 번호를
  거꾸로 풀어** 맞는지 본다.  16384 화소 전부 이 텍스처의 텍셀이다.
* **거절**: 네 조건을 하나씩 깨뜨리면 각각 거절되고, **되돌리면 가속이
  돌아온다** — 한 번 거절된 뒤 영영 못 돌아오는 것이 아니다.
* **원근**: 다른 조건이 아니라 **아핀 게이트의 계기**가 올랐음을 본다.

회귀는 전부 그대로다: 커버리지 스윕, 업로드 10 사례, 아레나 시험,
사다리꼴 불변식.

## 8. 나머지 셋도 닫았다 (2026-08-22)

### 8-1 쪼개지는 삼각형

가운데 꼭짓점이 있는 텍스처 삼각형을 그렸다.  **한 삼각형에서 배치가 둘**
나가고(`hookBatches` 로 확인 — `hookDrawn` 은 삼각형을 세므로 이것을 못
본다), 그린 **15780 화소 전부가 이 텍스처의 텍셀**이다.  이음매에서 텍스처가
끊기지 않는다 — `tmr[]` 이 배치 상태라서 사다리꼴마다 배치를 하나씩 낸 것이
값을 하는 자리다.

### 8-2 아레나 고갈

256×256 텍스처를 계속 만들어 아레나를 채웠다.  어느 시점에서 그리기가
**소프트웨어로 넘어가고**(`hookTexAbsent` 가 오른다) 사각형은 **여전히
온전히 그려진다**.  고갈은 그리다 마는 것이 아니라 되돌림이다.

### 8-3 소프트웨어와의 화소 비교

같은 장면(사각형 하나와 쪼개지는 삼각형 하나)을 두 경로로 그려 비교했다:

| | 값 |
|---|---|
| 하드웨어가 칠한 화소 | 25964 |
| 소프트웨어 | 25974 |
| 하드웨어에만 | 0 |
| 소프트웨어에만 | **10** |
| 공통 화소 중 색이 다른 것 | **137 (0.53%)** |

* **10 화소**는 이미 아는 커버리지 규칙 차이다(소프트웨어가 더 칠한다).
* **137 화소**는 전부 **정확히 텍셀 하나** 차이이고, 방향이 (0,1)·(1,0)·(1,1)
  뿐이며 **언제나 하드웨어가 앞선다** — `M1_4C3` §10 에서 잰 **+511** 이
  실제 장면에서 내는 값이다.

**설명되지 않는 화소가 하나도 없다.**

### 8-4 그러므로 다음은 재부팅이다

137 화소를 없애려면 `+511` 을 보정해야 하고, 그 자리는 **커널 인코더**다
(교차분석이 그렇게 권했고, 그래야 프로토콜과 검증기가 논리 좌표를 유지한다).
0.53% 는 눈에 안 보이지만 이제 **값이 있는 차이**이므로, 다음 커널 변경에
넣는다.

`GL_RGBA`(텍스처 알파를 목적지까지 따라가야 한다), bilinear, `GL_MODULATE`,
원근 보정.
