# M1-3k — 깊이 매핑의 정렬을 고치고, 정착 읽기를 조건부로 만든다

두 가지를 한 묶음으로 한다. 앞엣것은 유저랜드라 재부팅이 없고, 뒤엣것은
드라이버라 재부팅이 필요하다. **앞엣것을 먼저 고쳐 검증하고, 그 다음
드라이버를 고쳐 재부팅을 한 번만 쓴다.** 아직 코드 없음.

## A. §3-20 — 깊이 매핑이 4 KiB 로 정렬한다 (유저랜드)

### 무엇이 틀렸나

```c
/* mesa/OpenStepMGAMesaBuffer.c */
tail = (tail + 4095UL) & ~4095UL;      /* 오프셋 */
need = (need + 4095UL) & ~4095UL;      /* 길이 */
```

이 기계의 페이지는 **8192** 이고(`vm_page_size` 와 `getpagesize()` 둘 다
8192 로 확인), 페이지 정렬이 아닌 오프셋은 **`EINVAL` 로 거절된다**
(§3-19 를 재면서 오프셋 × 길이 행렬로 직접 확인: +4096, +12288 은 길이와
무관하게 전부 거절).

**처음 계산은 전제가 틀렸다** — 보폭을 디스플레이 보폭으로 놓았는데, 이
경로는 `bufStride != bufWidth` 면 아예 안 타므로 보폭이 곧 버퍼 너비다.
다시 셌다: `h*w*4` 가 8192 의 배수인 것은 `h*w` 가 2048 의 배수일 때뿐이고,
너비 1..1024 × 높이 1..768 의 786432 조합 중 **395172 개(50.2%)가 실패한다.**
**800×600 과 320×240 이 지금 하드웨어 깊이를 못 쓴다**; 시험이 늘 1024×768
이라 안 걸렸을 뿐이다.

실패하면 `OpenStepMesaAccelDepthBuffer` 가 0 을 돌려주고 Mesa 는 **말없이**
소프트웨어 깊이 버퍼로 되돌아간다. 그림은 맞고 가속만 조용히 사라진다.

### 고침

- **오프셋(`tail`) 만** `vm_page_size` 에서 유도한 값으로 정렬한다.
  그 파일은 이미 `vm_allocate` 때문에 Mach 를 들이고 있으므로 새 의존이 없다.
- **길이(`need`) 의 반올림은 없앤다.** 처음에 "4095 두 곳"이라고 적은 것은
  틀렸다 — 내 오프셋 × 길이 행렬에서 **487424(페이지 배수가 아닌 길이)가
  이미 통과했다.** 길이는 정렬이 필요 없다. 게다가 올림은 공짜가 아니다:
  위쪽 용량 검사가 `bufHeight > (avail - tail) / (bufStride * 2)` 로
  **반올림 전** 크기를 쓰므로, 올린 길이는 창 끝을 넘길 수 있고 `d_mmap` 은
  페이지마다 `off > windowEnd - PAGE_SIZE` 를 거절한다.
- 상수를 박지 않는다. 8192 라고 적으면 이 기계에서만 맞는 코드가 된다.
- 정렬 산식은 `(x + (p - 1)) & ~(p - 1)` 이고 `p` 가 **0 이 아닌 2 의
  거듭제곱**임을 전제한다. 전제를 코드에서 검사하고, 아니면 매핑을 포기한다
  — 조용히 틀린 주소를 쓰는 것보다 낫다. 덧셈의 넘침도 함께 막는다.
- **말없이 물러나지 않는다.** 깊이 매핑이 실패하면 한 번만 알린다.
  단 **자원 확보가 실패했을 때만** 알린다 — 두 번째 컨텍스트, 지원하지 않는
  깊이 폭, 표면 불일치 같은 정상적인 `return 0` 은 알리지 않는다.

### 검증 (재부팅 없음)

**"매핑이 됐다"로는 부족하다.** 이 고침은 성능이 아니라 **어느 코드 경로가
도는지**를 바꾼다 — 지금까지 통째로 소프트웨어로 떨어지던 크기가 하드웨어
깊이를 타게 된다. 그래서:

1. 걸리는 크기(320×240, 800×600)와 안 걸리는 크기(640×480, 1024×768)에서
   깊이 매핑이 되는지, `depthOrigin` 이 0 이 아닌지.
2. 같은 장면을 하드웨어와 **강제 소프트웨어**로 그려 색과 16 비트 깊이를
   비교한다.
3. `glClear(GL_DEPTH_BUFFER_BIT)`, 하드웨어→소프트웨어 폴백, 그리고 그
   반대를 한 프레임 안에서 섞는다.
4. 색과 깊이 할당 둘레에 canary 를 두고 **서로 넘지 않는지** 본다.

계산은 python 으로 미리 하고 실기 결과와 대조한다.

## B. M1-3j — 정착 읽기를 조건부로 (드라이버, 재부팅 1 회)

### 술어 — 검증기가 이미 증명한 것에서 유도한다

검증기는 `dstorg >= 창시작` 과 넘침 없음을 이미 증명한다. 그 아래에서는
"쓰기 범위가 창의 첫 64 바이트에 닿는가" 가 **비교 하나로 줄어든다** —
앞으로만 나아가는 범위는 죽은 구간 뒤에서 시작하면 뒤로 못 닿기 때문이다.

python 으로 확인했다: `org` 를 창 시작부터 8192 까지 4 바이트씩, 보폭·행수
다섯 조합, **10240 가지에서 범위 검사와 `org - WS < 64` 가 한 번도 안
갈렸다.**

```
색   : (dstorg - windowStart) < 64
깊이 : (zorg   - windowStart) < 64        -- 어떤 삼각형이 ZI 일 때만
```

`anyZI` 는 검증기·인코더가 쓰는 것과 **같은 식**으로 구한다.
**스냅샷과 검증을 마친 뒤에** 계산한다.

### 손잡이의 상태를 셋으로

지금은 `0 = 끔`, `N = 워드 N-1 을 항상 읽음` 두 가지다. 출시하려면 세 번째가
필요하다.

| 값 | 뜻 |
| --- | --- |
| `0` | 완전히 끔 |
| `1..probeWords` | **강제**: 성공한 모든 제출 뒤 워드 N-1 을 읽음 (측정 재현용) |
| `OSMGA_HW3D_SETTLE_AUTO` | **기본값**: 겹칠 때만, 워드 16(바이트 64)을 읽음 |

기본값이 `AUTO` 여야 하므로 전역의 초기값을 그렇게 둔다. `0` 이 초기값이면
부팅 직후가 "끔"이 되어 버린다.

워드 16 은 훑기에서 **처음으로 통한** 자리다. 그보다 멀리도 전부 통했으므로
여유를 더 둘 수도 있지만, **측정된 값을 쓰고 그 사실을 적는다.**

### AUTO 는 조용히 "끔" 이 되면 안 된다

드라이버는 **별칭 만들기가 실패해도 mmap 장치를 등록한다** — 소스에서
확인했다. 그 상태에서 AUTO 는 아무 일도 안 하면서 성공을 보고한다.

Mesa 의 표면은 언제나 창 시작에 놓이므로 **언제나 겹친다.** 그러니
"별칭이 없으면 겹치는 제출을 거절한다"는 사실상 "별칭이 없으면 3D 가
없다"이다. 그것이 맞다 — 별칭은 이 경로의 정확성 요건이다. 등록 시점에
크게 알리고, 겹치는 제출은 `IO_R_RESOURCE` 로 거절한다. **쓰고 나서
실패를 보고하지 않는다.**

### 셈을 하나 둔다

자동 읽기가 몇 번 일어났는지 센다. 세터가 불릴 때 그 수를 함께 알린다.
새 표면을 만들지 않고, **조건부가 정말 조건부인지** 확인할 수 있다 —
안 겹치는 목적지로 돌린 뒤 셈이 안 늘면 그렇다.

### 검증 (재부팅 뒤, 모드 5 로 설정마다 80 시행)

| 설정 | 목적지 | 예상 |
| --- | --- | --- |
| 강제 끔 | 창 시작 | 80/80 짧음 |
| 강제 워드 0 | 창 시작 | 80/80 짧음 |
| 강제 워드 16 | 창 시작 | 0/80 |
| **자동** | **창 시작** | **0/80**, 셈이 는다 |
| 자동 | 한 페이지 아래 | 0/80, **셈이 안 는다** |
| **자동, 세터 호출 전** | 창 시작 | 0/80 — 기본값이 지키는 구간 |
| 자동 | `WS+60` | 셈이 **는다** (경계 안쪽) |
| 자동 | `WS+64` | 셈이 **안 는다** (경계 밖) |
| 자동, 비-ZI, `zorg = WS` | 색은 멀리 | 셈이 **안 는다** |
| 자동, ZI, `zorg = WS` | 색은 멀리 | 셈이 **는다** |
| 자동, ZI, 둘 다 멀리 | — | 셈이 **안 는다** |

아래 다섯 줄이 술어가 정말 술어임을 보이는 줄이다. 셈은 단조로 두고,
세터가 불릴 때 값을 알린다 — 시험은 앞뒤로 세터를 불러 차이를 본다.

## C. 안 하는 것

- **원인을 안다고 적지 않는다.** 왜 64 바이트인지, 왜 창 시작 한 자리인지
  모른다. 경험적 고침이고 그렇게 적는다.
- **다른 MGA 부품으로 일반화하지 않는다.** 이 G450/OPENSTEP 구성에서 쟀다.
- **무조건 읽기를 기본으로 하지 않는다** — 비용을 안 쟀다. 손잡이의 강제
  모드가 남아 있으므로 나중에 잴 수 있다.
- **§3-19 관련 코드는 안 건드린다.** 철회됐다.

## D. 순서

A 코드 → 빌드 → 검증(재부팅 없음) → B 코드 → 빌드 → 설치 → **재부팅 요청**
→ B 검증.

## E. 결과 (2026-08-21, 재부팅 뒤)

설치 20:50, 부팅 20:53:11, 별칭 경고 없음 — 새 드라이버가 도는 것을 시각으로
확인했다.

### 화소로 본 것 (설정마다 80 시행, 모드 5 로 매 시행 무장)

| 설정 | 짧게 나온 시행 |
| --- | --- |
| **기본값 — 세터를 한 번도 안 부름** | **0 / 80** |
| 강제 끔 | 80 / 80 |
| 강제 워드 0 (바이트 0) | 80 / 80 |
| 강제 워드 16 (바이트 64) | 0 / 80 |
| 자동, 명시적으로 요청 | 0 / 80 |

첫 줄이 기본값이 지키는 것을 보여주고, 둘째 줄이 **시험이 여전히 옳은 것을
재고 있음**을 보여준다 — 드라이버가 안 도와주면 결함은 그대로다.

### 셈으로 본 것 — 조건부가 정말 조건부인가

세터가 불릴 때마다 그때까지의 자동 읽기 수를 알린다. 연속 실행의 차이가 그
실행의 읽기 수다.

| 그 실행의 목적지 | 자동 읽기 |
| --- | --- |
| 창 시작 | **86** (두 번 독립적으로) |
| 두 행(8192 B) 아래 | **6** |
| `창시작 + 60` | **86** |
| `창시작 + 64` | **6** |
| `창시작 + 128` | **6** |
| 비-ZI 배치에 `zorg = 창시작`, 색은 두 행 아래 | **6** |

**86 − 6 = 80** 이고, 시행 블록이 제출하는 배치가 정확히 80 개다
(40 시행 × 두 패스). 남는 6 은 프로그램 앞부분의 구간들로, 시행 블록에
무엇을 시키든 언제나 창 시작에 그린다.

그러니 **겹치지 않는 80 회 제출은 자동 읽기를 0 번 유발했다.**

그리고 경계가 코드가 말하는 자리에 있다 — 바이트 60 은 읽고, 64 와 128 은
안 읽는다. **바깥에서 확인한 것**이지 상수를 다시 읽은 것이 아니다.

깊이 술어도 맞다: 비-ZI 배치에 `zorg` 를 창 시작에 놓아도 안 읽는다.
깊이는 **삼각형이 실제로 깊이를 건드릴 때만** 묻는다.
