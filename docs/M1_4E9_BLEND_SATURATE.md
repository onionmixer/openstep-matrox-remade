# M1.4E9 — 소스 인자 8 은 `GL_SRC_ALPHA_SATURATE` 가 아니다 (실측)

## 질문

`GL_SRC_ALPHA_SATURATE` 는 인자 하나가 아니라 **둘**이다. GL 은 색 채널에
`min(As, 1-Ad)` 를, 알파에는 **정확히 1** 을 요구하고, 이 Mesa 가 바로 그렇게
구현한다 (`Mesa-3.4.2/src/blend.c:550-557` 색, `:616-618` 알파에서 `sA = 1.0`).

엔진에는 그 이름의 인코딩이 **있다**: `AC_src_src_alpha_sat = 0x8`, 그리고 GL 의
규칙 그대로 **소스에만** 있다(목적지 목록은 7 에서 끝난다 —
`xf86-video-mga-2.0.0/src/mgareg_flags.h:50`, `:52-59`). 커널 검증기도 이미
소스 인자 8 을 허용한다(`OSMGA_HW3D_AC_SRC_MAX 8UL`). 즉 **커널 변경이 필요 없다.**

기존 거절 사유는 정직했다: "엔진엔 인자 필드가 하나뿐이라 그 분리를 나르는지
**아무도 재지 않았다**". 그래서 쟀다.

## 왜 §86 으로는 답할 수 없었나

`reach` §86 은 두 가지 이유로 이 질문에 답하지 못한다:

* 결과를 `& 0xFFFFFFUL` 로 마스크해 **알파를 아예 보지 않는다**
  (`test/openstep-mga-hw3d-texreach-probe.m:6106`). 분리 질문은 바로 그 채널의
  질문이다.
* 목적지가 `0x00804020` 이라 **Ad = 0** 이고(`:6093`), 그러면 `255-Ad = 255`,
  `min(As,255) = As` — 인자 8 이 인자 4 와 **구별조차 되지 않는다**.

## 측정 (`tsa`, 신규 프로브)

목적지 인자는 ZERO 로 고정해 소스 인자만 읽히게 한다. 텍셀 `C08040`, 목적지
`804020`, 그리고 `TEXALPHA` 를 켜 스테이지 알파가 **텍셀의** 알파가 되게 한다
(보간 알파는 일부러 다른 값 `0x10` 으로 두어, 잘못된 쪽을 읽으면 우연히 맞을 수
없게 했다).

```
  As   Ad    f   engine     half     split    onefactor plain
  64   64   64   40302010   40302010 40302010 10302010 10302010
 128  127  128   80604020   80604020 80604020 40604020 40604020
 192  128  127   c0916030   c0916030 c0604020 60604020 91916030
 240  200   55   f0b5783c   f0b5783c f0291c0e 34291c0e e2b5783c
 128    0  128   80604020   80604020 80604020 40604020 40604020
```

**다섯 행 전부 `half` 와 일치한다** — 색에는 `As`(인자 4 와 같은 값), 알파에는
`ONE`. `255-Ad` 는 어느 행에서도 들어오지 않는다.

### 대안 설명을 닫은 대조군

"엔진이 목적지 알파를 0 으로 읽는다면" `min(As,255)=As` 가 되어 같은 숫자가 나온다.
그래서 같은 설정에서 **소스 인자 7(`1-Ad`)** 을 쟀다:

```
Ad= 64 -> 30906030   Ad=127 -> 40604020   Ad=128 -> 60604020
Ad=200 -> 34291c0e   Ad=  0 -> 80c08040     (전부 python 과 일치)
```

**엔진은 Ad 를 정확히 읽는다.** 그러므로 최소값을 안 취하는 것이지 목적지 알파를
못 보는 것이 아니다.

## 결론

소스 인자 8 = **색에 `SRC_ALPHA`, 알파에 `ONE`**. 이것은
`glBlendFuncSeparate(GL_SRC_ALPHA, ..., GL_ONE, ...)` 의 소스 쪽이며, GL 1.1 이
요청할 방법이 없는 상태다.

→ **`GL_SRC_ALPHA_SATURATE` 는 계속 거절한다.** 달라진 것은 사유다: "재지 않았다"
가 아니라 "재어 보니 GL 이 요구하는 것이 아니다".

## 이 회차에 내가 틀렸던 것

프로브 첫 판에서 "f == As 인 행에서는 인자 8 과 인자 4 가 같아야 한다"는 대조
단언을 넣었다. **틀렸다** — 알파에 ONE 이 걸리므로 그 행들에서도 알파는 다르다.
색에 대해서만 참인 명제를 네 채널에 적용한 것이다. 단언을 걷어내고 인자 7 대조군으로
바꿨다.
