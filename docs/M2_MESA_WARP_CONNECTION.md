# M2 — Mesa 를 WARP 에 잇는다 (2026-08-28, 코딩 전)

## 0. 제약 — 소프트웨어 경로는 그대로 산다

**`opennstep-mesa342` 는 손대지 않는다.** 확인했다: 그 트리의 `src` 에 우리 심볼이
하나도 없다. 훅은 `ctx->Driver.TriangleFunc` 등을 저장하고 갈아 끼우는 방식이고
(`OpenStepMGAMesaHook.c:2535`), **못 그리면 NULL 을 돌려 소프트웨어가 그린다**
(`:41` *"the refusal is a NULL return and the software function ..."*).

바뀌는 것은 **matrox 쪽 셋뿐**이다:

```
openstep-matrox-remade/mesa/     우리 백엔드
openstep-matrox-remade/hw3d/     커널과의 계약
드라이버 .m                       인코더·제출
```

## 1. 층이 셋이 된다

```
1  WARP        정점 -> 하드웨어 셋업        (새로 만드는 것)
2  사다리꼴     CPU 셋업 -> 레지스터          (지금 동작하는 것, 남긴다)
3  Mesa 소프트웨어                            (바닥, 남긴다)
```

**각 층은 아래로 거절한다.** WARP 가 못 하는 상태는 사다리꼴로, 사다리꼴이 못 하는
상태는 소프트웨어로. 이것이 이 작업의 안전 속성이다 — **새 층이 실패해도 잃는
기능이 없다.**

거절은 **부작용이 없어야** 한다. WARP 가 삼각형 하나를 거절하면 그 배치의 상태가
반쯤 나간 채로 남으면 안 된다.

## 2. 무엇이 WARP 로 대체되는가

Mesa 쪽에는 **이미 정점이 있다** — `OSMGAMesaVertex { x, y, qw, tq, r,g,b,a, z, s, tc }`.
`OSMGAMesaBuildTriangle(a,b,c,...)` 이 그것을 받아 사다리꼴로 바꾼다:

```
osmgaEdgeRegs      엣지 기울기 -> ar0..ar6, sgn
osmgaTrapezoid     y, h, fxbndry, dr[12]
osmgaPerspPlanes   원근 텍스처 평면 -> tmr[6]
osmgaClampSlope / osmgaClampDepthSlope / osmgaFixed / osmgaStartFixed
```

**이 전부가 WARP 가 하드웨어로 하는 일이다.** 대체 지점은 `OSMGAMesaBuildTriangle`
하나로 깔끔하다.

## 3. M-0 — 코드를 쓰기 전에 잰다

`docs/M1_4EA_FRAME_COST.md` 가 이미 말한다:

```
512x384  small triangle + finish : 145.556 ms (20 batches)
         표면 전체를 엔진으로 덮기 :   0.912 ms
```

**엔진 일은 프레임의 1% 도 안 된다.** 나머지는 동기 제출·ioctl·DMA 완료 대기다.
그러므로 **WARP 가 빠를 것이라는 가정은 이 측정과 맞지 않는다.** D2-2g 에서
"측정하지 않은 병목을 없애지 마라"를 방금 배웠고, 여기에도 그대로 적용한다.

M-0 은 WARP 가 **실제로 바꾸는 두 가지**를 잰다:

| | 재는 것 | 결과가 뜻하는 것 |
| --- | --- | --- |
| **(a)** 삼각형당 `osmgaTrapezoid`+`osmgaEdgeRegs`+`osmgaPerspPlanes` 시간 | 무시할 만하면 **속도 논거는 죽는다** |
| **(b)** Mesa 가 삼각형마다 `dwgctl`/`alphactrl` 을 바꾸는 빈도 | 잦으면 WARP 제출이 삼각형 하나씩으로 쪼개져 **배치 이득이 사라진다** |

(b)가 중요한 이유: 사다리꼴 계약은 `OSMGAHW3DTri` 에 **삼각형마다** `dwgctl`·
`alphactrl` 을 담는다. **WARP 는 그럴 수 없다** — 한 제출 안의 프리미티브는
상태를 공유한다. W2 §8 이 지적하고 답하지 않은 채로 남은 문제다.

**M-0 이 통과하지 못하면 M-1 이하는 하지 않는다.**

## 4. M-1 — 계약

`OSMGAHW3DTri` 는 사다리꼴 모양이다. 정점 형태를 **나란히** 추가한다(대체 아님):

```c
typedef struct {          /* 정확히 WARP 정점 한 개, 8 dword */
    unsigned long x, y, z, rhw;   /* IEEE 754 비트 패턴 */
    unsigned long diffuse;        /* BGRA */
    unsigned long specular;       /* BGR + fog */
    unsigned long tu0, tv0;       /* IEEE 754 비트 패턴 */
} OSMGAHW3DVertex;
```

**커널은 부동소수를 쓸 수 없다.** 그러므로 변환은 전부 **유저랜드(Mesa 쪽)**에서
일어나고, 커널은 **비트 패턴을 검증하고 복사할 뿐**이다. D2-2c 에서 정수 연산으로
IEEE 패턴을 만든 것과 같은 이유이고, 여기서는 클라이언트가 double 을 갖고 있으니
훨씬 쉽다.

배치 구조(`dstorg`, `dstPitch`, `zorg`, `texorg`, `texW/H`, ...)는 **그대로 WARP
컨텍스트가 된다.** 버전을 올린다(`OSMGA_HW3D_VERSION` 9 → 10).

## 5. M-2 — 드라이버

D2-2f 가 증명한 것을 그대로 쓴다:

```
상태가 바뀌었을 때만  GENERAL 목록 (파이프 7 + 컨텍스트 + tex0 + 전역 + 클립)
매 배치              VERTEX 제출 N x 24 dword
버퍼 재사용          포인터가 지나가면 자유 (펜스 불필요)

```

**컨텍스트 재발행이 불필요함은 이미 실기로 확인했다** — 참조보다 강한 결과다.

## 6. 가장 큰 미해결 — 텍스처 봉쇄

지금의 봉쇄는 **커널이 텍스처 기울기(`tmr[0..5]`)를 경계 검사**하는 데 있다.
네 모서리에서 좌표가 선언된 텍스처 안에 있으면 모든 픽셀에서 안에 있다는 논증이다.

**WARP 는 그 기울기를 스스로 계산한다.** 커널이 볼 수 있는 것은 **정점의 `tu0/tv0`**
뿐이다. 그러므로 봉쇄 논증을 다시 세워야 한다:

- 선형 보간이면 세 정점이 범위 안이면 삼각형 전체가 범위 안이다(볼록결합). **참이다.**
- **원근 나눗셈이 들어가면 그렇지 않다.** `rhw` 가 정점마다 다르면 보간된
  `s/w ÷ 1/w` 는 세 정점의 볼록결합이 아니다.

→ **원근이 있는 삼각형에서 정점 좌표만으로는 봉쇄를 증명할 수 없다.**
그러면 선택지는 셋이고, 어느 것도 자명하지 않다:
1. 원근 텍스처는 WARP 로 보내지 않는다(거절 → 사다리꼴). 기능 손실 없음, 이득 축소.
2. 텍스처 wrap/clamp 하드웨어가 봉쇄를 대신하는지 확인한다(`TEXCTL` 의 클램프).
3. 텍스처를 2 의 거듭제곱 + wrap 으로 강제해 **범위 밖이 정의되게** 만든다.

**이것이 M2 에서 답해야 할 가장 어려운 질문이다.**

## 7. 그 밖의 미해결

- **깊이**: 우리 WARP 실행은 깊이가 꺼져 있었다. `atype` 이 `I` 냐 `ZI` 냐,
  `ZORG`, `MACCESS.zwidth` 를 어떻게 채우나.
- **텍스처 상태 자체**: pipe 7 은 텍스처 파이프다. 실제 텍스처링은
  `TEXORG/TEXWIDTH/TEXHEIGHT/TEXCTL/TEXFILTER` 와 WR 매직 값을 요구한다.
  우리는 전부 0 으로만 돌려 봤다.
- **거절의 원자성**: 배치 중간에서 WARP 가 거절하면 무엇을 되돌려야 하나.

## 9. codex 에 물을 것

1. **§6 이 핵심이다.** 원근 텍스처에서 정점 `tu0/tv0` 만으로 봉쇄를 증명할 수
   있나. 못 한다면 세 선택지 중 어느 것이 옳은가. 하드웨어 클램프가 답이 되나.
2. M-0 을 게이트로 두는 것이 맞나. 재야 할 것이 (a),(b) 말고 더 있나.
3. 삼각형마다 상태가 바뀌는 빈도가 높으면 WARP 는 쓸모가 없나, 아니면

4. 3 층 거절 구조가 건전한가. WARP 가 거절할 때 무엇을 보장해야 하나.

   커널이 **검증할 수 있는 것**은 무엇인가(NaN·무한대·범위).
6. 깊이·텍스처 상태를 WARP 컨텍스트에 어떻게 채우나. 우리는 전부 0 으로만 돌렸다.
7. 빠진 것.

## 12. 봉쇄 정책 (정정)

원근을 거절할 이유가 없다. 필요한 것은:

- 세 정점의 유효 `rhw` 가 **유한하고 강한 양수**이며 검증된 구간 안
- 변환된 `tu0/tv0` 가 유한
- clamp 모드는 커널이 소유한 `TEXCTL.CLAMPU/V` — 저장소가 **실측으로**
  이것이 좌표가 아니라 **가져오는 주소**를 묶는다고 적어 뒀다(`HW3D.h:286`)
- `GL_REPEAT` 는 2 의 거듭제곱 + `texPitch == texW`(`:11365`, 사양서 3-211)
- **필터 footprint** — bilinear/mipmap 은 점 좌표보다 넓게 읽는다(3-217~218).
  하드웨어 clamp/wrap 이 그것까지 묶어야 한다
