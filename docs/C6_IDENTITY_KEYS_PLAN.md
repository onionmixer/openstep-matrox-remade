# C6 — 보존 규칙에 정체 키를 예외로 (2026-08-29, 코딩 전)

## 1. 왜

`C4` 가 Installer 경로에 보존을 넣었다: 기계의 인스턴스 표를 **바이트 단위로**
되돌린다.  그 규칙의 힘은 **무조건적**이라는 데 있었다 — 병합하지 않고, 새
릴리스가 추가한 키로 채우지도 않는다.  이유도 좋았다: *부재가 의미를 가진다*
(`BW:4` 인데 `Gray Levels` 가 없으면 legacy 4 단계).

그런데 운영자가 화면에서 `v1.1` 과 `v0.5` 가 함께 나오는 것을 봤다.
`"Version"` 이 그 표에 있고, 보존 규칙이 **개발 시절 0.5 를 영원히 지키고
있었다.**  1.0 도 1.1 도 그것을 못 바꿨다.

## 2. 규칙이 틀린 게 아니라 **덜 정확했다**

살아 있는 표의 키 28 개를 분류하니 **미분류가 없다**:

```
드라이버를 서술 (패키지가 정본, 9개)
  Driver Name  Class Names  Server Name  Family  Title
  Version  Auto Detect IDs  Bus Type  VGA Memory Maps

기계를 서술 (운영자·시스템이 정본, 19개)
  Location  Instance  Display Mode  Gray Levels  MGA Memory Size
  Mesa Acceleration  VRAM Mmap  WARP 3D
  Raster Test  Storm 2D Test  DMA Ring Test
  WARP Test  WARP Triangle Test  WARP Depth Test
  FB Address  I/O Ports  IRQ Levels  DMA Channels  Memory Maps
```

`C4` 의 규칙을 다시 쓰면:

> **기계는 자기 설정을 소유하고, 패키지는 드라이버의 정체를 소유한다.**

`Version` 은 예외가 아니라 **아홉 중 하나**다.

## 3. 이 규칙이 있었다면 오늘 손으로 한 일이 없었다

이번 개명에서 `Driver Name`·`Server Name` 을 살아 있는 표에서 손으로 고쳤고,
Installer 설치가 옛 이름을 다시 써 넣어 **재부팅했으면 화면이 안 나올 뻔했다**
(`C3 §14`).  그 셋이 전부 정체 키다.  규칙이 이랬으면 자동이었다.

## 4. 설계

`post_install` 이 지금 하는 일: 기계의 표를 되돌린다.
더할 일: **되돌린 표에서 정체 키 아홉 개만 패키지 값으로 바꾼다.**

```
1  기계의 표를 되돌린다 (지금 그대로, 검증 포함)
2  패키지가 실은 표에서 정체 키의 값을 읽는다
3  되돌린 표의 그 키들만 그 값으로 치환한다
   -- 기계에 없던 정체 키는 더한다 (이름이 바뀌면 필요하다)
   -- 기계에만 있는 정체 키는 지운다? -> 하지 않는다 (§5)
4  줄 수와 기계 키가 하나도 안 변했음을 확인한 뒤에 자리에 놓는다
```

## 5. 하지 않는 것

* **기계 키는 절대 건드리지 않는다.**  `C4` 의 이유가 그대로 살아 있다.
* **기계에만 있는 정체 키를 지우지 않는다.**  없애는 쪽은 부재를 만들고,
  부재가 의미를 가질 수 있다는 것이 이 규칙의 출발점이다.
* **병합이 아니다.**  아홉 개의 **닫힌 목록**을 치환할 뿐이고, 그 목록은
  코드에 적혀 있어 릴리스마다 자라지 않는다.

## 6. codex 에 물을 것

1. 분류가 맞나?  특히 `Bus Type`·`VGA Memory Maps`·`Auto Detect IDs` 는
   드라이버가 정하나 기계가 정하나?  `Instance` 는?
2. `Title` 을 패키지가 덮어도 되나 — 운영자가 Configure 에서 바꿀 수 있는
   값인가?
3. 아홉을 한꺼번에 하는 것과 `Version` 하나만 하는 것 중 어느 쪽인가?
   전자는 오늘 개명에서 손으로 한 일을 자동화하지만 표를 더 많이 건드린다
4. csh 에서 한 표의 특정 키만 안전하게 치환하는 방법 — `sed` 로 줄을
   바꾸는 것이 옳나, 아니면 다시 쓰는 것이 옳나?  실패 시 표가 깨지면
   부팅이 안 된다
5. 이 변경이 **첫 설치**에서 무엇을 하나 — STASH 가 비어 있으면 아무것도
   안 하는 것이 맞나?
6. 빠뜨린 것

## 7. codex 교차검토 판정

| codex 주장 | 내 검증 | 결과 |
|---|---|---|
| **아홉이 아니라 다섯**: `Driver Name`·`Server Name`·`Class Names`·`Family`·`Version`.  둘 다 실증된 실패(낡은 버전, 개명 불일치)를 고치면서 표를 덜 건드린다 | 논리 | ✅ 채택 |
| **`Auto Detect IDs`·`Bus Type` 은 인스턴스 표에서 기계 것**이다 — `Default.table` 은 지원 장치 **카탈로그**이고 `InstanceN.table` 은 **감지·설정된 기록**이다 | `doc/driverkit.md:150-162` 확인: *"`Instance0.table`은 **감지된 하드웨어의 실제 위치**를 담는다"* 이고, 동작 중인 DEC 21041 의 인스턴스 표 예시에 **`Auto Detect IDs` 가 들어 있다** | ✅ **사실.  내 분류가 틀렸다** |
| `Instance` 는 기계 것 | 형제 드라이버가 `"Instance" = "0"` 을 싣지만 그것은 기본값이고, 표마다 자기 번호를 가진다 | ✅ 일치 |
| `VGA Memory Maps` 는 보존 — 설정된 하드웨어에 묶인 자원 선언이고 바꿔서 얻을 것이 없다 | 논리 | ✅ 채택 |
| **`Title` 을 덮지 마라** | 근거로 든 *"Matrox 프로파일 표들이 서로 다른 Title 로 G400/G450 프로파일을 구분한다"* 는 **이 트리에 없다** — `Title` 은 우리 것 하나뿐이다 | ⚖️ **결론은 채택, 근거는 기각.**  덮지 않는 이유는 다른 데 있다: 오늘 확인했듯 Configure 가 보여 주는 것은 `Title` 이 아니라 `Long Name` 이므로 **덮어서 얻을 것이 없다.**  이득 없는 변경은 위험만 남는다 |
| **in-place `sed` 를 쓰지 마라.**  `set-config-key.sh` 는 삭제 후 append 라 **위치와 주석을 잃고** 검증이 줄 수뿐이다 | `tools/set-config-key.sh:57-60` 확인: `sed "/^\"$K\"/d"` 뒤 `echo >>`, 검증은 `grep -c .` 비교 | ✅ **사실.**  후보를 `.config` **밖에서** 만들어 검증하고 원자적으로 rename |
| 정체 값의 출처는 **`Default.table`** 이어야 한다 — 복원이 페이로드의 `Instance0.table` 을 덮으므로 | 코드 확인: `cp "$stash/$t" "$cfg/$t"` 가 정확히 그렇게 한다.  **내가 구현 전에 스스로 발견한 순서 문제와 같은 것** | ✅ **채택.  이것이 순서 문제를 통째로 없앤다** |
| 불변식을 "줄 수 동일" 로 잡지 마라 — 없던 키를 더하면 깨진다.  **선택된 줄을 제거한 나머지가 바이트로 같은지** 보라 | 논리 | ✅ 채택 |
| 첫 설치는 아무것도 안 한다 | 현재 동작 그대로 | ✅ 일치 |
| `driverLoader` 는 이 상태를 **쓰는** 주체다 (읽기만 하는 것이 아니다) | `driverkit.md` 가 부팅 시 인스턴스를 만든다고 적고 있다 | ✅ 채택 — 그래서 "Configure 가 정체 필드를 안 건드린다" 고 **약속하지 않는다** |

## 8. 그러므로 다섯 개, 그리고 awk 한 번

```
정체 키   Driver Name, Server Name, Class Names, Family, Version
출처      번들의 Default.table (복원을 견디고, 패키지 자신의 것이다)
방법      awk 2-pass: Default.table 에서 값을 읽고,
          복원된 표를 다시 쓰되 그 다섯 줄만 제자리에서 바꾼다
          -- 위치도 주석도 다른 줄도 그대로
검증      선택 줄을 뺀 나머지가 바이트로 동일
          정체 키가 어느 쪽에서든 중복이면 거절
배치      .config 밖에서 만들어 검증한 뒤 rename
실패      아무것도 안 옮기고 STASH 를 남긴다
```

csh 의 `foreach` 는 공백이 든 키 이름을 다루지 못하므로 변환은 **awk 한 프로그램**이
한다 — csh 의 단어 분해를 아예 지나간다.

## 9. 시행 — 옛 awk 가 세 가지를 가르쳐 줬다

```
사용자 정의 함수 없음     "syntax error near line 34"       시끄럽게 실패
/dev/stderr 없음          같음                               시끄럽게 실패
FNR 없음                  아무 말 없음                       ** 조용히 망친다 **
```

마지막 것이 제일 나빴다.  `NR == FNR` 이 옛 awk 에서 **결코 참이 아니므로**
첫 파일이 둘째 규칙으로 흘러들어 `Default.table` 의 주석 블록 전체가 후보
표에 복사됐다.  **없어서 죽는 기능은 싸고, 없어서 그럴듯한 쓰레기를 만드는
기능은 비싸다.**  파일 구분을 `FILENAME` 으로 바꿨다.

## 10. 그리고 중복 규칙이 실기에서 틀렸다

가드가 `Default.table` 에서 `Server Name` 중복을 신고하며 멈췄다.  추적해 보니
**OPENSTEP 의 드라이버 빌드가 `Server Name` 을 표 끝에 덧붙인다** — 소스가
이미 선언하고 있어도.  우리 스크립트가 아니고, 형제 드라이버도 같을 것이다.

규칙을 정확하게 고쳤다: **같은 값의 중복은 무해하고, 다른 값의 중복만 결함이다.**
같은 값이면 선례가 무엇이든 결과가 같으니 물을 필요가 없다.

## 11. 실기 확인

살아 있는 표의 `Version` 을 일부러 `0.5` 로 되돌린 뒤 훅을 돌렸다:

```
Version       0.5 -> 1.1          패키지를 따라간다
Driver Name   OSMGADisplay        그대로
Location      Dev:0 Func:0 Bus:4  기계의 것, 안 움직인다
WARP 3D       Yes                 운영자의 것, 안 움직인다
Display Mode  1600x1200           안 움직인다
```

그리고 **BOM 확인이 한 번 거짓 음성을 냈다** — `.bom` 은 바이너리라
`grep -c` 가 파일이 들어 있는데도 0 을 답했다.  `lsbom` 으로 봐야 하고,
검증기도 그렇게 고쳤다.  복사 위치도 틀렸었다(`package` 가 BOM 을 만든
**뒤**여서 스테이지엔 있고 BOM 엔 없었다).
