# M1-4ce — 분자의 `2(q − 2^e)` 를 어떻게 할 것인가 (계획, 2026-08-23)

**코드는 건드리지 않았다.** 이 문서가 교차검토 대상이다.

## 1. 확인된 것

원근 경로에서, `q` 가 **상수**이고 슬로프가 0 일 때:

* **제수는 정확히 `q`** — 다섯 값(256·300·384·511·512), 두 경계(9·25)에서
  여덟 점 중 일곱이 정확, 하나가 1 단위.
* 분자에 **`E = 2(q − 2^e)`** 가 더해진다.  `= (2q) mod 2^(e+1)`, 곧 `q` 의
  **정규화된 가수를 한 칸 왼쪽으로 민 값**이다.
* 텍셀로는 `8f/(1+f)` (`f` 는 정규화 가수), **거듭제곱에서 0, 다음 거듭제곱
  직전에 약 4 텍셀**.

## 2. 이것이 왜 결정적인가

실제 원근 프리미티브의 `q` 는 **화소마다 다르다**.  `E` 가 `q` 의 가수에
달렸다면 `E` 는 **평면이 아니다** — 거듭제곱 경계를 넘을 때마다 0 으로
떨어졌다가 다시 오른다.  그러면 드라이버가 평면 보정으로 상쇄할 수 없다.

그러므로 **가장 먼저 물어야 할 것은 "이 법칙이 변하는 `q` 에서도 성립하는가"**
이지, 기전이 무엇인가가 아니다.  성립하지 않으면 기전을 몰라도 진행할 수
있고, 성립하면 기전을 알아도 이 경로로는 원근을 못 연다.

## 3. 재야 할 것 (순서대로)

| # | 물음 | 방법 | 이것이 가르는 것 |
|---|---|---|---|
| 1 | 변하는 `q` 에서도 `E` 가 붙는가 | `dq/dx ≠ 0` 으로 한 행을 걸어 열마다 텍셀을 읽고, `q` 가 거듭제곱을 넘는 자리에서 **불연속**이 보이는지 | 평면 보정 가능/불가 |
| 2 | `E` 가 분자 크기에 의존하는가 | 같은 `q`, 여러 경계(9·25 는 했다; 49·63 추가) | 진짜 상수인지 |
| 3 | 텍스처 크기가 바뀌면 | 32·64·128 텍셀에서 같은 `q` | H 행 정규화 문제 |
| 4 | `v` 축도 같은가 | `t`/`TMR7` 로 반복 | 축 대칭 |

## 4. 후보 기전 (하나로 정하지 않는다)

| 후보 | 왜 이 모양이 나오나 | 가르는 측정 |
|---|---|---|
| 정규화 누설 | `q = 2^e(1+f)` 로 정규화할 때 `f` 가 분자 경로로 새어 들어감 | 3 — 텍스처 크기를 바꾸면 지수가 바뀌므로 무늬가 따라 움직여야 |
| 조기 종료 나눗셈기 | 나머지에 비례한 오차 | 2 — 분자를 키우면 오차가 따라 커져야 |
| `H` 의 미사용 decal 필드 | 우리 인코더가 "decal 없음"으로 쓰고 있다 | 3, 그리고 `TMR8` 의 비트를 하나씩 흔들어 무시되는 비트 찾기 |
| 내 모형이 아직 부족 | 다섯 점 두 경계는 두 자유도를 겨우 넘는다 | 2·4 — 점을 늘린다 |

## 5. 결과에 따른 선택지 (미리 정하지 않는다)

| 안 | 조건 | 내용 |
|---|---|---|
| (a) | 변하는 `q` 에서 `E` 가 사라진다 | 상수 `q` 는 원근이 아니므로 문제가 아니었다. 그대로 진행 |
| (b) | `E` 가 남지만 평면으로 근사 가능 | 빌더가 상쇄한다 |
| (c) | `E` 가 남고 불연속 | 이 경로로는 원근 불가. `NOPERSP` 로 되돌리고 아핀 세분을 별도 이름으로 검토 |
| (d) | 기전이 밝혀져 프로그래밍으로 회피 가능 | 예: `q` 를 항상 거듭제곱으로 정규화하고 `s`·`t` 를 같이 조정 |

**(d) 는 지금 유력해 보인다** — `q` 를 `2^e` 로 반올림하고 `s`, `t` 를 같은
비율로 조정하면 몫은 그대로이고 `E` 는 0 이 된다.  다만 `q` 가 화소마다 변하면
`2^e` 도 변하므로 평면이 아니게 된다.  1 번 측정이 이것도 함께 답한다.

## 7. 옥타브를 가로질러 재니 법칙이 바뀌었다 — 그리고 좋아졌다 (2026-08-23)

교차검토가 "다섯 점이 거의 한 옥타브에 몰려 있어 법칙이라 부르기 이르다"고
했고 옳았다.  같은 가수를 여러 옥타브에서 재니:

```
        q       s9      s25        D        E 2(q-2^e) texels
      256      561     1585      256        0        0 0.00
      257      561     1589      257        2        2 0.03
      300      572     1772      300       88       88 1.17
      384      593     2129      384      256      256 2.66
      448      609     2401      448      384      384 3.42
      511      624     2668      511      510      510 3.99
      512     1137     3185      512        0        0 0.00
      513     1138     3190      513        1        2 0.00
      600     1247     3647      600       88      176 0.58
      768     1457     4529      768      256      512 1.33
     1200     2597     7397     1200       88      352 0.29
     1536     3185     9329     1536      256     1024 0.66
```

**`D = q` 가 열두 점 전부에서 정확하다** — 나눗셈기는 확실히 멀쩡하다.

그리고 `E` 는 `2(q − 2^e)` 가 **아니다**.  300·600·1200 이 전부 **88**,
384·768·1536 이 전부 **256** — 옥타브를 따라 커지지 않는다.

### 7-1 진짜 법칙

```
   E = 512 · f      f = q/2^e − 1  (q 의 정규화 가수)
```

열두 점 전부 오차 1 이내로 맞는다.  **지수와 무관하고, `E ≤ 512` 로 유계다.**

### 7-2 그래서 보정이 필요 없다

한 텍셀은 분자로 `q/4` 단위이므로 오프셋은 **`4E/q ≤ 2048/q`** 다:

```
   q =    256 -> 최대 8      텍셀        q =  65536 -> 0.031 텍셀
   q =   2048 -> 최대 1      텍셀        q = 2^20   -> 0.002 텍셀
   q =   8192 -> 최대 0.25   텍셀        q = 2^23   -> 0.0002 텍셀
```

그리고 사영 삼중항 `(s, t, q)` 는 **λ 로 자유롭게 비례**할 수 있다 — 몫이
변하지 않는다.  그러므로 빌더가 `q` 를 크게 잡으면 `E` 는 **저절로** 무시할 수
있게 된다.  평면 보정도, 옥타브 분할도 필요 없다.

### 7-3 `Q_MIN` 의 의미가 이제 정해진다

`Q_MIN` 은 나눗셈기가 무너지는 자리가 아니라 **원하는 정확도**가 정한다:

| 원하는 오차 | 필요한 `q` |
|---|---|
| 1 텍셀 | 2048 |
| 1/4 텍셀 | 8192 |
| 1/16 텍셀 | 32768 |

지금 값 256 은 **8 텍셀까지 허용**한다 — 너무 낮다.  측정이 근거를 준다.

### 7-4 교차검토 판정

| codex 주장 | 내 검증 | 결과 |
|---|---|---|
| 한 옥타브 안에서 `E` 는 평면이라 상쇄 가능, 거듭제곱에서만 끊긴다 | 대수로 확인 — `e` 가 상수면 `E` 는 `q` 의 1차식 | ✅사실 (다만 §7-2 로 **불필요**해졌다) |
| 다섯 점 두 경계로 법칙이라 하기 이르다; 같은 가수를 다른 옥타브에서 재라 | 재보니 **법칙이 실제로 틀렸다** | ✅**채택 — 이것이 진짜 법칙을 찾아냈다** |
| (d) `q` 를 거듭제곱으로 정규화하는 것은 화소마다 `2^e` 가 변하면 불가 | 맞다 — 그러나 §7-2 의 λ 비례는 **하나의 상수**라 사영 불변성 안에 있다 | ✅사실, 그리고 더 나은 길이 있다 |
| 오차가 분자 가산이 아니라 나눗셈 뒤 편향일 수도 | 구분 못 했다 — 다만 **어느 쪽이든 `E ≤ 512` 라는 결론은 같다** | ⏭️미검증, 행동이 안 바뀌므로 건너뜀 |
