# §3-12 B — 정점의 소수부를 싣는다 (계획, 2026-08-21)

A(부동소수 잡음)는 `M1_4A9` 에서 끝났다. 남은 것이 B 다: 훅이 정점의
**진짜 소수부**를 버린다.

## 1. 크기 (측정)

동률 없는 소수 도형(도형 9, `37/128` 이동)에서 하드웨어는 규칙과 **80 화소**
다르다(11240 중 0.7%). 정점마다 독립적인 소수부를 준 무작위 삼각형 120 개로
넓히면:

| 정점 소수부를 몇 비트 남기나 | 규칙과 다른 화소 | 면적 대비 |
|---|---|---|
| **0 (지금)** | 삼각형당 170.5 | **4.211%** |
| 1 | 84.7 | 2.093% |
| 2 | 42.2 | 1.042% |
| 3 | 21.8 | 0.539% |
| 4 | 10.4 | 0.256% |
| 6 | 2.7 | 0.067% |
| 8 | 0.6 | 0.014% |
| 11 | 0 | **0.000%** |

**비트 하나가 오차를 절반으로 줄인다.** 11 비트에서 정확히 0 인 것은
Mesa 자신이 11 비트 고정소수점이기 때문이다.

## 2. 실을 수 있는 비트는 삼각형이 정한다

지금 인코딩은 반 화소를 정수로 만들려고 2 배로 키운다(`AR0 = 2H`).
소수부 `s` 비트를 더 실으면 `AR0 = 2^(s+1)·H`, `AR2 = 2^(s+1)·|D|` 다.

커널 검증기는 `|AR2|`·`|AR1|` 을 `maxEdgeWalk = 16384` 로 묶고 **`AR0` 에는
상한이 없다**. `AR1 = -AR2 - e` 이고 `|e| < AR0` 이므로 묶이는 것은

```
   2^(s+1) · (|D| + H)  <=  16384        (그리고 2^(s+1)·H <= 131071)
```

**커널을 안 건드리고** 나오는 값:

| 표면 | H | \|D\| | 비트 | 잔차 |
|---|---|---|---|---|
| 320x240 보통 | 240 | 160 | **4** | 0.256% |
| 320x240 넓은 | 240 | 320 | 3 | 0.539% |
| 640x480 | 480 | 640 | 2 | 1.042% |
| 1600x1200 | 1200 | 1600 | 1 | 2.093% |
| 작은 삼각형 | 64 | 64 | 6 | 0.067% |

**보통 크기에서 16 배, 가장 큰 표면에서도 2 배 개선이고 재부팅이 없다.**

커널 예산을 필드 한계까지 올리면 보통 7 비트(0.031%), 1600x1200 에서
4 비트(0.256%)가 된다 — **별건으로 다룬다.**

## 2-1. 교차검토가 "배율만으로는 안 된다"고 했다 — **재 보니 된다**

> Merely changing AR0 = 2F*H, AR2 = 2F*|D| does not make a fractional xa or
> ya observable to the hardware.

**불가능 주장은 틀렸다.** `1/4` 격자와 `1/8` 격자에서 무작위 소수 변
각각 60 개를 잡고, `dy = 2·M·H` 로 규칙의 경계열을 **모든 행에서** 재현하는
`e` 가 있는지 찾았다 — **60/60 둘 다 있다.**

이유는 `e` 가 위상을 **정확히** 담을 필요가 없기 때문이다. 필요한 것은
`ceil((mag·k + e)/dy)` 가 **정수 수열**을 맞히는 것이고, 올림은 계단이라
더 거친 `e` 로도 같은 계단을 낼 수 있다. 대수적으로 위상의 분모가
`2M²H` 로 보였던 것이 곧 `dy` 가 그만큼 커야 한다는 뜻은 아니다.

**그러나 그 밑에 깔린 설계 요구는 옳다**: 시작 열과 `e` 를 **위상을 아는
식**에서 유도해야지, 정수 정점용 옛 식을 그대로 쓰면 안 된다. 계획이
"인코딩을 일반화한다"고만 적고 유도를 안 적었다. §3 에 유도를 넣는다.

## 3. 이번 회차: 유저랜드만

1. 훅이 정점의 소수부를 **버리지 않고 넘긴다**(고정소수점 정수로).
2. 빌더가 **삼각형마다 하나의 `s`** 를 고른다 — 그 삼각형의 **모든 변이
   허용하는 최소값**. 처음에 "변마다" 라고 적었는데 **교차검토가 옳게
   짚었다**: 두 변이 다른 `s` 를 쓰면 **공유 정점이 변마다 다른 자리**가 되어
   중간 정점 이음매에 틈이나 겹침이 생기고, 이웃 삼각형과 공유하는 변에서도
   갈라진다. 그리고 "그 삼각형 자신의 `s` 로 예측한 잔차" 라는 성공 기준
   자체가 변마다 다르면 뜻이 없어진다.
3. 인코딩을 `2` 대신 `2^(s+1)` 로 일반화하고, **시작 열과 오차항을 위상을
   아는 식에서 유도한다.** 정수 정점용 `A = 2·D·k0 + D - H` 를 그대로 쓰면
   안 된다 — `k0` 는 이제 정점에서 잰 기하 거리가 아니라 **표본 행의 수**다.

   ```
      규칙이 요구하는 경계:  B(r) = ceil( xa + (r + 1/2 - ya)·D/H - 1/2 )
   ```

   `x0 = B(첫 행)`, 그리고 `e` 는 `ceil((mag·k + e)/dy)` 가
   `B(첫 행 + k) - x0` 를 모든 `k` 에서 맞히도록 고른다. **닫힌 식을 세우고
   전수 확인한다** — 탐색으로 때우지 않는다.

### 3-0. 행 소유를 표본 행 공간에서 정의한다

`ya` 가 소수면 사다리꼴의 첫 행과 높이가 정점 좌표가 아니다. **반열린 규칙
하나**를 정하고 두 사다리꼴의 행 수를 거기서 유도한다: 행 `r` 은 `r + 1/2`
가 그 구간에 드는 사다리꼴에 속한다. 교차검토가 짚은 경우를 명시적으로
다룬다 — `0 < ymid - ytop < 1`, 같은 정수 행에 있으나 소수 높이가 다른 두
정점, 양자화로 `H = 0` 이 되는 경우, 중간 정점이 표본 중심에 정확히 놓이는
경우.

### 3-1. 넘침 — 이미 묶여 있다

지금 좌표 한계 8192 는 `2·|D|·k0` 가 32 비트에 들도록 고른 것이다.
`2^(s+1)` 로 키우면 16 배가 되지만, §2 의 부등식이 `2^(s+1)·|D| <= 16384`
를 이미 강제하므로

```
   2^(s+1)·|D|·k0  <  16384 · H  <=  16384 · 8192 = 1.34e8
```

**걷기 예산이 넘침을 이미 막는다.** 좌표 한계를 줄일 필요가 없다 —
그래도 python 으로 다시 확인하고 시험에 사례를 넣는다.

## 4. 성공/실패 기준 (숫자를 미리 적는다)

- **정수 정점 도형은 한 화소도 변하지 않아야 한다.** 소수부가 0 이면
  `s` 가 무엇이든 같은 그림이어야 한다. 도형 1·2·3·4·5·6·7 이 계속 규칙과
  일치.
- **도형 9**: 80 화소 → `s = 4` 이므로 **10 화소 근처**
  (연속 소수부 표로는 5.01% → 0.31%, 즉 16 분의 1).
- **무작위 소수 삼각형**: 각 삼각형의 `s` 를 §2 로 계산해 표의 잔차를
  예측하고, **삼각형마다** 그 예측과 맞는지 본다. 총합이 좋아지는 것으로는
  부족하다 — A 회차에서 총합이 경우별 퇴행을 숨기는 것을 봤다.
- **커널이 거절하지 않아야 한다**: `refused by the kernel validator: 0`.
  다만 이것만으로는 약하다(교차검토) — 부호 극단·필드 극단·양쪽 변 방향을
  일부러 넣는다.
- **`s = 0` 이 오늘과 정확히 같은 경로여야 한다.** 강제로 `s = 0` 으로 두고
  커버리지·깊이·색을 지금 코드와 대조하는 **차분 시험**을 만든다. 그래야
  "가장 큰 표면에서는 오늘로 되돌아간다"가 검증 가능한 말이 된다.
- **동률과 공유 변**: 지금 시험 도형은 동률을 피한다. 소수 정점에서는
  화소 중심에 정확히 걸리는 경우와 **대각선을 공유하는 삼각형 둘**을 넣어야
  한다 — 고립된 삼각형이 좋아 보이면서 이웃과 갈라질 수 있다.
- **`s` 가 바뀌는 경계**: 정점이 조금 움직여 `s` 가 한 단계 바뀔 때 그림이
  튀지 않는지 본다.
- **깊이·색은 안 변해야 한다**: 정점 좌표가 바뀌면 평면도 바뀌므로 **소수
  정점에서는 변한다**. 정수 정점에서 변하면 결함이다.

## 5. 안 하는 것

- 커널 예산 인상(재부팅). 유저랜드 결과를 보고 정한다.
- 클램프(`M1_4A7` §10-3), Z3. 별건.
- **정점 `z` 의 소수부.** 좌표와 같은 줄이지만 크기가 다르다(−0.43 코드).
  좌표가 끝난 뒤에 따로 본다.

## 5-1. 정수 정점 불변은 수학적으로는 성립한다 (확인함)

분자와 분모를 같이 키우면 모든 올림이 그대로다. 무작위 변 3000 개 × `s` 여섯
값에서 **불일치 0**. 다만 이건 **수학**의 확인이지 **구현**의 확인이 아니다 —
교차검토가 옳게 짚었듯 반올림 방향·좌표 영역·정렬이 새 경로에서 달라지면
깨진다. 그래서 §4 의 차분 시험이 필요하다.

## 6. 기대던 가정 — **재 보니 틀렸다** (2026-08-21)

계획은 "Mesa 가 넘기는 소수부가 11 비트 격자 위에 있다" 에 기대고, 재고
시작하라고 적었다. **재 보니 아니다.**

계기로 소수 좌표를 요청하고 받은 값을 찍었다:

```
   요청 40.0030000000  ->  받음 40.0029945374
   요청 40.0186250000  ->  받음 40.0186233521
   1/1, 1/16, 1/256, 1/2048, 1/4096, 1/65536 격자 위에 있는가 : 전부 아니다
   요청과 받은 값의 차이 : 최대 5.5e-6  (= float 정밀도)
```

**`VB->Win` 은 그냥 float 다.** Mesa 의 11 비트 고정소수점은 `VB->Win` 이
아니라 **소프트웨어 래스터라이저 안에서** 일어난다(`tritemp.h`).

### 6-1. 그래서 §1 의 표를 다시 쟀다

앞의 표는 **정점을 1/2048 격자 위에서 생성**해 만든 것이라 11 비트에서
0 이 나왔다. 그건 표본이 만든 값이다. 연속 소수부로 다시 재면:

| 비트 | 0 (지금) | 1 | 2 | 3 | 4 | 6 | 8 | 11 | 16 |
|---|---|---|---|---|---|---|---|---|---|
| 격자 표본 (틀림) | 4.211% | 2.093% | 1.042% | 0.539% | 0.256% | 0.067% | 0.014% | 0.000% | — |
| **연속 (맞음)** | **5.009%** | 2.474% | 1.200% | 0.610% | **0.314%** | 0.074% | 0.016% | 0.0009% | 0.000% |

**모양은 같고 값이 조금 크다.** 실을 수 있는 4 비트는 `5.01% → 0.31%`,
**16 배**다. 그리고 "11 비트면 정확하다" 는 **취소한다** — 그 자리에서도
0.0009% 가 남는다.

설계는 바뀌지 않는다. 바뀐 것은 **기대치와, 표를 만든 표본이 결론을 만들고
있었다는 사실**이다.
