# M1-4E4 — 알파 테스트

## 1. 저장소가 예고해 둔 것

`D3_5_ALPHA_BLEND_PLAN.md:305` 근처:

> `AC_aten`(비트 12) + `AC_atmode`(비트 13-15) + `AC_atref`(비트 16-23)이
> **`glAlphaFunc`에 그대로 대응한다.** … **미측정이다.**

지금 관문은 `glAlphaFunc` 를 아예 안 본다 — 알파 테스트가 켜진 상태는
`RasterMask` 검사에서 걸린다.

## 2. 인코딩은 깊이와 같은 모양

`mgareg_flags.h:68-80`:

```
   AC_aten    비트 12      disable 0 / enable 1
   AC_atmode  비트 13-15   noacmp 0, ae 2, ane 3, alt 4, alte 5, agt 6, agte 7
   AC_atref   비트 16-23   8 비트 기준값
```

값 **1 만 이름이 없다** — zmode 와 똑같다.  검증기도 이미 그 값을 거절한다
(`((ac >> 13) & 0x7) == 1`).

GL 과의 대응:

| GL | atmode | |
|---|---|---|
| `GL_NEVER` | 없다 | 거절 |
| `GL_LESS` | `alt` 4 | |
| `GL_EQUAL` | `ae` 2 | |
| `GL_LEQUAL` | `alte` 5 | |
| `GL_GREATER` | `agt` 6 | |
| `GL_NOTEQUAL` | `ane` 3 | |
| `GL_GEQUAL` | `agte` 7 | |
| `GL_ALWAYS` | `aten` 을 끈다 | |

## 3. 커널은 이미 열려 있다

`AC_CLIENT = 0x03FFFBFF` 이 비트 11-25 를 포함하므로 `aten`·`atmode`·`atref`
전부 클라이언트 것이다.  **Mesa 만 바뀌고 재부팅이 필요 없다.**

## 4. 그러나 세 가지가 미측정이다

### 4-1 무엇의 알파와 비교하나

GL 은 **텍스처 환경을 지난 뒤의** 프래그먼트 알파와 비교한다.  엔진의 알파
테스트가 보는 것이 그것인지, 아니면 보간된 알파인지는 안 쟀다.

§81 이 블렌드 **선택자**가 텍스처 단의 출력을 읽는다고 밝혔다.  알파 테스트가
같은 값을 보는지는 **다른 질문**이다 — 선택자는 `AC_alphasel` 이고 테스트는
`AC_atmode` 다.

가르는 법: 텍셀 알파와 프래그먼트 알파를 **다르게** 주고, 기준값을 그 둘
사이에 놓는다.  통과하면 하나, 버려지면 다른 하나다.

### 4-2 기준값이 어떻게 매핑되나

GL 의 `glAlphaFunc(func, ref)` 는 `ref` 를 `[0,1]` 로 클램프한다.  엔진은 8
비트다.  `round(255·ref)` 인가 `floor` 인가는 경계에서 갈린다 — `ref = 0.5`
에서 127 인가 128 인가.

가르는 법: 알파를 127 과 128 로 두고 `ref = 0.5`, `GL_GEQUAL` 로 그린다.

### 4-3 버려진 프래그먼트가 깊이도 안 쓰나

GL 은 알파 테스트를 **깊이 검사보다 먼저** 하고, 버려진 프래그먼트는 깊이도
안 쓴다.  엔진이 그러는지는 안 쟀다 — 안 그러면 알파 테스트로 뚫은 구멍이
깊이 버퍼에 남아 뒤엣것을 가린다.

가르는 법: 알파로 버려질 사각형을 그린 뒤 **깊이를 읽는다.**

## 5. 무엇을 재나 (§87)

레지스터 수준에서 먼저, GL 은 그 다음이다:

1. 일곱 모드 각각, 기준값 아래·같음·위 세 경우 (`§tdf` 와 같은 구성)
2. §4-1: 텍셀 알파 200, 프래그먼트 알파 100, 기준값 150
3. §4-2: 알파 127·128, 기준 0.5
4. §4-3: 버려진 뒤 깊이가 그대로인가

## 6. 공허하지 않게

- 세 경우(아래·같음·위)를 다 물어야 한다.  하나로는 "언제나 그린다"와
  구별되지 않는다
- §4-1 은 두 알파가 **기준값을 사이에 두고** 갈라져야 한다.  같은 쪽이면
  아무것도 안 갈린다
- §4-3 은 **버려지지 않는 대조군**이 필요하다 — 깊이가 안 바뀐 것이 "테스트가
  막았다"인지 "애초에 아무것도 안 그렸다"인지 갈라야 한다

## 7. 교차검토에 물을 것

- §4-1 을 가르는 구성이 정말 가르는가.  선택자와 테스트가 같은 값을 볼 수도,
  다를 수도 있는데 내 구성이 그걸 관측 가능한 차이로 만드나
- 알파 테스트가 블렌드보다 **먼저**인지 어떻게 확인하나
- `GL_ALWAYS` 를 `aten` 끄기로 하는 것과 `noacmp` 로 하는 것 중 어느 쪽인가.
  둘이 다른가
- Mesa 소프트웨어의 알파 테스트가 기준값을 어떻게 다루나
- 이 확장이 깊이·블렌드와 겹칠 때 처음 도는 조합

## 8. 쟀다 (§87)

```
   the largest reference that still drew:      200
   coming down from 255, the first that drew:  200
   ok  both directions meet at 200

   discarded by alpha: depth 8000    passing control: depth 4000  (cleared 8000)
   ok  a fragment the alpha test discards writes no depth either
```

텍셀 알파 200, 프래그먼트 알파 100, `GEQUAL` 로 기준값을 쓸었다.  `GEQUAL` 에서
그려지는 가장 큰 기준값이 곧 비교되는 알파다 — **200**, 즉 **텍스처 단의
출력**이다.  §81 이 블렌드 선택자에 대해 밝힌 것과 같은 값이고, 다른 필드이니
같을 이유가 없었는데 같았다.

그리고 **버려진 프래그먼트는 깊이도 안 쓴다** — GL 이 요구하는 순서다.
통과하는 대조군이 4000 을 썼으므로 "애초에 안 그렸다"가 아니다.

### 8-1 세 점으로는 틀린 답이 나왔다

처음엔 기준 50·150·250 세 점만 물었고 **셋 다 "그려짐"** 이라 나왔다 —
250 은 어떤 가설로도 버려져야 하는데.  쓸기가 201 부터 안 그려진다고 하므로
그 읽기는 틀린 것이다.

두 실행이 같은 질문에 다른 답을 주면 **어느 쪽도 읽기가 아니다.**  그래서
반대 방향으로 다시 쟀고 둘이 200 에서 만났다.  세 점 판은 텍스처를 고리 안에서
`blank()` 와 그리기 사이에 다시 썼는데, 그것이 원인인지는 **확정하지 않았다** —
확정한 것은 쓸기가 양방향에서 자기와 일치한다는 것뿐이다.

## 10. 다음 — 세 가설을 실제로 가른다

`REPLACE` 로는 "단"과 "텍셀"이 같은 값이라 §87 은 **보간 알파를 배제했을
뿐**이다.  `MODULATE` 로 셋을 가른다:

```
   Af = 192, At = 128  ->  단 = (192·129)>>8 = 96
   기준 112:  단 실패 / 텍셀 통과 / 보간 통과
   기준 160:  단 실패 / 텍셀 실패 / 보간 통과
```

`실패·실패` 면 단, `통과·실패` 면 텍셀, `통과·통과` 면 보간이다.

## 11. 됐다

```
   GL_LESS      below/equal/above 100   software 100   wanted 100
   GL_LEQUAL                      110            110          110
   GL_GREATER                     001            001          001
   GL_GEQUAL                      011            011          011
   GL_EQUAL                       010            010          010
   GL_NOTEQUAL                    101            101          101
   GL_ALWAYS                      111            111          111

   ok  the green witness shows through the discarded red
   ok  and the control keeps the red, so it could have drawn
   ok  GL_NEVER does not reach the engine
```

기준은 `128/255` 이고 알파는 그 한 단계 아래·같음·위다 — 그래서 등호 경우가
**Mesa 가 실제로 비교하는 바이트**의 등호이지 근처에서 반올림한 실수의 등호가
아니다.

### 11-1 기준값 질문이 사라진 이유

Mesa 는 `glAlphaFunc` 의 실수를 **이미 `GLubyte` 로 만들어 두고**
(`ctx->Color.AlphaRef`) 소프트웨어도 그 바이트를 비교한다.  드라이버가 그
바이트를 그대로 실으면 두 경로가 **구성상** 같은 기준을 쓴다 — 재현할 양자화가
없다.

### 11-2 증인

깊이만 읽으면 "버려졌다"와 "애초에 안 그렸다"가 안 갈린다.  그래서 구멍 뒤에
초록 사각형을 두고 **비치는지**를 본다.  통과하는 대조군이 빨강을 남기므로 앞
사각형이 그려질 수 있었음도 증명된다.
