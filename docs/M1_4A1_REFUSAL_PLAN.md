# M1-4a1 — 평범한 그리기가 왜 거절되는가 (§3-25)

아직 코드 없음.

## 1. 무엇을 봤나

대체 경로 시험이 우연히 드러냈다. 뷰포트 밖으로 크게 뻗은 삼각형을 그리면
**Mesa 가 먼저 자르고**(그래서 좌표는 백엔드 범위 안이다), 그렇게 만들어진
배치를 **커널이 거절한다** — 같은 프레임에 두 번.

그림은 이제 맞다(소프트웨어가 그린다). 하지만 **평범한 그리기가 가속을 못
탄다.** 이것이 잦다면 이 작업 전체의 값어치가 줄어든다.

## 2. 지금은 이유를 알 수 없다

훅은 거절을 세기만 하고 **`verdict` 를 어디에도 남기지 않는다.** 제출 블록에
이미 들어 있는데 버린다:

```c
if (OSMGAMesaProbeSubmit(&res) != 0) {
    hookDeclined++;
    ...                      /* res.verdict 를 아무도 안 본다 */
```

## 3. 후보 (계약을 읽어 좁힘)

| 판정 | 왜 그럴 수 있나 |
| --- | --- |
| `E_TRIROW` (8) | 잘린 결과가 클립 밖 행에 닿는다 |
| `E_TRICOL` (9) | 같은 것을 열에서 |
| `E_TRISLOPE` (10) | 기울기가 표현 범위를 넘는다 — 40000 짜리 변에서 그럴 법하다 |
| `E_EDGEDIV` (15) | `ar0`/`ar6` 가 사다리꼴 높이와 안 맞는다 |

처음엔 "경계 하나 차이일 것"이라고 적었다. **검사를 읽으니 그 추측이
약해진다.**

```c
if (t->y < 0L || t->h <= 0L)                              return E_TRIROW;
if ((unsigned long)t->y > lim->clipY1)                    return E_TRIROW;
if ((unsigned long)t->h > lim->clipY1 + 1UL - t->y)       return E_TRIROW;
```

셋째가 `>` 이지 `>=` 가 아니다. 그러니 삼각형이 **정확히 높이까지** 차지하는
경우는 통과한다. 열 검사도 `left > clipX1 + 1` 로 반열림을 이미 허용한다.

그리고 기울기도 아닐 것 같다 — 자르는 것은 변을 짧게 만들 뿐 **기울기를
바꾸지 않고**, 이 삼각형의 긴 변은 거의 수직이라 가로 기울기가 작다.

**즉 지금 가진 후보가 전부 약하다. 그러니 더더욱 재야 한다.**
추측을 세 번 다듬는 것보다 한 번 재는 것이 싸다 — 이 세션이 계속 그랬다.

## 4. 단계

### (a) 이유를 남긴다 — 동작은 안 바꾼다

훅이 마지막 거절의 `verdict` 와 `triangle`(어느 사다리꼴이었는지)을 보관하고
내보낸다. 판정별 횟수도 센다 — 하나만 남기면 **첫 번째만 보인다.**

동작을 안 바꾸므로 회귀 위험이 없다.

### (b) 잰다

대체 시험을 돌려 무엇이 나오는지 본다. 그리고 **얼마나 잦은지**를 재려면
평범한 장면이 필요하다 — 화면을 채우는 삼각형 여러 개, 일부는 뷰포트를
넘기고 일부는 안 넘긴다.

### (c) 그 다음에 정한다

- 경계 하나 차이면 **어디가 옳은지**부터 정한다. 커널이 옳고 백엔드가
  화소를 하나 더 주장하는 것일 수도 있다 — **커널을 느슨하게 만들기 전에
  백엔드를 본다.** 커널의 검사는 창 밖을 못 건드리게 하는 것이고, 그것을
  약하게 만드는 것은 마지막 수단이다.
- 기울기 표현 범위면 그건 **자를 값이 아니라 표현의 한계**이고, 대체 경로가
  옳은 답이다. 그러면 §3-25 는 "고칠 것 없음"으로 닫힌다.

## 5. 안 하는 것

- **커널의 경계 검사를 먼저 느슨하게 하지 않는다.** 그 검사가 이 저장소에서
  가장 여러 번 값을 한 것이다.
- **거절을 숨기지 않는다.** 지금 거절이 세어지고 대체되는 것은 옳다. 이
  작업은 왜 그런지를 알아내는 것이지 조용하게 만드는 것이 아니다.


## 6. 답이 나왔다 — 재기 전에, 읽어서 (2026-08-21)

codex 가 `E_TRISLOPE` 를 지목하며 **한계가 잘못 모델링됐다**고 했다.
확인했고, 맞다.

### 검사가 `h` 배만큼 과하다

```c
/* OpenStepMGAHW3D.c */
if (h != 0UL && sl > lim->maxEdgeWalk / h)
    return OSMGA_HW3D_E_TRISLOPE;          /* 즉 sl * h <= 16384 */
```

`sl` 은 `|ar2|`/`|ar5|` 다. **그것이 행당인가 총량인가**가 전부를 가른다.

**총량이다.** X.Org DDX 가 그대로 보여준다:

```c
/* mga_storm.c:1566, mgaSubsequentSolidFillTrap */
int ar2 = sdxl ? dxL : -dxL;
OUTREG(MGAREG_AR0, dyL);      /* 변의 총 dy */
OUTREG(MGAREG_AR1, ar2 - eL); /* 변의 총 dx */
```

그러니 한 변이 실제로 걷는 x 거리는 `|ar2|` 이지 `|ar2| * h` 가 아니다.

### 헤더의 주석이 스스로를 반증한다

```
 * Pixels of x travel an edge may accumulate over one triangle.  Chosen to
 * be far larger than any real triangle needs -- a 768-row edge at one
 * pixel per row is 768 -- ...
```

그 예시를 코드에 넣어보면 (python):

```
h = 768, |ar2| = 768
검사: 768 > 16384 / 768 = 21   ->  거절
```

**코드가 "어떤 진짜 삼각형보다도 훨씬 크다"며 든 예시를 거절한다.**
의도는 `|ar2| <= 16384`, 구현은 `|ar2| * h <= 16384` — **`h` 배 차이**다.

### 얼마나 아픈가 (python)

320 폭 표면에서 변이 폭을 가로지르면:

| 높이 | 허용되는 최대 dx |
| --- | --- |
| 32 | 512 |
| **51** | **321** |
| 52 | 315 |
| 240 | 68 |
| 480 | 34 |

**51 행보다 높은 삼각형은 화면 폭을 가로지르는 변을 가질 수 없다.**
가장자리 사례가 아니라 큰 삼각형 대부분이다. §3-25 가 이것이다.

### 그러므로 §5 의 결정 나무가 틀렸다

"기울기면 표현의 한계이니 대체 경로가 옳은 답"이라고 적었다. **아니다.**
표현의 한계가 아니라 **검사가 잘못 모델링된 것**이고, 고칠 것이 있다.

그리고 **검증기 시험도 같은 가정을 담고 있다** — `maxEdgeWalk / 20` 같은
값으로 경계를 확인한다. 그 시험이 통과한다고 전제가 옳은 것이 아니다.
시험도 함께 고쳐야 한다.

## 7. 그래서 다음 (아직 코드 아님)

1. **진단은 그래도 넣는다.** 판정별 수와 마지막 표본(`status`, `verdict`,
   `triangle`, 그리고 그 사다리꼴의 `y/h/ar/fxbndry`)을 남긴다 — 읽어서 얻은
   답을 **실기에서 확인**하기 위해서다. codex 말대로 `status` 도 남긴다:
   `verdict == OK` 인데 실패한 것과 검증 거절은 훅에서 이미 다르게 다룬다.
2. **확인되면 검사를 고친다** — `sl * h` 가 아니라 `sl`. 그리고 **검증기
   시험의 경계 사례도 함께 고친다**(지금 값들은 잘못된 모델을 굳히고 있다).
3. **커널을 느슨하게 하는 것이 아니다.** 의도된 한계는 그대로 16384 이고,
   구현이 그 의도와 어긋나 있던 것을 맞추는 것이다.


## 8. 실기가 확인했다 (2026-08-21)

진단만 넣고(동작 변경 없이) 대체 시험을 돌렸다:

```
refusals by verdict: [10]=2                       <- E_TRISLOPE, 두 번
last refusal: status 22 verdict 10, trapezoid 0 of 1, surface 320x240
   y=4 h=236 ar0=236 ar2=0 ar5=-179 ar6=236 fxbndry=00780078
   travel 179: against the limit itself inside, against limit/h (69) OUTSIDE
```

**읽어서 얻은 답 그대로다.** 236 행에 179 화소 움직이는 평범한 사다리꼴이,
한계 자체(16384)에는 한참 못 미치는데 `limit/h`(69) 에만 걸려 거절됐다.
`status 22` 는 `EINVAL` — 검증 거절이므로 대체 경로가 넘긴 것도 옳았다.

## 9. 고쳤다

검사를 `sl > maxEdgeWalk / h` 에서 `sl > maxEdgeWalk` 로 바꿨다.

**커널을 느슨하게 만든 것이 아니다.** 의도된 한계는 그대로 16384 이고,
`ar2` 가 총 변위이므로 **변이 걷는 거리를 묶는 것은 그 값 자체**다. 봉쇄는
여전히 선다 — 변은 클립 안에서 시작해 그만큼만 움직인다.

**검증기 시험도 함께 옮겼다.** 그 시험들은 같은 잘못된 모델을 담고 있어서
(`maxEdgeWalk / 20`) 통과해도 전제를 보증하지 못했다. 그리고 실기가 거절한
그 모양을 사례로 넣었다 — 하네스의 한계가 64 행이라 그 사례만 표면 크기를
넓혔다. **재현 못 하는 시험은 고쳤다는 증거가 못 된다.**

```
ok    slope at the walk limit                        0
ok    a tall triangle with an ordinary edge          0     <- 실기가 거절하던 것
ok    slope one past the limit                       10
ok    right edge past the limit                      10
ok    one row past the limit                         10
all cases behave as specified (0 failing)
```

설치 16:00. **재부팅 뒤 확인할 것**: 같은 시험에서 `declined 0`, 그리고
그 삼각형이 소프트웨어가 아니라 **가속으로** 그려지는가.


## 10. 재부팅 뒤 (2026-08-21)

설치 16:00, 부팅 16:02:56, 321888 바이트.

```
the ordinary triangle alone: accelerated 1, green 1596
with the far triangle: accelerated 3, handed to software 0, declined 0
   green 1596 (unchanged), red 42245
   refusals by verdict:            (비었다)
```

**거절이 사라졌고 그 삼각형이 하드웨어로 그려진다.** §3-25 가 닫힌다.

회귀 없음:

| 시험 | 결과 |
| --- | --- |
| `zagree` 320x240 / 640x480 / 800x600 | **이전과 숫자까지 동일** |
| `bind` 1~5 | 전부 0 |
| `zsize` 800x600 / 333x222 | 동일 |

### 화소 수가 227 줄었다 (python)

같은 삼각형이 소프트웨어로 42472, 하드웨어로 42245 — **227 차이, 도형의
0.53%**. 가장자리가 약 712 화소이므로 **행당 한 화소도 안 되는 차이**다.
`zagree` 가 재는 두 래스터라이저의 커버리지 불일치와 같은 것이고, 고침이
무언가를 잃은 것이 아니다. 다만 **논증이지 측정이 아니다** — 아래 참조.

### 시험이 뒤집혔다, 그리고 대체 경로가 시험을 잃었다

이 파일은 "커널이 거절한 삼각형이 잃히지 않고 소프트웨어로 간다"를
확인하려고 썼다. 그 거절이 **잘못된 검사였고** 고쳐졌으므로, 이제 같은
삼각형은 가속으로 그려진다. 그래서 단정문을 뒤집어 **고침을 지키는 시험**으로
바꿨다(거절 0, 가속 > 0).

**그 대신 삼각형 단위 대체 경로에 시험이 없어졌다.** 지렛대가 없다 — 커널이
이제 받아들이고, 좌표 범위 경로는 Mesa 가 먼저 잘라서 닿지 않는다.
그것은 **정확성 기계**다(실패 뒤 삼각형을 다시 그릴지 잃을지 정한다).
시험 없는 정확성 기계는 썩는다. `REMAINING_WORK` 로 세운다.
