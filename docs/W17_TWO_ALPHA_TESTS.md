# W17 — 알파 테스트는 두 개다 (2026-08-28, 코딩 전)

W16 §9.4 는 `aten` 을 **"문서 ≠ 실측"** 목록에 올렸다. **그 판단을 다시
본다** — 사양서를 더 읽으니 모순이 아닐 수 있다.

---

## 1. 사양서가 두 개라고 말한다

`ALPHACTRL` 의 `alphasel` 아래 주(3-34):

> *"**Alpha testing is done in two separate places.** Both use the same
> reference value (atRef) and alpha test mode (atMode).
> **The first test is done right after texture filtering** and can be
> disabled by setting the '**atEn**' bit to '0', or by setting 'atmode' to
> "ALWAYS".
> **The second test is done before alpha blending** and can be disabled by
> programming '**atmode**' to "ALWAYS"."*

| | 어디서 | 무엇으로 끄는가 |
| --- | --- | --- |
| 첫 번째 | 텍스처 필터링 직후 | `aten=0` **또는** `atmode=ALWAYS` |
| **두 번째** | **알파 블렌딩 직전** | **`atmode=ALWAYS` 뿐** |

**`aten=0` 은 알파 테스트를 끄지 않는다.** 첫 번째만 끈다.

## 2. 그러면 W16 의 "어긋남" 이 사라진다

| | |
| --- | --- |
| 4.5.5.4 | Gouraud 사다리꼴은 `aten=0` 이어야 한다 |
| `tat` | 텍스처 없는 알파 테스트가 **동작한다** |

**모순이 아니다.** 텍스처가 없으면 첫 테스트는 자리가 없고(텍스처 필터링이
없다), 우리가 보는 것은 **두 번째** 테스트다. 그것은 `atmode` 가 몰고
`aten` 과 무관하다.

> **내가 사양서를 덜 읽고 "하드웨어가 문서보다 관대하다" 고 적었다.**
> W16 §9.4 는 정정 대상이다 — **다만 정정하기 전에 재야 한다.**

## 3. 재는 것 — 하나의 질문

> **`aten=0` 이고 `atmode≠ALWAYS` 일 때, 텍스처 없는 삼각형에서 알파 테스트가
> 동작하는가?**

| 결과 | 뜻 | 해야 할 일 |
| --- | --- | --- |
| **동작한다** | 두 번째 테스트가 일한다. 사양서가 맞다 | Mesa 가 `aten=0` 을 보내게 한다. **동작 변화 없음** |
| 안 한다 | 이 보드에서는 `aten` 이 필요하다 | W16 §9.4 를 **어긋남으로 유지**하고 아무것도 안 고친다 |

**어느 쪽이든 배운다. 그리고 어느 쪽이든 지금보다 정확해진다.**

## 4. 어떻게 잰다

Mesa 를 거치지 않는다 — Mesa 는 알파 테스트가 켜지면 항상 `aten` 을 세우므로
그 경로로는 `aten=0` 을 만들 수 없다. **원시 배치 클라이언트**를 쓴다
(`test/` 에 `alphactrl` 을 직접 세우는 것이 이미 여럿 있다).

```
같은 기하, 같은 atref, 같은 atmode(=ALT), 알파만 기준값 아래/같음/위
  A: aten=1  ->  폐기 패턴 P1
  B: aten=0  ->  폐기 패턴 P2
  C: aten=0, atmode=ALWAYS -> 아무것도 폐기 안 됨 (대조군)
```

> **정정 (§8.2)**: 이 문단은 틀렸다. `atmode=ALWAYS` 는 **두 테스트를 모두**
> 끄므로, `C` 는 "두 번째가 돌았지만 전부 통과" 와 "아무 테스트도 안 돌았다" 를
> **가르지 못한다.** `C` 는 판별자가 아니라 **그리기 기준선**이다 — 기하가
> 그려지고 읽히는지만 말한다.
>
> **판별자는 `B` 자신이다.** `B` 에 반드시 폐기돼야 할 알파와 반드시 통과해야
> 할 알파가 함께 있으면, 섞인 패턴이 나오는 것 자체가 "`atmode` 가 모는
> 무언가가 `aten=0` 을 넘어 살아 있다" 는 뜻이다.
>
> 그리고 **`P1 == P2` 가 "두 번째 테스트가 일한다" 를 뜻하지도 않는다.**
> 대안이 여럿이다 — 이 out-of-spec 조합에서 하드웨어가 `aten` 을 무시할 수도,
> opcode 상 첫 테스트가 애초에 없을 수도, 두 설정이 우연히 같은 유효 알파를
> 볼 수도 있다. **주장을 그만큼만 한다.**

### 4.1 알파는 어디서 오는가 — 먼저 확인할 것

`alphasel<25:24>` 가 픽셀의 알파를 정한다(0=텍스처, 1=diffused, 2=modulated).

**`tat` 은 `alphasel = 0` 으로 돈다** — 확인했다. Mesa 가 `ALPHASEL_TEX` 를
대입하는 조건은 `BlendEnabled && texOn` 인데(`:1620`), `tat` 은 둘 다 끄므로
기반 상수 `BLEND_OPAQUE = 0x00000101` 의 `alphasel = 0` 이 그대로 남는다.
**텍스처가 없는데 "텍스처에서" 를 고른 상태이고, 선택자 표는 그것을 정의하지
않는다.** 그런데 동작한다.

> **그러므로 `alphasel=1` 로 고정하면 `tat` 이 제기한 질문에 답하지 못한다**
> (§8.3). **둘 다 잰다:**
>
> ```
>   alphasel ∈ {0, 1}   x   aten ∈ {0, 1}   x   atmode ∈ {비교, NOACMP}
> ```
>
> `alphasel=0` 행만이 W16 의 `tat` 서술을 고쳐 쓸 자격을 준다.
> `alphasel=1` 행은 **문서화된** Gouraud 구성이 동작함을 보일 뿐이다.

## 5. 위험

**없다.** 정상 3D 제출 한 번이고, 오프스크린에 그린다. 새 레지스터를 쓰지
않는다 — `ALPHACTRL` 은 이미 모든 배치가 쓰는 레지스터다.

## 6. 하지 않는 것

- **Mesa 를 아직 고치지 않는다.** 측정이 먼저다
- **`atmode` 의 값 표를 건드리지 않는다** — 이미 검증된다
- **W16 §9.4 를 아직 정정하지 않는다** — 재고 나서

## 7. codex 에 물을 것

- 두 테스트 해석이 맞는가 — 다른 곳에 이를 뒤집는 문장이 있는가
- `alphasel=1`(diffused) 고정이 옳은가, 아니면 `tat` 과 같은 조건(`0`)으로
  재야 비교가 되는가
- 대조군 `C` 가 충분한가
- 두 번째 테스트가 **블렌딩 직전**이라면, 블렌딩이 꺼진 배치에서도 도는가
  (`tat` 은 `glDisable(GL_BLEND)` 로 잰다)
- Mesa 를 고칠 때 `aten` 을 끄면 **텍스처 있는** 경로가 달라지는가

## 8. codex 교차검토 판정 — 전부 채택

| # | 지적 | 검증 | 판정 |
| --- | --- | --- | --- |
| 1 | 두 테스트 해석은 맞다. 그러나 **"어긋남이 없다" 는 과하다** | 4-41 표 | ✅ |
| 2 | **`ALWAYS` 대조군이 판별자가 아니다** | 3-34 주 | ✅ |
| 3 | **`alphasel` 은 둘 다 필요하다** | `:1620` 조건 | ✅ **핵심** |
| 4 | 블렌딩 꺼짐이 두 번째 테스트를 우회하지 않는다 | 3-32 | ✅ 사실 |
| 5 | **`aten` 전면 해제는 허가되지 않는다** | 파이프라인 위치 | ✅ |
| 6 | 빠진 작업이 여럿 | — | ✅ |

### 8.1 어긋남은 절반만 사라진다

두 테스트 해석은 옳고, 4-41 이 다리를 놓아 준다: Gouraud 표가 **`alpha test
mode` 와 `alphasel` 을 허용하면서 동시에 `aten=0` 을 요구한다.** 표가 자기
모순이 아니라면 **텍스처 없는 Gouraud 도 두 번째 테스트를 쓸 수 있어야 한다.**

**그러나 `tat` 은 여전히 `aten=1` 을 보낸다** — 사양서가 `"must"` 0 이라고 한
자리에. 보드가 그것을 견딘다는 관측은 **남는다.**

> **사라지는 것**: *"사양서를 지키면 Gouraud 알파 테스트가 불가능하다"*
> **남는 것**: *"이 보드는 사양서가 금지한 비트를 견딘다"*
>
> **W16 §9.4 는 이 둘을 구분해 다시 써야 한다** — 통째로 지우는 것이 아니다.

### 8.2 `ALWAYS` 대조군 (§4 정정)

`atmode = NOACMP` 는 **두 테스트를 모두** 끈다(3-34). 그러므로 `C` 는
그리기 기준선일 뿐이고, 판별은 **`B` 에 실패할 알파를 넣어** 한다.

### 8.3 ★ `alphasel` — 하나를 고르면 다른 질문에 답한다

`tat` 은 `alphasel=0` 이다(`:1620` 이 `BlendEnabled && texOn` 을 요구하고
`tat` 은 둘 다 끈다). **`alphasel=1` 만 재면 `tat` 을 설명하지 못한다.**
둘 다 잰다.

### 8.4 ★ `aten` 전면 해제는 허가되지 않는다

텍스처 경로에는 **첫 테스트가 실재한다.** 첫 테스트는 **필터링된 텍스처
알파**를, 두 번째는 **텍스처 블렌딩 이후 알파**를 본다. 변조가 걸리면 둘이
`atref` 의 **반대편**에 놓일 수 있다:

```
ALT, 텍스처 알파 > atref, 최종 변조 알파 < atref
  aten=1 : 첫 테스트가 폐기
  aten=0 : 두 번째 테스트가 통과
```

**"동작 변화 없음" 은 텍스처 경로에서 거짓이다.** 그리고 어느 쪽이 GL 에
맞는지는 별개 질문이다 — GL 의 알파 테스트는 **최종** 프래그먼트 알파를
봐야 하므로, `aten=0` 이 오히려 **옳을** 수도 있다. **재기 전에는 모른다.**

### 8.5 착수 조건

1. **`alphasel` 0 과 1 을 모두** 잰다
2. `C`(ALWAYS)는 **그리기 기준선**으로만 쓴다. 판별은 `B` 의 혼합 패턴
3. **여섯 비교 모드 전부** — Mesa 변경이 모든 GL 함수에 걸리므로 `ALT` 하나로는 부족
4. **텍스처 단계 분리 프로브**: 텍스처 알파와 최종 알파를 `atref` 반대편에
   두어 두 테스트의 **위치**를 실제로 가른다
5. `ALPHASTART` 의 고정소수점 값을 **명시**한다 (원시 클라이언트는 Mesa 의
   바이트 변환을 안 거친다)
6. **제출 판정·배경 sentinel·양성 대조**를 확인한다 — 픽셀이 같은 것은
   "거부됐다" 로도 만들어진다
7. 네 주장을 **분리해서** 적는다:
   - `aten=0` 에서 `atmode` 비교가 남는가
   - 그것이 문서의 두 번째 테스트와 일관되는가
   - `tat` 의 `alphasel=0` 동작이 그대로인가
   - 텍스처 경로에서 `aten` 을 꺼도 되는가

## 9. 결과 (2026-08-28 실기)

`test/openstep-mga-hw3d-alphatest-probe.m`, 24 행 × 알파 3 개 = **72 제출**.

```
draw baseline -- atmode ALWAYS, both tests off
  alphasel 0: drew (verdict 0)
  alphasel 1: drew (verdict 0)

  sel en mode    a=127 a=128 a=129   expected
    0  0 AE  ==   gone  draw  gone   gone
    0  0 ALT  <   draw  gone  gone   draw
    0  1 AE  ==   gone  draw  gone   gone
    0  1 ALT  <   draw  gone  gone   draw
    1  0 AGTE>=   gone  draw  draw   gone
    1  1 AGTE>=   gone  draw  draw   gone
      ... 24 행 전부 ...

every row matched the comparison it asked for (0 rows disagreeing)
```

### 9.1 `aten=0` 에서도 비교가 산다

**`aten` 은 결과를 하나도 바꾸지 않는다.** 여섯 비교 모드 × 두 `alphasel` ×
세 알파, 전부 요청한 비교 그대로다.

**혼합 패턴이 판별의 근거다** — 각 행에 draw 와 gone 이 함께 나오므로
*"테스트가 안 돌아 전부 통과"* 가 아니다. §8.2 가 요구한 것이 이것이다.

### 9.2 `tat` 의 구성이 재현된다

`sel=0, en=1` 행이 `tat` 의 상태다(텍스처 없이 `alphasel=0`). 그 행이
`sel=0, en=0`(사양서를 지킨 구성)과 **여섯 모드 전부에서 같다.**

**선택자 0 을 재지 않았으면 `tat` 을 설명하지 못했을 것이다** — §8.3 의 지적이
정확했다.

### 9.3 이 결과가 허가하는 것과 하지 않는 것

| 주장 | 판정 |
| --- | --- |
| `aten=0` 에서 `atmode` 비교가 남는다 | ✅ **측정됨** (24/24) |
| 문서의 두 번째 테스트와 **일관된다** | ✅ 일관 — 다만 *그것임*을 증명하진 않는다 |
| `tat` 의 `alphasel=0` 동작이 그대로다 | ✅ **측정됨** |
| **텍스처 경로에서 `aten` 을 꺼도 된다** | ❌ **허가되지 않음** — 텍스처를 안 그렸다 |

**네 번째는 §8.4 의 반례가 그대로 살아 있다**: 첫 테스트는 필터링된 텍스처
알파를, 두 번째는 텍스처 블렌딩 이후 알파를 본다. 그 둘이 `atref` 반대편에
놓이는 경우를 재기 전에는 텍스처 경로를 건드리지 않는다.

### 9.4 W16 §9.4 를 좁힌다

| | 이전 기록 | 정정 |
| --- | --- | --- |
| 사라짐 | ~~*"하드웨어가 문서보다 관대하다"*~~ | 사양서를 지켜도 알파 테스트가 된다 |
| 남음 | — | **이 보드는 `aten=1` 을 견딘다** (사양서가 `must` 0 이라 한 자리에서) |

**어긋남은 절반이었다.** 그리고 절반은 실재한다.

### 9.5 남은 것

**텍스처 단계 분리 프로브** — 텍스처 알파와 최종 알파를 `atref` 반대편에 두어
두 테스트의 **위치**를 가른다. 그것이 Mesa 를 고칠 자격을 주는 실험이고,
이 프로브는 그것을 하지 않았다.
