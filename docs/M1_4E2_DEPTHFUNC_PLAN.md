# M1-4E2 — 깊이 비교 여섯 개를 더 받는다

## 1. 지금

```c
    if (ctx->Depth.Func != GL_LESS)   return NULL;
    if (ctx->Depth.Mask != GL_TRUE)   return NULL;
```

`OpenStepMGAMesaHook.c`.  GL 의 여덟 비교 중 **하나만** 받는다.  `GL_LEQUAL`
은 다중 패스·데칼에서 `GL_LESS` 다음으로 흔하고, `GL_ALWAYS`·`GL_GEQUAL` 도
평범하다.

## 2. 엔진은 일곱을 갖고 있고, 문서가 이름을 붙였다

`mgareg_flags.h:254-261` (Xorg 의 `xf86-video-mga`):

```
   DC_zmode_nozcmp  0     DC_zmode_zlt    4
   DC_zmode_ze      2     DC_zmode_zlte   5
   DC_zmode_zne     3     DC_zmode_zgt    6
                          DC_zmode_zgte   7
```

값 **1 만 이름이 없다.**  그러니 미명명 인코딩을 추측으로 넘기는 일은 없다 —
그 규칙은 `MINMODE` 화이트리스트에서 이미 쓴 것과 같다.

GL 과의 대응:

| GL | zmode | 상태 |
|---|---|---|
| `GL_NEVER` | **없다** | 계속 거절 |
| `GL_LESS` | `zlt` 4 | 이미 있다 |
| `GL_EQUAL` | `ze` 2 | 새로 |
| `GL_LEQUAL` | `zlte` 5 | 새로 |
| `GL_GREATER` | `zgt` 6 | 새로 |
| `GL_NOTEQUAL` | `zne` 3 | 새로 |
| `GL_GEQUAL` | `zgte` 7 | 이미 상수만 있다 |
| `GL_ALWAYS` | `nozcmp` 0 | 새로 — §4 의 함정 |

## 3. 커널은 안 바뀐다

검증기는 zmode 를 **검사하지 않는다** — `HW3D.c:432`:

> zmode is not checked: every value only decides whether a pixel is written,
> never where.

즉 봉쇄와 무관한 필드다.  **Mesa 만 바뀌고 재부팅이 필요 없다.**

## 4. `nought` 이 두 가지를 뜻한다 — 고쳐야 할 곳

빌더가 `zmode != 0` 으로 "깊이를 쓰는가"를 정한다 (`Triangle.c:463`, `647`,
`811`).  그런데 `nozcmp` 가 **0** 이다.  `GL_ALWAYS` 를 그대로 넣으면
"깊이 없음"으로 읽혀 `atype I` 가 되고, 비교도 쓰기도 사라진다.

그러니 "깊이가 켜졌는가"를 zmode 값과 **분리**한다.  가장 작은 방법:
`OSMGA_MESA_ZMODE_ON` 비트를 하나 두고, 실제 zmode 는 그 아래 3 비트로 싣는다.
빌더는 그 비트로 atype 을 정하고, 인코더에 넘길 때는 마스크로 벗긴다.

`dwgctl` 의 zmode 는 비트 8-10 이므로, 표지 비트는 그 밖(예: 비트 11)에 두고
빌더가 지운다 — 클라이언트 마스크(`DWG_CLIENT = 0x77F`)가 비트 11 을 포함하지
않으므로 커널까지 새어 나가도 걸러진다.  그래도 빌더에서 지운다.

## 5. `glDepthMask(GL_FALSE)` 는 계속 거절한다

깊이 쓰기를 따로 끄는 제어가 **문서에 없다.**  쓰기는 `atype zi` 에 묶여
있고(`mgareg_flags.h:245-250`), 별도의 `zdrwena` 류가 없다.  그러니 "시험은
하되 쓰지 않는다"는 이 엔진에 없다 — 기록하고 거절한다.

(다른 깊이 버퍼로 쓰기를 흘리는 우회는 **시험도** 그 버퍼를 읽게 되므로 안
된다.)

## 6. 어떻게 재나

`openstep-mga-mesa-depth-anchor-test.c` 가 이미 깊이를 직접 읽는 하네스다.
일곱 비교 각각에 대해:

1. 배경을 알려진 깊이로 채우고
2. 그 앞·같은 자리·뒤에 삼각형을 그려
3. **색과 깊이 둘 다** 하드웨어와 소프트웨어를 비교한다

각 비교마다 통과해야 할 경우와 버려야 할 경우를 python 이 지정한다.  `GL_EQUAL`
과 `GL_NOTEQUAL` 은 **같은 깊이**가 필요하므로 양자화를 건드리지 않는 값을
골라야 한다 — 그게 이 시험의 함정이다.

## 7. 공허하지 않게

- 각 비교마다 **통과하는 경우와 버리는 경우가 둘 다** 있어야 한다.  한쪽만
  있으면 "언제나 그린다"와 구별되지 않는다
- 하드웨어가 실제로 돌았음을 세어 확인한다 (`Drawn` 증가, 폴백 0)
- `GL_NEVER` 와 `Mask FALSE` 는 **거절되는지** 확인한다 — 열린 관문이 조용히
  넓어지지 않았음을 보이는 쪽
- 깊이 버퍼도 읽는다.  색만 보면 "비교는 맞고 쓰기가 틀린" 경우를 놓친다

## 8. 교차검토에 물을 것

- §4 의 표지 비트가 옳은 방법인가.  더 나은 방법이 있나
- `nozcmp` 가 정말 "언제나 통과"인가, 아니면 "깊이 단을 아예 끈다"인가.
  후자면 `GL_ALWAYS` + 쓰기가 안 된다 — 무엇으로 가르나
- `GL_EQUAL`/`GL_NOTEQUAL` 이 16 비트 양자화에서 의미 있게 시험될 수 있나
- 일곱 중 Mesa 소프트웨어와 갈릴 만한 것이 있나 (경계에서의 `<` 대 `<=`)
- 이 확장이 열어주는 조합 중 지금까지 한 번도 안 돈 것은

### 9-1 §85 — `NOZCMP` 는 쓴다

```
   NOZCMP  colour 0000c4  depth 4000   (cleared to 8000, drawn at 4000)
   ZLT     colour 0000c4  depth 4000
```

저장소의 옛 D3-3a 측정은 이걸 못 갈랐다 — 그 밴드의 깊이가 클리어값과 **같아서**
"썼다"와 "안 썼다"가 구별되지 않았다.  클리어에 없는 값으로 그리면 갈린다.

## 10. 고친 설계

- 표지 비트를 쓰지 않는다.  빌더가 `zmode` 와 **따로** `depthOn` 을 받는다.
  `dwgctl` 은 `depthOn` 으로 atype 을 고르고 `zmode & 0x700` 을 싣는다
- `glDepthMask(GL_FALSE)` 는 **"이 계약이 표현하지 못한다"** 로 적는다.
  `PLNWT` 가 하드웨어에 있고 드라이버가 매 제출마다 `0xffffffff` 로 세우며,
  계약은 그것을 노출하지 않는다.  "하드웨어가 못 한다"는 증명된 바 없다
- 시험은 **평평한 보정 깊이 코드**로, 같은 코드·한 코드 가까이·한 코드 멀리
  세 경우를, 가속과 강제 소프트웨어 양쪽에서

## 11. 됐다

```
   GL_LESS      far/same/near 001   software 001   wanted 001
   GL_LEQUAL                  011            011          011
   GL_GREATER                 100            100          100
   GL_GEQUAL                  110            110          110
   GL_EQUAL                   010            010          010
   GL_NOTEQUAL                101            101          101
   GL_ALWAYS                  111            111          111

   ok  GL_NEVER does not reach the engine
   ok  a masked depth write does not either
```

**일곱 전부** GL 이 요구하는 대로 그리고, 엔진과 소프트웨어가 세 경우 모두
일치한다.  거절해야 할 둘은 여전히 거절된다.

### 11-1 세 경우여야 하는 이유

한 경우만으로는 "언제나 그린다"와 "언제나 안 그린다"가 구별되지 않는다.
`far/same/near` 셋을 다 물으면 일곱 함수의 답이 서로 다른 세 비트가 되고, 그
표가 곧 함수의 정의다.

### 11-2 평평한 깊이여야 하는 이유

두 경로의 깊이 코드가 기울어진 프리미티브에서 최대 2 만큼 다르다(기록됨).
`GL_EQUAL` 은 관용이 0 이므로, 기울어진 깊이로 재면 비교가 아니라 **반올림**을
재게 된다.  평평한 사각형은 한 코드에 앉으므로 "같다"가 정말 같다.

## 12. 두 번 틀린 것

### 12-1 열 이름이 거꾸로였다

`glOrtho(0, W, 0, H, −1, 1)` 에서 창 깊이는 `(1 − z)/2` 다 — `z = −0.5` 가
**0.75 로 먼 쪽**이다.  시험을 `near/same/far` 로 이름 붙이고 기대값을 그렇게
썼더니 부등식 넷이 전부 "실패"했다.

그런데 **하드웨어와 소프트웨어는 넷 모두에서 서로 일치했다.**  그게 단서다 —
드라이버가 틀렸으면 둘이 갈렸을 것이다.  python 으로 창 깊이를 계산하니 일곱
값이 실기 읽기와 정확히 일치했다.

### 12-2 `ZMODE_NONE` 값을 바꾸면서 리터럴 호출부를 깼다

`NONE` 이 0 에서 `0xFFFFFFFF` 로 바뀌었는데, 시험 넷이 zmode 자리에 **리터럴
`0UL`** 을 넘기고 있었다.  이제 0 은 `ALWAYS` 이므로 그 시험들이 깊이를 켠 채로
돌았고, `zorg` 가 없어 거절돼 도달범위가 0 으로 나왔다.

`tr` 의 `reach v 0 oracle v 7225344` 가 잡아냈다.  네 곳 모두 상수 이름으로
바꿨다 — 이런 값은 이름으로만 넘겨야 한다.
