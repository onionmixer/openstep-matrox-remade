# §3-12 — 깊이 평면을 화소 중심으로 (계획, 2026-08-21)

측정: `M1_4A6_DEPTH_ANCHOR_PLAN.md` §9. 원인이 셋 확인됐고 **크기가 천 배
차이**난다.

| | 무엇 | 도형 1 | 도형 2 |
|---|---|---|---|
| **Z2** | 평면을 화소 **모서리**에서 읽는다 | **+2662.36** | **−2612.89** |
| Z1 | 정점 z 를 자른다 | −0.42 | −0.44 |
| Z3 | 출력을 절단한다 | −0.50 | −0.50 |

## 1. 범위 — Z2 만

Z1·Z3 은 **한 코드 미만**이다. Z2 는 삼각형 자신이 걸치는 40000 코드의
**6.5%**, 깊이 버퍼 전체의 4% 다. 그리고 Z2 는 색·알파에 이미 적용한
**바로 그 한 줄**이다.

Z1 은 훅에 있고 **x·y 절단과 같은 줄**(§3-12 의 나머지 절반)이므로 손대려면
그 관계부터 정리해야 한다. Z3 은 색이 쓰는 `osmgaStartFixed` 를 깊이가 안
거치기 때문이고, 반 코드짜리다. **둘 다 이번이 아니다.**

## 2. 고칠 것

`mesa/OpenStepMGAMesaTriangle.c` 의 깊이 시작값:

```c
double ox = (double)left - (double)a->x + 0.5;
double oy = (double)y    - (double)a->y + 0.5;
```

## 3. 클램프 — 엄격한 개선이 **아니다**, 재 봤다

깊이 시작값은 `[0, 65535]` 로 잘린다. 반 화소가 2662 코드나 되므로 이 잘림이
새로 걸릴 수 있다고 의심해 **세어 봤다.**

무작위 삼각형 + 무작위 정점 깊이, 사다리꼴 **236940 개**:

```
   아무 데도 안 걸림      235148
   모서리만 걸림            1093    <- 수정이 없앤다
   중심만 걸림               475    <- 수정이 만든다
   둘 다 걸림                224
```

**순개선이지 엄격한 개선이 아니다.** 그리고 둘 다 **sliver 현상**이다 —
2×면적의 중앙값이 각각 292 와 127 인데, 걸리지 않는 경우는 8983 이다.
2×면적 200 미만 비율이 42.5% 와 56.2%. 그런 삼각형의 깊이 평면은 어느
점에서 표본하든 조건수가 나쁘다.

**처음에 세우려던 논거는 틀렸다**: "중심은 첫 그려지는 화소 안이니 범위
안"이라고 적으려 했는데, 사다리꼴의 **첫 행이 빈 행**일 수 있다(도형 1 의 위
사다리꼴이 실제로 그렇다 — 53 행은 안 그려진다). 그러면 시작 화소는 덮이지
않았고 그 중심은 삼각형 밖일 수 있다. 논거 대신 **숫자를 쓴다.**

### 3-1. 화소로 다시 셌다, 그리고 무엇이 망가지는지 소스로 말한다

교차검토: **사다리꼴 수는 안전 논거가 아니다** — 클램프된 시작값은 한 화소가
아니라 **그 사다리꼴 전체**를 옮긴다. 맞다, 그리고 이건 추정이 아니라
**우리 소스가 말한다**: `z0` 는 사다리꼴마다 한 번 계산되고 엔진은
`z0 + i·zdx + j·zdy` 를 걷는다. 잘린 만큼 **모든 화소가 통째로 어긋난다.**

그래서 화소로 셌다:

```
   모서리만 걸림   572 사다리꼴,  253822 화소   <- 수정이 없앤다
   중심만 걸림     238 사다리꼴,   58502 화소   <- 수정이 만든다
   잘린 양: 중앙값 3320 / 6477 코드,  최대 80 만 코드
```

**화소로 재도 4.3 : 1 개선**이다. 그리고 걸렸을 때의 오차는 크다(중앙값
수천 코드) — 그러니 "적게 걸린다"가 아니라 **"걸리는 경우를 따로 본다"** 로
간다(§5).

### 3-2. Z1 은 삼각형 안에서 한 코드를 못 넘는다 (교차검토 Q1)

정점 오차가 각각 1 코드 미만이고 내부 점의 무게중심 좌표는 음이 아니며 합이
1 이므로, **내부에서는 1 코드를 못 넘는다** — 모양과 무관하다. 확인:
무작위 삼각형 3947 개에서 덮인 화소 최대 오차 **0.9844 코드**.

그리고 "설정 원점에서 멀어질수록 계수 오차가 쌓인다"도 쟀다: 기울기 양자화
오차 × 320 열 = **0.0049 코드**. 무시할 수 있다.

## 4. 예측 (숫자를 미리 적는다)

| | 지금 | 수정 뒤 |
|---|---|---|
| 하드웨어 중심 잔차 (도형 1) | +2661.46 | **−0.9 근처** |
| 하드웨어 중심 잔차 (도형 2) | −2613.83 | **−0.9 근처** |
| 흉내(**자른 정점 z + 중심**) 대 하드웨어 | 0/704 | **704/704 정확** |
| 커버리지 | 704/704, 703/703 | **안 변함** |

−0.9 는 Z1(−0.43)과 Z3(−0.50)이 남기는 것이다. **0 이 아니라 −0.9 를
예측한다** — 0 이 나오면 그것대로 설명이 필요하다.

**두 잔차는 서로 다른 신탁에 대고 잰다** (교차검토가 이 모호함을 짚었다):

- **「중심 잔차」** = 측정 코드 − **연속 평면**을 화소 중심에서 평가한 값.
  양자화 전 값이라 −0.9 같은 소수가 나온다.
- **「흉내 대 하드웨어」** = 정수 대 정수. 여기서 704/704 정확을 요구한다.

둘은 충돌하지 않는다. 앞의 것은 **규칙에서 얼마나 벗어났나**, 뒤의 것은
**엔진이 우리가 준 것을 그대로 칠했나** 다.

그리고 −0.9 는 **예측이지 전제가 아니다.** Z1 은 평면 계수를 바꾸고 Z3 은
화소마다 자르므로 둘이 정확히 더해질 이유는 없다(교차검토). 어긋나면
그것이 결과이고, **위치·방향과 상관된 패턴**이면 계수·좌표 쪽을 본다.

## 5. 새로 넣을 시험 — 클램프를 일부러 건드린다

§3 이 새 클램프 사례를 만든다고 했으니, 그것을 **보고 나서** 넘어간다.
깊이가 버퍼 끝에 닿는 가파른 삼각형을 도형 3 으로 넣는다:

```
   꼭짓점 (160,40) (168,48) (150,200),  물체 z 를 창 z 가
   65500 / 200 / 30000 이 되도록 고른다
```

지금은 아래 사다리꼴의 모서리 시작값이 67461.8 로 **잘린다**. 수정 뒤에는
중심이 63380.5 로 **안 잘린다.**

**그리고 반대 방향도 넣는다** (교차검토): 도형 3 은 수정이 **없애는** 부류다.
수정이 **만드는** 부류 — 중심만 클램프되는 경우 — 를 도형 4 로 넣지 않으면
내가 도입하는 회귀를 안 보고 넘어가는 것이다. §3-1 의 탐색이 실제 사례를
가지고 있으므로 거기서 하나 고른다.

## 6. 「커버리지 불변」은 좁은 기준이다 — 층을 쌓는다

far 로 클리어하면 어떤 깊이든 통과하므로, 커버리지 불변은 **변 걷기가 안
바뀌었다**는 말일 뿐 깊이가 맞다는 말이 아니다(교차검토). 그래서 두 층으로
나눈다:

1. **거절 없는 설정**(far 클리어 + `GL_LESS`): 여기서 **래스터 커버리지가
   변하면 결함**이다. far 값에 닿은 화소가 없음을 단정한다.
2. **층을 쌓은 설정**: 보정으로 값을 아는 **평평한 배경**을 여러 깊이로 먼저
   그리고, 그 위에 기울어진 삼각형을 `GL_LESS` 로 그린다. 여기서는
   **보이는 마스크와 깊이 버퍼가 소프트웨어와 일치**해야 한다.
   임계값 하나는 일부러 **동률**에 놓는다.

2 번에서 수정 전후로 보이는 것이 달라지는 것은 **정상**이다 — 값이 2662 코드
틀렸다가 맞아지는 것이니까. 판정 기준은 "안 변함"이 아니라
**"소프트웨어와 같아짐"** 이다.

`GL_ALWAYS` 는 쓸 수 없다 — 백엔드 선택자가 `GL_LESS` 만 받아서 가속이
꺼진다(지난 회차에서 실측).

## 7. 순서

1. 도형 3 을 시험에 넣고 **지금** 재서, 클램프가 실제로 무엇을 하는지 본다.
2. Z2 를 고친다.
3. 세 도형 재측정. §4 의 표와 맞는지.

재부팅 없음.

## 8. 이 회차가 안 보는 것

- Z1·Z3 (반 코드 미만, 각자 별건).
- 깊이 시험의 **동률** 동작. 값이 맞은 뒤에 볼 일이다.
- 겹치는 기하에서의 실제 가시성 변화. 값이 맞으면 따라오지만 별도 시험이다.
