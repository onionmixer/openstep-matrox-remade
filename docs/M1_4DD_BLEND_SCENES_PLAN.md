# M1-4DD — 관문을 열기 전에 무엇을 재는가

## 1. 앞선 계획에서 바뀐 것

`M1_4DC` 는 선택자를 **형식과 환경으로 고르는** 세 줄 표를 전제했다.  §81 이
그걸 뒤집었다 — 선택자는 텍셀이 아니라 **텍스처 단의 출력**을 읽고, 인코더의
`TDUALSTAGE` 가 이미 GL 의 알파 표를 구현하므로 **`fromtex` 하나가 네 조합
전부** 맞다.  Mesa 는 그렇게 고쳤다.

그러니 이 계획이 재야 하는 것은 "어느 선택자냐"가 아니라 **"그 하나가 네
조합에서 정말로 GL 을 준다"** 이다.

## 2. 부정 시험부터 — 지금 뒤집으면 거짓 실패가 난다

`texdraw` 의 `k == 3` 은 `glEnable(GL_BLEND)` 만 한다.  인자는 기본값
(`GL_ONE`/`GL_ZERO`)이고 관문은 `SRC_ALPHA`/`ONE_MINUS_SRC_ALPHA` 를 요구한다
(`OpenStepMGAMesaHook.c`).  즉 텍스처+블렌딩 거절을 없애도 **이 경우는 여전히
거절된다** — 뒤집어 놓으면 공허한 통과가 아니라 **거짓 실패**가 난다.

그래서 `k == 3` 은 둘로 나뉜다:

1. **호환되지 않는 블렌드 인자**는 계속 거절돼야 한다 (`GL_ONE`/`GL_ZERO`)
2. **호환되는 인자**는 이제 그려져야 한다 (`SRC_ALPHA`/`ONE_MINUS_SRC_ALPHA`)

1 이 없으면 "블렌딩이면 무조건 통과"로 관문을 부순 것을 못 잡는다.

## 3. 오라클 — 기하를 모델링하지 않는다

블렌딩된 화소에서는 텍셀 정체가 파괴되므로 `(s,t)` 를 되찾을 수 없다.  그래서
같은 장면을 **두 번** 그린다:

```
   A: 블렌딩 끄고   -> 그 화소의 원천 색과 알파 그대로 (GL_REPLACE 는 텍셀,
                      MODULATE 는 Cf·Ct, 알파는 단의 출력)
   B: 블렌딩 켜고   -> A 를 알려진 목적지와 섞은 것이어야 한다
```

**A 가 오라클의 입력이다.**  기하도, 표본점도, addend 사다리도 모델링하지
않는다 — 그것들은 이미 기준 열 개가 지키고 있고, 여기서 묻는 것은 **블렌드
산술 하나**다.

그리고 A 와 B 는 각각 하드웨어와 소프트웨어로 돈다.  네 덤프가 나온다:

```
   Ahw  Bhw    엔진의 곱 (x·y·257 + 32768) >> 16 으로 채점
   Asw  Bsw    Mesa 의 곱으로 채점
```

각 경로를 **자기 산술로** 채점하면, 두 경로가 갈리는 것은 설명된 차이이고
자기 산술과 갈리는 것은 결함이다.  세는 것이 아니라 **분류**한다:

| 분류 | 뜻 |
|---|---|
| 덮임 불일치 | A 에 있고 B 에 없거나 그 반대 |
| 원천 불일치 | `Ahw` 와 `Asw` 가 다르다 — 블렌드 이전의 문제 |
| 알파 불일치 | 풀어낸 알파가 그 조합에서 GL 이 요구하는 것이 아니다 |
| 반올림 | 자기 오라클과 1 이내 |
| 설명 안 됨 | 나머지 — 이것만이 실패다 |

## 4. 네 장면

| 이름 | 텍스처 | 환경 | 단이 주는 알파 | GL |
|---|---|---|---|---|
| `bl_rgb_rep` | RGB | `GL_REPLACE` | `Af` | `Af` |
| `bl_rgb_mod` | RGB | `GL_MODULATE` | `Af` | `Af` |
| `bl_rgba_rep` | RGBA | `GL_REPLACE` | `At` | `At` |
| `bl_rgba_mod` | RGBA | `GL_MODULATE` | `Af·At` | `Af·At` |

값이 공허하지 않도록:

- 정점 알파는 **평평하지 않게** 준다 — 평평하면 `a0` 만 재고 `adx/ady` 는 못
  잰다.  기울어진 알파를 쓴다
- 텍스처 알파는 `x·8 + y·3 + 17` 로 이미 0 도 255 도 정점 알파도 아니다
- 목적지는 소거색이 아니라 **따로 칠한 값**으로, 각 채널이 원천과 다르게
- 네 조합의 답이 서로 달라야 한다 — python 으로 확인하고 시작한다

## 5. 깊이까지 셋

텍스처+블렌딩+깊이는 한 번도 같이 돈 적이 없다.  가까운 것을 먼저 그리고 먼
것을 겹쳐 그린 뒤, **색·알파·깊이 셋 다** 안 바뀌었는지 본다.  순서를 뒤집으면
셋 다 바뀌어야 한다.  깊이는 직접 읽는다.

## 6. 그러고 나서 관문

`M1_4DC` 의 한 줄.  Mesa 만 바뀌므로 되돌리는 것도 한 줄이다.

## 7. 교차검토에 물을 것

- §3 의 "A 가 오라클"이 무엇을 **숨기는가** — A 와 B 가 같은 방식으로 틀리면
  둘의 차이는 옳아 보인다.  그 실패 모드를 어떻게 잡나
- 블렌드가 **알파 채널 자체**에도 적용되는가 — `OSMGA_MESA_BLEND_OVER` 가
  알파 인자로 무엇을 싣는지, 그리고 GL 이 요구하는 것과 같은지
- 목적지 알파가 `SRC_ALPHA`/`ONE_MINUS_SRC_ALPHA` 아래에서 하는 일
- 네 장면이 서로를 대조군으로 쓸 수 있는 방법

## 9. 값을 못 박는다 (python 으로 고른 것)

기존 `maketexRGBA` 의 알파는 `8x+3y+17` 로 17…182 이고, `RGBA MODULATE` 를
곱하면 최소 2 까지 내려가 끝점에 붙는다.  블렌드 장면은 **자기 RGBA 텍스처**를
쓴다 — 알파 `8x+3y+64`, 즉 64…229:

```
   정점 알파  Af = 96 + 128·x/15        96 … 224
   텍셀 알파  At = 8x + 3y + 64         64 … 229
   단의 곱    (Af·(At+1))>>8            24 … 201     <- §81 이 잰 형태

   RGB (양쪽 환경)  vs  RGBA REPLACE     256 중 5 에서만 일치
   RGB (양쪽 환경)  vs  RGBA MODULATE    0
   RGBA REPLACE     vs  RGBA MODULATE    0
   끝점(0 또는 255)에 닿는 알파: 없음
```

`RGB REPLACE` 와 `RGB MODULATE` 는 알파가 **정의상 같다** — GL 이 그렇게
말한다.  그 둘은 **색**으로 가른다: 정점 색을 흰색이 아니고 화소마다 변하게
준다(흰색이면 modulate 가 항등이 되어 대조가 사라진다).

## 10. 고친 절차

1. `Ahw == Asw` 를 먼저 통과해야 한다 (**전제조건**, 분류 아님)
2. A 와 B 각각에 대해 하드웨어가 실제로 돌았음을 따로 단언 (제출 수 증가,
   소프트웨어·거절 수 0)
3. 각 경로를 **자기 산술로 정확히** 채점, 관용치 없음
4. 알파는 `As·As + Ad·(1−As)` 로 — GL 이 그렇게 하고 Mesa 가 그렇게 한다
5. 부정 시험은 `glBlendFuncSeparateEXT` 로 RGB 인자와 알파 인자를 따로
6. 깊이 시험은 §5 에 codex 가 준 상태 목록을 명시적으로 세운다
7. 그러고 나서 관문
