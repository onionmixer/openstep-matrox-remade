# M1-4a2 — 두 래스터라이저의 차이를 넓이가 아니라 **마스크**로 (§3-27)

아직 코드 없음.

## 1. 왜

§3-25 를 고친 뒤 같은 잘린 삼각형이 소프트웨어로 42472, 하드웨어로 42245
화소였다. 나는 그것을 "알려진 커버리지 불일치"라고 적었다.

**그건 논증이지 측정이 아니다.** 넓이 하나로는 이것들을 구분할 수 없다:

- 가장자리 규칙이 반 화소 다른 것 (무해)
- 도형 **속에 구멍**이 있는 것 (결함)
- 잘림이 만든 **삼각분할 이음매**의 불연속 (결함)
- 감는 방향이나 순서에 따라 달라지는 것 (결함)

넓이는 이 넷에 같은 숫자를 낼 수 있다.

## 2. 지렛대는 이미 있다 (확인함)

`OSMGA_MESA_ACCEL=0` 이면 가속이 통째로 꺼진다 — 실기에서 확인했다:
`accelerated 0, surface 0`. 표면을 안 잡으므로 OSMesa 가 애플리케이션
버퍼에 바로 그린다.

가속을 켜면 VRAM 에 그리고 **미러가 같은 애플리케이션 버퍼로 되돌린다.**
그러니 두 경우 모두 **끝은 같은 버퍼**이고 비교가 성립한다.

### 다만 이 관측에는 사각지대가 있다 (확인함)

미러는 정확히 `bufWidth × bufHeight` 만 옮긴다:

```c
w = bufWidth;
for (y = 0; y < bufHeight; y++) {
    const unsigned long *s = src + y * bufStride;
    unsigned long *d = dst + y * bufAppRow;
    for (x = 0; x < w; x++) d[x] = s[x];
}
```

그러므로 **하드웨어가 그 사각형 밖에 쓴 화소는 옮겨지지 않고, 애플리케이션
버퍼만 보는 이 시험에는 안 보인다.** 커널의 클립이 막아야 하는 것이고 별도
가드 시험이 드라이버 쪽에 있지만, "막아야 한다"는 이 세션이 계속 뒤집어온
종류의 문장이다.

**그러니 이 회차의 결론은 "미러되는 사각형 안에서" 라는 단서를 달고 적는다.**
표면 자체를 직접 읽어 바깥을 보는 것은 별개 작업이다.

## 2b. 원인은 이미 세워져 있다 — 이건 발견이 아니라 확인이다

계획을 쓰면서 "알려진 불일치"라고 얼버무렸는데, **`REMAINING_WORK §3-12` 가
원인을 이미 적어놨다**:

> 우리는 정점 좌표의 소수부를 버리고(`(long)` 캐스트) Mesa 는 유지하며
> **픽셀 중심에서 표본한다.**

훅을 보면 그대로다:

```c
(dst).x = (long)VB->Win.data[idx][0];      /* 소수부가 사라진다 */
```

그리고 Mesa 는 `tritemp.h` 에서 표준 top-left 규칙에 화소 중심 표본이라고
주석에 명시한다 — *"on or to the right of the left edge, strictly to the
left of the right edge, on or below the top edge, and strictly above the
bottom edge"*.

**그러므로 227 화소는 원인 미상이 아니다.** 이 회차가 할 일은 그 차이가
**정말로 가장자리에만 있고 절단으로 설명되는지** 확인하는 것이고, 구멍이나
이음매가 섞여 있지 않은지 가리는 것이다.

§3-12 은 고치는 법까지 적어놨다(변 기울기는 분수를 표현할 수 있으니
`FXBNDRY` 시작 열을 소수부만큼 치우친다). **재기 전에는 손대지 않는다.**

## 2c. 소프트웨어를 정본으로 삼지 않는다 — 이 저장소에는 신탁이 있다

`docs/P3_REFERENCE_ORACLE.md` 와 `reference/OpenStepMGAReference.c` 가 있다.
"소프트웨어가 맞고 하드웨어가 틀렸다"고 적는 대신 **셋을 비교한다.**
GL 규격은 구현마다 화소가 같기를 요구하지 않는다 — 요구하는 것은 불변량이다
(꼭짓점 순서를 바꿔도 커버리지가 안 변할 것, 정수 평행이동이 정확히 평행이동
될 것). **그 불변량은 각 경로 안에서 정확히 성립해야 한다.**

## 3. 재는 법
## 3. 재는 법

한 프로그램이 도형 하나를 그리고 **커버리지를 행별 런으로 찍는다**:

```
row 12: 40-219
row 13: 39-219
```

이것을 두 번 돌린다 — `OSMGA_MESA_ACCEL=0` 과 기본값. **별개 프로세스**여야
한다(표면은 프로세스마다 한 번 잡힌다).

그리고 **python 이 비교한다**:

| 물음 | 어떻게 |
| --- | --- |
| 소프트웨어만 칠한 화소 | 집합 차 |
| 하드웨어만 칠한 화소 | 집합 차 |
| 교집합 | 집합 교 |
| 차이가 가장자리에만 있나 | 차이 화소가 각 행 런의 **양 끝**인가 |
| 속에 구멍이 있나 | 각 행에서 런이 **하나**인가 |
| 이음매가 있나 | 행별 런 경계가 매끄럽게 변하나 |

**출력은 원시 런이고, 유도는 전부 python 에서 한다** — 이 저장소의 방침이다.

## 4. 무엇을 그릴 것인가

한 도형으로는 못 말한다. 그리고 **"작은 삼각형은 분해가 없다"는 틀렸다** —
백엔드는 어떤 삼각형이든 가운데 y 에서 사다리꼴 둘로 쪼갠다
(`OpenStepMGAMesaTriangle.c`, 주석이 "at most one column at the join" 이라고
적어놨다). 그래서 목록을 고친다:

1. **평평한 밑변(또는 윗변) 삼각형** — 이것만이 백엔드 내부 이음매가 없다.
   여기서 나는 차이는 **순수한 가장자리 규칙**이다.
2. **보통 삼각형** — 가운데 y 에서 쪼개진다. 1 번과의 차이가 **그 이음매**다.
3. **§3-25 의 잘린 삼각형** — Mesa 가 자른 것. 원본 하나가 여럿으로 온다.
4. **1 번의 감는 방향을 뒤집은 것** — **각 경로 안에서 정확히 같아야 한다.**
   GL 불변량이지 "대체로 비슷"이 아니다.
5. **대각선을 공유하는 삼각형 둘** (사각형). 두 가지로 그린다:
   - **같은 색** → 대각선에 **틈**이 있으면 클리어색이 보인다.
   - **다른 색, 두 순서 모두** → 대각선이 **겹쳐 그려지면** 순서에 따라
     색이 달라진다. 같은 색으로는 겹침이 안 보인다.

5 번이 4 번보다 일을 더 한다. 평행이동은 정수뿐이라 소수부 반올림을 못
건드리므로(훅이 `(long)` 으로 자른다) **뺀다.**

## 5. 무엇이 무해하고 무엇이 아닌가 (미리 적는다)

**미리 적는 이유**: 숫자를 보고 나서 기준을 정하면 무엇이든 통과시킬 수 있다.

- **기록되는 호환성 결과** (「무해」라고 적지 않는다): 차이가 전부 각 행
  런의 첫/끝 화소이고, **덮여야 할 모든 행에 런이 정확히 하나**이며,
  §3-12 의 절단으로 설명된다.
  「무해」는 신탁이나 규격에 비추어 판정할 일이지 지금 회차가 정할 것이
  아니다.
- **결함**:
  - 덮여야 할 행에 런이 **0 개**(행이 통째로 빠짐) 또는 **2 개 이상**(구멍)
  - 차이가 런 **안쪽**에 있음
  - 5 번에서 같은 색인데 대각선에 클리어색이 보임(틈)
  - 5 번에서 두 순서의 결과가 다름(겹침)
  - 4 번이 1 번과 다름(감는 방향 의존)

「폭이 한 화소」는 기준에서 뺐다. 그 수는 백엔드가 **가운데 y 이음매**에
대해 스스로 적어둔 한계일 뿐, MGA 와 Mesa 사이의 일반 한계가 아니다.

## 5b. 재는 조건을 미리 못박는다

- **상태**: 컬링·깊이·스텐실·블렌딩·시저·디더·텍스처·안티앨리어싱 전부 끔.
  단색 불투명 하나. 읽기 전에 `glFinish`.
- **정말 하드웨어가 그렸는지 증명한다.** 가속을 켠 것만으로는 부족하다 —
  거절된 배치는 일부러 소프트웨어로 다시 그려진다. 그 실행은
  `hookDrawn` 이 기대만큼 오르고 `declined`/`unsupported`/`software` 가
  **전부 0** 이어야 한다.
- **출처를 함께 찍는다**: 크기, 행 길이, 꼭짓점 좌표, 뷰포트, 카운터,
  그리고 **빈 행까지 포함한 모든 행**. 안 그러면 런을 되짚을 수 없다.
- **되풀이한다**: 순서를 바꿔 여러 번. 이 드라이버에는 VRAM 가시성
  단서가 붙어 있고, 프로세스 한 쌍은 증거로 얇다.

## 6. 안 하는 것

- **차이를 없애려 들지 않는다.** 이 회차는 그것이 무엇인지 아는 것이다.
  무해하다고 밝혀지면 숫자를 기록하고 닫는다.
- **소프트웨어를 정본으로 가정하지 않는다.** 둘 중 어느 쪽이 GL 의 채움
  규칙에 맞는지는 별개 질문이고, 필요하면 규격을 보고 따진다.
