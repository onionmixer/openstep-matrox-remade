# M4 — T4(원근)와 T5(클램프) (2026-08-29, 코딩 전)

M3 가 다섯 답을 냈다(§20). 남은 두 질문을 **한 번에** 간다.

## 0. 런타임 트리거는 새 코드를 돕지 않는다

`OSMGAWarpQual` 은 **로드된** 드라이버를 다시 돌린다. 새로 빌드한 코드는
드라이버가 다시 로드돼야 하고, 언로드는 이 프로젝트에서 금지다(매핑 수명).
**그러므로 T4 와 T5 는 묶어서 한 재부팅에 넣는다.**

트리거가 준 것은 따로 있다 — **로그가 살아남는다.** 부팅 때 25 중 4 줄이던 것이
런타임 재실행에서 25 중 25 였다. 그래서 M4 는 부팅 실행을 **판정용으로 쓰지 않고**,
재부팅 뒤 트리거로 다시 돌려 읽는다.

## 1. T4a — z 가 `rhw` 로 나뉘는가

M3 가 정한 것 위에 선다: **z 는 `[0,1]` 정규화이고 배율은 65536**(참조의 65535 아님).

```
삼각형   오른쪽 각 (col0,row0), 다리 48
z        v0 = 0.25,  v1 = 0.75,  v2 = 0.25     -> dx 축으로만 변한다
rhw      v0 = 1,     v1 = 2,     v2 = 4        -> 정점마다 크게 다르다
상태     atype ZI + NOZCMP  (비교 없이 쓴다)
```

**두 가설이 얼마나 갈리는가** (python, 1176 픽셀 전수):

```
가설 A  z = Σ λᵢ zᵢ                      화면공간 affine  <- 정본이라 보는 것
가설 B  z = Σ λᵢ wᵢ zᵢ / Σ λᵢ wᵢ         원근 보정
최대 차이 5622 코드  (dx=20, dy=0 에서 affine 30037 vs 원근 35659)
```

**5622 코드는 16 비트에서 압도적으로 구별된다.** 이 시험은 답을 낼 수 있다.

**기대값은 정수로 계산된다**: `code(dx) = 16384 + (32768·dx)/48`.
`dx = 0/12/24/36` 에서 정확히 `16384/24576/32768/40960`.

**판정은 등호가 아니라 잔차 범위로.** T2 가 배율은 잡았지만 램프의 반올림은
잡지 않았다. `±2` 코드 안이면 affine 확정, 수천 코드면 원근 확정.

## 2. T4b — 투영 텍스처(`tq`)

`rhw = qw·tq`, `tu = s/tq` 를 참조가 정한다(`mgavb.c:69-83`). T4a 가 `qw` 를
흔들었으니 여기서는 **`tq` 만** 흔든다: `qw = 1`, `tq = 1/2/4`.

텍스처 좌표는 **경계 정렬을 피한다** — M3 §20.3 이 앵커가 경계에서 조금
음수 쪽임을 실측했다. `+½` 텍셀 편향을 넣는다(세 위상 중 한가운데).

**판정**: 주소 코드가 원근 보정된 자리를 가리켜야 한다. 기대 텍셀을 python 으로
미리 계산해 표로 넣는다 — 커널은 부동소수를 못 쓴다.

## 3. T5 — 클램프 (§19 의 앵커 독립 설계 그대로)

```
할당    71 x 66 텍셀, pitch 71        [TEXORG = base+288, 32 정렬]
선언    64 x 64,  TEXORG = 물리 (1,1)
코드    선언 안 = (x<<16)|(y<<8)|0x40      헤일로 = (x<<16)|(y<<8)|0x80
좌표    u,v = -2/64 .. 66/64
```

앵커 오차 `±1` 텍셀까지 양끝이 선언 밖이므로 **M3 §20.3 의 앵커 편차와 무관하다.**

**판정**: 출력 하위 바이트가 `0x80` 이면 **클램프 실패**이고 어느 헤일로
텍셀인지가 상위 바이트로 나온다. 전부 `0x40` 이고 `tx,ty ∈ 0..63` 이면 클램프가
**가져오는 주소**를 묶는다.

**못 하는 것**(§16.2): 색은 *바깥 텍셀이 출력에 기여하지 않았음*만 보인다.
캐시가 바깥 물리 주소를 투기적으로 읽고 버렸을 가능성은 배제하지 못한다.

## 4. 순서와 게이트

```
T4a  z affine 확인          <- 실패하면 ABI 의 z 규약이 바뀐다. T4b 를 gate 한다
T4b  tq 투영 텍스처
T5   클램프                 <- T4 와 독립. T3 가 이미 나왔으므로 지금 가능
```

## 5. codex 에 물을 것

1. T4a 의 가설 대조가 옳은가. `rhw` 1/2/4 와 z 0.25/0.75/0.25 조합이
   두 가설을 최대로 벌리는가, 아니면 더 나은 배치가 있나.
2. `atype ZI + NOZCMP` 로 깊이를 쓰면서 **색도 함께** 나오는데, 색 쪽 원근이
   깊이 판정을 오염시킬 여지가 있나.
3. T4b 의 기대 텍셀을 python 으로 미리 계산해 표로 넣는 것이 맞나 —
   커널이 못 하는 계산을 호스트가 대신하는 형태.
4. T5 의 헤일로 값 `0x80` 태그가 충분한가. 캐시 라인 단위로 읽힐 때
   인접 선언-안 텍셀이 함께 와서 결과가 정상으로 보일 여지는.
5. M3 §20.2 의 **65536 배** 발견이 ABI 말고 다른 곳(예: `glDepthRange`,
   사다리꼴 경로와의 일관성)에 영향을 주나.
6. 빠진 것.

## 7. 사양서가 T4a 의 답을 구조로 예고한다

`DR0` = z 시작, `DR2` = **x 축 z 증분**, `DR3` = **y 축 z 증분**, 셋 다
부호 있는 **17.15 고정소수점** (3-118 ~ 3-120, `TRAP`/`TEXTURE_TRAP` with z).

곧 **그리기 엔진의 깊이는 구조상 화면공간 평면이다.**  원근 보정 z 는
화면공간에서 평면이 아니므로 이 세 레지스터로 **표현될 수 없다.**  WARP 의
일은 꼭짓점에서 이 셋을 계산해 주는 것이다.

이것이 T4a 를 없애지 않는다 — **답을 아는 확인 시험으로 바꾼다.**  어긋나면
WARP 가 우리가 모르는 경로로 깊이를 쓴다는 뜻이고, 그건 지금 알아야 한다.
누적 오차 한계도 이 구조에서 나온다: 증분이 `1/32768` 코드 단위로 반올림되니
48 걸음의 누적은 최대 `48 × ½ / 32768 ≈ 0.0007` 코드다.  **관측 잔차가
±1 코드(최종 절단)를 넘으면 평면 가설이 깨진 것이다.**

그래도 **판정은 A/B 대조군으로 한다.**  위 논증은 WARP 가 `DR` 경로를
쓴다는 전제 위에 서 있고, 그 전제는 실측으로만 배제된다.

## 8. 개정된 T4a

```
도형    직각삼각형, 다리 48, 두 밴드
z       (1/4, 3/4, 1/4)            <- dx 축으로만 변한다
A 밴드  rhw = (1, 1, 1)            <- 대조군
B 밴드  rhw = (1, 4, 2)            <- 최대 분리 10923 코드
atype   ZI + NOZCMP,  무텍스처, 단색
판정    1) A 와 B 의 깊이가 코드 단위로 전부 같아야 한다  <- 이것이 판정이다
        2) A 가 code(dx) = 16384 + (32768·dx)/48 에서 ±1 이내   <- 온전성 확인
        3) z=1 을 꼭짓점 하나에 준 세 번째 밴드로 끝점 포화 확인
```

## 9. 개정된 T4b

```
필터    NEAREST   (판정이 "어느 텍셀" 이므로 blend 면 뜻이 없다)
꼭짓점  tq = (1, 2, 4),  qw = 1
        s,t 는 텍셀 좌표로 (8,8) (56,8) (8,56) 을 목표로 하고,
        반 텍셀 편향을 **투영 공간에서** 준다:  sᵢ ← (sᵢ + tqᵢ/(2N))
        그다음 tu = s/tq, tv = t/tq 를 실어 보낸다
오라클  u = Σλᵢsᵢ / Σλᵢtqᵢ  를 정수 교차곱으로,  텍셀 = floor(u·N)
추가    화소마다 텍셀 경계까지의 거리를 미리 계산해, 가장 가까운 화소가
        반 텍셀의 몇 분의 몇인지 기록한다 (편향이 전 구간에서 듣는지)
게이트  T4a 결과와 무관하게 돌린다
```

## 10. 개정된 T5 배치 — 헤일로를 발자국 크기로

필요 범위는 논리 `−4 … 67` 이다(§6).  여유를 두어 **가드 8 텍셀**로 간다.

```
가드      8 텍셀 (네 변 전부)
할당      80 x 80 텍셀,  pitch 80          = 25,600 바이트
선언      64 x 64  (twmask = 63)
TEXORG    base + (8·80 + 8)·4 = base + 2592     2592 % 32 = 0   ✅
행 길이   80·4 = 320 바이트                     320 % 32 = 0    ✅
덮는 논리 좌표  −8 … 71   (필요 −4 … 67, 여유 4)
위치      OSMGA_M4_TEXORG = 14 MiB   (T3 의 13 MiB 와 별도 — 텍스처 캐시
          잔류를 대안 설명으로 남기지 않기 위해 새 물리 영역을 쓴다)
```

codex 의 `73 x 72` 보다 이쪽이 낫다 — 73 은 여유가 0 이고 행이 292 바이트라
32 바이트 정렬이 아니다.

텍셀 값:

```
선언 안   (x<<16) | (y<<8) | 0x00
헤일로    (x<<16) | (y<<8) | 0xFF
```

**하위 바이트가 곧 헤일로 기여 가중치다** (`M1_4C8` 가 쓴 0/255 기저).
`0x00` 이 아닌 값이 나오면 관측 가능한 헤일로 기여이고, 상위 두 바이트가
어느 텍셀이었는지 말한다.

밴드 셋 — M3 §12.4 를 되살린다:

```
T5a  MAG=BILIN, MIN=NEAREST   확대(128x128 화소에 −2/64…66/64)
T5b  MIN=BILIN, MAG=NEAREST   축소(32x32 화소에 같은 범위)
T5c  네 변·네 모서리 — 삼각형 하나로는 high-high 모서리에 못 닿는다.
     **정사각형 두 삼각형**으로 간다
```

| **T5a** (확대) | `2304 px drawn (0 never drawn), 0 carry halo, max weight 0` | ✅ |

### 12.1 T4a — 사양서의 예고가 맞았다

`rhw=(1,1,1)` 과 `(1,4,2)` 의 깊이가 **코드 단위로 완전히 같다**(worst 0).
원근 보정이었다면 최대 **10923 코드** 벌어졌어야 한다.  `DR0`·`DR2`·`DR3` 가
시작·x증분·y증분이라는 구조에서 나온 예측 그대로다.

그리고 아핀 램프 대비 잔차가 `−1..0` — **17.15 누적 한계(0.0007 코드)와
최종 절단만큼**이다.  깊이 평면은 예측 가능하다.

### 12.2 T4c — 깊이 변환이 확정됐다

`z = 1.0` 이 **65535 로 포화**한다(감기면 0 이 나왔을 것이다).  T2 의
`0.75 → 49152` 와 합치면 규칙은 하나다:

```
code = min( floor(z_warp * 65536), 65535 )
z_warp = code / 65536.0            <- 왕복이 전 코드에서 정확하다
```

`65535/65536 = 0.9999847…` 이고 다시 곱하면 정확히 65535 로 돌아온다.
**참조 DRI 의 `1.0/0xffff`(`mga_xmesa.c:362`)를 그대로 쓰면 안 된다.**

### 12.3 T4b — 나눗셈이 있고, 오라클과 전 화소가 맞는다

`vs PROJECTIVE 1176 exact, residual 0..0`.  **1176 화소 전부**가 독립적으로
계산한 정수 오라클

```
texel(dx) = (5424 + 3*dx) / (2 * (48 + 3*dx))
```

과 정확히 같다.  나눗셈이 없었다면 `(5424 − 84*dx)/96` 이어야 했고 그쪽은
48 화소만 맞았다(잔차 `−14..0`).  그리고 `v` 는 1176 화소 전부 행 8 —
분모가 두 축에 같게 적용된다.

투영 공간 반 텍셀 편향이 이 결과를 만들었다.  T3 이 앵커가 경계 바로 아래
있음을 보였고, 편향 없이는 이 밴드가 경계에서 갈렸을 것이다.

### 12.4 T5 — 클램프가 확대·축소 양쪽에서 민다

가드 헤일로에서 **가중치 0**.  네 변과 네 모서리(정사각형 두 삼각형)를 전부
지나고, `magfilter=BILIN`(step 0.42) 밴드와 `minfilter=BILIN`(step 1.42)
밴드 양쪽에서 그렇다.  2304 화소 중 미그림 0.

**주장하는 것은 여기까지다** — 바깥 텍셀이 **출력에 기여하지 않았다**.
텍스처 캐시가 바깥 물리 주소를 투기적으로 읽고 버렸는지는 색만 보는 실험이
보일 수 없다(M3 §16.2).

### 12.5 남은 미측정

- 24/32 비트 깊이의 배율.  **65536 을 외삽하지 않는다.**
- `z < 0` 과 `z > 1` 의 하한 포화(상한만 쟀다).
- 이방성·밉맵 필터에서의 클램프.
