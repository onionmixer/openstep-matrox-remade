# M1-4cd — `Q_MIN` 을 고르지 말고 재기 (계획, 2026-08-23)

**아직 코드를 고치지 않았다.** 이 문서가 교차검토 대상이다.

## 1. 문제

원근 경로의 `Q_MIN` 은 지금 **256**(`q = 1/256`)이고, **내가 고른 값**이다.
근거가 없다.

무엇을 위한 값인지는 정해져 있다: **안전 논거가 아니다.** 주소를 텍스처 안에
붙잡는 것은 주소 지정 방식(클램프는 포화, repeat 은 마스크)이고 8 스팬 밖까지
측정됐다.  `Q_MIN` 이 하는 일은 **나눗셈기의 입력을 아무도 안 본 범위 밖으로
내보내지 않는 것** — 좌표 경계와 같은 종류의 규칙이다.

그러니 재야 할 것은 "어디서 위험해지는가"가 아니라 **"어디서 몫이 산술과
어긋나기 시작하는가"** 다.

## 2. 계기

`q` 를 작게 만드는 것은 이상한 장면이 아니다.  원근에서 `q = 1/w` 이므로
`q` 가 작다는 것은 **먼 곳**이다.  `Q_MIN = 1/256` 은 가까운 면 대비 256 배
먼 지점부터 거절한다는 뜻이고, 그게 넉넉한지 빡빡한지 **모른다**.

## 3. 재는 법 (한 가지 도형, 여러 `q`)

좌표를 **고정**하고 `q` 만 낮춘다: 목표 좌표 `C` 를 정하고 각 `q` 에 대해
`s = C·q/65536` 을 준다.  이상적인 몫은 `q` 와 무관하게 언제나 `C` 이므로,
읽히는 텍셀이 흔들리기 시작하는 지점이 곧 나눗셈기가 무너지는 지점이다.

정확하게 나누어떨어지도록 `C = 8.5 텍셀 = 139264 = 2^13 × 17`, `q = 2^k` 를
쓰면 `s = C >> (16−k)` 가 `k ≥ 3` 에서 **정수로 정확**하다(python 확인).
`k = 3..16` 이면 `q` 는 `1/8192` 에서 `1.0` 까지다.

## 4. 그런데 지금은 절반밖에 못 잰다

`Q_MIN = 256` 이므로 `k < 8` 은 **검증기가 거절**한다.  그래서 순서를 나눈다.

### 4a — 지금 당장, 코드 수정 없이 (`k = 8..16`)

허용 범위 **안에서만** 쓸어 본다.  결과는 두 가지뿐이다:

* 전부 텍셀 8 → `Q_MIN` 이 **너무 낮지는 않다**. 더 낮출 수 있는지는 모른다.
* 어딘가에서 흔들림 → `Q_MIN` 이 **너무 낮다**. 흔들리기 시작한 곳 위로
  올려야 하고, 이 경우 **코드 수정의 근거가 측정에서 나온다**.

어느 쪽이든 **공짜이고 되돌릴 것이 없다.**

### 4b — 그다음에야, 그리고 별도 판단으로 (`k < 8`)

4a 가 깨끗하면 "더 낮출 수 있는가"가 남는데, 그걸 재려면 `Q_MIN` 을 내려야
한다.  그것은 **클라이언트가 보낼 수 있는 범위를 넓히는 변경**이므로 그
자체가 계획과 교차검토의 대상이다.  4a 결과를 보고 나서 판단한다.

## 5. 선택지 (하나로 정해두지 않는다)

| 안 | 내용 | 값 |
|---|---|---|
| (a) | 4a 만 하고 `Q_MIN` 은 그대로 | 공짜. "너무 낮지 않다"만 안다 |
| (b) | 4a 뒤 `Q_MIN` 을 **측정된 무너짐 지점 위로** 올린다 | 흔들림이 나왔을 때만 |
| (c) | `Q_MIN` 을 일시적으로 1 로 내려 전 구간을 재고, 그 결과로 최종값을 정한다 | 가장 많이 알지만 범위를 넓혔다 되돌리는 변경이 두 번 |
| (d) | `Q_MIN` 을 없애고 몫 자체를 검사한다 | 몫은 엔진이 계산하므로 검증기가 볼 수 없다 — 불가 |

## 6. 아직 모르는 것

* 나눗셈기가 무너지는 방식 — 정밀도만 잃는가, 포화하는가, 엉뚱한 값인가
* `q` 가 **작아지는 방향**과 **커지는 방향**이 대칭인가 (`Q_MAX` 도 고른 값이다)
* 기울기가 있을 때(`dq/dx ≠ 0`)와 상수 `q` 일 때가 같은가

## 7. 검토에 묻고 싶은 것

1. 좌표를 고정하고 `q` 를 낮추는 이 설계가 나눗셈기의 무너짐을 실제로
   드러내는가, 아니면 `s` 도 같이 작아져서 **두 오차가 상쇄**되는가?
2. `k = 8..16` 만 보고 "너무 낮지는 않다"고 말할 수 있는가?
3. 내가 빠뜨린 선택지가 있는가?
4. `Q_MAX` 도 같은 방식으로 물어야 하는가?

## 8. 교차검토 재검증 (2026-08-23)

codex 회신을 **채택하지 않고 하나씩 검정**했다.

| codex 주장 | 내 검증 방법 | 결과 |
|---|---|---|
| "텍셀 8 을 읽는다"는 오라클이 무디다 — 틀린 몫도 8 에 떨어진다 | **산술**: `C = 8.5 텍셀`은 두 경계에서 각각 8192 떨어져 있으므로 **±8192(상대 5.9%)까지 눈감는다** | ✅**사실** |
| 대신 값을 재라 | 이분 설계의 분해능을 계산: `s` 1 단위 = 좌표 `65536/q` → `q=65536` 에서 1 단위, `q=256` 에서 256 단위. **원래보다 32~2048 배 예민** | ✅**채택 — 설계를 바꾼다** |
| `k=8..16` 만으로 "너무 낮지 않다"를 말할 수 없다 | **논리**: `q<256` 은 검증기가 거절하므로 관측 자체가 불가. 벼랑 위인지 구분 불가 | ✅**구조적으로 참** |
| 2 의 거듭제곱 `q` 는 쉬운 정규화 경로를 탈 수 있다 | 하드웨어 가설이라 산술로 확인도 반증도 못 한다 | ⏭️**미검증 가설로 유지** — 채택하지 않고, 홀수 `q` 를 섞어 **측정이 가르게** 한다 |
| `Q_MAX` 는 다른 문제다 | **검산**: 좌표를 고정하면 `s = C·q/65536` 이라 `q` 와 함께 커진다. `q = Q_MAX` 에서 `s = 17,825,792` 로 **아핀 상한(8,388,608)을 넘고**, 비율경계는 `128·Q_MAX = 2^30` 까지 허용 — **아핀이 허용한 적 없는 크기의 128 배** | ✅**사실이고, 검산하다 내 설계의 더 큰 구멍을 찾았다** |
| 거절되는 `q` 없이는 아래 경계를 못 배운다 | 논리적으로 자명 | ✅사실 |

### 8-1 검산이 찾아낸 것 — `Q_MAX` 가 `Q_MIN` 보다 급하다

`Q_MIN` 은 "얼마나 먼 곳까지 그릴 수 있나"의 문제라 **못 그리면 소프트웨어로
간다**.  그런데 `Q_MAX` 는 `s` 자체를 아핀 경로가 한 번도 보낸 적 없는 크기로
열어 준다.  그 영역에서 엔진의 `s` 누산기가 어떻게 구는지는 **재지 않았다**.
그리고 이건 **지금 허용된 범위 안에서 잴 수 있다** — 공짜다.

## 9. 고친 계획

1. **§45** — `q` 별로 텍셀이 8→9 로 넘어가는 `s` 를 **이분**해 이론값
   `ceil(9q/4)` 와의 차를 낸다.  통과/실패가 아니라 **오차 값**이 나온다.
   `q` 는 2 의 거듭제곱과 **홀수**를 섞고 `Q_MIN` 근처를 촘촘히 둔다.
2. **§46** — `q` 를 `Q_MAX` 까지 올려 **큰 `s`** 를 보낸다.  아핀 경로가 본
   적 없는 크기에서 좌표가 여전히 맞는지.
3. 그 결과를 보고 `Q_MIN`·`Q_MAX` 를 정한다.  **지금은 아무것도 안 바꾼다.**

## 10. 재보니 `Q_MIN` 이 문제가 아니었다 (2026-08-23)

### 10-1 첫 측정은 창이 좁아 벽을 쟀다

이분 창을 `이론값 ± 64` 로 두었더니 세 점이 창 바닥에 붙었다.  그건 측정이
아니라 **벽**이다.  창을 `1 .. 2×이론값` 으로 넓히고 21 번 halving 했다.

### 10-2 편향은 나눗셈 **전**, 분자에 걸린다

`q = 65536` 에서만 맞고 나머지가 크게 어긋나기에 모형을 고쳤다.  커널이 빼는
496 과 엔진의 사다리(`512 − g`)가 **좌표가 아니라 `s` 에** 걸린다고 두면
2 의 거듭제곱 `q` 다섯 점이 **정확히** 맞는다:

```
   좌표 = ( s − 496 + 512 − g(s−496) ) × 65536 / q
```

### 10-3 그런데 2 의 거듭제곱이 아닌 `q` 에서 무너진다

전환점에서 엔진이 실제로 나눈 값을 역산하면:

```
        q       s*        eff    유효제수   q 대비
      256      561        576      256.0    1.000
      257      561        576      256.0    0.996
      300      572        587      260.9    0.870
      384      593        608      270.2    0.704
      511      624        639      284.0    0.556
      512     1137       1152      512.0    1.000
     1024     2289       2304     1024.0    1.000
     4096     9201       9216     4096.0    1.000
    16385    36851      36866    16384.9    1.000
    65536   147444     147456    65536.0    1.000
```

**2 의 거듭제곱에서는 정확하고, 그 사이에서는 `q` 가 한 옥타브 오르는 동안
유효제수가 11% 만 오른다.**  `(유효제수 − 256)/(q − 256)` 이 0.111 로 거의
일정하다.

### 10-4 그래서 계획이 바뀐다

원근 장면의 `q` 는 **임의값**이다.  거듭제곱에서만 맞는 나눗셈은 원근 텍스처링을
쓸 수 없게 만든다.  `Q_MIN` 을 정하는 일은 이것에 비하면 사소하다.

**아직 아무 결론도 내리지 않는다.**  후보는 여럿이다 — 엔진이 `H` 를 다른
형식으로 읽는다, `TEXCTL` 의 텍스처 크기 필드가 `H` 해석에 관여한다,
나눗셈기가 가수를 거의 안 쓴다, 아니면 내 역산 모형이 아직 틀렸다.  다음
회차의 계획 대상이고, **코드는 건드리지 않는다.**

### 10-5 이번 회차의 절차

교차검토 회신을 **채택하지 않고 하나씩 검정**했다(§8).  그 결과 "오라클이
무디다"는 산술로 사실이었고, "2 의 거듭제곱이 쉬운 경로를 탄다"는 **미검증
가설로 남겨 두고 측정이 가르게** 했는데 — 그 가설이 가리키던 자리에서
실제로 무너짐이 나왔다.  채택했더라면 "그렇겠지" 로 끝났을 것이고, 기각했더라면
못 봤을 것이다.

## 11. 두 번째 경계가 답을 갈랐다 — 나눗셈기는 멀쩡하다

### 11-1 "1/9" 는 내 측정 기하의 산물이었다

교차검토가 경고한 대로다: 경계 `k` 하나에서 제수를 역산하면 분자의 가산오차
`E` 가 `4E/k` 로 섞여 들어오고, `k = 9` 였으므로 **1/9 계수가 엔진이 아니라
내 산술에서 나왔다.**  검정해 보니 실제로 `E = −2(q − 2^e)` 라는 전혀 다른
설명이 다섯 점을 똑같이 맞췄다 — **한 경계로는 구분 불가**였다.

### 11-2 25 번째 경계를 재고 둘을 함께 풀었다

```
        q   측정 k=9   측정 k=25        D          E     2(q-2^e)
      256      561      1585      256.0        0.0            0
      300      572      1772      300.0       88.0           88
      384      593      2129      384.0      256.0          256
      511      624      2668      511.0      510.8          510
      512     1137      3185      512.0        0.0            0
```

**제수 `D` 는 모든 `q` 에서 정확히 `q` 다.**  나눗셈기는 멀쩡하다 — 이것이
원근 작업에 대한 가장 큰 걱정을 없앤다.

대신 분자에 **`E = 2(q − 2^e)`** 가 더해진다(`2^e` 는 `q` 이하의 최대
거듭제곱).  여덟 점 중 일곱이 정확히 맞고 `q = 511` 만 1 단위 어긋난다.

### 11-3 크기 — 무시할 수 없다

`E` 를 텍셀로 환산하면 `4E/q = 8(q − 2^e)/q` 로 **최대 약 4 텍셀**이다:

```
   q = 300 -> 1.17 텍셀    q = 384 -> 2.67 텍셀    q = 511 -> 3.99 텍셀
```

거듭제곱에서 0 이고 다음 거듭제곱 직전에 최대다.  원근 장면의 `q` 는
임의값이므로 **설명되기 전에는 원근을 열 수 없다.**

### 11-4 다음

  원근은 그쪽이다
* `E` 의 정체.  `2(q − 2^e)` 는 정규화된 가수와 관계있어 보이지만 지금은
  **관측된 규칙일 뿐 기전이 아니다**
* 텍스처 크기를 바꾸면 달라지는가 (H 행의 정규화 문제와 얽힌다)
