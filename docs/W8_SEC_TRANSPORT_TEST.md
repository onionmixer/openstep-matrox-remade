# W8 — 2 차 DMA 수송 시험 설계 (T1) — **철회**

**이 설계는 돌리지 않는다.** 사용자가 금지 시험을 승인했고 그래서 설계했는데,
**설계 자체가 자기 질문에 답할 수 없다.** codex 교차검토가 그것을 지적했고
검증한 결과 맞다.

## 철회 사유 — 셋, 그리고 첫째만으로 충분하다

### (1) 이 시험은 Q1 에 답할 수 없다 — 논리 결함

T1 은 `SECADDRESS` 를 쓰고, `SECEND` 를 쓰고, 채우기가 나타나는지 본다.
**그 채우기를 `SECEND` 탓으로 돌리려면 `SECADDRESS` 단독이 아무것도 안 한다는
것을 알아야 한다.** 그것이 바로 §6 이 "범위도 회수도 없다" 며 뺀 음성 대조다.

`SECEND` 의 사전 값을 알면 되지 않느냐 — **`SECEND` 를 알려진 값으로 두려면
`SECEND` 를 써야 하고, 그게 시험 대상이다.** 부팅 시 값은 전원이 남긴 것이다.

> **설계가 자기 관측을 해석 가능하게 만드는 유일한 단계를 빼놓고, 그 관측을
> 해석하겠다고 썼다.** 이 하나만으로 시험은 실격이다 — **프리즈를 감수하고
> 애매한 관측을 사는 것**이 된다.

### (2) 봉쇄 논증이 시험 대상을 가정한다

§3.3 은 *"목적지가 오프스크린이니 실패해도 콘솔이 산다"* 고 썼다. **그것은
2 차 스트림이 잘 형성됐다는 가정 위에 있다.** 잘못 파싱되면 인덱스 바이트가
지목하는 아무 레지스터나 쓰이고, `PITCH`·`DSTORG`·클립·`DWGCTL` 은 채우기가
쓰는 것과 **같은 인덱스 공간에** 있다. 즉 가시 표면을 망칠 수 있다.

**시험하려는 바로 그것을 가정한 봉쇄다.**

### (3) GENERAL 을 고른 것이 보수적이지 않았다

참조 전체에서 `SECADDRESS` 사용은 **한 곳뿐이고 `MGA_DMA_VERTEX` 다**
(`mga_state.c:679`; 전수 grep 확인).

| | T1 (GENERAL) | 참조 충실 (VERTEX) |
| --- | --- | --- |
| SEC 수송 | 우리에게 새것 | 우리에게 새것 |
| 그 채널의 모드 | **어디에도 전례 없음** | **유일한 전례** |
| 페이로드 형식 | 증명됨(S1 채우기) | 우리에게 새것 |
| WARP | 안 씀 | 먼저 지어야 함 |

**GENERAL 은 미지 하나(WARP)를 빼고 미지 하나(전례 없는 채널의 전례 없는
모드)를 더한다.** 나는 그것을 보수적 선택이라고 여겼는데 아니었다.

## 그리고 복구 채널에 대한 낙관도 근거가 없다

"화면이 죽어도 telnet 이 살아 있다" 고 기대할 근거가 우리 기록에 없다.
**일곱 번째 프리즈에서 ICMP 가 죽었다** — 화면이 아니라 기계가 갔다.
직접 관측한 표본이 하나이고 그 하나가 반대쪽이다.

## 그래서 무엇을 하는가

**WARP 하드웨어 작업을 동결한다.** 지금 렌더 경로를 유지한다. 다음 중 하나가
생기기 전에는 `SECADDRESS` 를 쓰지 않는다:

1. **G400/G450 프로그래밍 매뉴얼** — 2 차 인출의 경계 의미론이 적힌 것.
2. **Matrox 가 주 카드가 아닌 희생 호스트** — 그러면 X.Org 의 `MGASoftReset`
   이 **문서화된 자기 영역**(`!pMga->Primary`)에서 쓰이고, 얼어도 콘솔이 아니다.
3. **IOMMU 등 DMA 구경** — 스테이징 할당 밖 읽기를 원천적으로 불가능하게.

그 위에서라면 순서는 **회수·봉쇄를 먼저 실증하고, 그다음 참조 충실한
`SECADDRESS|VERTEX`** 다. **GENERAL 로 시작하지 않는다.**

---

**아래는 철회된 설계 원문이다.** 지우지 않고 남긴다 — 무엇을 왜 설계했고
어디서 틀렸는지가 다음 시도의 출발점이기 때문이다.

## 0. 금지 목록 대조 — 설계 **전에** 했다

| 금지 (W2 §7) | 이 시험 |
| --- | --- |
| 시저 + 계측을 같은 실행에 | **시저를 쓰지 않는다** (§4.3 이 왜인지 적는다) |
| 제출마다 `gettimeofday` | 계측을 아예 넣지 않는다 |
| 이상 징후 후 재시도 | §7 이 조문으로 못박는다 |
| **`SECADDRESS` 를 회수 절차 없이 쓰기** | **이것을 한다.** §3 이 회수 대신 무엇을 세우는지 적는다 |

그리고 2 차 DMA 시험의 절차 조문 — 제출 **한 번**, 격리된 오프스크린 canary,
외부 로그 캡처, 전후 정지 확인, **이상 시 재시도 금지** — 은 §5·§6·§7 이
항목별로 따른다.

## 1. 네 질문 중 **하나만** 한다

W7 이 남긴 실기 간극은 넷이다:

| # | 질문 | 이 시험이 답하는가 |
| --- | --- | --- |
| **Q1** | `SECEND` 가 2 차를 발사하는가 | **예 — 이것만 한다** |
| Q2 | 1 차 파서가 2 차에 대해 직렬화하는가 | 아니오 (§4.3) |
| Q3 | 달리는 WARP 를 SUSPEND 로 세울 수 있는가 | 아니오 — WARP 가 돌아야 한다 |
| Q4 | 클립이 WARP 가 만든 기하도 묶는가 | 아니오 — 같은 이유 |

**Q3·Q4 는 WARP 파이프가 실제로 도는 상태를 요구한다.** 그것은 D2-1
(마이크로코드 업로드)과 D2-2(파이프 실행)를 먼저 지어야 하고, 둘 다 **아직
없다.** 지금 그것까지 묶으면 **한 번의 실기 실행에 미검증 기계 셋을 겹쳐
넣는 것**이고, 실패했을 때 무엇이 원인인지 알 수 없다.

**Q1 이 나머지 셋의 관문이다.** `SECADDRESS` 를 쓸 수 있는지 모르는 채로
WARP 를 짓는 것은 순서가 거꾸로다.

---

## 2. 그리고 Q1 은 **WARP 없이** 답할 수 있다

W2 §8 의 W2-1 이 이미 적어 둔 것이다:

> `SECADDRESS` 는 general/blit/vector/vertex 네 모드를 정의하므로
> (`mgaregs.h:620`) 2 차 DMA 는 정점 전용이 **아니다** — **수송과 형식을
> 나눌 수 있다.**

그러므로 T1 은 **2 차 채널로 GENERAL 모드 명령 블록을 보낸다.** 정점도,
마이크로코드도, WARP 도 필요 없다.

**보낼 페이로드는 이미 증명된 것을 쓴다**: S1 이 실기 PASS 한 오프스크린
단색 채우기(`DWGCTL=0x000C7804` TRAP|SOLID|…, 13-write 상태 초기화)와 같은
모양의 블록열. **새로운 것은 그것이 도착하는 경로 하나뿐이다.**

```
지금 (증명됨)   1 차 목록 = [상태] [채우기] [SOFTRAP] [패딩]
T1              1 차 목록 = [상태] [SECADDRESS|GENERAL, SECEND] [SOFTRAP] [패딩]
                2 차 버퍼 = [채우기]
```

**한 변수만 바뀐다.**

## 3. 회수 절차가 없다 — 그래서 무엇을 세우는가

W6 이 확인한 대로 **검증된 회수 절차는 없다.** X.Org 의 `MGASoftReset` 은
있으나 **주 카드에 쓴 전례가 없고**(호출부 둘 다 `!pMga->Primary`), 우리 카드는
콘솔을 소유한다.

**그래서 회수 대신 봉쇄를 세운다.** 넷이다:

### 3.1 읽기 범위를 구조적으로 가둔다

2 차 버퍼는 **`IOMallocLow` 로 64 KiB 를 잡고 페이로드를 맨 앞에 둔다.**
`SECEND` 는 페이로드의 진짜 끝을 가리킨다.

```
[페이로드 ~256 B][........ DMAPAD 블록으로 채운 여백, 64 KiB 까지 ........]
 ^SECADDRESS      ^SECEND                                              ^할당 끝
```

**카드가 `SECEND` 를 넘어 읽더라도 우리 할당 안에 떨어진다.** 1 차가 SOFTRAP
뒤에 패딩을 두는 것과 같은 이유이고(`:9611`), 이것이 "읽기가 남의 메모리에
닿는다" 는 최악을 없앤다.

**여백은 `DMAPAD` 블록으로 채운다. 0 으로 채우면 안 된다.**

> **초안이 여기서 틀렸고, 하필 가장 나쁜 쪽으로 틀렸다.** 초안은 *"여백은 0
> 으로 채운다 — 명령 스트림으로 해석되더라도 무해하도록"* 이라고 썼다.
> 우리 인코더의 인덱스는 `(reg - 0x1c00) >> 2` 이므로 **인덱스 0 은 0x1c00 =
> `DWGCTL`** 이다. 즉 0 으로 채운 dword 는 **`DWGCTL` 에 네 번 쓰는 블록**이고,
> 그리기 제어 레지스터는 무해한 것의 반대다.
>
> **참조가 쓰는 것은 `DMAPAD`(0x1c54, 인덱스 0x15)다**:
> `DMA_BLOCK(MGA_DMAPAD, 0, MGA_DMAPAD, 0, MGA_DMAPAD, 0, MGA_DMAPAD, 0)`
> → 인덱스 dword `0x15151515`. 여백은 그 블록을 반복해서 채운다.

### 3.1a 이 봉쇄가 증명이 아니라 여유라는 것

참조가 실제로 다는 패딩은 **한 블록(20 바이트)**이고, DRM 주석은
*"the card actually **(partially?)** reads the first of these commands"* 라고
**저자 자신이 불확실을 인정한 채** 적는다.

```
64 KiB 버퍼 - 페이로드 ~256 B = 여백 3,264 블록
관측된 필요량 1 블록 대비 3,264 배
```

**그러나 read-ahead 가 얼마나 멀리 가는지는 아무도 한계를 적지 않았다.**
3,264 배는 **큰 여유이지 증명이 아니다.** 이 문서는 그것을 증명이라고 부르지
않는다.

### 3.2 절대 해제하지 않는다

1 차 링과 같은 규칙(`:6647`)이다. 시험이 실패하든 성공하든 **이 64 KiB 는
부팅 동안 보유한다.** 해제된 페이지를 카드가 읽는 것이 이 설계에서 유일하게
회복 불가능한 사고이고, 해제하지 않으면 그 사고가 존재하지 않는다.

### 3.3 목적지를 격리된 오프스크린 canary 로 둔다

§7 의 조문이다. 채우기의 목적지는 **가시 화면이 아니라** S1·S4a 가 쓴
오프스크린 블록이고, 그 둘레에 **가드 열·행**을 둔다 — D3-2 가 클립을 잰
방식과 같다. 화면은 건드리지 않으므로 **실패해도 콘솔이 살아 있다.**

### 3.4 실패해도 래치가 있다

기존 격리를 그대로 쓴다(`osmgaSubmitGaveUp`, `:2263`): 래치를 먼저 세우고,
카운터는 RAM 에서 올리고, **핸들러는 칩을 건드리지 않는다.**

## 4. 시험 절차

### 4.1 전

1. `waits` 텔레메트리와 `osmga-stats` 를 읽어 **기록**한다(기준선).
2. **정지 확인**: 기존 완료 예측이 idle 을 보고하는지.
3. canary 블록 전체에 **sentinel 을 쓰고 되읽어 확인**한다. 되읽기가
   sentinel 이 아니면 **여기서 멈춘다** — 목적지가 우리 것이 아니다.
4. 2 차 버퍼를 할당하고, 페이로드를 쓰고, **되읽어 바이트 비교**한다.
5. `IOPhysicalFromVirtual` 로 물리주소를 얻고 **정렬·범위를 검증**한다.

### 4.2 제출 — **한 번**

1 차 목록 하나를 만들어 도어벨을 울린다. 그 목록 안에 SEC 쌍이 들어간다.
**반복 없음. 루프 없음.**

### 4.3 시저를 쓰지 않는 이유

Q2(직렬화)를 보려면 DRM 처럼 **클립을 바꿔 가며 같은 버퍼를 두 번 발사**해야
한다. 그것이 자연스러운 다음 시험이지만 **이번에는 하지 않는다.**

§7 의 조문이 `scissor 계측 금지` 라고 적혀 있고, 이 시험에 타이밍 계측은
없으므로 "계측이 아니니 시저를 써도 된다" 고 읽을 여지가 있다. **그렇게 읽지
않는다.** 조문을 자기에게 유리하게 읽는 것이 일곱 번째 프리즈를 만든 기전이고
(W2 §21), 첫 `SECADDRESS` 시험에서 그 해석을 시험할 이유가 없다.

**Q2 는 Q1 이 통과한 뒤 별도 설계로 다룬다.**

### 4.4 후

1. **정지 확인** — 완료 예측, `waits` 의 give-up 카운터, 진입 트랩.
2. canary 를 읽는다. **가드 열·행이 sentinel 그대로인지 먼저** 본다.
3. 채우기 영역이 기대값인지 본다.
4. `waits`·`osmga-stats` 를 다시 읽어 **차분**을 낸다.
5. 2D 자가시험과 화면 무변화를 확인한다.

### 4.5 로그

**외부 캡처를 켠 상태로 한다**(`tools/nx-logcatch.sh`). 프리즈가 나면
`IOLog` 가 디스크에 닿지 못하므로, 시리얼/원격으로 흘려둔 것만 남는다.

## 5. 판정표 — 무엇을 보면 무엇으로 읽는가

| 관측 | 읽는 법 |
| --- | --- |
| 채우기가 canary 에 나타나고 가드 0 px, 정지 확인 통과 | **Q1 = 예.** `SECEND` 로 2 차가 발사되고 실행된다 |
| canary 가 sentinel 그대로, 정지 확인 통과 | **Q1 = 아니오 또는 미발사.** 안전한 음성. 왜인지는 별도 조사 |
| 가드가 오염됨 | **즉시 중단.** 2 차가 범위 밖을 그렸다 — Q1 은 "예" 지만 봉쇄가 깨졌다 |
| 완료 예측이 타임아웃 | **즉시 중단.** 래치가 서고, 칩을 더 읽지 않는다 |
| 화면 이상·2D 회귀 | **즉시 중단** |
| 기계가 얼음 | **8 번째 프리즈.** 전원 재시작. **재시도 금지** |

## 6. 무엇을 하지 않는가 — 명시한다

- **음성 대조를 하지 않는다.** `SECADDRESS` 만 쓰고 `SECEND` 를 안 쓰는
  것은 W6 §2 가 뺀 그것이다. 범위도 회수도 없다.
- **시저를 쓰지 않는다**(§4.3).
- **WARP 를 켜지 않는다.** 마이크로코드도 파이프도 이 시험에 없다.
- **정점 형식을 쓰지 않는다.** GENERAL 모드다.
- **반복하지 않는다.** 성공해도 한 번, 실패해도 한 번.
- **MMIO 로 `SECADDRESS` 를 쓰지 않는다.** W7 §1.6 이 확인한 대로 세 참조 중
  아무도 그러지 않는다. **1 차 목록 안에서만 낸다.**

## 7. 실패 정책 — 조문

1. §5 의 "즉시 중단" 행 중 **하나라도** 나오면 그 자리에서 멈춘다.
2. **재시도하지 않는다.** §3-62 의 판정 그대로다.
3. 멈춘 뒤 **칩을 더 읽지 않는다.** 세 번째 프리즈가 가르친 것이다
   (`osmgaSubmitGaveUp` 의 주석).
4. 관측한 것을 적고, **다음 시도를 설계하기 전에 왜인지 먼저 밝힌다.**
5. 프리즈가 나면 전원 재시작 후 **출하 드라이버로 되돌리고**, 이 시험용
   빌드는 설치하지 않는다.

§17 의 선례를 따른다. 시험 경로 전체를 **`OSMGA_HW3D_SEC_T1`** 뒤에 두고,
`tools/build-matrox-driver.sh` 의 이름 붙은 인자로만 켠다(기본 꺼짐).
**켠 빌드는 "포장하면 안 된다" 고 찍는다.** 그리고 스위치 없이 지은
드라이버가 출하본과 **바이트까지 같은지** 확인한다 — 게이팅이 샜는지 보는
유일한 방법이다.

`osmgaDmaIndex` 는 지금 `SECADDRESS`/`SECEND` 를 **거부**한다(`:6102`).
**그 거부를 푸는 것이 아니라, 쌍으로만 허용하는 전용 경로**를 만든다 —
거부는 미래의 다른 호출자를 위해 남는다.

### 내가 틀렸던 것 — 셋

1. **시험이 자기 질문에 답할 수 없게 설계했다.** 안전을 위해 음성 대조를
   뺐는데, 그 대조가 관측을 해석 가능하게 만드는 유일한 것이었다. **안전과
   해석 가능성을 맞바꿨다는 것을 알아채지 못했다.**
2. **봉쇄가 시험 대상을 가정했다.**
3. **GENERAL 을 보수적 선택이라고 봤다.** 전례 없는 채널에 전례 없는 모드다.

신뢰할 이유는 아니다** — 앞선 회차들에서 codex 도 틀렸고, 확인은 매번 한다.
