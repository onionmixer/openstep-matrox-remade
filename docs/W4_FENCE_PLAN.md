# W4 — 완료 판정 (2 판)

1 판은 codex 교차검토에서 **중심 사실이 틀렸고, 이미 답이 나온 것을 다시
재자고 했고, Stage B 가 메모리를 깨는 설계**라는 판정을 받았다. 전부 확인했고
이 문서는 그 정정본이다. 판정표는 §8.

---

## 0. 금지 목록 대조 — 설계 **전에** 했다

`docs/W2_WARP_RENDER_PATH_PLAN.md` §7 의 표를 먼저 읽었다. 넷 중 **하나가 이
작업을 직접 구속한다**:

> **`SECADDRESS` 를 회수 절차 없이 쓰기 — 금지.**

그리고 2 차 DMA 를 건드리는 모든 실기 시험에 적용되는 절차: 제출 **한 번**,
격리된 오프스크린 canary, 외부 로그 캡처, **scissor 계측 금지**, 전후 정지
확인, **이상이 보이면 재시도 금지**.

이 계획에는 시저가 없다. 제출당 `gettimeofday` 추가도 없다.

## 1. 요구사항을 다시 쓴다 — 다만 1 판이 든 근거는 틀렸다

§6 은 블로커를 "2 차 DMA 완료 판정 부재" 로 적는다.

**1 판은 "STATUS 는 SOFTRAPEN·DWGENGSTS·ENDPRDMASTS 셋뿐이고 그게 카드가 주는
전부" 라고 썼다. 틀렸다.** 근거로 쓴 `mga-drm/mga_drv.h` 는 **축약 헤더**다.
전체 헤더(`mga-dri-xf410/mgaregs.h:719`)의 STATUS 는 열둘이다:

```
bit 0  softrapen     bit 7  wpen        bit 16 dwgengsts
bit 2  pickpen       bit 8  wcpen       bit 17 endprdmasts
bit 3  vsyncsts                         bit 18 wbusy      <- 1 판이 놓친 것
bit 4  vsyncpen                         bits 28-31 swflag <- 소프트웨어 플래그
bit 5  vlinepen
bit 6  extpen
```

**결론은 살아남지만 근거가 바뀐다.** 2 차 DMA 의 완료를 알리는 비트는
여전히 **없다**(`endsecdmasts` 같은 것은 어느 헤더에도 없다). 그러나
"카드가 주는 전부" 라고 말할 자격은 없었다 — 축약본을 전수로 착각했다.

새로 보이는 둘은 나중에 쓸모가 있다:

- **`wbusy`(비트 18)** 는 WARP 실행 상태다. WARP 경로를 만든다면 이것이
  완료 판정의 일부가 된다. 2 차 DMA 인출 완료는 아니다.
- **`swflag`(비트 28-31)** 는 **소프트웨어 플래그 4 비트**다. 펜스 세대를
  카드에 실어 보낼 수 있는 자리인지 조사 대상이다.

## 2. 참조 구현은 두 가지를 쓴다 — 1 판은 둘을 섞었다

**1 판은 `AGE_BUFFER` 를 DRM 의 펜스라고 썼다. 아니다.** DRM 에는 **두 개의
서로 다른 기전**이 있다:

**(a) 펜스 = SOFTRAP + 인터럽트** (`mga-drm/mga_irq.c:73`):

```c
if (status & MGA_SOFTRAPEN) {
    const u32 prim_start = MGA_READ(MGA_PRIMADDRESS);
    const u32 prim_end   = MGA_READ(MGA_PRIMEND);
    MGA_WRITE(MGA_ICLEAR, MGA_SOFTRAPICLR);
    if ((prim_start & ~0x03) != (prim_end & ~0x03))
        MGA_WRITE(MGA_PRIMEND, prim_end);      /* DMA 를 다시 출발시킨다 */
    atomic_inc(&dev_priv->last_fence_retired);
    DRM_WAKEUP(&dev_priv->fence_queue);
}
```

이것이 DRM 의 펜스 API 다. **인터럽트로 돈다.** 우리는 SOFTRAP 을 폴링으로
처리하는 유일한 스택이고, 그 구조적 차이는 §3-62 가 이미 미해결로 남긴
것이다.

**(b) 버퍼 aging = PRIMADDRESS 비교** (`mga_drv.h:373`). 2 차 버퍼를 언제
재사용해도 되는지 정하는 것이고, 펜스 API 와 별개다.

`SECADDRESS`/`SECEND` 를 **1 차 스트림 안에서** 쓴다는 관찰
(`mga_state.c:679`)은 맞고 중요하다. 다만 그것이 "그래서 완료 비트가 필요
없다" 를 증명하지는 않는다.

**주목할 것**: 위 IRQ 코드가 `~0x03` 으로 마스크하고 `prim_start` 와
`prim_end` 를 비교한다. 이것이 우리가 쓸 비교식이다.

## 3. 이미 답이 나온 것 — 1 판이 다시 재자고 했던 것

**`docs/D1_PRIMARY_DMA_RING_PLAN.md` §7 (2026-08-19, 이 G450 실기):**

```
D1-2 | 음성 대조 통과 -> PRIMADDRESS 0 -> 0x20064(발행 tail과 일치)
     | -> 픽셀 불일치 0, checksum dbeef000
```

**1 판 Stage A 의 질문 1 — "STATUS 가 완료라 할 때 PRIMADDRESS 는 무엇을
읽는가" — 은 아홉 날 전에 답이 나와 있었다.** 발행한 tail 과 같다.

같은 실패다: **코드는 grep 했고 우리 문서는 안 했다.** 프리즈를 만든 것과
같은 기전이고(§21), 같은 날 두 번 반복했다.

**남은 진짜 미지는 하나뿐이다**: PRIMADDRESS 가 tail 에 도달한 시점이
**그리기까지 끝났음**을 뜻하는가, 아니면 **인출만 끝났음**을 뜻하는가.
D1-2 는 픽셀 불일치 0 으로 끝났지만 그것은 **최종 정지 후**의 검사다.

## 4. 그리고 그 미지가 1 판 Stage A 를 무너뜨린다

1 판은 "PRIMADDRESS 가 STATUS 보다 **일찍** 완료를 알리면 지금 대기가 필요
이상으로 길다는 뜻이고 그것만으로 값어치가 있다" 고 썼다. **개념이 틀렸다.**

PRIMADDRESS 가 먼저 도달하는 것은 **명령이 인출됐다**는 뜻이지 **실행됐다**는
뜻이 아니다. 그 위에서 일찍 반환하면 엔진이 아직 픽셀을 쓰는 중에
소프트웨어가 표면을 읽는다. **일찍 알리는 것은 이득이 아니라 위험 신호다.**

`dwgengsts`(비트 16)가 그리기 엔진 상태이고 `MGA_DMA_DONE_MASK` 가 그것을
**0 이기를** 요구하는 이유가 이것이다. 지금 코드가 옳다.

## 5. Stage A 는 그대로 두면 안 된다 — 자기 질문에 답할 수 없다

1 판 Stage A 는 "제출당 읽기 하나" 라고 쓰면서 **단조성**과 **조기 도달**을
묻는다. 그 둘은 **완료 루프 안에서 매 반복 표본**을 요구한다. 실측:

```
완료 폴 반복  71.19 회/제출     다른 대기 4 회
루프 안에서 재면 대기 읽기 트래픽 +94.7%
완료 후 한 번만 재면              +1.3%
```

**+94.7% 는 §3-62 가 미해결로 남긴 두 후보(완료 토폴로지, 버스 중재) 한복판에
들어간다.** 드라이버 자신이 폴 트래픽이 기다리는 DMA 와 버스를 다툰다고
적는다(`:2045`). 1 판은 스스로 금지된 영역으로 걸어 들어가고 있었다.

### Stage A0 — 이것만 승인한다

- **완료 예측이 성립한 뒤 PRIMADDRESS 를 정확히 한 번** 읽는다.
- **완료 루프 안에서는 절대 읽지 않는다.**
- `~0x03` 으로 마스크하고 발행한 end 와 비교한다. **관측만 하고 완료 판정을
  바꾸지 않는다.**
- 결과는 RAM 에 누적한다. 제출당 `IOLog` 도 시계 호출도 없다.
- 시저·계측과 **상호 배타**임을 산문이 아니라 **코드로** 강제한다.
- §7 절차: 격리 제출, 외부 로그, 전후 정지 확인, **이상 시 재시도 금지**.
- D1-2 가 이미 보인 것과 **무엇이 다른지 먼저 적는다**: D1-2 는 정지 후
  한 번이었고, A0 은 **연속 부하 아래 3 만 회**를 본다. 그게 새 사실이다.

## 6. Stage B 는 지금 형태로는 메모리를 깬다

스냅샷은 하나(`:823`), 인코딩 리스트도 **고정 물리주소 하나**(`listPhys3`)다.
조기 반환하면 **엔진이 아직 인출 중인 리스트를 다음 제출이 덮는다.**

이중 버퍼는 **자리가 없다** — 두 가지로 따로 계산했고 둘 다 안 들어간다:

| 산정 | 최악 리스트 | 두 개 | 가용 |
| --- | --- | --- | --- |
| 실측 dwords/사다리꼴 기준 | 27,978 B | 55,956 B | **40,960 B** |
| 구조적 상한 기준 (codex) | 32,640 B | 65,280 B | **40,960 B** |

Stage B 를 하려면 **먼저 설계 문서가 있어야 한다**: 비동기 ABI(수락 + 펜스
세대 반환), 버퍼 수명, drain 지점 전수(present, 미러, 소프트웨어 폴백, 2D,
모드 변경, 해제), 지연 오류 귀속, 다중 클라이언트 소유권, 질의 페이싱.
**1 판은 그중 아무것도 적지 않았다. 지을 수 있는 상태가 아니다.**

그리고 이득도 정정한다:

```
draw 만          13.18 -> 8.81 ms   1.50 배
프레임 전체      21.27 -> 16.90 ms  1.26 배
```

**1.50 은 draw 만의 값이고 사용자가 보는 것은 1.26 배다.** §19.10 의 1.28 은
프레임 값이었으므로 그쪽이 맞다.

**동기 ioctl 은 폴 조건을 바꾸는 것만으로는 아무것도 겹치지 못한다.** 같은
스레드가 같은 자리에서 막힌다. 겹치려면 SUBMIT 이 **수락 + 펜스**를 즉시
반환하고 의존 지점에서 기다리는 **계약 변경**이 필요하다.

## 7. Stage C — 막힌 것은 맞지만 이유를 정정한다

1 판은 "엔진 리셋이 없어서" 막혔다고 썼다. **하드웨어 리셋은 있다** —
`MGA_RST` 0x1e40, `SOFTRESET` 비트 0 (세 헤더 전부). 없는 것은
**검증된 리셋·재초기화 절차**다. DRM 의 `mga_do_dma_reset` 도 소프트웨어
카운터만 되돌리고 WARP 에 FIXME 를 남긴다.

그리고 **2 차 DMA 는 WARP 에 필수가 아니다.** PRIMADDRESS 자체가 VERTEX
모드를 갖는다(`MGA_DMA_VERTEX = 3 << 0`). 1 차 스트림으로 정점을 보내는 길이
있고, DRM 의 편리한 발사 순서를 잃을 뿐이다. **"2 차 DMA 가 WARP 의 유일한
수송" 이라는 1 판의 전제는 틀렸다.**

`SECADDRESS` 는 여전히 **쓰지 않는다**. 회수 절차가 없다.

### 내가 틀렸던 것 — 넷

1. **축약 헤더를 전수로 착각**해 "카드가 주는 전부" 라고 썼다.
2. **DRM 의 두 기전을 하나로 섞었다** (펜스 = SOFTRAP 인터럽트, aging =
   PRIMADDRESS).
3. **아홉 날 전에 답이 나온 것을 다시 재자고 했다.** 코드는 grep 했고 우리
   문서는 안 했다 — **프리즈와 같은 기전을 같은 날 반복했다.**
4. **조기 도달을 이득으로 읽었다.** 위험 신호다.

## 9. 그래서 다음에 할 일

**Stage A0 만.** 완료 후 PRIMADDRESS 한 번, 루프 안에서는 절대 읽지 않기,
시저·계측과 코드로 상호 배타, §7 절차 준수. 답할 질문은 하나로 좁힌다:

> **연속 부하 아래에서, STATUS 가 완료라고 한 순간 PRIMADDRESS 는 언제나
> 발행한 end 와 같은가?** D1-2 는 정지 상태에서 한 번 그렇다고 했다.
> 3 만 회에서도 그런지는 모른다.

같다면 펜스의 **전제**가 선다(충분조건은 아니다). 다르면 그 자체가 지금
완료 판정에 대한 새 사실이고, Stage B 는 그때 다시 생각한다.

**Stage B 는 설계 문서가 나오기 전에는 코드를 쓰지 않는다.**
**Stage C 는 검증된 회수 절차가 나오기 전에는 열지 않는다. `SECADDRESS` 는
쓰지 않는다.**

아래 8.6 만 회, 목록 길이 7.1 배 폭**에서 보인다. 그것이 A0 이 더한 전부이고,
계획이 A0 에 허락한 전부다.

**새롭지 않은 것, 그리고 착각하면 안 되는 것**: 이 등식은 **1 차 파서가 목록을
소비했다**는 뜻이지 **엔진이 그리기를 마쳤다**는 뜻이 아니다. `dwgengsts`(비트
16)가 별개의 비트이고 지금 완료 예측이 그것을 **0 이기를** 이미 요구한다.
**펜스의 전제가 섰을 뿐 충분조건이 선 것이 아니다.**

### 10.3 안 한 것 — 그리고 안 한 이유

**시저 건너뛰기 경로를 실행으로 시험하지 않았다.** 시험하려면 시저 걸린
워크로드를 관측기가 든 드라이버로 돌려야 하고, **그것이 정확히 §7 이 금지한
조합**이다. 코드로 확인했고(`scissorOn != 0` 이면 관측을 건너뛰고 `skipped`
만 증가), `skipped = 0` 은 이 실행들에 시저 제출이 없었다는 사실과 일치한다.
**여덟 번째 프리즈를 만들어 가드를 시험하지 않는다.**

### 10.4 게이팅 — 관측기는 출하본에 없다

```
스위치 없이 지은 드라이버   413,268 바이트   <- 출하본과 바이트까지 동일
fence 로 지은 것            414,876 바이트   <- +1,608, 관측기
```

기본 빌드가 출하본과 **같은 크기**라는 것이 게이팅이 새지 않았다는 증거다.
스위치는 `tools/build-matrox-driver.sh` 의 이름 붙은 인자(`fence`, `dry`)이고
**둘 다 기본 꺼짐**이며, 켜면 빌드가 "이것은 포장하면 안 된다" 고 찍는다.

`OTHER_CFLAGS` 를 make 명령줄로 넘기면 번들 preamble 의 `-I./compat` 을
**교체해서** 인스펙터가 `appkit/appkit.h` 를 못 찾는다. 그리고 부모 Makefile
자신이 적어 두었듯 common.make 는 `OTHER_CFLAGS` 를 커널 서브프로젝트로
내려보내지 않는다. 그래서 **환경변수 `OSMGA_XFLAGS`** 로 넘기고 서브프로젝트
preamble 이 그것을 `+=` 한다.

### 10.5 다음

**Stage B 는 여전히 설계 문서가 먼저다.** A0 은 펜스의 전제를 세웠을 뿐,
§6 이 나열한 것들 — 비동기 ABI, 버퍼 수명(리스트가 하나뿐이고 이중 버퍼는
자리가 없다), drain 지점 전수, 지연 오류 귀속, 다중 클라이언트 소유권 —
가운데 무엇도 해결하지 않았다.

**Stage C 와 `SECADDRESS` 는 그대로 닫혀 있다.**
