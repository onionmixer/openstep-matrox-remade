# 이웃한 삼각형이 변을 공유할 때 (계획, 2026-08-21)

## 0. 왜 이것인가

래스터화·색·알파·깊이가 전부 규칙에 맞았다. 그런데 **지금까지 잰 것은 거의
전부 고립된 삼각형이다.** 실제 내용은 메시이고, 메시는 변을 공유한다.
교차검토가 여러 회차에 걸쳐 같은 말을 했다:

> Isolated-triangle coverage can look excellent while adjacent polygons crack,
> overlap, or get different depth/color along a shared boundary.

**크기를 모르는 유일한 위험**이다. 재기 전에는 좋다고도 나쁘다고도 말할 수
없다.

## 1. 이미 잰 것과 안 잰 것

커버리지 시험의 도형 5·6·7 이 **대각선을 공유하는 삼각형 둘**이다. 거기서
확인된 것:

- 틈 없음(같은 색으로 그려 클리어색이 안 보임)
- 겹침 없음(두 색·두 순서에서 순서 의존 화소 0)

**안 잰 것:**

| | 왜 중요한가 |
|---|---|
| **소수 정점** | 도형 5·6·7 은 정수 정점이다. 소수부를 싣는 인코딩이 두 삼각형에서 **같은 공유 정점을 같은 자리로** 보내는지는 안 봤다 |
| **기울어진 사각형** | 축에 나란한 사각형은 공유 변이 대각선 하나뿐이고 기울기가 특수하다 |
| **속성 연속성** | 틈이 없다는 것과 **색·깊이가 이음매에서 이어진다**는 것은 다른 말이다. 이음매 한 줄만 값이 튀면 눈에 띈다 |
| **셋 이상** | 삼각형 띠(strip)에서는 한 변을 **세 개**가 공유할 수 있다 |

## 2. 신탁이 성립하는지 먼저 확인했다

규칙(화소 중심 + top-left) 자체가 사각형을 대각선으로 쪼갰을 때 **깨끗하게
타일링하는가** — 안 그러면 하드웨어를 탓할 수 없다.

```
   정수 사각형        t1 11200, t2 11200, 합집합 22400, 겹침 0
   소수 37/128        t1 11200, t2 11200, 합집합 22400, 겹침 0
   기울어진 소수      t1 11158, t2 11037, 합집합 22195, 겹침 0
```

**겹침 0.** 규칙은 틈도 중복도 만들지 않는다. 그러므로 하드웨어가 보이는
것은 전부 우리 것이다.

## 3. 재는 법

세 도형, 각각 두 순서로:

1. **정수 사각형** (도형 5·6·7 의 확장 — 회귀 대조군)
2. **소수 사각형** — `37/128` 만큼 옮긴 것
3. **기울어진 소수 사각형** — 네 꼭짓점의 소수부가 서로 다른 것

각각에 대해:

- **틈**: 같은 색으로 그리고 합집합을 규칙과 대조. **누락 0** 이어야 한다.
- **겹침**: 두 색으로 두 순서로 그리고, **순서에 의존하는 화소 0**.
  같은 색으로는 겹침이 안 보인다.
- **속성 연속성**: Gouraud 로 그리고, 이음매를 가로지르는 **행마다** 값이
  평면에서 벗어나는지 본다. 두 삼각형이 **같은 평면**을 공유하도록 꼭짓점
  색을 고른다 — 그러면 이음매가 보이면 그건 결함이다.
- **깊이 연속성**: 같은 방식으로 깊이 평면을 공유시키고 이음매를 본다.

## 4. 성공/실패 기준 (숫자를 미리 적는다)

- **틈**: 규칙의 합집합 대비 누락 **0**, 초과 **0** — 세 도형 모두.
- **겹침**: 순서 의존 화소 **0** — 세 도형 모두.
- **색 연속성**: 이음매를 가로지르는 값이 공유 평면에서 **1 단계 이내**
  (양자화 한계). 이음매 줄만 튀면 결함.
- **깊이 연속성**: 같은 기준으로 **1 코드 이내**.
- **소프트웨어도 같이 잰다.** 소프트웨어가 이음매를 못 맞추면 그건 Mesa 의
  성질이고 우리 판정 기준이 아니다 — 도형 8 에서 이미 겪었다.

## 5. 이 시험이 못 보는 것 (미리 적는다)

- **혼합 프레임**: 하드웨어 삼각형 옆에 소프트웨어로 되돌려진 삼각형이
  놓이는 경우. 지금은 되돌림이 거의 없으므로 별건이다.
- **긴 띠**: 셋 이상이 한 변을 공유하는 경우를 도형 셋으로는 못 덮는다.
  이번에 틈·겹침이 0 이면 그다음에 본다.

## 6. 교차검토 판정 (2026-08-21) — 전건 재검증

| codex 주장 | 검증 방법 | 판정 |
|---|---|---|
| **합집합 검사는 충분하지 않다** — 한쪽이 덜 덮고 다른 쪽이 더 덮으면 합집합은 멀쩡하다 | 논리 확인. 두 색·두 순서 시험도 **나중 삼각형이 실제로 덮어써야만** 본다 | ✅ **채택**. 삼각형마다 따로 마스크를 재고 **점유수**를 센다 |
| **두 삼각형이 정말 다른 정밀도를 고르는지 먼저 증명하라** | 내 후보 네 개는 **전부 `s=4` 로 같았다** — 위험이 시험에 안 들어간다. 무작위 사각형 60000 개를 훑어 **5 개(0.008%)** 를 찾았다 | ✅ **채택**. 위험은 실재하고, 이제 그것을 밟는 도형이 있다 |
| 「셋 이상이 한 변을 공유」는 기하적으로 불가능하다 | 2D 에서 겹치지 않는 삼각형 셋은 온전한 한 변을 공유할 수 없다 | ✅ **채택**. 내 표현이 틀렸다 — strip 은 쌍쌍이 공유하고, 한 정점에 여럿이 모이는 것은 **fan** 이다 |
| 소프트웨어는 **진단**이지 합격 도피구가 아니다 | 논리 확인 | ✅ **채택**. 판정 권한은 유리수 신탁에만 있고, 소프트웨어는 설명 자료다 |
| 공유 평면은 `C = a·x + b·y + c` 로 구성 가능하고 **네 번째 색은 자유롭지 않다** | 구성해서 확인: 두 삼각형의 평면이 `dx=1/2, dy=1/3, k=60` 으로 **동일** | ✅ **채택**. 제약이 하나 더 붙는다 — 네 색이 **0..255 정수**여야 `glColor4ub` 로 낼 수 있다 |
| 이음매 양쪽 화소가 "같은지" 보지 말고 **모든 덮인 화소를 해석적 평면에** 대라 | 기울기가 있으면 양쪽이 달라야 정상이다 | ✅ **채택**. 원래 계획도 평면 대비였으나 명시한다 |
| 세 도형은 가장 잘 깨지는 기하를 안 덮는다 | 맞다 — 축에 나란한 둘은 위상만 다르고 대각선 기울기가 같다 | ✅ **채택**. strip 하나와 fan 하나를 더한다 |

### 6-1. 가장 값어치 있었던 지적

**"두 삼각형이 정말 다른 정밀도를 고르는지 먼저 증명하라."** 내 계획은
"소수 정점이면 정밀도가 갈릴 수 있다"를 위험으로 적어 놓고, 그 위험을
**밟지 않는 도형 넷**을 골라 놨다. 재 보니 전부 `s=4` 로 같다. 그 상태로
시험했으면 **"공유 정점 문제 없음"** 이라고 적었을 것이고, 그건 시험이 그
경우를 안 만든 것을 확인한 것에 불과했다.

## 7. 고친 계획

1. **삼각형마다 따로** 마스크를 재서 각자의 규칙 마스크와 대조한다.
   그다음 **점유수**(`I_A + I_B`)를 세어 **내부 화소가 정확히 1** 인지 본다.
   합집합은 보조 지표로만 남긴다.
2. 도형에 **정밀도가 갈리는 사각형**(위에서 찾은 것)과 **fan** 하나,
   **strip** 하나를 넣는다.
3. 공유 평면의 네 색은 `a·x + b·y + c` 가 네 꼭짓점에서 **정수**가 되도록
   고른다.
4. 판정은 **하드웨어 대 유리수 신탁**으로만 한다. 소프트웨어 대 신탁은
   같이 찍되 합격 판정에 쓰지 않는다.

## 8. 결과 (2026-08-21) — 하드웨어는 깨끗하고, **소프트웨어가 아니다**

삼각형마다 따로 그려 **각자의 규칙 마스크**에 대고 잰 값이다. 합집합은
보조 지표다.

```
              t1 누락/초과   t2 누락/초과   양쪽소유  합집합틈  순서의존  평면오차
   도형 A  hw     0 / 0        0 / 0         0        0        0       0.75
           sw     0 / 0        0 / 0         0        0        0       0.75
   도형 B  hw     0 / 0        0 / 0         0        0        0       0.50
           sw     0 / 5        5 / 0         0        0        0       0.50
   도형 C  hw     0 / 0        0 / 0         0        0        0       0.75
           sw     4 / 4        4 / 1         0        4        0       0.75
```

**하드웨어는 세 도형 모두 누락 0·초과 0·양쪽소유 0·순서의존 0** 이고,
공유 평면에서 최대 **0.75 단계**(양자화 한계 안) 벗어난다.

### 8-1. 도형 C 가 이번 회차의 요점이다

C 는 볼록해서 대각선 분할이 타일링하고, **두 삼각형이 다른 정밀도를
고른다(s=5 대 s=4)**. 교차검토가 "그 위험을 실제로 밟는지 먼저 증명하라"고
한 바로 그 경우다 — 첫 계획의 도형 넷은 **전부 같은 정밀도**여서 그 위험을
안 밟았다.

밟게 해서 재 보니 **하드웨어는 공유 정점을 같은 자리에 놓는다.** 정밀도가
달라도 공유 변이 갈라지지 않는다.

### 8-2. 소프트웨어가 이음매를 못 맞춘다

Mesa 는 도형 B 에서 이음매 화소 **5 개의 소유가 어긋나고**(한쪽이 5 개 더
그리고 다른 쪽이 5 개 덜 그린다), 도형 C 에서는 **합집합에 4 화소 틈**을
남긴다 — 실제 균열이다. 11 비트 고정소수점 변 걷기의 성질이다.

**이것은 우리 합격 기준이 아니다.** 판정 권한은 유리수 신탁에만 있고,
소프트웨어 대 신탁은 설명 자료로만 찍는다(교차검토 지적). 다만 기록해 둘
값은 있다 — **가속 경로가 소프트웨어보다 메시에서 안전하다.**

### 8-3. fan 과 strip 까지 (같은 회차에 이어서)

시험을 N 개 삼각형으로 일반화하고 둘을 넣었다.

- **D — fan**: 삼각형 넷이 **한 정점에 모인다**. 부채꼴 크기를 일부러
  다르게 해서 정밀도가 **셋으로 갈리게** 했다 — `5, 6, 5, 4`.
- **E — strip**: 삼각형 넷이 변을 **쌍쌍이** 공유한다.

```
                     삼각형별      두번소유  합집합틈  순서의존  평면오차
   도형 D fan (4)  hw   정확          0        0        0       0.75
                   sw   6 화소 어긋남   0        0        0       0.75
   도형 E strip(4) hw   정확          0        0        0       0.75
                   sw   정확          0        0        0       0.75
```

**정밀도가 셋으로 갈리는데도 공유 정점이 정확히 같은 자리에 놓인다.**
교차검토가 지목한 위험 — 삼각형마다 정밀도를 고르므로 공유 정점이 두 자리가
될 수 있다 — 을 가장 강하게 밟는 경우이고, 깨끗하다.

### 8-4. 그래서 메시는 안전한가

다섯 도형, 열넷의 삼각형, **삼각형마다 자기 신탁과 정확히 일치**하고,
두 번 그려진 화소 0, 틈 0, 순서 의존 0, 공유 평면에서 최대 0.75 단계.

**남은 미지**는 셋이다: 혼합 프레임(하드웨어 옆 소프트웨어 되돌림),
깊이 이음매(색 평면만 봤다), 그리고 훨씬 긴 메시.
- **혼합 프레임**(하드웨어 옆 소프트웨어 되돌림). 되돌림이 거의 없어 별건.
- 깊이 이음매. 색 평면만 봤다.
