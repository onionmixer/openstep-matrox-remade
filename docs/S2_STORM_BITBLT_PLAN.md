# S2 — Storm BITBLT 계획 (오프스크린→오프스크린, 이어서 오프스크린→가시)

기준일: 2026-08-19
상태: ✅ **완료 — 실기 PASS(§9).** 오프스크린→가시 복사가 동작한다.
선행: [S1](S1_STORM_ENGINE_LIVENESS_PLAN.md) PASS — 엔진이 유도 시퀀스에 반응함이 실증됨.

## 0. 목적

**프레젠테이션 원시연산**을 확보한다. OpenGL 로드맵에서 Mesa가 오프스크린 VRAM에
렌더한 결과를 화면으로 옮기는 수단이 바로 이 BITBLT다(로드맵 2단계).

S1과 결정적으로 다른 점: S1은 오프스크린만 건드려 **"화면 무변화"가 안전 기준**이었으나,
S2는 정의상 가시 스캔아웃에 쓰므로 그 기준을 쓸 수 없다. 대신 **의도한 위치에 의도한
것만** 나타나는지가 기준이 된다.

## 1. 위험 분리 — S2a / S2b 로 쪼갬

BITBLT는 단색채우기와 달리 **소스 주소지정**이 새로 필요하다(`AR0`/`AR3`/`AR5`/`SGN`).
새 레지스터 의미론과 "가시영역에 쓰기"라는 두 변수를 동시에 도입하지 않는다.

| 단계 | 내용 | 새 위험 | 실패 시 |
| --- | --- | --- | --- |
| **S2a** | 오프스크린 → **오프스크린** BITBLT | 소스 주소지정 의미론 전부 | 화면 영향 **0** |
| **S2b** | 오프스크린 → **가시** BITBLT | 목적지 주소만 (시퀀스는 S2a에서 검증됨) | 화면에 잘못된 사각형(일시적) |

S2b는 S2a가 PASS했을 때만 실행한다(런타임 게이팅). 한 번의 부팅에서 순차 수행.

## 2. 레지스터 정본 (X.Org 2.0.0 동작 관찰)

S1의 레지스터에 더해:

| 이름 | 오프셋 | 용도 |
| --- | --- | --- |
| SGN | `0x1c58` | 스캔 방향 (`BLIT_LEFT=1`, `BLIT_UP=4`) |
| AR0 | `0x1c60` | 소스 span 끝 |
| AR3 | `0x1c6c` | 소스 span 시작 |
| AR5 | `0x1c74` | 행 증분 = `ydir * stridePixels` |

### DWGCTL (화면간 복사, ROP=copy)

```
AtypeNoBLK[GXcopy] (RPL | 0x000C0000) | SHIFTZERO(1<<14) | BITBLT(0x08)
| BFCOL(0x02<<25)
= 0x04000000 | 0x000C0000 | 0x4000 | 0x08 = 0x040C4008
```
`BLK`(block) 모드와 `TRANSC`(투명)는 사용하지 않는다.

### 소스 주소 계산 (top-down, left-to-right 한정)

```
w = w - 1                                  ← 먼저 감소
start = end = srcY * stridePixels + srcX + YDSTORG
end   = end + w                            (BLIT_LEFT 미사용이므로 end 쪽)
AR3 = start ,  AR0 = end
FXBNDRY = ((dstX + w) << 16) | (dstX & 0xffff)
YDSTLEN + EXEC = (dstY << 16) | h
```

### ⚠ `FXBNDRY` 우변 의미가 프리미티브마다 다르다

X.Org 원본 대조 결과:
- **단색 채우기**(S1): `((x + w) << 16) | x` — 원래 `w`, 우변 **exclusive**
- **BITBLT**(S2): `w--` 이후 `((dstX + w) << 16) | dstX` — 즉 `dstX + w_orig - 1`,
  우변 **inclusive**

두 코드가 같은 레지스터에 다른 규약으로 쓴다. codex 교차검토에서 **같은 레지스터의
opcode 의존 해석이 맞다**고 확인됐다(§8-4). 우리 구현은 **각 프리미티브마다 원본
형식을 그대로** 따른다.

### `LARGE_ADDRESSES` 경로는 해당 없음

X.Org는 `FbMapSize > 8 MiB` **그리고** `depth == 8`일 때만 `LARGE_ADDRESSES`를
켜고 `SRCORG`/`DSTORG` 재배치를 한다. 우리는 32bpp이므로 **단순 경로**를 쓰며
`SRCORG=DSTORG=0`을 유지한다.

## 3. 실행 시퀀스

```
[G] S1과 동일한 게이트 (플래그/32bpp/실증VRAM/매핑범위)
[G] S2b는 S2a PASS일 때만

--- 소스 준비 ---
1. uncached 별칭으로 소스 블록에 **위치 인코딩 패턴** 기록
      px(row,col) = 0xFF000000 | (row << 8) | col
   (단색이 아니라 위치를 encode → 어긋난 복사/오프셋 오류를 잡아냄)

--- S2a: 오프스크린 → 오프스크린 ---
2. bounded wait: idle ; FIFO >= 13 → S1과 동일한 상태 초기화
   클립은 **목적지 사각형에만** 맞춘다 (§4)
3. FIFO >= 5 → DWGCTL=0x040C4008, SGN=0, PLNWT=0xffffffff,
               AR5=stridePixels
4. FIFO >= 4 → AR0=end, AR3=start, FXBNDRY, YDSTLEN+EXEC
5. bounded wait: idle
6. uncached 별칭으로 목적지 전수 비교 (기대값 = 소스 패턴과 동일)

--- S2b: 오프스크린 → 가시 (S2a PASS 시에만) ---
7. 목적지를 가시영역 **우하단 구석**으로 바꾸고 클립도 그 사각형으로 재설정해 3~5 반복
8. uncached 별칭으로 가시영역 목적지 전수 비교
```

**타임아웃 시**: 로그 남기고 즉시 중단, 정리 write 금지(S1과 동일).

## 4. 주소·클립 설계

1024×768×32 기준(S1과 동일하게 실증 VRAM 7.32 MiB 안쪽):

| 블록 | 위치 | 픽셀 범위 | 바이트 |
| --- | --- | --- | --- |
| 소스 | `y=1024`, 64×64 | 1,048,576~ | 4.00 MiB |
| S2a 목적지 | `y=1152`, 64×64 | 1,179,648~ | 4.50 MiB |
| S2b 목적지 | `x=960, y=704`(우하단) | 가시영역 내 | ~2.9 MiB |

소스와 S2a 목적지는 128행(0.5 MiB) 떨어뜨려 겹침을 원천 배제한다.

**클립 설정 — 목적지 전용으로 좁힌다** (codex 지적으로 정정, §8-2):

클립(`CXBNDRY`/`YTOP`/`YBOT`)은 **목적지 쓰기에만** 적용되고 소스 읽기
(`AR3`/`AR0`/`AR5`)에는 적용되지 않는다. 따라서 소스를 포함하도록 넓힐 필요가
없을 뿐 아니라 **넓히면 봉쇄가 약해진다**. 매 제출마다 목적지 사각형에만 맞춘다:

| | CXBNDRY | YTOP | YBOT |
| --- | --- | --- | --- |
| S2a | `(63<<16)\|0` | `1152*1024` | `1215*1024` |
| S2b | `(1023<<16)\|960` | `704*1024` | `767*1024` |

이렇게 하면 소스는 오프스크린에 남아 읽히면서 목적지 봉쇄는 최대로 유지된다.
S2b에서는 클립 창이 **테스트 대상 가시 사각형만** 포함하므로, 잘못된 명령이
스캔아웃의 나머지를 건드리는 것은 여전히 봉쇄된다(원래 계획대로 넓혔다면
S2b의 X 클립이 `0..1023` 전체 폭, Y가 `704..1087`로 벌어져 훨씬 많은 영역이
노출됐을 것이다).

**S2b 우하단 선택 이유**: 목적지가 `y=704..767`, `x=960..1023`. 오버런이 나면
`y>=768` 즉 **오프스크린 방향**으로 흐르므로 화면 훼손이 커지지 않는다.

## 5. 안전 분석

| 위험 | 완화 |
| --- | --- |
| 소스 주소지정 오류 | **S2a에서 화면과 무관하게 먼저 검증**. 위치 인코딩 패턴으로 오프셋 오류까지 검출 |
| 가시영역 훼손 | S2b는 S2a PASS 후에만. 64×64 = 화면의 0.5%. WindowServer가 이후 리페인트하므로 **일시적·미관 문제**이며 재부팅으로 완전 소거 |
| 클립 범위(S2b) | 클립을 **목적지 사각형에만** 맞추므로 스캔아웃의 나머지는 여전히 봉쇄된다. 다만 테스트 대상 64×64 자체는 정의상 클립 안에 있다 |
| 무한 대기 → 행 | S1과 동일한 bounded wait, 타임아웃 시 EXEC 미실행 |
| VRAM aliasing | S1과 동일: 실증 7 MiB 가드 + 1024×768 한정 |
| 엔진 상태 잔류 | S1과 동일 — 평상시 드라이버는 엔진 미사용 |

**S1 대비 상향된 위험은 "화면에 잘못된 64×64 사각형이 잠시 보임" 뿐이다.**
머신 행/영구 손상 위험은 S1과 동일한 수준으로 묶여 있다.

## 6. 검증 방법

### 6-1. 하드웨어 이전 (호스트) — ✅ 완료

```
DWGCTL(blit) = 0x040C4008  OK
visible = 0 .. 3145727 (3.00 MiB); proven VRAM 7 MiB

S2a offscreen->offscreen
  AR3=1048576  AR0=1048639  AR5=1024
  FXBNDRY=0x003F0000  YDSTLEN=0x04800040
  src 4.00..4.25 MiB   dst 4.50..4.75 MiB
  overlap: no | under proven VRAM: YES | dst clear of visible: YES

S2b offscreen->visible(bottom-right)
  FXBNDRY=0x03FF03C0  YDSTLEN=0x02C00040
  dst 2.75..3.00 MiB, inside visible (x+w=1024<=1024, y+h=768<=768)
  overlap with src: no
```

확인된 것: `DWGCTL` 조립값 일치, 소스·목적지 비겹침, 전부 실증 VRAM 안쪽,
S2b 목적지가 가시영역 안에 정확히 들어감.

주목: S2b 목적지 끝이 가시영역 끝(3.00 MiB)과 **정확히 일치**한다. 즉 1픽셀이라도
넘치면 오프스크린 방향으로 흐른다 — §4에서 우하단을 고른 의도대로다.
`FXBNDRY=0x03FF03C0`은 left=960, right=1023(inclusive)으로 마지막 가시 열이다.

### 6-2. 타깃 빌드
클린 빌드, 경고 0, `nm -u` 미해결 심볼 0.

### 6-3. 실기 1회 부팅
성공 판정:
1. S2a: 목적지 4096픽셀이 **소스 패턴과 정확히 일치**(위치 인코딩이므로 어긋나면 즉시 검출)
2. S2b: 가시영역 목적지 4096픽셀이 소스 패턴과 일치
3. 모든 bounded wait 타임아웃 없음
4. 화면: 우하단에 사각형이 **잠깐 보이거나, WindowServer가 이미 덮어써서 안 보임** —
   둘 다 정상. **다른 위치에 이상이 나타나면 실패**
5. telnet 생존

> 주의: 이 테스트는 `enterLinearMode` 말미, 즉 **WindowServer가 화면을 그리기 전**에
> 실행된다. 따라서 S2b 사각형은 곧바로 덮여 안 보일 가능성이 높다. **육안 확인은
> 보조 수단이고, 판정의 정본은 CPU readback**이다.

### 6-4. 복구
플래그 off, 또는 재부팅(가시영역 훼손은 재부팅으로 완전 소거). 최악은 R5-VGA.

## 7. 이 단계가 증명하지 않는 것

- 성능(복사 대역폭), DMA, 인터럽트
- 겹치는 영역 복사(방향 처리 `BLIT_UP`/`BLIT_LEFT`) — 지금은 비겹침 top-down만

- 다중 클라이언트 직렬화

## 8. codex 교차검토 결과 (2026-08-19)

codex 답변을 **그대로 채택하지 않고** X.Org 원본과 대조했다.

### 8-1. 채택하지 않음 — `RPL` → `RSTR` 변경 요구

codex는 "화면간 복사는 `RSTR`을 써야 하므로 `0x040C4008`이 아니라 `0x040C4018`"
이라며 하드웨어 실행 보류를 권고했다. **원본 대조 결과 이 주장은 틀렸다.**

1. `pMga->AtypeNoBLK = MGAAtypeNoBLK` — 칩별 대체 경로가 없다(대입 2곳 모두 동일).
2. `MGAAtypeNoBLK[GXcopy=3] = MGADWG_RPL | 0x000c0000` — **RPL이다.**
3. 표의 패턴이 이를 뒷받침한다: `RPL`이 놓인 인덱스는 0(GXclear)·3(GXcopy)·
   12(GXcopyInverted)·15(GXset) — 정확히 **목적지를 읽을 필요가 없는** ROP들이다.
   `RSTR`은 소스·목적지 조합이 필요한 ROP용이다. 단순 복사에 RPL은 의미상 옳다.
4. 결정적으로, FastBlit 경로가 끝나며 DWGCTL을 **복원**하는 코드가
   `AtypeNoBLK[GXcopy] | SHIFTZERO | BITBLT | BFCOL`을 그대로 쓴다 — 즉 소스
   두 곳에서 동일한 조합이 확인된다.

→ **`DWGCTL = 0x040C4008` 유지.**

### 8-2. 채택 — 클립은 목적지 전용, 넓히지 말 것

codex 지적이 맞고 **내 계획의 실질적 안전 결함**이었다. 클립은 목적지 쓰기에만
적용되고 소스 읽기는 `AR3`/`AR0`/`AR5`가 담당한다. 소스까지 포함하도록 넓히면
불필요할 뿐 아니라 봉쇄가 크게 약해진다(§4 표 참조).

독립 근거: X.Org는 **오프스크린 픽스맵 캐시에서 가시 화면으로** 복사하면서
클립은 목적지 윈도우 경계로 설정한다(`PIXMAP_CACHE`/`OFFSCREEN_PIXMAPS` 사용).
클립이 소스에도 걸린다면 이 동작이 성립할 수 없다.

→ §4를 목적지 전용으로 정정했다.

### 8-3. FBITBLT 정렬 제약은 우리에게 적용되지 않음

`mga_reg.h`에 "bfcol + bitblt를 지정하면 fbitblt가 수행되니 fbitblt 규칙을
지키라"는 경고가 실재하며, codex가 이를 근거로 접근 타입을 문제 삼았다.
조사 결과:

- 정렬 조건은 `((srcX ^ dstX) & masks[bpp/8]) == 0`이며, 실패하면
  `FASTBLIT_BAILOUT`으로 떨어진다.
- **그 bailout이 수행하는 4개 write가 우리 계획과 완전히 동일**하다
  (`AR0`, `AR3`, `FXBNDRY`, `YDSTLEN+EXEC`, DWGCTL은 setup 값 그대로).
- 즉 정렬 제약은 **최적화 경로 전용**이고, 우리가 쓰는 경로가 X.Org의
  범용·항상-정확 경로다.
- 참고로 32bpp의 `masks[4]=0x1f`이므로 S2b(`srcX=0, dstX=960`)도
  `960 & 0x1f == 0`으로 정렬 조건을 만족하긴 한다.

### 8-4. 확인만 하고 변경 없음

- `AR3 = srcY*PITCH + srcX + YDSTORG`, `AR0 = AR3 + w - 1`, `AR5 = +PITCH`
  (픽셀 단위, 부호 있는 행 델타) — 계획대로.
- `FXBNDRY` 우변이 TRAP 채우기는 exclusive, BITBLT는 inclusive인 것은
  **같은 레지스터의 opcode 의존 해석이 맞다.** 프리미티브마다 원본 형식을 따른다.
- 비겹침 복사에서 `SGN=0` 안전. 겹칠 때 규칙(후속 단계용): 목적지가 소스보다
  아래면 `BLIT_UP`+마지막 행부터+`AR5=-PITCH`, 오른쪽이면 `BLIT_LEFT`+오른쪽
  끝부터, 둘 다면 둘 다.
- `SRCORG = DSTORG = 0` 명시 기록 유지(리셋 상태에 의존하지 않음).
- 영구적 디스플레이 손상 경로 없음 — PLL/DAC/전원/타이밍/영구설정을 건드리지
  않는다. 잘못된 프레임버퍼 쓰기는 리페인트나 재부팅으로 소거된다.
  머신 행 가능성은 남아 있으며 §5의 완화책으로 묶는다.


## 9. ✅ 실기 결과 — PASS (2026-08-19)

1024×768×32, `"Storm 2D Test" = "Yes"`, 콜드 부팅 1회. S1에 이어 순차 실행.

```
S1: PASS -- engine filled 4096 px with deadbeef, checksum dbeef000
S2: begin stride=1024 src y=1024 dstA y=1152 dstB (960,704)
```

### 판정

| 기준 | 결과 |
| --- | --- |
| S2a 목적지 4096px이 위치 인코딩 패턴과 정확히 일치 | ✅ |
| S2b 가시영역 목적지 4096px 일치 | ✅ |
| bounded wait 타임아웃 없음 | ✅ (있었다면 로그가 남고 중단됨) |
| 화면 이상 없음 | ✅ operator 확인 — 사각형 미관측 |
| telnet 생존 | ✅ |

**사각형이 안 보인 것은 §6-3에 예고한 정상 결과다**: 이 테스트는 WindowServer가
화면을 그리기 전에 실행되므로 즉시 덮인다. 판정 정본은 CPU readback이며,
단색이 아닌 **위치 인코딩 패턴**을 썼으므로 한 픽셀이라도 어긋났다면 검출됐다.

### S1 무회귀 확인

S1의 상태 초기화를 공유 헬퍼 `osmgaStormInitState`로 리팩터했으므로 회귀 위험이
있었다. 같은 부팅에서 S1이 다시 PASS하고 체크섬이 `dbeef000`으로 이전과 동일함을
확인했다. 리팩터 전후 클립 레지스터 값이 동일함은 하드웨어 이전에 호스트에서도
대조했다.

### 확보한 것

- **S2a**: 소스 주소지정 의미론 전부 — `AR3`/`AR0`(소스 span), `AR5`(행 델타),
  `SGN`(방향), BITBLT `DWGCTL=0x040C4008`
- **S2b**: **오프스크린 VRAM → 가시 스캔아웃 복사** = Mesa 렌더 결과를 화면에
  올리는 수단 그 자체(로드맵 2단계 완료)

### 교차검토에 대한 사후 확인

codex는 `DWGCTL`의 access type을 `RSTR`로 바꾸지 않으면 실행을 보류하라고
권고했으나(§8-1), 원본 대조 결과 `RPL`이 옳다고 판단해 유지했고 **실기에서
동작했다.** 원본 검증이 교차검토 의견보다 우선한다는 원칙이 실증됐다.
