# M1-4DF — 남은 미측정 둘

`M1_4D5` 가 미측정으로 남긴 것 둘이다.  **커널은 안 바뀐다** — 둘 다 탐침이다.

## 1. TD 2048 의 이음매

### 1-1 무엇이 문제인가

bias 는 **사다리꼴의 것**이고 도달범위에서 고른다.  그러니 이웃한 두
프리미티브가 **같은 좌표를 다른 bias 로** 볼 수 있다:

```
   A 의 도달범위 2^20   -> bias 496
   B 의 도달범위 2^23   -> bias 384
   좌표가 2^20 이하면 그 addend 는 496 이므로
      A 의 잔차 496-496 =   0
      B 의 잔차 496-384 = 112       <- 창 112 단위
```

같은 좌표가 두 프리미티브에서 **112 단위 어긋난다.**  텍셀에 대한 비율은
크기에 달렸다:

```
   TD 16     텍셀 65536   창 0.17%
   TD 1024   텍셀  1024   창 10.9%
   TD 2048   텍셀   512   창 21.9%
```

### 1-2 평범한 타일링에서 표본이 그 창에 드는가

`M1_4D5` 는 TD 16 에서 **안 든다**고 실측했고(`bandseam` 0 어긋남), TD 2048
에서는 들 수 있다고 보고 **미측정으로 남겼다.**  python 이 텍셀당 표본 4 로
위상을 쓸어 세었다:

```
   TD 16     256 표본 위치 중  0 이 창을 넘는다
   TD 1024   256 중 28
   TD 2048   256 중 56
```

**그러니 TD 2048 에서는 나타나야 한다.**  나타나지 않으면 잔차 모형이 틀린
것이고, 나타나면 크기가 예측과 맞는지 본다.

### 1-3 어떻게 재나 (§82)

`§63` 의 구성을 크기만 바꿔 쓴다.  같은 좌표를 두 번 그린다:

- **A**: `v` 를 상수 `c` 로 (기울기 0) → 도달범위 `c` → bias 496
- **B**: `v` 를 `c` 에서 시작해 기울기로 2^23 까지 올린다 → bias 384,
  그리고 **첫 행**을 읽는다 — 거기서 `v` 는 여전히 `c` 다

`c` 를 텍셀 경계 아래로 쓸어 두 읽기가 갈리는 구간을 찾는다.  그 구간의 폭이
112 여야 하고, 텍셀 하나가 512 이므로 21.9% 여야 한다.

그 다음 **타일링 비율**로: `c` 를 텍셀당 표본 4 의 위상들에 놓고 두 읽기를
비교한다.  python 이 56/256 을 예측한다.

### 1-4 공허하지 않게

- 텍스처가 2048 줄이어야 하고 각 줄이 **자기 번호를 담아야** 한다.  §56 이
  쓰던 8×2048 텍스처가 그것이다
- B 의 첫 행에서 `v` 가 정말 `c` 인지 먼저 확인한다 — 아니면 이 절은 다른
  좌표 둘을 비교하는 것이 된다
- A 와 B 의 bias 가 정말 496 과 384 인지, 도달범위로 확인한다

## 2. u 축 레인의 미세구조

### 2-1 무엇이 안 밝혀졌나

`M1_4D5` 의 판정: *"u 축 레인 미세구조가 v 만큼 확립되지 않았다"* → **부분
채택**, `§62` 가 u 축을 재긴 했으나 **한 대역(2^21)·한 크기(1024 폭)**
에서만이다.

v 축은 여러 대역에서 잤고, **음수 좌표**에서도 잤다(음수는 평평한 511).  u 축은
둘 다 없다.

### 2-2 어떻게 재나 (§83)

`§62` 를 두 축으로 넓힌다:

1. **대역**: 2^20, 2^21, 2^22, 2^23 각각에서 u 의 사다리 단을 확인 —
   경계 바로 아래·위에서 addend 가 496/480/448/384 로 바뀌는지
2. **크기**: 폭 64 와 1024 와 2048 에서 같은지.  텍셀 크기가 다르면 같은
   단위 오차가 다른 텍셀 비율이 되므로, 사다리가 **단위**의 성질임을 보이려면
   크기를 갈라야 한다
3. **음수**: u 가 음수일 때 addend 가 v 와 같이 평평한 511 인지

### 2-3 공허하지 않게

- 각 대역에서 **경계 양쪽**을 읽어야 한다.  한쪽만 읽으면 사다리가 아니라
  값 하나를 확인하는 것이다
- 크기를 바꿀 때 **좌표를 단위로 고정**한다.  텍셀 번호로 고정하면 좌표가
  같이 바뀌어 대역이 달라진다
- 음수 쪽은 `TEX_NEG_ALLOW` 안에 있어야 검증기를 통과한다

## 3. 교차검토에 물을 것

- §1-3 의 A/B 구성이 정말 **같은 좌표**를 두 bias 로 보게 하는가.  B 의 첫
  행에서 도달범위가 이미 2^23 으로 잡히는 것이 맞나 — 도달범위는 프리미티브
  전체에서 걷히므로 첫 행에서도 큰 bias 가 적용될 텐데, 그게 이 시험의 전제다
- 56/256 예측이 기대야 하는 가정 중 틀릴 수 있는 것
- §2-2 의 세 축(대역·크기·부호) 말고 u 에서 갈릴 수 있는 것이 더 있나
- 이 둘 중 하나라도 **커널 변경을 요구하는 결과**가 나올 수 있는 경우

## 4. 잰 결과

### 4-1 이음매는 TD 2048 에서 문다 (§82)

```
   they part from k = 13 to k = 124, a window of 112 units
   at four samples a texel: 12 of 64 positions read a different row
   phases that crossed, per sample: e000 0e00 00e0 000e
```

폭도, 위치도, **어느 위상이 넘는지까지** python 과 일치한다.  TD 16 에서는
0 이었다(`M1_4D5` §17-3).  그러니 미측정으로 남았던 항목의 답은
**"TD 2048 에서는 나타난다"** 이다.

### 4-2 그러나 제 산술이 처음에 틀렸다

잔차를 0 과 112 로 잡았는데, **좌표 자신의 addend** 는 그 크기가 정한다.
쓸어본 경계는 262144, 즉 `2^18` 이라 addend 가 496 이 아니라 **508** 이다:

```
   가까운 쪽 잔차  508 - 496 =  12
   먼   쪽 잔차   508 - 384 = 124
   창              112          <- 두 bias 의 차, 이건 맞았다
```

그래서 창은 1..112 가 아니라 **13..124** 다.  하드웨어가 먼저 그렇게 말했고
python 을 고치니 맞았다.

### 4-3 codex 의 "적어도 2^23 에 닿게"는 여기서 틀리다

먼 쪽 프리미티브가 대역에 확실히 닿도록 나눗셈을 **올림**하라고 했다.  올리면
`2^23` 을 **넘고**, `2^23` 은 대역의 중간이 아니라 `COORD_MAX` — 범위의 천장이라
모든 읽기가 거절됐다.  내림이 맞다: 그 아래에 앉아도 대역은 여전히 `2^23`
이다(대역은 값이 넘지 않는 가장 작은 2 의 거듭제곱이므로).

### 4-4 u 레인은 어디서도 갈리지 않는다 (§83)

```
   width   64  band 2^20/2^21/2^22/2^23   여덟 열 전부 63
   width 1024  band 2^20/2^21/2^22/2^23   여덟 열 전부 1023
   width   64  아래 -1/-2/-4 텍셀        63 / 62 / 60
   width 1024  아래 -1/-2/-4 텍셀      1023 / 1022 / 1020
```

**열네 조합, 여덟 열, 전부 python 대로.**  짝·홀 열이 갈리는 곳은 없었다 —
`§62` 가 한 대역·한 크기에서 본 것이 네 대역·두 크기·음수까지 유지된다.

폭 2048 은 시험하지 않는다: `TEXCTL` 의 피치 필드가 11 비트라 검증기가 피치를
2047 로 묶는다(`OpenStepMGAHW3D.h:167`).  codex 가 짚었고 확인했다.
