# T2 — GL_REPEAT 좌표 재기준 (계획, 코드 없음)

## 1. 무엇이 문제인지 (측정으로 확정됨)

드라이버는 **그리는 픽셀에서** 텍스처 좌표가 ±8 반복을 넘으면 배치를 거절한다
(`OpenStepMGAHW3D.c` 행 끝점 검사). 8회 연속 거절이면 가속을 영구 반납한다.

GLQuake 60초, 드라이버의 지점별 카운터:

```
refusals(all)  513        (텍스처 457, 그 외 56)
  anchor-uv       44   9.6%
  q-budget        37   8.1%
  slope-x          2   0.4%
  row-ends       374  81.8%   ← 정밀 검사 = 정책 그 자체
  empty-row        0
```

맵 데이터 전수 계산(`openstep-quake/tools/measure-texcoord-range.py`,
23개 맵 48849 면, 실기 불필요):

```
  past   8 repeats:  33348 faces  68.27%      최대 222.88 반복
```

**레벨 면의 68% 가 정책을 넘는다.** 검사의 버그가 아니라 정책과 워크로드의
불일치다.

## 2. 왜 정책을 넓히지 않는가

±8 은 하드웨어 한계가 아니다. 헤더 주석이 말하듯 "실제로 측정된 배율"이고,
그 너머는 "아무도 시험하지 않은 성질"(CLAMPUV)에 기댄다. 223 반복을 허용하려면
측정된 봉투의 **28배** 너머를 신뢰해야 한다. 게다가 그 검증은 hang 위험이 있는
하드웨어 실험이고, 이 머신의 규칙은 실기 실험을 read-only 또는 복원·검증으로
제한한다.

기존 bias 사다리(`osmgaHW3DTexBandHeadroom`)는 6단짜리이고
`reach + addend − bias ≤ COORD_MAX` 를 만족하는 단이 없으면 0단으로 떨어진다 —
수백 반복을 감당하도록 만들어진 것이 아니다.

## 3. 고칠 것

`GL_REPEAT` 에서 `s` 와 `s − K` 는 **같은 텍셀을 샘플한다**(K 는 정수 반복 수).
그러니 삼각형마다, 축마다, 그 축이 `GL_REPEAT` 일 때만 정수 K 를 빼서 좌표를
범위 안으로 내린다.

- 아핀: `s' = s − K`
- 원근: 좌표는 `s/q` 이므로 **동차형** `s' = s − K·q`.
  `s` 와 `q` 가 둘 다 화면 선형이므로 `s − K·q` 도 선형이다 — 평면이 유지된다.

`K = floor(min_i s_i/q_i)` (축별, 삼각형별). 빌더가 이미 `q_i > 0` 을 요구한다.

백엔드는 이미 축별 wrap 을 안다 — `OpenStepMGAMesaHook.c:2552` 가
`REPEATU`/`REPEATV` 를 세운다. `GL_CLAMP` 축에는 적용하지 않는다.

## 4. 왜 충분한가 (측정)

재기준이 없앨 수 없는 것은 **삼각형 하나 안의 좌표 폭**이다. 면 폭(삼각형 폭의
상계) 분포:

```
   50.0%     1.061 반복
   90.0%     3.500
   99.0%     4.500
   99.9%     7.000
  100.0%    17.000
  폭 > 8 반복인 면: 34 / 48849  (0.07%)
```

**99.93% 가 재기준 후 ±8 안에 들어온다.** 나머지 0.07% 는 오늘처럼 소프트웨어로
깨끗이 떨어지면 된다(빌더가 제출 전에 거절하므로 revoke 를 부르지 않는다).

## 5. 어디에

`mesa/OpenStepMGAMesaTriangle.c`, 분자(`ua/va`)에 대해, 범위 검사(≈1204) **전에**.

## 6. 검토받고 싶은 위험

1. **배치 분할.** `tmr[]` 는 배치 상태이고 훅은 값이 달라지면 배치를 가른다
   (`OpenStepMGAMesaHook.c:103`).
   - 아핀: K 는 사다리꼴별 앵커 `tu0/tv0` 만 바꾼다. 기울기 불변 → **추가 분할 없음.**
   - 원근: `s' = s − K·q` 는 `ds/dx` 를 `−K·dq/dx` 만큼 바꾼다 → 기울기가 바뀌고
     **K 가 달라질 때마다 배치가 갈린다.** 비용 미측정. 완화책: K 를 배치 단위로
     고르거나, 원근에서는 어차피 갈리는 경우에만 재기준한다.
2. **GLQuake 는 어느 갈래인가.** 미측정. `q-budget` 이 37회 울렸으니 원근이
   *존재*하는 것은 확실하나 비율은 모른다. 위험 1의 비용이 여기에 달렸다.
3. **bias 사다리와의 상호작용.** 재기준하면 reach 가 줄고 커널이 **다른 단**을
   고른다. 단이 바뀌면 적용되는 bias 가 바뀐다. 그림이 동일하게 유지되는가?
4. **필터 이음매.** REPEAT + `GL_LINEAR` 에서 엔진은 마스킹으로 감는다(주석
   ≈2864, 그래서 REPEAT 는 2의 거듭제곱을 요구한다). 정수 반복을 빼면 마스킹된
   주소가 같아야 한다 — 확인 필요.
5. **정밀도.** 빌더는 double 로 계산하지만 방출되는 앵커는 고정소수점이다.
   K 가 200 을 넘을 때 `s − K·q` 의 상쇄 오차가 텍셀 하나를 어긋나게 하는가?
6. **삼각형별이 맞는가, 면별이 맞는가.** 한 면을 팬으로 자른 삼각형들이 서로 다른
   K 를 가지면 이음매에서 어긋나는가? (샘플이 modulo 라면 안 어긋나야 한다.)
7. **`anchor-uv` 44 건**은 재기준으로 같이 사라지는가, 별개인가.

### 내가 틀렸던 것 둘

1. **K 공식.** 창이 대칭이 아니라 `[−1, +8]` 인데 `floor(min)` 은 그걸 무시한다.
   올바른 K 는 `[ceil(max−8), floor(min+1)]` 에서 고르고, 반올림 여유를 위해
   구간 가운데를 택한다.
2. **측정이 WARP 를 통제하지 않았다.** WARP 는 Configure 체크박스로 켜져 있고
   빌더보다 먼저 프리미티브를 가져간다. 지금까지의 거절 분포는 "WARP 가 거절한
   나머지"에 대한 것일 수 있다.

### 배치 비용에 대한 판단

codex 도 지적했듯 원근 삼각형은 어차피 서로 다른 투영 평면을 가지므로
`tmr[]` 가 달라 **이미** 배치가 갈리고 있을 가능성이 크다. 반대로 같은 벽면을
쪼갠 삼각형들은 평면을 공유하는데, 그 삼각형들은 **좌표 범위도 공유하므로 K 도
같다.** 즉 배치가 합쳐져 있는 경우에는 K 도 같아서 추가 분할이 없을 공산이 크다.
다만 이것은 논증이지 측정이 아니다 — 구현 시 배치 flush 수를 전후 비교한다.

## 9. 수정된 계획

1. **K 선택**: 축별·삼각형별로 `Klo = ceil(max−8)`, `Khi = floor(min+1)`,
   `Klo > Khi` 면 재기준하지 않고 오늘처럼 소프트웨어로 떨어뜨린다.
   그렇지 않으면 `K = floor((Klo + Khi) / 2)` — 반올림 여유를 양쪽에 남긴다.
2. **wrap 전달**: `OSMGAMesaTex` 에 축별 REPEAT 플래그를 더한다(훅은 이미 안다).
   REPEAT 가 아닌 축은 건드리지 않는다.
3. **적용 지점**: 정규화 좌표 단계, 원근 평면을 풀기 전. `ua' = ua − K·SPAN·tq`.
4. **WARP 통제**: 모든 측정은 `OSMGA_MESA_WARP` 를 명시적으로 0/1 로 두고 한다.
5. **검증**: 각 drawn endpoint 의 최종 좌표가 정확히 K 반복 차이인지(앵커가 아니라).
   그리고 인접 삼각형이 다른 K → 다른 bias 단으로 갈라져 이음매가 보이는지.
6. **측정할 것**: 원근 비율, 배치 flush 수 전후, 재기준 후 지점별 거절 분포.

## 10. WARP 통제 재측정 (§8 의 채택 항목)

각 45초, 실행 전후 카운터 차이:

```
WARP=0  refusals  40 (텍스처  31, 그 외  9)  revoked 1
    row-ends    16   51.6%
    anchor-uv   10   32.3%
    q-budget     5   16.1%
    slope-x      0    0.0%

WARP=1  refusals 473 (텍스처 423, 그 외 50)  revoked 0
    row-ends   345   81.6%
    anchor-uv   44   10.4%
    q-budget    32    7.6%
    slope-x      2    0.5%
```

### 진단은 살아남는다

`row-ends` 가 **양쪽 모두에서 지배적**이고(51.6% / 81.6%), `slope-x` 는 양쪽
모두 0 에 가깝다. 즉 "거절 분포가 WARP 가 거절한 나머지에 대한 것일 뿐"이라는
가능성은 배제된다. 사다리꼴 티어의 문제는 실재하고 WARP 와 독립이며, 재기준은
옳은 표적을 겨눈다.

### 뜻밖의 것: WARP 는 revoke 를 가린다

WARP 를 켜면 거절이 **12배 많은데 revoke 가 나지 않고**, 끄면 거절이 훨씬 적은데
**revoke 가 난다.** 거절 카운터가 세는 것은 *연속* 8회이기 때문이다 — WARP 가
성공시키는 배치들이 사이에 끼어 연속을 끊는다.

이것은 revoke 유무가 거절률의 척도가 아니라는 뜻이다. WARP 를 켠 45초 동안
텍스처 삼각형 **423개가 소프트웨어로 떨어졌고**, 그동안 아무 경고도 없었다.
"revoked 0" 을 건강함으로 읽으면 안 된다.

### 이 숫자들의 한계

두 실행은 같은 양의 일을 하지 않았다. WARP=0 실행은 도중에 revoke 가 나서 이후
소프트웨어로 돌았고, 그래서 제출 자체가 적다. **절대 수는 비교 대상이 아니고,
비교할 수 있는 것은 분포의 모양뿐이다.**

| backstop(연속 8회 revoke)은 **이번에 같이 바꾸지 말 것**. 묶으면 재기준의 효과와 정책 완화를 구분할 수 없다 | 논리 확인 | ✅ 채택. 별건으로 미룬다 |
| §9 의 검증 조건("각 endpoint 가 정확히 K 반복 차이")은 너무 강하고 형식도 틀렸다. λ 와 정수 반올림이 달라진다 | 논리 확인 | ✅ 채택. 고정밀 원평면 대비 **오차 상한**, 방출된 TMR 의 endpoint 정책 통과, 소프트웨어 화면 비교로 바꾼다 |

## 12. 첫 구현 (여기까지만 한다)

1. `OSMGAMesaTex` 에 축별 REPEAT 플래그. 훅이 채운다.
2. **`tq == 1` 인 삼각형에서만** 재기준한다 — 아핀 분기 위험을 통째로 피한다.
   GLQuake 의 원근은 `qw`(1/w)에서 오지 텍스처 q 에서 오지 않으므로, 이 제한은
   사실상 전부를 덮는다(그 삼각형들은 `osmgaPerspPlanes` 를 타고, 그쪽은 제대로
   나눈다).
3. K 는 축별로 `Klo = ceil(max−8)`, `Khi = floor(min+1)`, 비면 재기준하지 않는다.
   그렇지 않으면 `K = clamp(round((min+max−7)/2), Klo, Khi)`.
4. 뺄셈은 `Triangle.c:1141` 직후, double 로. `tq == 1` 이므로 `ua -= K * us`.
5. 측정은 `OSMGA_MESA_WARP=0` 고정, 전후로 지점별 거절 분포와 `hookFlushKey`.
6. WARP 지원·backstop 변경·배치 K 공유 최적화는 **보류**.
