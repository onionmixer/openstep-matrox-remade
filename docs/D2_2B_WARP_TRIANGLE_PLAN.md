# D2-2b — WARP 로 삼각형 (2026-08-28, 코딩 전)

D2-2a 가 **파이프를 기동해도 엔진이 살아 있음**을 실기로 확인했다(2026-08-19).
남은 질문은 하나다: **삼각형이 나오는가.**

---

## 1. 범위가 바뀐다 — **2 차 DMA 없이 시도한다**

D2-2 초판은 D2-2b 에 *"파이프 기동 + 컨텍스트 + 텍스처 + 정점 버퍼(2 차 DMA)"*
가 전부 필요하다고 적었다. **그 마지막 항목이 이 프로젝트를 넉 달 막았다** —
2 차 DMA 설계가 네 번의 교차검토에서 전부 NO-GO 였다(W11·W13·W14).

**그런데 `WR0`~`WR63` 이 개별 주소지정 가능하다:**

```
WR0   WO  2D00h  인덱스 C0h
WR63  WO  2DFCh  인덱스 FFh      -> 전부 group1 (0x2c00~0x2dff)
```

**즉 1 차 DMA 의 일반 모드 레지스터 쓰기로 WR 뱅크에 닿을 수 있다.**
이미 신뢰하는 경로다 — 86,554 회 제출로 검증된 그 경로.

### 1.1 비용 (python)

```
정점 하나 = 8 dword (WVRTXSZ 0x1807)

  2차 vertex 모드      8 dword
  1차 general WR 쓰기 10 dword   (블록 2개 x 5)   +25%
  1차 vertex 모드      8 dword + run 2개 추가

W2 23 실측: 정점 패킹은 프레임 6.36 ms 의 0.8~1.6%
  -> general 방식의 추가 비용은 프레임당 13~25 us
```

**W2 §24 가 기각한 것은 1 차 *vertex 모드*(run 3 개, +3.96 ms)였다.**
**일반 모드 WR 쓰기는 검토된 적이 없고, 비용이 두 자릿수 다르다.**

## 2. 그러나 전례가 없고, 그것이 이 시험이다

DRM 은 정점을 **항상** `SECADDRESS | MGA_DMA_VERTEX` 로 보낸다. WR 에 쓰는
것은 파이프 셋업 상수뿐이다(`WR49/52/53/...`).

그리고 사양서가 걸린다 — `wvrtxsz` 는 *"the number of registers (minus one)
to be written sequentially in **the WR register** before switching to the
next bank (…) only used by the **ACCEPT** command"* 다. **단수**다.

> **사양서가 답한다 (교차검토를 기다리는 동안 확인).**
>
> `WR` 의 속성 (3-276): **`WO, DB, DYNAMIC, DWORD, FIFO`**
>
> 그리고 속성 정의 (3-30): **`FIFO: Data written to this register will pass
> through the BFIFO.`**
>
> `STATUS.wfipath` (3-189): *"WARPFIFO Input Path. This bit indicates which
> WARPFIFO (**between the BFIFO and the two WARPFIFOs**) has the data path."*
>
> **즉 경로가 이렇다: 레지스터 쓰기 → BFIFO → WARPFIFO → WARP.**
> vertex 모드 DMA 도 같은 BFIFO 로 들어간다 — 인덱스 dword 를 안 싣는 것이
> 다를 뿐이다.
>
> 그리고 `WR` 의 설명이 못을 박는다:
>
> > *"These are the 64 multi-purpose WARP registers (…) **It is up to the
> > software to define what to put in these registers and how the microcode
> > will interpret them.**"*
>
> **WR 뱅크가 소프트웨어 인터페이스다.** `ACCEPT.seq` 의 `seqdst<5:0>` 이
> 6 비트, 즉 `WR0`~`WR63` 을 가리키는 것도 같은 그림이다(3-260).

**그러므로 "될 것" 이 아니라 "사양서상 되어야 한다" 로 올라갔다.** 남은
불확실성은 **정점의 배치**(어느 WR 부터 몇 개)이지 **도달 가능성**이 아니다.

## 3. 왜 이것이 더 싼 시험인가

| | 2 차 DMA 경로 | **일반 모드 WR** |
| --- | --- | --- |
| 새 수송 | 필요 | **없음** |
| 회수 필요성 | 있음(그리고 회수가 없다) | 1 차와 같음 |
| 교차검토 | 네 번 NO-GO | 미검토 |
| 실패 시 | 기계가 물릴 수 있다 | **1 차 경로의 기존 위험뿐** |

**실패해도 새 실패 모드가 없다.** 잘못된 정점은 잘못 그리거나 엔진을 물리게
하고, 그 둘은 이미 유계 폴과 `stormBlitFailed` 가 다루는 것들이다.

## 4. 무엇을 그리는가

**오프스크린에 삼각형 하나.** 화면이 아니다.

```
1) 파이프 기동      D2-2a 가 이미 한 것 (WIADDR2 등)
2) 컨텍스트 상태    DWGCTL, 목적지, 클립
3) 정점 3 개        general 모드로 WR 뱅크에 24 dword
4) SOFTRAP          기존 완료 판정
```

**텍스처는 쓰지 않는다** — 단계를 하나 줄인다. 평면 색 삼각형이면 충분하다.

## 5. 판정

| | |
| --- | --- |
| 통과 | 오프스크린에 **삼각형 모양**이 나온다 (배경 sentinel 이 세 꼭짓점 안에서만 바뀐다) |
| 실패-A | 아무것도 안 그려진다 → ACCEPT 가 순차 포트를 요구한다 |
| 실패-B | 엉뚱한 것이 그려진다 → 정점 배치가 틀렸다 |
| 실패-C | 엔진이 안 돌아온다 → 유계 폴이 잡고 `stormBlitFailed` 가 선다 |

**실패-A 와 실패-B 를 가르려면** 정점을 다 쓴 뒤 WR 을 되읽을 수 없으므로
(`WO`), **정점 수를 바꿔 가며** 무엇이 바뀌는지 본다.

## 6. 위험

- **하드웨어 위험은 1 차 경로의 기존 위험과 같다.** 새 수송이 없다
- **다만 WARP 마이크로코드가 처음으로 정점을 받는다** — D2-2a 는 파이프를
  기동만 했지 정점을 준 적이 없다
- **엔진이 물릴 수 있다.** 유계 폴이 타임아웃하고 가속이 래치로 꺼진다.
  `OSMGAAccelRearm` 이 그것을 푼다(W10 §9.9 가 이 목적으로 만든 것)
- **화면은 건드리지 않는다** — 오프스크린 목적지

## 7. codex 에 물을 것

- WR 뱅크가 인터페이스인가, ACCEPT 가 순차 포트를 요구하는가 — 사양서에
  이를 가르는 문장이 있는가
- 정점 8 dword 가 **어느** WR 레지스터로 가는가 (뱅크 포인터의 시작점)
- 파이프 기동 뒤 정점을 주기 전에 필요한 상태가 더 있는가
  (`WACCEPTSEQ`, `WFLAG`, `WGETMSB` 등)
- 판정 §5 가 네 결과를 실제로 가르는가
- D2-2a 가 확인한 것 중 이 계획이 놓친 전제가 있는가

## 8. codex 교차검토 판정 — **NO-GO. 이 계획은 죽었다.**

### 8.1 ★ 정점은 `WDBR` 로 도착한다. `WR` 이 아니다.

`ACCEPT` 의 설명(3-25x):

> *"When the WARP executes an `ACCEPT.w` instruction **after receiving the
> last DWORD WDBR (vertex information)** the flag Q is programmed with…"*

레지스터 맵:

```
WVRTXSZ      WO   1DCCh   73h  WARP Vertex Size
    —         —   1DD0h   74h  Reserved (WDBR)      <- 여기
WACCEPTSEQ   WO   1DD4h   75h  WARP Accept Sequence
```

**`WDBR` 은 별개의 레지스터이고, 공개 맵에서 `Reserved` 다.**

`seqdst<5:0>` 이 `WR0`~`WR63` 을 가리킨 것은 **시퀀서가 데이터를 *넣는*
목적지**였지 데이터가 *들어오는* 경로가 아니었다. 나는 그 둘을 뒤집어 읽었다.

### 8.2 ★ 그리고 참조 구현이 논리적으로 못을 박는다

`mga_g400_emit_tex0`(`mga_state.c:182~`)이 렌더링 도중 **텍스처 상태로**
`WR49`·`WR57`·`WR53`·`WR61`·`WR52`·`WR60` 을 쓴다.

> **개별 WR 쓰기가 정점 도착이라면, 텍스처 상태를 바꿀 때마다 정점 스트림이
> 깨진다.** 깨지지 않으므로, 그것은 정점 도착이 아니다.

**사양서와 참조가 각각 독립적으로 같은 결론을 준다.**

### 8.3 내가 무엇을 잘못했나

`WR` 이 `FIFO` 속성을 갖는다는 것을 확인하고 **"BFIFO 를 지나가니 WARP 에
도달한다"** 로 건너뛰었다. 도달은 맞다 — **레지스터 파일에** 도달한다.
정점 **수집기**에 들어가는 것과는 다른 이야기였고, 그 구분을 하지 않았다.

`FIFO` 속성은 *"이 레지스터에 쓴 데이터는 BFIFO 를 지난다"* 이지
*"이 레지스터가 정점 입력이다"* 가 아니다.

### 8.4 그 밖에 채택한 지적

- **비용 논거가 틀렸다** — 정점 패킹 시간의 25% 를 DMA 트래픽 25% 의 비용으로
  슬쩍 바꿔 놓았다. 둘은 다른 비용이고, W2 자신이 그 측정에서 상태 블록·검증·
  제출·완료를 **뺐다**고 적어 두었다. `13~25 µs` 는 근거 없다.
- **삼각형 셋은 24 dword 가 아니라 30 dword** 다(일반 모드). 내 실행 개요가
  자기 모순이었다.
- **판정표가 판별하지 못한다** — "아무것도 안 그려짐" 의 원인이 아홉 가지다.
  그리고 **정점 수를 바꾸는 진단은 더 나쁘다**: `primsz=24` 에서 3 이 아닌
  정점 수는 부분 프리미티브를 만들어 원인을 하나 더 늘린다.
- **`runWarpPipeOnce` 는 `stormBlitFailed` 를 세우지 않는다**(`:8031`).
  완료 마스크에 `STATUS.wbusy`/`wbusy1` 이 없다 — WARP 가 RUN/WAIT/STALL
  중이어도 완료로 읽힌다.
- **D2-2a 는 마이크로코드 주소를 지역 변수로 두고 일부러 흘린다**(`:8072`).
  *"D2-2a 처럼 파이프를 기동한다"* 는 재사용 가능한 상태 계약이 아니다.
- **"오프스크린이니 봉쇄된다" 가 아니다** — 원점·맵 선택자·클립·깊이/텍스처
  목적지를 전부 강제해야 봉쇄다.

### 8.5 그래서 D2-2b 는 여전히 막혀 있다

| 경로 | 상태 |
| --- | --- |
| 2 차 DMA vertex 모드 | 네 번의 NO-GO. 회수 수단 없음 |
| **일반 모드 WR 쓰기** | **불가능** — 정점 수집기가 아니다 |
| 일반 모드 `WDBR` 쓰기 | `Reserved`. **문서가 없다** — 다른 종류의 위험 |
| 1 차 vertex 모드 | run 3 개. 생산에는 부적합하나 **일회성 대조군으로는 유효** |

**마지막 줄이 이 검토가 준 것 중 유일하게 앞으로 가는 길이다** — 생산 비용
3.96 ms 는 삼각형 하나짜리 시험에서 무의미하므로, **1 차 vertex 모드가
D2-2b 의 양성 대조군이 될 수 있다.**

### 8.6 이 문서의 결론

**코딩하지 않는다.** 중심 가설이 사양서와 참조 양쪽에서 반증됐다.

건진 것: `WR` 이 주소지정 가능하다는 것과 일반 모드가 한 run 으로 끝난다는
것은 사실이고, 언젠가 쓸 수 있다. **그러나 정점을 나르지는 못한다.**
