# M1-4cb — `GL_REPEAT` (2026-08-23, 재부팅 대기)

## 1. 왜 막혀 있었나 — 그리고 왜 그냥 열면 안 되나

`GL_REPEAT` 는 GL 의 **기본** 감싸기 모드다.  커널은 `TEXCTL` 의
`CLAMPUV`(0x18000000) 두 비트를 **항상 켜 왔고**, 검증기의 좌표 경계 검사는
그 선택 **위에** 서 있었다: 클램프면 허용 범위 안의 어떤 좌표도 텍스처 안의
텍셀을 가리킨다.

비트를 끄면 repeat 이다 — X.Org 의 mga 드라이버가 그렇게 고른다
(`mga_exa.c`: `if (!repeat) texctl |= MGA_CLAMPUV`).  그러면 **클램프가 주던
안전이 사라지므로 다른 데서 와야 한다.**

## 2. 안전은 셋이 함께 만든다

| | |
|---|---|
| 음수 | 검증기가 **그리는 화소에서 음수가 되는 좌표를 거절**한다(§29 에서 확인). 그래서 repeat 은 0 ~ 8 스팬만 본다 |
| 2 의 거듭제곱 | 축소가 마스크가 되려면 그 축의 크기가 거듭제곱이어야 한다 |
| 피치 = 폭 | 교차검토가 짚은 것: 폭이 거듭제곱이어도 **피치가 다르면** 마스크된 색인이 엉뚱한 행을 가리킨다 |

셋 다 인코더에서 **요구**한다(가정하지 않는다).  하나라도 어긋나면 그 축은
클램프로 남는다.

## 3. 비트가 축인지부터 잰다

두 비트가 축 하나씩이라는 것은 **추측**이다.  모드 부호화일 수도, 하나가
테두리 클램프일 수도 있다.  그래서 §37 이 네 상태를 모두 걸고 **한 번에 한
축만** 범위 밖으로 내보낸다:

```
   both set     u 도 v 도 가장자리 텍셀
   one clear    정확히 한 축만 감긴다 — 어느 축인지가 이름이다
   both clear   둘 다 감긴다
```

한 비트를 껐는데 **두 축이 다** 감기면 축이 아니라 모드다.  범위 밖 표본이
텍셀이 아니라 상수로 나오면 repeat 이 아니라 테두리다.

## 4. 한 번 감기는 것과 주기적인 것은 다르다

§38 은 같은 텍셀 중심을 **n 스팬씩 밀어** 0..7 까지 읽는다.  뺄셈 한 번으로
구현된 감기는 첫 스팬 근처에서만 맞고 그 뒤로 어긋난다.  여덟 번 모두 같은
텍셀이어야 주기적이다.

## 5. 재부팅 뒤 순서

1. §37 로 비트의 정체를 정한다 (이름이 뒤집혀 있으면 상수를 맞바꾼다)
2. §38 로 주기성을 확인한다
3. 그다음에야 Mesa 관문에 `GL_REPEAT` 를 **축마다** 연다 (유저랜드, 재부팅 불필요)
4. 선형 필터에서의 이음매(가장자리에서 반대쪽 끝과 섞이는지)를 잰다

관문은 아직 열지 않았다.  §37 이 무엇을 말할지 모르는 채로 여는 것은
이 저장소가 계속 피해 온 일이다.
