# §3-12 — 보간 평면을 화소 중심으로 옮긴다 (계획, 2026-08-21)

측정: `M1_4A4_ATTRIB_ANCHOR_PLAN.md` §9. 두 효과가 **서로 독립**으로 확인됐다.

| 효과 | 크기 | 근거 |
|---|---|---|
| A. 시작값을 화소 **모서리**에서 읽는다 | `−(dx+dy)/2` | 모서리 잔차 −0.48, 중심 잔차 −13.42/+12.46 (예측 −12.94/+12.94) |
| B. 고정소수점 출력이 **절단**된다 | 평균 −0.5 | **화소별 항등식**(아래) |

### 0-1. B 는 히스토그램이 아니라 항등식으로 확정됐다

교차검토가 "균일 분포는 최종 절단을 유일하게 증명하지 않는다 — 단계별
양자화도 뭉치면 균일해 보인다"고 짚었다. 맞는 지적이라 뭉치지 않고 봤다:

```
   red    잔차 != -frac(정확한 평면):  0 / 704   (최대 오차 0.000000)
   green  잔차 != -frac(정확한 평면):  0 / 704   (최대 오차 0.000000)
```

즉 `hw(x,y) = floor(정확한 평면(x,y))` 가 **704 화소 전부에서 성립**한다.
단계별로 오차가 쌓였다면 이 항등식이 깨진다.

### 0-2. 덤으로 나온 것 — 엔진의 실효 기울기가 수학적 평면과 같다

교차검토는 "보정은 인코딩된 실효 증분에 대해 정확한 것이지 원본 double 에
대해서가 아니다"라고 했다. 위 항등식이 그것을 **정량적으로** 묶는다.
어떤 화소는 평면값이 **정확히 정수**여서(소수부 0) 엔진 값이 그보다 조금만
작아도 floor 가 한 단계 내려간다. 모든 화소에 대해 교집합을 취하면

```
   0 <= (엔진 내부값 - 정확한 평면) < 0.0057 단계 = 고정소수점 LSB 의 0.19 배
```

그러므로 `(dx+dy)/2` 보정은 인코딩된 증분에 대해서도 정확하다.

## 1. 고칠 곳 — 같은 표현식이 세 군데

`mesa/OpenStepMGAMesaTriangle.c` 에서 색·알파·깊이가 **똑같이** 쓴다:

```c
double ox = (double)left - (double)a->x;   /* left, y 는 정수 */
double oy = (double)y    - (double)a->y;
... p->at_a + p->dx * ox + p->dy * oy
```

## 2. 효과 A — 우리 산술이다, 엔진 이야기가 아니다

평면도 알고 GL 이 무엇을 원하는지도 안다. `ox`/`oy` 에 **0.5 씩 더한다.**

```c
double ox = (double)left - (double)a->x + 0.5;
double oy = (double)y    - (double)a->y + 0.5;
```

처음에 **세 군데 모두** 고친다고 적었다. **깊이는 뺀다** — 교차검토가
옳게 짚었다:

- 깊이의 반 화소는 `0.5·(dz/dx + dz/dy)` 이고 가파른 다각형에서는 **16 비트
  코드로 여러 단계**가 될 수 있다. `<`, `<=`, 동일평면, polygon offset 결과를
  뒤집는다.
- 깊이 시험이 켜져 있으면 **커버리지까지 바뀐다.** 이번 회차의 성공 기준에
  "커버리지 불변"이 들어 있는데, 재지 않은 변경으로 그것을 흔들면 안 된다.
- 깊이에는 뷰포트 Z 변환과 버퍼 양자화가 더 붙는다. 별건이다.

**색과 알파만 고친다.** 둘 다 같은 실행에서 잰다. 깊이는 자기 측정 계획을
가진 뒤에 고친다.

측정으로 뒷받침되는 것: 엔진이 시작 화소에서 우리가 준 값을 **그대로**
칠한다(파랑 잔차가 704/704 화소에서 정확히 0 — 첫 화소 포함). 그러므로
시작값을 옮기면 전체가 옮겨진다.

## 3. 효과 B — 이건 엔진 이야기다, 그래서 **잰 것만** 고친다

절단 보정은 "엔진이 아래 15 비트를 버린다"는 관찰에 기댄다. **색에 대해서만
쟀다.** 알파와 깊이의 인터폴레이터가 같이 행동한다는 증거는 없다.

- **색**: 시작값에 반 단계(`1 << 14`)를 더해 반올림으로 만든다.
- **알파**: 같은 실행에서 **같이 잰다** — 시험이 이미 알파 바이트를 찍고
  있고, 정점에 알파 기울기를 주는 것은 공짜다. 재고 나서 고친다.
- **깊이**: **건드리지 않는다.**

넘침 확인(python 으로): 최댓값은 `255.5 × 32768 = 8372224 = 0x7FC000`.
지금 코드가 이미 `255 << 15 = 0x7F8000` 을 쓰므로 폭이 같은 자리다.
출력은 `floor(255.5) = 255` 로 포화되지 않는다.

클램프 순서: `[0,255]` 로 자른 **뒤** 반 단계를 더한다. 그러면 실효 범위가
`[0.5, 255.5]` 이고 출력은 `0..255` 로 정확히 떨어진다.

## 4. 효과 A 가 클램프를 악화시키지 않는가

`osmgaStartFixed` 는 시작값을 `[0,255]` 로 자른다. 사다리꼴 모서리는
삼각형 **밖**일 수 있어 클램프가 걸릴 수 있다(§M1_4A4 에서 실측함).

0.5 씩 안으로 옮기면 표본점이 **화소 안쪽**, 즉 그려지는 영역 쪽으로
움직인다 — 클램프가 걸릴 이유가 **줄어든다.** 그래도 클램프는 방어로
남긴다. 그리고 시험은 **클램프가 안 걸렸음을 단정**한다.

## 5. 확인 — 예측을 먼저 적는다

`test/openstep-mga-mesa-attrib-test.c` + `attrib-compare.py` 를 그대로 다시
돌린다. 같은 도형, 같은 표.

| 채널 | 지금 HW 중심 잔차 | A 만 고친 뒤 | A+B 고친 뒤 |
|---|---|---|---|
| 빨강 | −13.420 | **−0.5 근처** | **0 근처(|0.1| 미만)** |
| 초록 | +12.458 | **−0.5 근처** | **0 근처** |
| 파랑 | 0.000 | **0.000 그대로** | **0.000 그대로** |
| 알파 | (이번에 처음 잰다) | | |

**B 의 합격 기준은 A 이후의 측정에서 다시 세운다.** 교차검토가 짚었듯이
A 는 모든 시작값의 고정소수점 위상을 바꾸므로, A 이전의 히스토그램이
A 이후를 예측한다고 가정하지 않는다. 위 가운데 열은 **예측**이지 전제가
아니다 — 어긋나면 그 자체가 결과다.

- **파랑이 계통적으로 움직이면 실패다.** 다만 "정확히 0" 은 과한 기준이다:
  실수 산술에서는 `0.5·(dx+dy) = 0` 이지만 코드는 double 로 계산하고
  `osmgaStartFixed` 가 반올림 문턱을 넘을 수 있다. **계통적 이동은 실패,
  경계 화소 몇 개는 설명해야 할 진단**이다 (교차검토 제안).
- 잔차 분포가 (−1,0] 균일에서 **0 중심**으로 바뀌어야 한다(B 의 서명).
- `left(row)` 기울기와 사다리꼴 절편 차이는 **계속 0 근처**여야 한다.
- **커버리지가 안 변해야 한다**: 하드웨어 704/704 EXACT 유지.
  색 시작값은 커버리지와 무관하므로 변하면 그건 다른 것을 건드린 것이다.

### 5-1. 도형 하나로는 부족하다

교차검토: 기하 하나는 좌변 기울기·감는 방향·위/아래 사다리꼴·얇은 삼각형을
다 못 본다. **두 번째 도형**을 넣는다 — 좌변 기울기의 부호가 반대이고
감는 방향도 반대인 것. 둘 다 위 표를 만족해야 한다.

## 6. 순서

1. A 를 세 군데에 적용 → 재측정 → 표의 가운데 열과 맞는지.
   **B 를 같이 하지 않는다.** 둘을 한 번에 하면 어느 쪽이 들었는지 모른다.
2. B 를 색에만 적용 → 재측정 → 오른쪽 열.
3. 알파·깊이는 각자 측정 계획을 세운 뒤(별건).

재부팅 없음 — 전부 유저랜드다.

## 7. 이 계획이 다루지 않는 것

- **깊이**: 뷰포트 Z 변환·깊이 양자화·`GL_ALWAYS` 쓰기·직접 읽기가 더 붙는다.
  이번 회차는 깊이를 **읽지도 고치지도** 않는다.
- **호출 지점 감사**: 다른 삼각형 변형·양면 색·안개·스페큘러·텍스처 좌표에
  같은 표현식이 또 있는지. 지금은 `OpenStepMGAMesaTriangle.c` 의 세 곳만
  안다.
- **Mesa 가 8 화소를 놓치는 것**(§M1_4A4 §9-3). 우리 결함이 아니다.
  기록만 하고 건드리지 않는다.

### 8-1. 기준을 다 지켰나

- **파랑이 안 움직였다** — 두 도형, 세 단계 모두 0.000. 정착도 절단도
  기울기가 상쇄되는 평면을 움직일 수 없고, 실제로 못 움직였다.
- **커버리지가 안 변했다** — 하드웨어가 규칙에 대해 704/704, 703/703 EXACT.
- **`left(row)` 기울기와 사다리꼴 절편 차이**가 계속 0 근처.
- 두 도형은 중간 정점이 긴 변의 **반대쪽**에 있다(좌변 기울기·분할 감는
  방향이 반대). 둘 다 같은 답.

### 8-2. 남은 것

- **깊이**: 손대지 않았다. 자기 측정이 필요하다(`GL_ALWAYS` + 깊이 직접
  읽기, 뷰포트 Z 변환, 16 비트 양자화).
- **Mesa 가 8 · 22 화소를 놓치는 것**: 우리 결함이 아니다. 기록만 한다.

  또 있는지는 아직 안 봤다.
