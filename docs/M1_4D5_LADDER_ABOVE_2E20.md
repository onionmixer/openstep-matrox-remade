# M1-4D5 — 편향 사다리는 2^20 위에서도 계속된다 (그리고 그게 그림을 망친다)

## 1. 헤더의 전제

`hw3d/OpenStepMGAHW3D.h` 의 `TEX_BIAS` 주석:

> 511 below 2^16, 510 below 2^17, 508 below 2^18, 504 below 2^19, 496 below 2^20
> … **Above 2^20 it stops mattering, because a coordinate past the last texel is
> clamped and no addend this small can change which texel that is.**

클램프에서는 참이다.  **repeat 에서는 아무것도 클램프되지 않는다** — 좌표는
감기고, 몇 단위 차이가 어느 텍셀로 감길지를 가른다.  그리고 양수 도달거리는
이미 텍스처 **8 장**이라 평범한 타일링이 지금도 그 대역에 좌표를 놓는다.

## 2. 실측 (§56)

2048 높이 텍스처(텍셀 512 단위)에서 각 대역의 경계를 이분법으로 찾았다.
계단이 나타나는 오프셋이 곧 순 편향의 반대 부호다.

```
   band 2^19  texel 1022 -> 1024 at offset  -8    net bias   +8
   band 2^20  texel 2046 -> 0    at offset  +0    net bias    0
   band 2^21  texel 2046 -> 2047 at offset +16    net bias  -16
   band 2^22  texel 2046 -> 2047 at offset +48    net bias  -48
   band 2^23  texel 2046 -> 2047 at offset +112   net bias -112
```

python 이 맞춘 모형: **`g = 2^(대역 − 16)`, 덧값 = 512 − g** — 2^20 아래에 대해
문서화된 것과 **같은 법칙이 그대로 이어진다.**

```
   2^16    1   511   net +15        2^20   16   496   net    0
   2^17    2   510   net +14        2^21   32   480   net  -16
   2^18    4   508   net +12        2^22   64   448   net  -48
   2^19    8   504   net  +8        2^23  128   384   net -112
```

측정된 다섯 대역 전부가 이 모형에 맞는다.

## 3. 왜 이게 결함인가

커널은 **평평한 496** 을 뺀다.  2^20 아래에서는 엔진이 496 이상을 더하므로 순
편향이 **음이 아니고**, "경계에 정확히 놓인 좌표는 정확하다"는 설계 불변식이
지켜진다.  2^20 위에서는 엔진이 496 **미만**을 더하므로 커널이 더 많이 빼고,
좌표가 caller 가 둔 자리보다 **아래로** 내려간다.  경계에 놓인 좌표는 아래
텍셀을 읽는다 — 헤더가 "첫 시도를 무너뜨린 실패"라고 적어둔 바로 그 형태다.

## 4. 기존 장면이 이걸 가리고 있었다

`tile`(s,t 0…3, TD=16)은 하드웨어와 소프트웨어가 **0 화소** 다르다.  결함이
없어서가 아니라 표본 격자가 경계를 피하기 때문이다 — python:

```
   화소 중심 표본의 텍셀 내 잔여: 4096 12288 20480 … 61440
   가장 가까운 경계까지 4096 단위.  필요한 이동은 48 -> 가려진다
```

## 5. 반증 가능한 예측, 그리고 실측 (`tilebnd`)

56 화소에 텍스처 7 장 = **화소당 정확히 2 텍셀**이면 화소 중심 표본이 모두
텍셀 경계에 **정확히** 앉는다.  python 예측:

> 첫 **8 열**(대역 ≤ 2^20, 순 편향 ≥ 0)은 일치하고, **나머지 48 열**은 한 텍셀
> 아래를 읽는다.

실측:

```
   # tilebnd: drawn 2 software 0 persp 0 unsupported 0 declined 0
   common 1792  differing 1534
   columns differing: 48..95        (48 of 56)
   columns that agree: 40 41 42 43 44 45 46 47
```

**예측과 정확히 일치한다.**  결함은 실재하고 화면에 보인다.

## 6. 왜 평평한 496 이었나 (그 논거는 여전히 유효하다)

헤더가 적어둔 대로, 대역마다 정확히 보정하면 **대역을 가로지르는** 프리미티브가
빼앗긴 것보다 적게 돌려받아 경계 좌표가 한 단위 아래로 떨어진다.  그래서 **가장
작은 덧값**을 빼기로 한 것이고, 그 선택은 옳다.  틀린 것은 "가장 작은 덧값이
496"이라는 **범위 가정**이다 — 도달거리가 2^23 이므로 실제 최솟값은 **384** 다.

## 7. 선택지

| | 무엇을 뺀다 | 순 편향 범위 | 대가 |
|---|---|---|---|
| **A** 지금 그대로 496 | 고정 | −112 … +15 | **음수 구간에서 경계가 깨진다 (측정됨)** |
| **B** 고정 384 | 고정 | 0 … +127 | 불변식 회복. 텍셀 끝 127 단위를 잘못 읽음 (크기 64 에서 0.0078 텍셀) |
| **C** 도달거리를 2^20 으로 제한 | 496 유지 | 0 … +15 | 타일링을 잃는다 |
| **D** 프리미티브의 최대 좌표로 대역을 골라 그 대역의 덧값을 뺀다 | 배치마다 | 0 … (대역 차) | 불변식 회복 + 한 대역에 머무는 프리미티브는 **정확**. 커널이 이미 좌표 범위를 계산한다 |

D 는 커널이 검증을 위해 이미 구하는 `hi` 를 재사용한다: 뺄 값 =
`512 − 2^(대역(hi) − 16)` = 그 프리미티브가 쓸 수 있는 **가장 작은 덧값**.
따라서 어느 화소에서도 순 편향이 음이 아니고, 대역을 안 가로지르면 0 이다.

## 8. 아직 확인 안 한 것

- 헤더가 말하는 "열이 관여하는 15 단위 미만의 미세 구조"가 높은 대역에서도
  같은 크기인지 — 지금 측정은 계단 위치만 봤다
- 대역 경계가 좌표의 **부호 있는** 크기로 정해지는지, 절댓값인지.  음수 쪽은
  −4096 까지만 열려 있어 2^16 대역 하나만 봤다
- 선형 필터에서 두 탭이 서로 다른 대역에 걸칠 때

## 9. 교차검토 1 라운드가 요구한 측정 (모두 실행)

### 9-1 대역이 화소의 것인가, 측정 도구의 것인가 (§57)

§56 은 전부 **기울기 0** 이라 "화소의 좌표로 고른 대역"과 "커널이 쓴 레지스터로
고른 대역"을 구별할 수 없었다.  같은 좌표(2096640, 경계 위)를 두 방법으로 도달:

```
   레지스터에 직접 넣고 읽음   2046
   0 에서 기울기로 올라가 읽음 2046      (레지스터는 2^19 대역에 있다)
```

**대역은 화소의 좌표를 따른다.**  §56 은 도구의 인공물이 아니다.

### 9-2 대역 꼭대기가 아니라 내부에서 (§58)

§56 은 각 구간의 `2^n − 512`, 즉 **꼭대기**만 쟀다.  25 / 35 / 50 / 75 % 지점을
같은 이분법으로 다시 쟀다:

```
   2^21   1310720 -16   1572864 -16   1835008 -16   1416704 -16
   2^22   2621440 -48   3145728 -48   3670016 -48   2833408 -48
   2^23   5242880 -112  6291456 -112  7340032 -112  5666816 -112
   2^20    655360  +0    786432  +0    917504  +0    708608  +0
```

덧값은 구간 **내부에서 일정**하다.

### 9-3 열 의존과 음 기울기 (§59)

헤더가 남긴 "열이 관여하는 15 단위 미만의 미세 구조"는 순 편향이 −16 인 대역에서
같은 크기라 무시할 수 없다.

```
   열 0..7, 같은 좌표:  2046 2046 2046 2046 2046 2046 2046 2046
   두 배 높이에서 음 기울기로 내려와 읽음: 2046
```

## 10. 설계 — 축마다, 배치마다, 실제로 닿는 가장 작은 덧값

```
   bias(축) = min(496, 덧값(그 축이 이 배치에서 닿는 최대 좌표))
```

- **`min(496, …)`** 이라 2^20 아래에 머무는 배치는 **오늘과 완전히 같다.**
  기존 기준값(24 / 257 / 24·24)을 건드리지 않으려는 것이다.
- 덧값은 좌표에 대해 **단조 비증가**이므로, 최대 좌표의 덧값은 그 배치에서
  엔진이 쓸 수 있는 **가장 작은** 덧값이다.  따라서 순 편향은 어느 화소에서도
  **음이 아니다** — 무너진 불변식이 회복된다.
- 텍스처 배치는 프리미티브를 **하나만** 담으므로(`nb = texOn ? n : 1`,
  `cnt = texOn ? 1 : n`) 배치 단위가 곧 프리미티브 단위다.
- `v` 는 프리미티브를 가로질러 누산되고 검증기가 이미 `texSpanY` 로 추적하므로,
  `v` 의 최대값은 그 누산을 포함해야 한다.

python 이 낸 결과:

```
   tilebnd  어긋나는 열  48 -> 0 of 56      순 편향 범위 0 … 126
   tile     경계까지 여유 4096, 최대 순 편향 63     -> 그대로 안전
```

**대가**: 각 텍셀의 마지막 `511 − bias` 단위가 위 텍셀로 읽힌다.  높이 닿는
배치일수록 커진다(최대 127 단위 = TD 16 에서 0.0019 텍셀, 2048 에서 0.248 텍셀).

## 11. 미측정 — 설계가 이것을 보수적으로 다뤄야 한다

- **원근**: 사다리가 몫(`s·65536/q`)에서 골라지는지 **분자**에서 골라지는지 모른다.
  → 둘 중 **큰 쪽**으로 대역을 고른다.  덧값이 단조 비증가이므로 큰 좌표를
  고르면 더 작은 덧값이 되어 순 편향은 어느 쪽이 참이든 음이 아니다.
- **정확히 2^20**: §56 은 `2^20 − 512` 를 쟀다.  정확히 2^20 의 덧값은 사다리에서
  **추론**한 것이지 측정이 아니다.  검증기의 상자 경로는 보수적이라 아핀 장면의
  최대 좌표가 정확히 2^20 으로 잡히고, 그러면 bias 가 480 이 되어 **기존 기준값이
  움직일 수 있다.**  구현 뒤 반드시 세 기준값을 다시 잰다.
- **u 축의 레인 미세 구조**: §59 는 `v` 로만 열 의존을 봤다.  `u` 는 짝·홀 열이
  다른 레인을 타므로 따로 봐야 한다.

## 12. 들어갔다 (재부팅 대기)

`bias(축) = min(496, 덧값(그 축의 최대 좌표))`, **원근이 아닐 때만**.

- `hw3d/OpenStepMGAHW3D.h` — `OSMGAHW3DTexReach`, `osmgaHW3DTexBiasFor()`,
  `osmgaHW3DValidateReach()`
- `hw3d/OpenStepMGAHW3D.c` — 기존 `osmgaHW3DValidate()` 는 **얇은 래퍼**로 남겼다.
  호출부가 13 곳이고 그중 11 곳은 도달범위가 필요 없다.  상자 네 모서리에서
  축별 최대를 모은다(상자는 실제 스팬보다 넓고, 넓은 쪽이 **안전한** 방향이다 —
  대역을 높게 잡으면 덜 빼게 되므로).
- 인코더 — `biasU` / `biasV` 를 따로 쓴다.

### 12-1 원근은 오늘 그대로 둔다

교차검토가 짚은 대로, 검증기는 분자를 `128·q` 까지 허용하므로 `q = 2^23` 에서
분자가 2^30 에 이른다.  사다리는 2^23 까지만 측정됐고 그 위 일곱 대역은 **모른다**.
"분자와 몫 중 큰 쪽"이라는 내 규칙은 그 미측정 구간으로 외삽하는 것이라 안전
증명이 되지 않는다.  그래서 `PERSP` 이면 496 — **오늘과 같다.**  원근에서의
결함은 남지만 회귀는 아니고, 미측정으로 명시해 둔다.

### 12-2 설치 전 확인

| 항목 | 결과 |
|---|---|
| 커널 빌드 | `BUILD_EXIT=0`, 경고 0 |
| `osmgaHW3DTexBiasFor` 12 개 값 | python 규칙과 전부 일치, 순 편향 하한 전부 0 이상 |
| 유저랜드 검증기 테스트 | 7 실패 — **HEAD 의 검증기로도 같은 7 건**. 오늘 회귀 없음 |
| 설치본 vs 빌드본 | `cmp` 일치 |

낡은 7 건은 앞선 변경(음수 허용, 기울기 상한 재작업)이 남긴 것이다.  별도로
정리해야 한다.

### 12-3 재부팅 뒤 확인할 것

1. `tilebnd` — 어긋나는 열 48 → **0** 이어야 한다
2. `tile`, `tile lin` — 0 / 257(전부 1 레벨) 그대로
3. 아핀 24 / 257 / 24·24 — 최대 좌표가 정확히 2^20 이라 bias 496, **불변**이어야
4. `perspfar` — `drawn 2 software 0`, 열 프로파일 그대로 (원근은 안 건드렸다)
5. 탐침 §51…§62 — 전부 그대로
6. **이음매**: 한 삼각형만 높은 대역에 닿는 사각형.  두 삼각형의 bias 가 달라
   위상이 최대 127 단위 어긋난다.  교차검토가 "실기에서 가장 먼저 깨질 곳"으로
   지목한 자리다 — 재부팅 뒤 장면을 만들어 잰다.
