# M1-4d2 — `s = 0` 모서리가 원근에서 폴백을 만든다 (계획, 2026-08-23)

**코드는 안 건드렸다.** 이 문서가 교차검토 대상이다.

## 1. 증상과 원인 (측정됨)

깊은 원근 사각형(`z` −1.5 … −24)의 두 삼각형 중 **하나가 소프트웨어로**
떨어진다.  계수기를 찍으니 `unsupported 0, declined 1, verdict 13`
(`E_TEXCOORD`) — **빌더는 통과시키고 커널이 거절**한다.

원인을 가르는 실험: 텍스처 좌표를 **0.02 만큼 안으로** 넣으면 폴백이 사라진다
(`drawn 2, declined 0`).  즉 문제는 **좌표가 정확히 0 인 모서리**다.

기전: 빌더가 평면의 시작과 두 기울기를 **정수로 반올림**해 보내고, 검증기는
행마다 그 정수들로 좌표를 다시 만든다.  참값이 0 인 변을 따라가면 반올림
오차가 쌓여 **0 보다 한두 단위 아래**로 내려가고, 검사는 `p < 0` 을 거절한다.

표류 상한은 `0.5 + 0.5·폭 + 0.5·높이` 분자단위이고, python 으로 재면:

```
   320×240 삼각형: 280.5 단위 -> q=Q_MIN 에서 0.137 텍셀, q=2^20 에서 0.001 텍셀
```

## 2. 왜 그냥 두면 안 되나

`s = 0` 은 예외적인 값이 아니라 **텍스처를 붙인 사각형이면 거의 항상** 있는
값이다.  원근에서 이것이 폴백을 만들면 "원근이 가속된다"가 반쪽이 된다.

## 3. 선택지

| 안 | 내용 | 값 / 걱정 |
|---|---|---|
| (a) | 빌더가 시작에 **표류만큼 여유**를 더한다 | 커널 불필요. 그러나 **모든** 삼각형을 조금씩 민다(아핀 포함), 그리고 기존 측정치가 바뀐다 |
| (b) | 빌더가 **필요할 때만** 민다 (참 최소가 표류보다 작을 때) | (a) 보다 낫다. 여전히 대증요법 |
| (c) | 커널이 **살짝 음수인 좌표를 거절하지 않는다** | 원인 자리에서 고친다. 주소는 클램프/마스크가 붙잡고(측정됨, 8 스팬), 소프트웨어도 GL 규칙대로 클램프한다 |
| (d) | 빌더가 기울기를 **바깥으로 반올림**해 참값 아래로 못 가게 한다 | 기울기가 양·음 섞이면 방향이 하나로 안 잡힌다 |

**(c) 가 원인 자리이지만 재본 적 없는 영역이다.**  §29 는 음수 좌표가
**거절된다**는 것만 보였고, 엔진이 음수에서 무엇을 하는지는 모른다.  §41 이
클램프가 주소를 붙잡는 것을 **+8 스팬까지** 재긴 했으나 음수 쪽은 아니다.

## 4. 그래서 순서

1. 커널이 좌표를 **한 텍셀만큼 음수까지** 허용하게 한다 — 그 이상은 아니다.
   이것 자체가 측정을 위한 최소 변경이고 재부팅이 든다.
2. 탐침으로 음수 좌표에서 **어느 텍셀이 표본되는지** 잰다.  클램프면 텍셀 0,
   repeat 이면 감긴 텍셀이어야 한다.
3. 클램프가 확인되면 (c) 로 확정하고 폴백이 사라지는지 끝단에서 본다.
   확인이 안 되면 **되돌리고** (b) 로 간다.

한 텍셀로 제한하는 이유: 표류 상한이 최악 0.14 텍셀이므로 **한 텍셀이면
충분히 넉넉**하고, 그보다 넓히면 아무도 안 본 영역을 그만큼 더 여는 것이다.

## 5. 검토에 묻고 싶은 것

1. (c) 가 (b) 보다 낫다는 판단이 맞는가?  대증요법이라는 이유만으로 (b) 를
   낮춰 보는 것은 아닌가?
2. 음수 허용폭을 한 텍셀로 잡는 근거가 타당한가?
3. `repeat` 일 때 음수 좌표는 감기므로 **다른 텍셀**을 준다.  소프트웨어도
   그러니 맞지만, 이것이 (c) 를 위험하게 만드는가?
4. 내가 못 본 선택지가 있는가?

## 6. 원인을 좁혔다 — 그리고 내 첫 고침은 자리를 못 맞췄다 (2026-08-23)

### 6-1 조합 행렬이 찾아냈다

원근 × (선형, MODULATE, REPEAT, 더 깊은 원근) 을 재니 앞 셋은 깨끗하고
**깊은 원근(16:1)에서만** 한 삼각형이 폴백한다.

| 조합 | 결과 |
|---|---|
| 원근 + 선형 | 799 / 14150 다름, **최대차 1** (이미 아는 가중치 반올림) |
| 원근 + MODULATE | 6 / 14150, 최대차 16 |
| 원근 + REPEAT | 6 / 14150, 최대차 16 — **이음매 없음** |
| 원근 16:1 | **삼각형 하나 폴백**, `declined 1, verdict 13` |

교차검토가 "repeat 에서 0 모서리가 반대편으로 감겨 이음매가 난다"고 우려했으나
이 깊이에서는 **나타나지 않았다**.

### 6-2 빌더가 실제로 내보낸 값

계기를 넣어 찍었다(`OSMGA_TMR_DUMP`):

```
   y=35 h=90 x 54..266   u 9992 39321 -43371   q 519777 0 -5421
   y=36 h=89 x 55..56    u 11004 74015 -81637  q 968366 0 -10207
```

두 번째가 **폭 1 화소의 슬라이버**다(89 행).  그래서 커널의 dx 기울기 검사는
`ex = 0` 이라 **건너뛴다**.  `u` 는 변을 따라 참값이 0 근처인데, 걷기가
`u = 시작 + dx기울기·(lx−lx0) + dy기울기·행` 으로 정수에서 되만들므로,
97 열 × 88 행에 걸쳐 반올림이 쌓여 **0 아래로 내려간다**.

### 6-3 내 첫 고침은 효과가 없었다 — 되돌렸다

빌더가 시작에 여유를 더하게 했는데, 여유를 **삼각형 경계상자**로 계산해서
이 슬라이버의 실제 누적(≈93 단위)을 덮긴 하나 폴백이 그대로였다.  즉 원인이
그것만은 아니거나, 참값 자체가 스팬 시작에서 음수일 수 있다(변 걷기의 채움
규칙이 참 변보다 한 화소 바깥을 잡는 경우).

**효과 없는 변경은 남기지 않는다** — 되돌렸고, 원근 4:1 장면이 6 화소로
그대로임을 확인했다.  계기는 환경변수 뒤에 남겨 뒀다.

### 6-4 지금 아는 것과 모르는 것

|---|---|
| 안다 | 깊은 원근에서 **폭 1 슬라이버 사다리꼴**이 생기고, 그것의 `u` 재구성이 음수로 내려가 `E_TEXCOORD` 로 거절된다 |
