# §3-12 후속 — 보간 평면은 어디에 걸려 있나 (계획, 2026-08-21)

앞선 회차(`M1_4A3_RASTER_RULE_PLAN.md` §12)가 커버리지를 규칙에 맞췄다.
그 회차의 **교차검토가 남긴 구멍**이 이것이다:

> 이 도형들은 전부 `GL_FLAT` 이라 기울기가 0 이고, 평면 정착이 어긋나도
> **보이지 않는다.** 그리고 이번 재작성에서 **시작 열이 움직였다.**

## 1. 무엇을 의심하나 — 코드가 이미 말한다

색·알파·깊이의 시작값은 사다리꼴의 `(left, y)` 에서 계산된다:

```c
double ox = (double)left - (double)a->x;
double oy = (double)y    - (double)a->y;
t->dr[i*3+0] = osmgaStartFixed(p->at_a + p->dx * ox + p->dy * oy);
```

`left` 와 `y` 는 **정수**다. 즉 화소의 **왼쪽 위 모서리**에서 평면을
읽는다 — 커버리지에서 방금 고친 것과 **같은 반 화소 문제**다.

## 2. Mesa 는 무엇을 하나 — 원본에서 확인함 (추측 아님)

`tritemp.h` 는 좌표를 옮겨 놓고 계산한다:

```c
vMin_fx = FloatToFixed(Win.x + 0.5F);
vMin_fy = FloatToFixed(Win.y - 0.5F);
fsy     = FixedCeil(vMin_fy);
adjy    = fsy - vMin_fy;
adjx    = fx  - fx0;                    /* fx0 = vMin_fx */
fr      = IntToFixed(colour[vLower]) + drdx*adjx + drdy*adjy;
```

풀면 평가점은 창 좌표로 `(ix + 0.5, iy + 0.5)` — **화소 중심**이다.
주석도 그렇게 말한다: *"creeping a sub-pixel amount into the triangle at
each scanline."*

**그러므로 예측은 구체적이다**: 우리 속성값은 소프트웨어보다 평면의
`(dx + dy)/2` 만큼 어긋나 있어야 한다 — 삼각형 전체에 걸친 **상수 편차**이지
화소마다 다른 오차가 아니다.

## 3. 재는 법 — 허용오차 비교를 하지 않는다

"소프트웨어와 ±2 안에 들면 통과" 같은 기준은 **정착 오류를 숨긴다.**
대신 **측정값에서 평면을 되맞춰(fit) 그 평가점을 읽는다.**

1. 강한 비대칭 기울기를 준 Gouraud 삼각형을 그린다(중간 정점에서 **분할되는**
   것). 빨강은 x 로, 초록은 y 로, 파랑은 둘 다로 변하게 한다.
2. 두 경로에서 **화소값을 그대로 찍는다**(행마다 런의 첫·중간·끝 화소).
3. python 이 정점에서 **정확한 평면**을 세운다(Fraction). 그리고 각 경로에
   대해 잔차를 둘 다 낸다:
   - `측정 − 평면(x, y)` (모서리에서 표본)
   - `측정 − 평면(x+0.5, y+0.5)` (중심에서 표본)
   **어느 쪽이 0 인지가 답이다.**
4. 평면성도 본다: 잔차가 상수가 아니라 행마다 **흘러가면** 그건 정착이 아니라
   변 걷기와의 상호작용이고, 다른 결함이다.
5. **분할 행을 따로 본다.** 사다리꼴이 둘이면 시작값도 둘이다. 그 경계에서
   불연속이 있으면 두 시작값이 서로 다른 곳에 걸린 것이다.

## 4. 양자화를 어떻게 다루나

엔진은 15 비트 고정소수점에서 8 비트를 낸다. 그래서 잔차는 정확히 0 이
아니라 **한 단계 안**일 수 있다. 그것을 허용오차로 쓰지 않기 위해:

- 기울기를 **크게** 준다. 40 열에 걸쳐 0→255 면 화소당 6.4 단계이고,
  반 화소 편차는 **3.2 단계**다 — 반올림 잡음(±0.5)과 헷갈릴 수 없다.
- 그리고 잔차의 **평균**을 본다. 상수 편차는 평균에 그대로 남고 반올림은
  씻겨 나간다.

## 5. 성공/실패 기준 (숫자를 미리 적는다)

- **소프트웨어**: 중심 잔차의 평균이 **|0.5| 미만**이어야 한다. 아니면 Mesa
  에 대한 내 독해가 틀린 것이고, 그때는 고칠 것이 무엇인지부터 다시 본다.
- **하드웨어(지금)**: 모서리 잔차의 평균이 0 근처, 중심 잔차의 평균이
  `(dx+dy)/2` 근처 — 그러면 §1 의 의심이 확인된다.
- **결함으로 볼 것**: 잔차가 상수가 아님(행마다 흐름), 분할 행에서 불연속,
  또는 두 예측 어느 쪽도 안 맞음.

## 6. 고치는 법 (측정 뒤에, 별도로)

맞다면 한 줄이다 — 시작값을 `(left + 0.5, y + 0.5)` 에서 읽는다:

```c
t->dr[i*3+0] = osmgaStartFixed(p->at_a + p->dx * (ox + 0.5)
                                       + p->dy * (oy + 0.5));
```

**그러나 이번 회차에는 고치지 않는다.** 지난 두 번 다 "모델이 맞다고
생각한 것"에서 틀렸다. 먼저 재고, 무엇이 걸려 있는지 확정한 다음에 고친다.

## 7. 순서

1. 시험을 쓰고, **지금 코드로 어긋나는 것을 확인**한다.
2. 색이 확정되면 알파, 그다음 깊이. **한 번에 하나씩.**
3. 재부팅 없음 — 이건 전부 유저랜드다.

## 8. 이 회차가 확인하지 못하는 것 (미리 적는다)

- 텍스처 좌표. 아직 그 경로가 없다.
- 디더링. `GL_DITHER` 는 끈다.
- 과다그리기. 같은 색 커버리지가 중복 쓰기를 숨기듯, 평면 비교도 숨긴다.
