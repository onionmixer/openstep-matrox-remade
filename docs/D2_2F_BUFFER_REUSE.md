# D2-2f — 버퍼 재사용 (2026-08-28, 코딩 전)

D2-2e 는 배치 두 개를 **서로 다른 오프셋**에 두어 재사용 질문을 피했다.
생산은 그럴 수 없다. 질문은 하나다.

## 1. 정점 버퍼는 언제 덮어써도 되는가

후보 둘:

| | 판정 | 비용 |
| --- | --- | --- |
| **(a)** `DWGSYNC` 펜스 뒤 — **그리기**가 끝났다 | 안전 | 배치마다 펜스. 비싸다 |
| **(b)** `(PRIMADDRESS & ~3) == end` — 카드가 **다 읽었다** | ? | 이미 하고 있는 검사. 공짜 |

**(b)라고 본다.** 근거 둘:

- 3-164: `primaddress` 는 *"시스템 메모리의 primaddress 에서 읽기 접근을 종료할
  때마다"* 증가한다. 끝에 도달했다는 것은 **모든 dword 가 칩 안으로 들어갔다**는 뜻이고,
  그 뒤 호스트 메모리를 바꾸는 것은 비행 중인 그리기에 닿을 수 없다.
- **DRM 이 자기 1 차 링에 정확히 그 규칙을 쓴다.** `mga_dma.c:151`·`:190`:
  `primary->space = head - tail`, `head = MGA_READ(MGA_PRIMADDRESS)`.
  **카드가 읽고 지나간 만큼이 곧 덮어써도 되는 공간이다.** 펜스도, 그리기 완료
  확인도 없다.

**(a)와 (b)는 서로 다른 질문에 답한다** — (b)는 *읽기* 완료, (a)는 *그리기* 완료.
결과를 **읽으려면** (a)가 필요하고, 버퍼를 **재사용하려면** (b)면 된다.
D2-2e 는 둘을 구별하지 않았다.

## 2. 위험 하나는 읽기로 제거했다

4.1.6 의 `Direct Access Read Cache` 는 **CPU 의 프레임버퍼 직접 읽기** 전용이다
(*"Direct read accesses to the frame buffer ... are cached by one eight-dword
cache entry"*). 시스템 메모리를 bus-master 로 읽는 경로와 무관하다.
**정점 버퍼가 칩에 캐시될 걱정은 없다.**

## 3. 설계 — R1 이 R2 를 gate 한다

**한 버퍼**(오프셋 하나)만 쓴다. 매번 그 자리를 다시 채우고 다시 제출한다.

```
R1  대조군 — 펜스를 끼고 재사용
    tri0 채움 -> 제출 -> 펜스 -> 검증(1)
    tri1 채움 -> 제출 -> 펜스 -> 검증(2)
    이게 깨지면 재사용 자체가 문제고 R2 는 의미가 없다.

R2  본 질문 — 포인터만 보고 재사용
    tri2 채움 -> 제출 -> 포인터만
    tri3 채움 -> 제출 -> 포인터만          <- 펜스 없음
    tri4 채움 -> 제출 -> 포인터만
    마지막에 펜스 한 번 -> 검증(5)
```

삼각형 표·기하는 D2-2e 것을 그대로 쓴다(이미 실기 검증됨). R2 는 중간 검증을
할 수 없으므로 — 그리기가 안 끝났으니 — **삼각형별 tally 가 어느 것이 빠졌는지 말한다.**

## 4. 같은 주소를 반복해서 쓰는 데서 오는 함정

D2-2e 는 **끝 주소가 서로 달라야 한다**는 불변식을 넣었다. 낡은 `PRIMADDRESS` 가
다음 배치의 완료로 오독되는 것을 막기 위해서다. **재사용은 그 불변식을 정면으로
깬다** — 세 번 다 `X`에서 `X+96`이다.

그래서 제출 절차를 바꾼다:

```
PRIMADDRESS = X | 0x3
PRIMADDRESS 를 되읽어 (값 & ~3) == X 임을 확인      <- 새로 넣는 단계
PRIMEND = X + 96
폴링
```

되읽기가 성공하면 그 시점의 포인터는 **확실히 이번 제출의 것**이고, 뒤이어
`X+96` 을 보는 것은 낡은 값일 수 없다. 읽기 한 번 값이다.

## 5. 무엇이 무엇을 뜻하는가

| 관측 | 결론 |
| --- | --- |
| R1 2 개, R2 3 개 전부 | **(b)가 맞다.** 생산은 배치마다 펜스를 칠 필요가 없다 |
| R1 실패 | 재사용 자체가 문제. (b) 이전에 (a)도 못 쓴다 — 원인을 따로 찾아야 |
| R1 통과, R2 에서 **뒤쪽 삼각형만** 남음 | 포인터가 이른 판정이다. 앞 데이터를 덮어썼다 → (a) 필요 |
| R2 에서 **모양이 섞임** | 같은 이유. tally 가 어느 지점인지 말한다 |
| 클립 밖 픽셀 | 봉쇄 실패 — 즉시 중단 |

## 6. 범위 밖 — 그리고 다음 차례

**`PRIMEND` 연장.** 4-15 이 명시한다: *"PRIMEND 를 쓸 때는 pseudo-DMA 시퀀스가
리셋되지 않는다 ... **전송 중에도** 목록을 늘리기 위해 여러 번 쓸 수 있다."*
이것이 DRM 이 실제로 쓰는 기법이고, `PRIMADDRESS` 재기록조차 없앤다.
**그러나 다른 메커니즘이다** — 재사용이 아니라 추가다. 한 번에 한 변수이므로
D2-2g 로 미룬다. 그리고 R2 가 통과해야 그쪽이 의미가 있다.

배치 사이 상태 변경, 인터럽트 완료, Mesa 연결도 그대로 미룬다.

## 7. 위험

D2-2e 와 같은 수준이다. 새 레지스터 없음, 새 모드 없음, 새 수송 없음.
**실패의 관측 형태는 "그림이 틀림" 이지 hang 이 아니다** — 호스트 메모리를
덮어써도 카드는 이미 읽은 데이터로 그린다. 실패 정책은 그대로 두 갈래:
펜스/전송 타임아웃이면 보유 + 재부팅, 그림만 틀리면 엔진 반납.

## 8. codex 에 물을 것

1. (b)가 맞나. 3-164 와 DRM 의 링 회계 말고 **반증**할 근거가 있나.
2. `PRIMADDRESS` 되읽기(§4)가 낡은 포인터 문제를 실제로 막나. 더 나은 방법이 있나.
3. **그리기가 진행 중일 때 `PRIMADDRESS` 를 다시 쓰는 것**이 허용되나.
   DRM 은 링을 쓰므로 중간에 `PRIMADDRESS` 를 재기록하지 않는다 — 선례가 없다.
4. R1 을 대조군으로 두는 것이 맞나, 아니면 R2 만으로 충분한가.
5. 같은 주소를 연속 제출할 때 `ENDPRDMASTS` 가 애매해지는 경로가 있나.
6. 빠진 것.
