# 깊이 시작값의 클램프 (계획, 2026-08-21)

`M1_4A7` §10-3 에서 남긴 것. 좌표·색·알파·깊이 정착이 끝난 지금 가장 큰
결함이다.

## 1. 무엇이 문제인가 (측정)

깊이 시작값은 `[0, 65535]` 로 잘린 뒤 `1<<15` 로 스케일된다. 사다리꼴의
시작 화소는 **덮이지 않은 화소일 수 있다** — 첫 행이 빈 행이면 그렇다 —
그리고 거기서 평면값이 범위를 벗어난다.

```
   도형 4 : 중심 시작값 65540.5 -> 65535 로 잘림.  측정된 잔차 -5.502 코드
   도형 3 : (수정 전) 67461.8 -> 65535.  그 화소가 65535 가 되어
            GL_LESS 가 거절 -> 규칙 676 중 675 만 그려짐
```

**값이 조금 틀리는 것이 아니다.** `z0` 는 사다리꼴마다 한 번 계산되고 엔진이
`z0 + i·zdx + j·zdy` 를 걷으므로 **그 사다리꼴의 모든 화소가 통째로**
어긋나고, `GL_LESS` 아래에서는 **화소가 사라진다.**

빈도: 무작위 삼각형에서 사다리꼴 **236940 개 중 475 개**(0.2%), 화소로는
58502 개. 둘 다 sliver 가 아니다 — 도형 4 는 2×면적 23090 에 11546 화소다.

## 2. 클램프를 넓힐 수 없다 (확인함)

```
   65535 * 32768 = 2147450880      2^31 = 2147483648
```

지금 인코딩이 **이미 32 비트를 거의 다 쓴다.** 65536 은 넘친다.
`osmgaFixed` 의 15 비트 시프트는 D3-2 에서 측정된 값이라 바꿀 것이 아니다.

## 3. 그러면 무엇을 하나 — **거절하고 소프트웨어로 보낸다**

시작값이 잘려야 하는 삼각형은 `OSMGA_MESA_TRI_UNSUPPORTED` 로 돌려보낸다.
그 기구는 이미 있고(`M1_4A1`), 훅이 소프트웨어로 다시 그린다.

- **맞다**: 잘린 값으로 사다리꼴 전체를 틀리게 그리는 것보다 낫다.
- **비싸다**: 사다리꼴의 0.2% 가 가속을 잃는다.
- **보수적이다**: 시작 화소가 **안 덮인** 경우에도 거절한다. 그려지는 화소는
  전부 정점 깊이 범위 안이라 사실 멀쩡한데도. 그래도 엔진의 보간 원점을
  옮길 수 없으므로 달리 방법이 없다.

### 3-1. 왜 원점을 못 옮기나

엔진은 `(left, y0)` 에서 시작해 증분을 더한다. 다른 곳에 정착시키려면
`z0` 를 그 자리 값에서 역산해야 하는데, 그 값이 곧 지금 잘리는 값이다.
사다리꼴을 쪼개 첫 행을 바꾸는 방법도 있지만, 그건 이 회차보다 크다.

## 4. 성공/실패 기준 (숫자를 미리 적는다)

- **도형 4**: 지금 잔차 −5.502 → **가속이 거절되고 소프트웨어가 그린다**.
  즉 `declined` 가 오르고, 깊이는 소프트웨어와 **정확히** 같아진다.
- **도형 1·2·3**: 거절되지 않아야 한다. `declined = 0` 유지, 잔차 그대로
  (−0.504, −0.518, −0.525).
- **커버리지**: 도형 3 이 규칙과 676 = 676 유지.
- **빈도**: 무작위 소수 삼각형에서 거절률을 재고 기록한다. 0.2% 근처여야
  한다. 크게 다르면 판정이 틀린 것이다.
- **거절은 조용하면 안 된다**: 훅의 카운터로 세어 보고한다.

## 5. 판정을 어디에 두나

`osmgaTrapezoid` 는 값을 돌려줄 수 없다(void). **빌더가 미리 본다**:
사다리꼴을 만들기 전에 각 사다리꼴의 시작 깊이를 계산해 범위를 벗어나면
`OSMGA_MESA_TRI_UNSUPPORTED` 를 돌린다. 깊이가 꺼져 있으면(`zmode == NONE`)
판정하지 않는다 — 그때는 `z0` 를 쓰지 않는다.

## 6. 안 하는 것

- **Z3**(출력 절단 −0.5 코드)과 **정점 z 의 소수부**. 별건이고 훨씬 작다.
- 사다리꼴을 쪼개 원점을 옮기는 것. 이 회차보다 크다.
