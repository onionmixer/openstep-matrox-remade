# 깊이 시작값의 클램프 (계획, 2026-08-21)

`M1_4A7` §10-3 에서 남긴 것. 좌표·색·알파·깊이 정착이 끝난 지금 가장 큰
결함이다.

## 1. 무엇이 문제인가 (측정)

깊이 시작값은 `[0, 65535]` 로 잘린 뒤 `1<<15` 로 스케일된다. 사다리꼴의
시작 화소는 **덮이지 않은 화소일 수 있다** — 첫 행이 빈 행이면 그렇다 —
그리고 거기서 평면값이 범위를 벗어난다.

```
   도형 4 : 중심 시작값 65540.5 -> 65535 로 잘림.  측정된 잔차 -5.502 코드
   도형 3 : (수정 전) 67461.8 -> 65535.  그 화소가 65535 가 되어
            GL_LESS 가 거절 -> 규칙 676 중 675 만 그려짐
```

**값이 조금 틀리는 것이 아니다.** `z0` 는 사다리꼴마다 한 번 계산되고 엔진이
`z0 + i·zdx + j·zdy` 를 걷으므로 **그 사다리꼴의 모든 화소가 통째로**
어긋나고, `GL_LESS` 아래에서는 **화소가 사라진다.**

빈도: 무작위 삼각형에서 사다리꼴 **236940 개 중 475 개**(0.2%), 화소로는
58502 개. 둘 다 sliver 가 아니다 — 도형 4 는 2×면적 23090 에 11546 화소다.

## 2. 클램프를 넓힐 수 없다 (확인함)

```
   65535 * 32768 = 2147450880      2^31 = 2147483648
```

지금 인코딩이 **이미 32 비트를 거의 다 쓴다.** 65536 은 넘친다.
`osmgaFixed` 의 15 비트 시프트는 D3-2 에서 측정된 값이라 바꿀 것이 아니다.

## 3. 처음 쓴 답 — 거절 — 은 **두 번째로 좋은 것이었다**

"시작값이 잘려야 하는 삼각형은 소프트웨어로 보낸다" 고 적었다. 맞지만
비싸고, **더 나은 것이 있다.**

시작 화소가 범위를 벗어나는 이유는 그것이 **덮이지 않은 화소**이기 때문이다
— 사다리꼴의 첫 행이 빈 행일 때 그렇다. 그런데 **빈 행은 아무것도 그리지
않는다.** 그러니 사다리꼴을 **첫 번째로 비지 않은 행에서 시작**하면:

- 시작 화소가 **덮인 화소**가 되고, 그 중심은 삼각형 안이므로 평면값이
  정점 깊이 범위 안이다 → **클램프가 걸릴 수 없다.**
- 그려지는 그림은 **한 화소도 변하지 않는다.**
- 거절이 **하나도 없다.**

재 봤다. 무작위 삼각형에서 사다리꼴 **118418 개**:

```
   지금 (0 행의 경계에서 정착)      클램프 359  (0.303%)
   앞쪽 빈 행을 건너뛰면            클램프   0  (0.000%)
   건너뛴 빈 행 합계 40456 (사다리꼴당 0.34)
```

**0 이다.** 교차검토도 같은 것을 짚었다 — 다만 "행이 하드웨어의 변 규칙
아래에서도 정말 비었는지" 확인해야 한다고 했고, 맞다. 우리는 그 걷기를
화소 단위로 실기와 맞춰 검증해 뒀으므로 **정확히 계산할 수 있다.**

### 3-1. 거절은 남긴다 — 다만 뒷문으로

건너뛰고도 벗어나는 경우가 남으면(측정으로는 0 이지만) 그때는 거절한다.
**0 인 것을 재고 나서 안전망으로 두는 것**과, 0.2% 를 거절하는 것을 답으로
삼는 것은 다르다.

### 3-2. 다른 후보들 — 왜 안 되나

- **`z0` 를 치우고 증분으로 보정**: 안 된다. 덮인 표본 셋이 평면을 유일하게
  정한다(교차검토). 1 차원으로 퇴화한 경우에만 성립한다.
- **클램프를 65535.99997 까지 넓히기**: 표현 범위는 `INT32_MAX/32768` 까지
  이므로 지금 클램프가 **조금 이르다**(교차검토 지적, 맞다). 그러나 문제의
  값은 65540.5 라 이걸로는 안 고쳐진다. 별건으로 적어 둔다.

## 4. 성공/실패 기준 (숫자를 미리 적는다)

- **도형 4**: 잔차 −5.502 → **0 근처**(다른 도형과 같은 −0.5 언저리).
  **거절되지 않아야 한다** — `declined` 는 0 그대로.
- **도형 1·2·3**: 아무것도 변하지 않아야 한다. 잔차 −0.504, −0.518, −0.525.
- **커버리지가 한 화소도 변하지 않아야 한다.** 빈 행을 자르는 것이므로
  그려지는 것은 같아야 한다 — 7 도형 스윕이 「nothing to report」.
- **클램프 발동 횟수**: 계기를 달아 **0 임을 확인**한다. 논증이 아니라 계수.
- **거절률**: 0 이어야 한다. 0 이 아니면 §3-1 의 뒷문이 열린 것이고, 그
  경우를 따로 본다.

교차검토가 짚은 것들 중 이번 회차가 **안 다루는** 것: 소프트웨어 되돌림의
실제 비용(이번엔 되돌림이 없으므로 해당 없음), 하드웨어와 소프트웨어가
**이웃한 변에서** 어긋나는지(별건, 그러나 실제 위험), 덮인 화소가 정당하게
범위를 벗어나는 경우(`glDepthRange`·depth clamp 경로가 없으므로 지금은
발생하지 않지만, 생기면 **원점만 자르는 것은 어차피 틀렸다** — 포화는
비선형이다).

## 5. 판정을 어디에 두나

`osmgaTrapezoid` 는 값을 돌려줄 수 없다(void). **빌더가 미리 본다**:
사다리꼴을 만들기 전에 각 사다리꼴의 시작 깊이를 계산해 범위를 벗어나면
`OSMGA_MESA_TRI_UNSUPPORTED` 를 돌린다. 깊이가 꺼져 있으면(`zmode == NONE`)
판정하지 않는다 — 그때는 `z0` 를 쓰지 않는다.

## 6. 안 하는 것

- **Z3**(출력 절단 −0.5 코드)과 **정점 z 의 소수부**. 별건이고 훨씬 작다.
- 사다리꼴을 쪼개 원점을 옮기는 것. 이 회차보다 크다.
