# M9 — WARP 층을 켠다 (2026-08-29, 코딩 전)

## 0. 자격검증이 푼 것

```
T7 / T7e   repeat 가 축마다 감긴다, 이음매도            -> 정책에서 repeat 허용
T8a / T8b  선택자가 고르고, 블렌딩이 계산과 일치        -> 정책에서 블렌딩 허용
T9         런 사이 펜스 불필요 (busy 1, leak 0 0)      -> 제출 루프에서 왕복 제거
```

**WARP 자격검증은 끝났다.**  남은 것은 그것을 쓰는 코드다.

## 1. 저장소가 이미 답해 놓은 것 — 훅의 누적·재생 계약

계획을 쓰기 전에 `mesa/OpenStepMGAMesaHook.c` 를 **질문으로** 읽었다.
사다리꼴 경로는 **이미 배치 누적을 한다**(`:540` 이하), 그리고 그 주석이
내가 새로 설계하려던 것을 전부 담고 있다:

| 이미 있는 것 | 내용 |
|---|---|
| **누적 상태** | `pendTraps`, `pendSrcCount` |
| **무엇이 배치를 공유하나** | `dwgctl`·`alphactrl` 은 사다리꼴마다라 자유롭게 섞인다.  **텍스처 블록과 scissor 가 플러시 키**다 |
| **재생 계약** | 거절된 배치는 아무것도 안 그렸으므로 **누적된 소스 삼각형 전부를 소프트웨어로 재생**한다 |
| **게이트 셋** | 렌더 브래킷을 넘지 않는다 / 클립하는 VB 는 배치하지 않는다(임시 정점을 나중 클립이 덮어쓴다) / multipass 는 배치하지 않는다 |
| **문맥 네 값** | 폴리곤 오프셋·`ColorPtr`·`IndexPtr`·`Specular` 를 삼각형마다 들고 다닌다.  **없으면 재생이 오프셋을 잃는다 — 실측: 깊이 16384 대 소프트웨어 17408** |
| **재진입 가드** | 플러시가 제출 전에 카운트를 떼어 놓는다 |

**그러므로 WARP 는 새 누적 설계가 필요 없다.**  같은 기계에 들어가고,
**다른 점은 하나뿐**이다:

> 사다리꼴은 `dwgctl`·`alphactrl` 이 프리미티브마다다.
> **WARP 는 그럴 수 없다** — 한 제출은 상태를 공유한다.
> 그래서 그 둘은 **런을 자르는 키**가 된다(v10 계약이 이미 그렇게 돼 있다).

이것이 열아홉 번째다.  그리고 이번 것은 큰 편이다 — 재생 계약은 실측으로
값을 치른 물건이다.

### 1.1 그리고 WARP 는 플러시 키 하나를 **없앤다**

주석이 아니라 코드를 읽었다(`Hook.c:1838` 이하).  지금 플러시를 부르는 키는
셋이다:

```
1  pendCtx != ctx  또는  pendVB != VB
2  배치가 가득 참
3  텍스처 블록이 다름 -- org, texW/H, pitch, flags,
   그리고 ** tmr[0..5] -- 텍스처 기울기 여섯 **
```

**3 번의 `tmr` 이 결정적이다.**  그것은 배치 상태인데 **삼각형마다 다른
기하**다.  그래서 사다리꼴 경로에서 텍스처가 있는 장면은 **삼각형마다
플러시**한다 — 배치가 사실상 하나짜리가 된다.

**WARP 에는 `tmr` 이 없다.**  기울기를 마이크로코드가 정점에서 직접
계산하므로 배치 상태가 아니다.  그러므로 WARP 의 플러시 키는

```
1  컨텍스트/VB
2  가득 참
3  텍스처 블록에서 ** 기울기를 뺀 것 ** (org, 크기, pitch, flags)
```

이고, `dwgctl`·`alphactrl` 은 플러시가 아니라 **런을 자른다**.

→ **텍스처가 있는 장면에서 WARP 배치는 사다리꼴 배치보다 훨씬 길어진다.**
이것은 셋업 비용 논거와 별개의, 그리고 아마 더 큰 이득이다.  W2 의 착수
판정은 셋업 시간만 셌다.

## 2. 정책 함수 (T7·T8 반영)

```c
osmgaHW3DWarpAdmits()
    repeat 거절     -> 지운다        T7  phasefail 1 1 1 (경계 위상 하나뿐)
    블렌딩 거절     -> 지운다        T8b wrong 0
    비정사각형 텍스처 거절 -> 남긴다  빌더가 아직 정사각형을 가정한다 (§4)
```

## 3. 제출 루프 (T9 반영)

M6 §11.1 의 순서에서 **런 사이 펜스를 뺀다**:

```
런마다:  GENERAL 목록 -> 포인터·SOFTRAPEN·ENDPRDMASTS -> ICLEAR
         VERTEX 제출  -> 포인터
배치 끝: DWGSYNC 펜스 -> WIADDR2=SUSPEND -> WBUSY·WBUSY1·DWGENGSTS
```

배치 끝의 펜스는 **남긴다** — 결과를 읽거나 present 하기 전에는 필요하고,
그것은 T9 가 답한 질문이 아니다(M2 §10).

## 4. M6 초안이 남긴 숙제

```
(a) E_DSTSIZE 검사 누락      v9 이 검증기 전에 따로 본다 (M6 §13.1)
(b) 조각 넷                  스냅샷 공용체 / lim 채우기 / 상태->텍스처 / fence-and-stop
(c) 빌더가 정사각형 가정      texH = texW.  높이 인자를 더한다
```

(c) 는 이제 해도 된다 — **자격검증이 끝나서 하네스를 다시 돌릴 일이 없다.**

## 5. 훅 (M2 §11 의 5)

```
1  a,b,c 를 OSMGAHW3DVertex 로 바꾼다 (OSMGAMesaBuildWarpVertex)
     - 폴리곤 오프셋을 z 에 접는다 (사다리꼴은 코드 공간에서 한다)
     - flat 이면 세 정점이 prov 의 색을 갖는다
2  OSMGAMesaWarpAdd 로 런에 붙인다 (dwgctl·alphactrl 이 런 키)
3  FULL 이면 플러시하고 다시 시도
4  거절이면 그 삼각형만 사다리꼴로 (부작용 없음, 이미 그 구조다)
```

**게이트 셋과 재생 계약은 그대로 쓴다.**  WARP 배치가 거절되면 사다리꼴
배치가 거절될 때와 똑같이 소스 삼각형을 소프트웨어로 재생한다.

## 6. 순서

```
1  정책 함수 + 빌더 높이 인자 + E_DSTSIZE          호스트 시험 가능
2  조각 넷 + 제출 경로                              하드웨어, 처음 도는 코드
3  훅 분기                                          하드웨어
4  혼합 층 A/B, 시간 측정
```

**2 와 3 을 같은 재부팅에 넣지 않는다.**  처음 도는 커널 경로와 처음 도는
클라이언트 경로를 한꺼번에 켜면 실패가 어느 쪽인지 못 가린다.

## 7. codex 에 물을 것

1. **§1 의 읽기가 맞나** — WARP 가 기존 누적·재생 기계에 그대로 들어가고
   `dwgctl`·`alphactrl` 만 런 키가 되는가?  놓친 결합이 있나?
2. **런 키가 플러시 키와 같아야 하나** 다른가?  텍스처 블록·scissor 는
   여전히 플러시 키이고 그 둘만 런을 자르는 것으로 충분한가?
3. **거절의 단위**.  WARP 배치가 거절되면 누적된 소스 삼각형 **전부**를
   재생하는 것이 맞나, 아니면 사다리꼴로 다시 만들어야 하나?
4. **폴리곤 오프셋을 z 에 접는 것**이 맞나.  사다리꼴은 코드 공간에서
   하는데, WARP 는 `[0,1]` 정규화 z 라 `offset/65536` 이 된다.
5. **2 와 3 을 나누는 것**이 옳은가, 아니면 훅 없이는 제출 경로를 시험할
   방법이 없나?
6. **§1.1 이 맞나** — `tmr` 이 플러시 키에서 빠지면 텍스처 장면의 배치가
   실제로 길어지는가, 아니면 다른 것이 먼저 자르나?
7. 빠진 것.

### 8.1 scissor — 결함이 아니라 주석이 틀렸다

이것은 반증이므로 근거를 적어 둔다.  `Mesa-3.4.2/src/scissor.c:43`:

```c
ASSERT_OUTSIDE_BEGIN_END_AND_FLUSH(ctx, "glScissor");
```

**`glScissor` 는 정점 버퍼를 플러시한다.**  훅의 누적은 렌더 브래킷 안에서만
살고(`RenderFinish` 래퍼가 플러시한다), 그러므로 **scissor 가 누적 중에 바뀌는
경로가 없다.**

→ 키를 더할 필요가 없다.  **주석을 고친다** — 지금 주석은 있지도 않은 기전을
근거로 들고 있고, 그것이 이번에 검토자를 잘못 이끌었다.

## 9. 개정

### 9.1 WARP 는 자기 pending 표현을 갖는다

기존 것을 **공유하는 것**과 **재사용하는 것**을 갈라야 한다:

```
공유한다   pendSrc 기록(색인 + 문맥 네 값), 게이트 셋, 재진입 가드,
           플러시 지점(RenderFinish, 소프트웨어 폴백, 컨텍스트 전환)
공유하지 않는다   pendTraps / firstTrap / batch->tri[] / 사다리꼴 색인 좁히기
```

### 9.2 거절의 단위 셋

```
(a) 삼각형 하나가 사전에 거절   정점 변환 실패, 정책 밖, 미지원
      -> 먼저 쌓인 WARP 를 플러시하고, 그 삼각형만 사다리꼴로
(b) WARP 배치가 가득 참
      -> 플러시하고 리셋한 뒤 같은 삼각형을 다시 시도
(c) 커널이 조립된 WARP 배치를 거절
      -> 누적된 소스 삼각형 **전부**를 소프트웨어로 재생
         (검증은 인코딩 전이므로 아무것도 안 그렸다)
         v9 의 "지목된 소스만 좁히기" 를 **재사용하지 않는다**
```

### 9.3 폴리곤 오프셋

```c
OSMGAMesaBuildWarpVertex(v, tex, zoffsetCodes, out)   /* 인자를 필수로 */

z_warp = (v->z + zoffsetCodes * 256) / 16777216.0
```

`v->z` 가 1/256 코드이므로 코드 단위 오프셋은 `x256` 이다.  **범위를 벗어나면
거절한다** — 사다리꼴이 그렇게 하고, 이유가 `Triangle.c:1027` 에 적혀 있다:
*"Clamping would draw something neither path draws."*

### 9.4 순서 (개정)

```
1  정책 + 빌더 높이 인자 + E_DSTSIZE + 오프셋 인자     호스트 시험
2  조각 넷 + 제출 경로 + **v10 직접 제출 프로브**      재부팅 1
3  훅 분기 + WARP pending + 거절 주입 시험             재부팅 2
4  혼합 층 순서 시험, 오프셋 시험, 시간 측정           재부팅 3
```

**2 는 훅 없이 시험한다** — 프로브가 커맨드 버퍼를 매핑하고 직접 제출한다.
