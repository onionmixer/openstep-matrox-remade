# D3 — 래스터라이저 직접 구동 (WARP 없이)

기준일: 2026-08-19
상태: **D3-0 실기 PASS(2026-08-19). 가설의 첫 시험 통과 — §8.**
codex 교차검토 1회 완료 후 개정판. 초판이 소스가 증명하는 것보다 넓게
말한 부분은 §0-1에서 좁혔다.

**이 문서는 3D 접근 경로를 바꾸자는 제안이다.** D2-2b(WARP로 삼각형)를 쓰려다
Storm 엔진 자체가 보간·Z·텍스처 래스터라이저를 갖고 있음을 발견했고, 그쪽이
Mesa 3.4.2에 훨씬 잘 맞는다.

## 0. 발견

`mga_storm.c`는 X.Org의 **2D DDX**다 — 유저스페이스이고, DRM도 WARP도
마이크로코드도 쓰지 않는다. 그런데 이런 코드가 있다(`mga_storm.c:420-455`):

```
DR4  = red << 7      DR6  = 0   DR7  = 0     /* 적색 시작값 + x/y 증분 */
DR8  = green << 7    DR10 = 0   DR11 = 0     /* 녹색 */
DR12 = blue << 7     DR14 = 0   DR15 = 0     /* 청색 */
ALPHASTART/ALPHAXINC/ALPHAYINC
TMR0..TMR8, TEXORG, TEXWIDTH, TEXHEIGHT, TEXCTL
DWGCTL = MGADWG_TEXTURE_TRAP | MGADWG_I | ARZERO | SGNZERO | SHIFTZERO | 0xc0000
```

즉 **텍스처가 입혀지고 색이 보간되는 사다리꼴을 순수 레지스터 쓰기로 그린다.**
`MGADWG_I`가 보간(interpolated), `MGADWG_ZI`가 Z까지 포함한 모드이며
(`mga_reg.h:165-169`), `DR0`~`DR15`가 보간기, `ZORG`(0x1c0c)가 Z 버퍼 원점이다.

**WARP는 래스터라이저가 아니다.** WARP는 정점을 받아 변환·조명·셋업을 해서
저 DR 증분값을 계산해 주는 앞단이다. 우리가 CPU로 그 값을 계산하면 WARP는
필요 없다.

### 0-1. 소스가 증명하는 범위 (교차검토 후 축소)

초판은 이 발견을 "Storm이 Gouraud 사다리꼴을 그린다"로 일반화했다. 정확히는
이렇다:

| 주장 | 상태 |
| --- | --- |
| Storm이 **`TEXTURE_TRAP \| I`** 로 보간·텍스처 사각형을 그린다 | **소스 확인됨** (`mga_storm.c:450`, `mga_exa.c:585`) |
| 그 경로에 WARP·마이크로코드·DRM이 없다 | **소스 확인됨** — `OUTREG`는 순수 MMIO(`mga.h:97`), `CHECK_DMA_QUIESCENT`는 DRI가 없으면 빈 매크로(`mga_macros.h:67`) |
| 그 경로의 용도 | **XAA/EXA의 X Render 가속**(`CPUToScreenAlphaTexture`/`CPUToScreenTexture`, `mga_storm.c:190`, `:948`) — OpenGL이 아니다 |
| 텍스처 **없이** `TRAP \| I`가 동작한다 | **미확인.** 소스에 그 조합을 쓰는 코드가 없다 |

→ D3-0은 `TRAP | I`로 시작하되, **실패했을 때 "보간이 안 된다"가 아니라
"`TRAP | I` 조합이 지원되지 않는다"일 수 있음**을 전제로 한다. 그 경우
`TEXTURE_TRAP | I`가 대안이며, 그것은 소스가 증명하는 조합이다(§3-0b).

## 1. 왜 이 경로가 Mesa 3.4.2에 맞는가

Mesa 3.4.2의 `dd_function_table` 드라이버(FX/Glide 등)는 **Mesa가 이미
변환·클리핑·셋업을 마친 뒤** 삼각형/스팬 단계에서 하드웨어에 넘긴다. 하드웨어
T&L을 쓰지 않는다. 즉 **우리에게 필요한 것은 래스터라이저이지 지오메트리
엔진이 아니다.**

근거(교차검토가 짚어준 구체적 훅):
- Mesa가 변환·조명·포그·텍스처 좌표를 먼저 적용한다고 명시
  (`Mesa-3.4.2/src/vb.h:29`)
- 드라이버가 구현하는 훅은 `PointsFunc`/`LineFunc`/`TriangleFunc`/`QuadFunc`와
  `RasterSetup`(`src/dd.h:148`, `:321`, `src/types.h:113`)
- FX 드라이버가 그 훅을 설정하고(`src/FX/fxdd.c:1065`, `:1068`),
  셋업은 `VB->Win`(**변환이 끝난 윈도 좌표**)을 하드웨어 정점으로 복사한다
  (`src/FX/fxvsetup.h:78`, `:84`)

| | 경로 A: WARP | 경로 B: 래스터라이저 직접 |
| --- | --- | --- |
| 마이크로코드 | 필요 (D2-1에서 배치 완료) | **불필요** |
| 정점 형식 | `WVRTXSZ=0x1807`이 규정 — **우리 소스에 문서 없음** | 불필요 |
| 2차 DMA | 필요 | 불필요 (primary만) |
| 참고 구현 | DRM(커널, AGP 전제) | **`mga_storm.c`(유저스페이스, 우리와 같은 조건)** |
| Mesa와의 정합 | 하드웨어 T&L — Mesa 3.4.2가 쓰지 않음 | **정확히 맞음** |

경로 A의 남은 미지수(정점 형식)가 우리 자료로는 풀리지 않는 반면, 경로 B는
**우리가 이미 하는 일의 연장**이다 — S1이 `MGADWG_TRAP | SOLID`로 단색
사다리꼴을 그렸고, 여기서 바뀌는 것은 atype이 `RPL`에서 `I`/`ZI`가 되고
DR 보간기가 채워지는 것뿐이다.

**D2 작업은 버려지지 않는다.** WARP가 서고 마이크로코드가 자리를 잡았다는
사실은 나중에 하드웨어 T&L을 붙일 때 그대로 쓰인다. 다만 **Mesa 가속의
임계 경로에는 없다.**

## 2. 확인된 사실

### 2-1. 필요한 레지스터가 전부 DMA 주소지정 가능하다

| 계열 | 오프셋 | 그룹 |
| --- | --- | --- |
| `DR0`~`DR15` (보간기) | 0x1cc0~0x1cfc | 0 |
| `ZORG` | 0x1c0c | 0 |
| `AR6` | 0x1c78 | 0 |
| `ALPHASTART`/`ALPHAXINC`/`ALPHAYINC`/`ALPHACTRL` | 0x2c70~0x2c7c | 1 |
| `TMR0`~`TMR8` | 0x2c00~0x2c20 | 1 |
| `TEXORG`/`TEXWIDTH`/`TEXHEIGHT`/`TEXCTL`/`TEXCTL2`/`TEXFILTER` | 0x2c24~0x2c58 | 1 |

**하나도 예외가 없다.** D1의 링과 조립기를 그대로 쓴다.

### 2-2. DWGCTL 조합

`mga_reg.h:144-195`:
- opcode: `MGADWG_TRAP 0x04`, `MGADWG_TEXTURE_TRAP 0x06`
- atype: `MGADWG_RPL 0<<4`(S1이 쓴 것), `MGADWG_I 7<<4`(보간),
  `MGADWG_ZI 3<<4`(Z + 보간)
- Z 비교: `MGADWG_NOZCMP`~`MGADWG_GTE` (8<<8 자리)
- `SOLID`(11), `ARZERO`(12), `SGNZERO`(13), `SHIFTZERO`(14)

S1의 단색 채우기가 `TRAP|SOLID|ARZERO|SGNZERO|SHIFTZERO|RPL|bop_copy`
(`0x000C7804`)였다. **Gouraud 사다리꼴은 여기서 `SOLID`를 빼고 atype을
`I`로 바꾸고 DR 보간기를 채우는 것**으로 시작한다.

## 3. 단계

### D3-0 — Gouraud 사다리꼴 하나 (텍스처·Z 없음)

가장 싼 질문부터: **보간 래스터라이저가 도는가.**

- 오프스크린 블록(S1과 같은 자리, 실증 7 MiB 안, 가시영역 위 256행 가드 밖)
- 왼쪽에서 오른쪽으로 색이 변하는 사각형 하나를 `TRAP | I`로 그린다
  (`DR4/DR8/DR12` 시작값, `DR6/DR10/DR14`에 x 증분, `DR7/DR11/DR15`에 y 증분)
- 텍스처 없음, Z 없음, 알파 없음 — 한 번에 하나씩만 켠다

**검증 방법**
- V0-1: uncached 별칭으로 되읽어 **색이 실제로 변하는지**. 단색이면
  보간이 동작하지 않은 것이다. 시작값·증분에서 **기대 픽셀값을 CPU로
  독립 계산**해 비교한다 — "뭔가 그려졌다"로는 부족하다.
- V0-2: 사각형 밖(가드 영역)이 sentinel 그대로인지 — 클립이 유효한지.
- V0-3: 2D 회귀(S1/S2/S3)와 D1/D2 전부 통과.
- V0-4: 화면 무변화.

### D3-0b — `TEXTURE_TRAP | I` 대안 (D3-0 실패 시)

D3-0이 실패하면 원인이 둘로 갈린다: 보간 자체가 안 되는가, 아니면 `TRAP | I`
조합이 지원되지 않는가. **후자를 배제하려면 소스가 증명한 조합으로 한 번 더
해봐야 한다.**

`TEXTURE_TRAP | I`는 텍스처 설정(`TEXORG`/`TEXWIDTH`/`TEXHEIGHT`/`TEXCTL`/
`TMR*`)이 함께 필요하므로 D3-0보다 손이 많이 간다. 그래서 순서를 이렇게
둔다 — 싼 것 먼저, 실패하면 확실한 것.

### D3-1 이후 (이 문서의 범위 밖)

Z 버퍼(`ZORG` + `MGADWG_ZI` + Z 비교), 텍스처(`TEXORG`/`TMR*`/`TEXCTL`),
알파 블렌딩(`ALPHACTRL`). 각각 별도 단계로 하나씩 켠다.

## 4. 가장 큰 미지수

- **DR 레지스터의 정확한 형식.** `mga_storm.c`가 `red << 7`을 쓰는 것으로
  보아 고정소수점이고 소수부가 있으나, 비트 배치는 우리 자료에 명시돼 있지
  않다. `<< 7`이 무엇을 뜻하는지 실험으로 확정해야 한다.
- 증분(`DR6`/`DR7` 등)의 부호와 스케일.
- `TRAP`이 사다리꼴을 어떻게 받는지 — S1은 `FXBNDRY`/`YDSTLEN`으로 사각형을
  줬다. 기울어진 변을 주려면 `AR` 레지스터군이 필요할 수 있다.

**D3-0을 사각형(기울기 0)으로 잡은 이유가 이것이다** — 기하는 S1에서 이미
검증된 것을 그대로 쓰고, **보간만** 새로 넣는다. 한 번에 하나씩.

## 5. 중단 조건

- 되읽기가 단색 → 보간이 동작하지 않음. 값 형식을 다시 조사한다.
- 사각형 밖이 오염 → 즉시 중단.
- 2D 회귀 또는 화면 이상.

## 6. 이 계획이 결정하지 않은 것

- 경로 A(WARP)를 완전히 접을지, 나중에 하드웨어 T&L로 되살릴지.
  **지금은 접지 않고 보류한다** — D2 자산은 그대로 두고 Mesa 임계 경로만
  경로 B로 옮긴다.
- Mesa 백엔드가 삼각형 단위로 받을지 스팬 단위로 받을지.

## 7. 아직 주장하지 않는 것

**경로 B가 경로 A와 동등하다고 말하지 않는다.** 교차검토가 지적했듯 WARP는
공개 레지스터로 노출되지 않는 내부 셋업 상태를 채울 수 있고, DRM/DDX 어디에도
`DR0`~`DR15`를 직접 쓰는 코드가 없다(위 Render 경로 제외). 경로 B가 성립하려면
우리가 **삼각형→사다리꼴 분할, 변(edge) 셋업(`AR`/`SGN`), DR 보간 산술**을
전부 직접 유도해야 하며, 그중 무엇도 아직 하지 않았다.

지금 주장하는 것은 **"Mesa 가속의 임계 경로에 WARP가 없어 보인다"** 까지다.
D3-0은 그 가설의 첫 시험이다.

## 8. 실행 결과 (2026-08-19)

**Storm 엔진이 WARP 없이 Gouraud 보간을 한다.** `TRAP | I`(dwgctl `0x000C7074`,
S1의 단색 채우기에서 `SOLID`를 빼고 atype을 `I`로 바꾼 것)에 DR 보간기만
채워 넣으면 색이 픽셀마다 변한다.

```
row0 x=0,16,32,48,63:  00ff40 3fff40 7fff40 bfff40 fbff40
col0 y=0,16,32,48,63:  00ff40 00ff40 00ff40 00ff40 00ff40
63 of 63 columns vary, 0 of 63 rows vary
```

빨강이 `255·x/64`를 정확히 따르고, 초록 `ff`·파랑 `40`은 지정한 대로 평평하다.

### 8-1. 확정된 DR 형식

| 항목 | 값 |
| --- | --- |
| 값 인코딩 | **`DR = colour << 15`** (비트 15~22 = 채널 비트 0~7) |
| 비트 23 | 넘침 — 255로 포화 |
| 비트 0~14 / 24~31 | 무시 |
| 시작값 | `DR4`=빨강, `DR8`=초록, `DR12`=파랑 |
| **x 증분** | `DR6`, `DR10`, `DR14` (실측) |
| y 증분 | `DR7`, `DR11`, `DR15` (추정 — 미측정) |
| 다중 비트 | 선형. 포화·감김 없음 |

### 8-2. 형식은 추측이 아니라 훑어서 얻었다

스케일을 네 번 추측했고 **네 번 다 틀렸다**. `value >> 23`도 아니고 bit23
임계값도 아니었다(`0x00ff0000`이 bit23이 서 있는데 검은색이었다). 3~4개
점으로 모델을 세우는 것을 그만두고, **비트 하나를 32개 자리에 옮겨가며**
한 부팅에 32점을 쟀다:

```
bit15 -> 010101   bit16 -> 020202   ...   bit22 -> 808080   bit23 -> ffffff
그 밖의 비트는 전부 0
```

모호함이 없다. **한 부팅으로 네 번의 추측보다 많은 것을 얻었다.**

### 8-3. 부수 검증

- 비트 훑기 실행에서 32번의 1행 그리기가 전부 자기 행에만 머물렀다
  (행 32~63 sentinel 그대로) → **행 단위 클립이 보간 모드에서도 유효**하다.
- 대조군(`SOLID`+`FCOL`)이 `ff8040`을 정확히 재현했다 → 검은 결과가
  그리기 경로의 문제가 아니었음을 그때 확인했다.

### 8-4. 문서의 부정확한 서술 하나 (D3와 무관)

operator가 부팅 중 화면에서 색 그라데이션 상자를 목격했다. **D3-0이 아니다** —
D3-0의 대상은 4.00 MiB 지점이고 가시영역은 3.00 MiB까지다. 보인 것은
**S2b(`960,704`)와 S3 self-test(`704,576` 등)** 로, 둘 다 가시영역에 일부러
그린다. `Storm 2D Test`를 V2a-4 회귀 확인을 위해 다시 켜면서 같이 살아났다.

S2 문서의 *"S2b 사각형은 즉시 덮여 육안으로 안 보인다"* 는 **부정확했다.**
부팅 타이밍에 따라 보인다. 위험이 새로 생긴 것은 아니고 서술이 낙관적이었다.

## 9. D3-1 결과 (2026-08-19) — 2차원 보간 완성

```
row0 (x):  000040 3f0040 7f0040 bf0040 fb0040     빨강만 증가
col0 (y):  000040 003f40 007f40 00bf40 00fb40     초록만 증가
대각선  :  000040 535340 a7a740 fbfb40            둘 다 증가
63/63 columns vary, 63/63 rows vary
```

대각선의 `53`/`a7`/`fb`는 `255·21/64 = 83.7`, `255·42/64 = 167.3`,
`255·63/64 = 251.0`과 일치한다. 파랑은 전 구간 `40` 고정.

### 9-1. 확정된 보간기 모델 (전부 실측)

| 채널 | 시작값 | x 증분 | y 증분 |
| --- | --- | --- | --- |
| 빨강 | `DR4` | `DR6` | `DR7` |
| 초록 | `DR8` | `DR10` | `DR11` |
| 파랑 | `DR12` | `DR14` | `DR15` |

- 인코딩: **`값 = colour << 15`**
- 픽셀 색상: **`start + x·xinc + y·yinc`**
- 세 채널·두 축이 서로 간섭 없이 동작

추측으로 채운 항목은 없다.

## 10. 다음
**여기까지 그린 것은 전부 축에 정렬된 사각형이다.** Mesa의 `TriangleFunc`를
채우려면 **기울어진 변**이 필요하고, 그것은 `AR` 레지스터군과 `SGN` 셋업을
요구한다(교차검토 §8). 색 보간이 된다는 것과 삼각형이 그려진다는 것은
별개의 문제이며, **사각형→삼각형이 남은 가장 큰 단계**다.

- 기울어진 변: `AR0`~`AR6`, `SGN`. 별도 계획서 대상.
- Z(`ZORG` + `MGADWG_ZI`), 텍스처, 알파는 각각 그 뒤 별도 단계.
