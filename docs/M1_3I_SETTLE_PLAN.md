# M1-3i — 완료 후 정착 읽기, 오프셋은 측정이 고른다

`M1_3G_SURFACE_READBACK_PLAN.md` §9 의 측정 위에서 세운다. 아직 코드 없음.

## 1. 왜 다시 하는가

드라이버 안에 정착 읽기를 넣었다가 "쓸모없다"고 판정하고 뺀 적이 있다
(`89ea285` → `608f084`). 그 코드가 읽은 자리는 이것이다:

```c
if (osmgaSettleAlias != 0)
    (void)osmgaSettleAlias[0];        /* 창 시작 바이트 0..3 */
```

그런데 §9 에서 잰 것은:

> **바이트 0..63 안을 읽으면 안 낫는다. 바이트 64 이상을 읽으면 낫는다.**

**즉 그 시도는 유일하게 안 통하는 자리를 골랐다.** "드라이버 쪽 읽기는
효과가 없다"는 현재 코드 주석의 단정은 근거가 무너졌다. 다시 재야 한다.

## 2. codex 교차검토 (계획 단계, gpt-5.6-terra) — 재검증 결과

**받아들인 것 (전부 소스에서 직접 확인했다)**

1. **재부팅하면 옛 진단이 되살아난다.** `osmgaProbeLeft` 는
   `static unsigned long osmgaProbeLeft = 8UL;` 이라 부팅마다 8 로 돌아가고,
   그 블록은 하필 `osmgaProbeAlias[0]` — **안 듣는 자리** — 를 두 번 읽는다.
   지금 부팅에서 꺼져 있는 것은 다 써버렸기 때문일 뿐이다.
   **훑기 전에 반드시 지우거나 꺼야 한다.** 안 그러면 처음 8 회가 오염된다.
   → 계획을 깨는 지적이었다.
2. **0 단계의 워크로드가 다르다.** C 클라이언트는 텍스처 없는 380 화소
   삼각형을 그린다. 거기서 0/40 이 나와도 "Mesa 경로는 무사하다"가 아니다.
3. **시행마다 상태 전이를 만들어야 한다.** 지금은 40 회 중 시행 0 하나만
   전이다. 매 시행을 `P → T` 로 만들면 설정당 기회가 40 개가 된다.
4. **세터에는 규율이 필요하다.** 단일 CPU 라도 인터럽트·스케줄 전환이 끼어든다.
   `stormLock` 아래에서 쓰고, `runHW3DSubmit` 이 `stormBusy` 를 claim 하는 그
   자리에서 지역 변수로 복사한 뒤 그것만 쓴다. 대기와 VRAM 읽기 동안에는
   락을 쥐지 않는다.
5. **세터는 개발용 표면이다.** 출시 전에 빼거나 잠근다.
6. **매핑 헬퍼가 `mmap()` 의 반환값을 버린다** — 두 클라이언트 다
   `vm_allocate` 주소를 그대로 돌려준다. §3-19 를 단정하기 전에 실제 반환
   주소를 찍어 확인해야 한다.
7. **비용 측정에 규율이 필요하다** — 손잡이는 타이밍 구간 밖에서 한 번만
   설정하고, 여러 번 재서 중앙값을 비교한다.

**고쳐서 받아들인 것**

- codex 는 0 단계를 **C 클라이언트를 텍스처 배치로 다시 만들어** 하라고 했다.
  더 나은 길이 있다: **ObjC 클라이언트가 이미 장치 fd 를 쥐고 있다**
  (`open(DEV_PATH, O_RDWR)`). 거기에 제출 방식만 바꾸는 인자를 더하면
  **같은 프로그램·같은 배치·같은 채우기**에 **호출만 다른** 비교가 된다.
  워크로드 교란이 아예 없어진다. 두 경로가 같은 `-runHW3DSubmit` 에
  도달한다는 것은 드라이버 주석이 명시하고 코드로 확인했다.

**틀려서 안 받아들인 것**

- codex 는 손잡이 범위를 `1..1024 = 워드 0..1023` 이라고 썼다. **틀렸다.**
  이 기계의 `PAGE_SIZE` 는 8192 이고(드라이버가 찍는 로그로 확인) 별칭은
  2048 dword 다. 내가 처음에 저지른 것과 같은 실수를 codex 가 되풀이했다.
  범위는 `PAGE_SIZE / sizeof(*osmgaProbeAlias)` 에서 유도한다.
- codex 는 기본값을 `dstorg == 창 시작` 으로 **좁히라**고 했다. 보류한다.
  그것이 유일하게 **시험한** 범위인 것은 맞지만, 실제 규칙이 더 넓다면
  (예: 어떤 페이지 정렬 목적지든 첫 64 바이트) 좁힌 조건은 아무 때도 안
  걸리는 죽은 코드가 된다. **0 단계가 Mesa 경로의 실제 `dstorg` 를 알려준
  뒤에 정한다.**

## 3. 먼저 물을 것 — 애초에 고칠 필요가 있는가 (0 단계, 재부팅 없음)

Mesa 는 **ioctl** 로 제출한다. 지금까지 ioctl 경로에서 증상을 본 적이 없는데,
그건 C 클라이언트의 시행 0 이 "상태가 바뀐 뒤의 첫 제출"이 아니었기
때문이다(루프 밖에서 이미 한 번 제출한다). **그 조건을 만들어 준 적이 없다.**
게다가 C 클라이언트는 텍스처 없는 380 화소 삼각형을 그린다 — 잰 것과 다른
그림이다.

그래서 **ObjC 클라이언트 안에서** 가른다. 이미 장치 fd 를 쥐고 있으므로
제출 호출만 바꾸면 된다:

- 인자로 제출 방식을 고른다: `setIntValues:` (Mach RPC) 또는
  `ioctl(OSMGA_IOC_SUBMIT)`. **배치도, 채우기도, 세기도 그대로다.**
- 매 시행을 상태 전이로 만든다: 유효한 예열 배치 `P` 를 제출하고 — `P` 는
  `T` 와 **한 레지스터만** 다르게 한다(`DSTORG` 를 사각형 밖 다른 행으로;
  encoder 는 `MGA_DSTORG` 를 항상 내보낸다) — 그 다음 `T` 의 사각형을
  미청소값으로 채우고, 사이에 아무것도 읽지 않고 `T` 를 제출한다.
  그러면 설정당 기회가 1 개가 아니라 **40 개**다.
- 양성 대조: 같은 하네스에서 워드 16 을 먼저 읽으면 반드시 나아야 한다.
  안 나으면 "결함 없음"은 해석할 수 없는 결과다.
- **ioctl 경로가 안 걸리면 드라이버를 고칠 이유가 없다.** 이 단계가 전부를
  가른다.

**2026-08-21 결과 — 걸린다.** ioctl 도 RPC 도 40 중 1, worst 4080 으로
같다. 그러므로 1 단계로 간다. 자세한 것은
`M1_3G_SURFACE_READBACK_PLAN.md` §10.

같은 측정이 **1 단계의 근거를 하나 지웠다**: 예열 제출을 무엇으로 하든
(다른 곳·동일 배치·텍스처 레지스터 변경·거부) 결과가 안 바뀌고, 같은 루프를
두 번 돌리면 두 번째는 깨끗하다. 즉 **프로세스당 한 번**이고 방아쇠는 아직
모른다. 1 단계의 코드는 그대로여도 된다 — 재는 대상이 "상태 전이"가 아니라
"그 한 번"으로 바뀔 뿐이다. 다만 **훑기는 프로세스당 기회가 하나뿐이므로,
설정마다 프로그램을 새로 띄워야 한다.**

이건 유저랜드에서 끝난다. 재부팅 없음.

## 3. 1 단계 — 오프셋을 실행 중에 바꿀 수 있는 정착 읽기 (재부팅 1 회)

**재부팅이 가장 비싸다.** 오프셋을 상수로 박으면 후보마다 재부팅해야 한다.
그래서 **런타임에 설정 가능**하게 만들고, 한 번의 재부팅으로 전부 훑는다.

- **먼저 옛 M1-3g 진단을 지운다.** 안 그러면 재부팅 직후 처음 8 회의
  일치 제출이 워드 0 을 몰래 읽는다 — 훑기가 오염된다.
- 드라이버 전역 `osmgaSettleWord`, **부호 없이 인코딩**: `0 = 끔`,
  `1..N = 워드 0..N-1`. 기본값 0.
- 세터는 `stormLock` 아래에서 쓴다. `runHW3DSubmit` 은 `stormBusy` 를
  claim 하는 그 자리에서 지역 변수로 복사하고, 그 뒤로는 지역 변수만 쓴다.
  대기와 VRAM 읽기 동안 락을 쥐지 않는다.
- 이 세터는 **개발용 표면**이다. 출시 전에 빼거나 잠근다.
- 별칭은 이미 한 페이지를 덮는다(`osmgaProbeAlias`,
  `osmgaMapUncachedBlock(... start, start + PAGE_SIZE ...)`).
  **이 기계의 `PAGE_SIZE` 는 8192 이다** — 드라이버가 스스로 찍은 로그로
  확인했다(`PAGE_SIZE=8192 PAGE_SHIFT=13`). 그러므로 별칭은 2048 dword 이고
  허용 범위는 **0..2047** 이다. (처음에 0..1023 이라고 적었던 것은 4096 을
  가정한 것이라 틀렸다.)
- `setIntValues:forParameter:` 로 새 파라미터 하나. **계약(`OpenStepMGAHW3D.h`)
  은 건드리지 않는다** — 훑는 데 쓰는 클라이언트는 ObjC 이고, Mesa 가 쓰는
  ioctl 표면은 그대로 둔다.
- `osmgaStormWaitIdle` 이 성공한 **뒤**, 켜져 있으면
  `(void)osmgaProbeAlias[osmgaSettleWord];` 하나.
- 레지스터 쓰기 없음. 읽기 전용. 실기 비파괴 원칙에 맞는다.

## 4. 2 단계 — 훑기 (추가 재부팅 없음)

| 설정 | 예상 |
| --- | --- |
| 끔 | 40 중 1 짧음 |
| 워드 0 (바이트 0) | 40 중 1 — 예전 시도의 재현 |
| 워드 15 (바이트 60) | 40 중 1 |
| **워드 16 (바이트 64)** | **40 중 0** |
| 워드 64 (바이트 256) | 40 중 0 |
| 워드 2047 (바이트 8188, 별칭의 끝) | 40 중 0 |

이 훑기는 예전 판정을 재현하면서 동시에 뒤집는다. 그리고 **커널의 언캐시드
별칭 읽기가 클라이언트의 매핑에까지 효과가 있는가** 라는, 아직 답이 없는
진짜 질문에 답한다. 클라이언트 쪽 읽기가 통한다고 커널 쪽 읽기가 통한다는
보장은 없다.

## 5. 3 단계 — 값 정하고 비용 재기

- 통하는 것 중 가장 안전한 오프셋을 기본값으로.
- 비용: 제출당 언캐시드 VRAM 읽기 1 회. 제출을 많이 돌려 켠 상태와 끈 상태의
  시간을 재고 **python 으로** 차이를 낸다.
- 프레임당 제출 수를 곱해 실제 부담을 말한다.

## 6. 아는 것과 모르는 것

**측정으로 아는 것** — 바이트 0..63, 경계는 64 에서 칼같이, `dstorg` 가 창
시작일 때만, 값이 바뀌는 첫 제출에서만, 시간으로는 안 낫고 버스 읽기라야
낫는다, 결국 값은 들어온다.

**모르는 것** — 왜 64 바이트인지, 왜 상태가 바뀐 첫 제출인지, 그 64 바이트가
매핑 소속인지 VRAM 자리 소속인지(§3-19 때문에 아직 못 가름).

**그러니 이 고침은 경험적이다.** 원인을 안다고 적지 않는다. 통하는 자리를
측정으로 고르고, 왜 그런지는 미해결로 남긴다.

## 7. 대안과 왜 안 고르는가

| 대안 | 왜 아닌가 |
| --- | --- |
| MMIO 레지스터 읽기 추가 | 이미 이 경로가 여러 번 한다. 안 통한다. |
| 클라이언트가 알아서 읽기 | 앱은 손대지 않는 것이 이 프로젝트의 전제다. |
| Mesa 미러가 처리 | 공유 표면 경로에는 미러가 없다. |
| 완료 판정을 더 엄격히 | 무엇을 기다려야 하는지 모른다. 시간은 안 통했다. |

## 8. 순서

1 단계 코드 → 빌드 → 설치 → **재부팅 요청** → 2·3 단계.
