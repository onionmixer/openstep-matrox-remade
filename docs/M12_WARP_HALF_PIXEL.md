# M12 — WARP 층의 반 화소 (2026-08-29)

M11 이 훅의 WARP 분기를 붙였다.  이 문서는 그것을 **켜서 한 장면을 그린**
결과와, 거기서 나온 두 결함이다.

## 1. 첫 장면 — 좌표는 맞고 색은 전부 0

`mesh16`(512 삼각형, 꼭짓점 전부 1/256 격자 위), 같은 프로세스·같은 표면,
층만 다르다.

| 층 | 안 칠함 | 넘게 | 귀속 틀림 |
|---|---|---|---|
| 사다리꼴 | 0 | 0 | 0 |
| WARP (1차) | 462 | 463 | 7707 |

그런데 WARP 가 그린 52225 화소가 **전부 `(0,0,0)`** 이었다.  모양은
460 화소 이내로 맞는데 색만 정확히 0 — 기하·클립·정점 경로가 전부 옳고
색만 없어지는 모양이다.

**DWGCTL.**  두 제출 경로는 클라이언트에게서 opcode·access type·z mode 만
받고 나머지 비트는 드라이버가 공급한다 — 클라이언트가 따져본 적 없는 비트는
클라이언트가 세울 수 있는 비트가 아니다.  버전 9 는 그 병합을 한다:

```c
unsigned long dwg = OSMGA_HW3D_DWG_FIXED | (t->dwgctl & OSMGA_HW3D_DWG_CLIENT);
```

버전 10 은 클라이언트 워드를 리스트 빌더에 그대로 넘겼다.  그리고
`DWG_FIXED`(`0x000C4000`) 가 **bop 이 사는 자리**다.  bop 0 은 불 연산
ZERO — 엔진이 정확히 맞는 화소 위에 0 을 썼다.

병합하면 텍스처·깊이 없는 경우가 `0x000C4074` 가 되는데, 이것이
`MGA_DWGCTL_SLOPED(MGA_DWGCTL_GOURAUD)` — **모든 자격검증 밴드가 넘기던 그
리터럴**이다.  이 일치가 "병합이 차이의 전부" 라는 근거다.

**왜 아무도 못 잡았나.**  밴드는 리스트 빌더에 *완성된* 값을 넘기므로 병합이
그 경로에 없었다.  검증기는 클라이언트 비트를 판정하니 `0x74` 를 옳게
통과시켰다.  호스트 스위트는 배치를 만들 뿐 레지스터를 쓰지 않는다.
깨진 것이 **소스 규칙**(한 경로가 병합하면 다른 경로도 해야 한다)이라
소스에서 검사한다 — `->dwgctl` 을 나르는 모든 `osmgaDmaBuildTriangleList`
호출은 `DWG_FIXED` 도 날라야 한다.  실제 파일에 대해 **양방향으로** 확인했고
(수정 전 형태에서 그 줄을 잡는다), **아무것도 매치하지 않으면 통과를
거부**한다.

## 2. 두 번째 결함 — 반 화소

색이 돌아오자 남은 것은 `(462, 463, 7707)` 이었다.  **같은 관측**을
꼭짓점을 `(dx,dy)` 만큼 민 오라클에 대고 다시 채점했다:

```
결합 5x5 격자, 값은 '귀속 틀림'
             7/16    15/32      1/2    17/32     9/16
dy 7/16        829      706      709      798      895
dy 15/32       516      287      269      366      461
dy 1/2         493      191    ->50      91      189
dy 17/32       638      333      146       70       62
dy 9/16        775      471      280      183       89
```

**결합 최소가 정확히 `(+1/2, +1/2)`**, `(0, 1, 50)`.  참고로
`(0,0) -> 7707`, `(1,1) -> 650`, `(-1/2,-1/2) -> 8276`.

### 2.1 주장하는 것과 하지 않는 것

주장: **좌표 계약**이다.  이 층은 오라클이 `V + 1/2` 에 대해 그리는 그림을
그린다.  그러므로 `V - 1/2` 를 주면 둘이 일치한다.

주장하지 **않는** 것: 메커니즘.  코너 샘플링도 이 결과를 낳고, 마이크로코드
안의 편향도, 반 화소 어긋난 셋업 원점도 낳는다.  병진 실험은 그 셋을
가르지 못하고, **가를 필요도 없다** — 보정은 셋 다에 대해 같다.

참조는 x 에서 자릿수까지 맞는다.  `mgavb.c:87` 이
`xoffset = drawX + SUBPIXEL_X`, `SUBPIXEL_X = -0.5`(`mgacontext.h:306`).
그리고 **`W2_WARP_RENDER_PATH_PLAN.md` 의 "진짜 남은 위험 — 좌표 규약" 이
1 년 전에 이것을 "화소가 어긋나면 먼저 의심할 것" 이라고 적어 두었다.**
그쪽 y 는 `-0.375` 지만 그쪽 y 는 뒤집혀 있고(`-win[1] + yoffset`) 우리는
아니다.  우리 쪽은 두 축 모두 깨끗한 반이 나온다.

### 2.2 내가 T4b 를 과독했다

빌더의 주석은 이렇게 적혀 있었다:

> No half-pixel is folded in: M4's T4b matched an oracle evaluated on the
> integer vertex lattice at all 1176 pixels

T4b 의 판정 코드를 열어 봤다.  오라클이 `dx = col - TRI_LO`, **정수 열
번호**로 색인하고 삼각형 꼭짓점도 정수 위에 있다.  그러므로 코너 샘플러와
중심 샘플러 **양쪽 모두와 일치한다.**  T4b 는 *나눗셈이 있는가* 를 쟀고 그
질문에는 답했지만, 표본점을 놓을 분해능은 애초에 없었다.  그것을 근거로
쓴 것은 과독이다.

### 2.3 고친 곳 — 유저랜드 한 군데

`mesa/OpenStepMGAMesaWarp.c`, `OSMGAMesaBuildWarpVertex`.  정점은 1/256
화소를 나르므로 반 화소는 **정확히 128**, 단 한 번의 float 변환 **전에**
하는 정수 뺄셈이다.

커널이 아니다: 커널에는 부동소수점이 하나도 없고(그 규칙 때문에 `double`
클립 상자를 걷어냈다), IEEE float 에서 반을 뺄 수 없다.

## 3. 결과

| | 안 칠함 | 넘게 | 귀속 틀림 |
|---|---|---|---|
| 사다리꼴 (대조군, 재측정) | 0 | 0 | **0** |
| WARP, 반 화소 전 | 462 | 463 | 7707 |
| **WARP, 반 화소 후** | **0** | **0** | **56** |

**커버리지는 정확해졌다.**  오라클 화소 52224 개를 전부 칠했고 밖은 하나도
건드리지 않았다.

남은 56 개(0.107%)의 성격:

```
정확히 변 위에 얹힌 표본        0 개
가장 가까운 변까지 거리         최소 0.00066  중앙값 0.00832  최대 0.01532 화소
1/16 화소 안                    56 / 56
이웃(꼭짓점 공유) 삼각형이 씀   56 / 56
아무 관계 없는 삼각형이 씀      0
```

즉 **변에 붙은 화소의 소유권**뿐이고, 커버리지도 주소 계산도 아니다.
`mesh12` 의 52 와 같은 종류의, 적어두는 값이다.

### 3.1 내 예측은 틀렸다

반 화소를 넣기 전에 나는 잔차가 **정확히 변 위에 얹힌 표본**(오라클의
top-left 규칙과 엔진의 채우기 규칙이 갈리는 자리)일 것이고, 수정 후에도
`(0, 1, 50)` 그대로일 것이라고 적었다.  둘 다 틀렸다:

* 50 개 중 **정확히 변 위는 0 개**였다(전부 변에서 0.0003~0.0206 화소).
* 수정 후는 `(0, 1, 50)` 이 아니라 `(0, 0, 56)` 이다.  엔진이 이제 **다른
  float 값**으로 셋업을 계산하므로 같은 집합이 나올 이유가 없었다.

**성격**은 유지됐다(변에 붙은 소유권뿐).  **집합**은 아니다.

### 4.1 검증 중에 내가 발견한 것

`M8_VERDICT_SUMMARY.md` 의 `M4 SUMMARY/...` 세 줄을 **측정값으로 인용할
뻔했다.**  그 줄들은 §3 "설계" 안의 **형식 예시**다.  실제 측정값은
`M9 §0` 에 있다(T7 phasefail, T8b wrong 0, T9 busy 1 / leak 0 0).

## 5. 남은 것

이 문서가 닫지 **않은** 것.  좌표 보정은 커버리지를 고쳤지만, WARP 가
커버리지·깊이·원근 분모·텍스처 좌표에 **같은 위상**을 쓴다는 보장은 없다.
쓰지 않는다면 커버리지가 맞으면서 텍스처가 반 표본 어긋날 수 있다.

그러므로 다음은 **Mesa 를 거치는** 통합 시험이다 — 커널 하네스는 자기
정점을 주므로 대조군이지 대체물이 아니다:

```
깊이 평면       Mesa 경유 WARP 대 사다리꼴
투영 텍스처     같음
nearest/linear  같음
알파 블렌딩     같음
공유 변 소유권  이미 잼 (56, 전부 변에서 1/16 화소 안)
```
