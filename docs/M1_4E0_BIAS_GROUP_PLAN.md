# M1-4E0 — 이음매를 없앤다: 연속성 그룹의 공통 bias

## 1. 무엇을 고치는가

§82 가 쟀다.  텍스처가 높으면(2048 줄, 텍셀 512 단위) 이웃한 두 사다리꼴이
**같은 좌표를 다른 bias 로** 보고, 평범한 타일링 비율에서 64 표본 중 12 개가
다른 텍셀을 읽는다.  타일 바닥에 **보이는 이음매**다.

`M1_4D5` 는 이걸 예상하고 설계 E 를 "다음 설계 변경으로" 적어 뒀다:

> E(연속성 그룹 bias)로 가되, 커널이 권한을 유지해야 한다:
> `0 ≤ 요청 ≤ biasFor(실제 도달범위)`

## 2. 왜 지금 할 수 있게 됐나

두 가지가 이번 사이클에 갖춰졌다:

1. bias 가 **사다리꼴별**이 됐다 — 검증기가 순회 중에 사다리꼴마다 도달범위를
   걷고 대역 코드를 인코더에 넘긴다.  그러니 "요청을 검사한다"는 것이
   사다리꼴마다 가능하다
2. 원자적 삼각형 — 한 배치가 GL 삼각형 하나를 통째로 싣는다.  그러니
   "그룹"의 자연스러운 단위가 이미 있다

## 3. 설계

배치 상태에 **요청 대역**을 하나 둔다 (축마다):

```c
    unsigned long texBiasReqU;   /* 0..5, 또는 NONE */
    unsigned long texBiasReqV;
```

검증기는 사다리꼴마다 이미 자기 대역을 구한다.  요청이 있으면:

```
    쓰는 대역 = max(요청, 그 사다리꼴 자신의 대역)
```

**최대값**인 이유: 대역이 클수록 bias 가 **작고**, 잔차 `addend − bias` 가
크다.  잔차는 음수만 아니면 되므로, 자기 대역보다 **큰** 쪽으로만 움직일 수
있다.  자기 대역보다 작은 것을 쓰면 bias 가 커져 잔차가 음수가 되고, 경계
정렬 좌표가 아래 텍셀로 떨어진다 — 이 규칙 전체가 막으려는 바로 그것이다.

즉 커널은 요청을 **믿지 않고 클램프한다.**  클라이언트는 "우리 그룹은 다 같이
이 정도까지 간다"고 말할 수 있을 뿐, 자기 사다리꼴이 실제로 요구하는 것보다
안전을 낮출 수는 없다.

### 3-1 그러면 이음매가 왜 사라지나

Mesa 가 한 장면의 텍스처 프리미티브들에 **같은 요청**을 보내면, 각 사다리꼴은
`max(요청, 자기)` 를 쓴다.  요청이 그 장면의 모든 도달범위를 덮을 만큼 크면
전부 같은 값이 되고, 잔차가 같아지고, 같은 좌표가 같은 텍셀을 읽는다.

요청이 덮지 못하는 사다리꼴은 자기 것을 쓰므로 **안전은 유지되고** 이음매만
그 자리에 남는다 — 즉 이 기구는 화질을 사는 것이지 안전을 파는 것이 아니다.

### 3-2 Mesa 는 무엇을 요청하나

가장 단순한 것부터: **그리기 하나 안에서** 같은 요청.  `glBegin/glEnd` 한
묶음의 삼각형들은 대개 같은 표면이므로, 그 묶음의 최대 도달범위를 예측해
넣으면 된다 — 그러나 빌더는 삼각형을 하나씩 본다.

그러니 1 단계는 **클라이언트가 명시적으로** 요청하는 것으로 두고, Mesa 는
아직 요청하지 않는다(요청 = NONE).  탐침이 요청을 직접 넣어 기구가 작동함을
보인다.  Mesa 쪽 정책은 그 다음 문제다.

## 4. 무엇이 바뀌나

| 자리 | 바뀔 것 |
|---|---|
| `OSMGAHW3DState` | `texBiasReqU`, `texBiasReqV` 두 필드 |
| 버전 | 5 → 6 (공유 레이아웃) |
| 검증기 | 요청 범위 검사(0..5 또는 NONE), 그리고 `max` 클램프 |
| 인코더 | 바뀌지 않는다 — 이미 `bands[i]` 를 쓴다 |
| 탐침 | §84: 요청으로 이음매가 사라지는지 |

**커널 변경이므로 재부팅이 필요하다.**

## 5. 안전 논증

잔차는 `addend(좌표) − bias(쓰는 대역)` 이다.  쓰는 대역이 자기 대역보다
크거나 같으므로 bias 는 자기 bias 보다 작거나 같고, 잔차는 자기 잔차보다
크거나 같다.  자기 잔차는 이미 음수가 아님이 증명돼 있다(그게 사다리꼴별
bias 의 근거다).  그러므로 **잔차는 여전히 음수가 아니다.**

경계를 넘는 방향은 위쪽뿐이고, 그건 §80 이 잰 그대로다.

## 6. 교차검토에 물을 것

- §3 의 `max` 가 옳은 방향인가 — `min` 이어야 할 이유가 있나
- 요청을 **축마다** 두는 것이 맞나, 아니면 하나로 충분한가
- 버전을 올리면 무엇이 깨지나 (탐침·시험·Mesa 를 함께 설치해야 한다)
- 이 기구가 열어주는 **오용**은 무엇인가.  클라이언트가 항상 대역 5(bias 0)를
  요청하면 어떻게 되나 — 안전한가, 화질은 어떻게 되나
- Mesa 가 나중에 정책을 넣을 때 무엇을 알아야 하나

## 8. 상한을 증명한다 — 고친 규칙

오늘 안전한 이유는 **자기 rung 에서는 도달범위 지점의 잔차가 정확히 0** 이기
때문이다: 그 좌표의 addend 와 그 대역의 bias 가 같은 사다리 값이다.

요청이 rung 을 올리면 그 지점의 잔차가 양수가 되고, 유효 좌표가 도달범위를
넘어선다:

```
   유효_최대 = 도달범위 + addend(도달범위) − bias(쓰는 rung)
```

그러니 검증기가 그것도 검사한다.  가장 큰 허용 rung 을

```
   headroom = 가장 큰 r 로서  도달범위 + addend(도달범위) − bias(r) ≤ COORD_MAX
```

라 하면, 쓰는 rung 은

```
   쓰는 rung = max(자기, min(요청, headroom))
```

`max(자기, …)` 가 바깥에 있는 이유: 원근에서는 **분자**가 `COORD_MAX` 를
넘을 수 있고(상한은 3·COORD_MAX), 그러면 headroom 이 자기보다 작게 나온다.
자기 rung 은 언제나 안전하므로(잔차 0) 그 아래로는 절대 내려가지 않는다.

## 9. ABI

```c
    unsigned long texBiasReqU;   /* 0 = 요청 없음, 1..6 = rung + 1 */
    unsigned long texBiasReqV;
```

`0` 이 "요청 없음"인 이유는 **묵은 값이 정책을 켜지 않게** 하기 위해서다 —
0 으로 남은 필드는 아무 일도 하지 않는다.  그래도 Mesa 는 매 제출마다 명시적
으로 쓴다.

## 10. 순서

1. 헤더: 두 필드, `NONE`, 버전 6, 대역/사다리 접근자
2. 검증기: 요청 범위 검사, headroom 계산, `max(자기, min(요청, headroom))`
3. 인코더: **바뀌지 않는다**
4. Mesa: 두 필드를 매번 0 으로 쓴다 (정책은 다음 문제)
5. 호스트 시험: 36 쌍 × 축, `NONE`, 잘못된 요청, 상한
6. 탐침 §84: 덮인 쌍은 12/64 가 0 이 되고, 안 덮인 쌍은 남는다
7. 빌드 → 설치 → **재부팅 요청**

## 11. 잰 결과 (§84)

```
   asking nothing         12 of 64 positions differ     <- §82 재현
   asking the far rung     0 of 64 positions differ     <- 이음매가 닫힌다
   asking below it        12 of 64 positions differ     <- 안 덮인 쪽은 자기 것
```

python 이 셋 다 12·0·12 를 예측했고 그대로 나왔다.

세 번째가 있어야 첫 두 개가 의미를 갖는다.  요청보다 자기 rung 이 높은
사다리꼴은 자기 것을 지키므로 이음매가 그 자리에 남는다 — 즉 이 기구는 화질을
사는 것이고, **안전을 파는 것이 아니다.**  두 번째만 있으면 "요청이 근처
좌표를 뭉갠 것"으로도 설명될 수 있다.

## 13. 남는 것 — Mesa 쪽 정책

기구는 있고 Mesa 는 아직 아무것도 요청하지 않는다.  어느 rung 을 공유해야
하는지는 **한 삼각형씩 보는 백엔드가 답할 수 없는 질문**이다:

- 너무 낮으면 덮이지 않는 사다리꼴이 생겨 이음매가 그 자리로 옮겨간다
- 너무 높으면 좌표가 작은 프리미티브까지 큰 잔차를 쓴다 (rung 5 는 TD 2048
  에서 텍셀의 96.9%, 즉 그림이 한 텍셀 밀린다)

가능한 방향 셋:

1. **면 단위 추적** — `glBegin/glEnd` 한 묶음의 최대 도달범위를 기억했다가
   다음 묶음부터 그 값을 요청.  첫 묶음은 이음매가 남는다
2. **텍스처 크기로** — 이음매가 무는 것은 텍셀이 896 단위 이하일 때, 즉
   대략 `TD ≥ 1170` 이다.  그보다 작은 텍스처에서는 요청할 이유가 없다
3. **응용이 말하게** — 확장으로 열어 두고 기본은 요청 없음

지금은 3 이다(요청 없음).  1 을 넣으려면 훅이 상태를 갖게 되므로 그때 다시
계획한다.
