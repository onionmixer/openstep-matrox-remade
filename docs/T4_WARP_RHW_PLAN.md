# T4 — WARP 을 주 경로로: 삼각형 단위 rhw 재스케일 (계획, 코드 없음)

## 1. 문제 (전부 실측)

100 프레임 실측: 제출 170,903회 / 삼각형 333,306개 = **배치당 2개**. flush 분해:
`bracket 6,155 · key 152,095 (texture 24 / gradients 152,071) · clip 12,636`.
배치를 끝내는 것은 사실상 전부 **텍스처 행렬 변경**이고, Quake 는 면마다 자기
텍스처 평면을 가지므로 사다리꼴 티어에서는 구조적입니다.

WARP 티어는 그라디언트를 배치 키로 쓰지 않는데(카드가 정점에서 계산), 켜 봐도
37%만 가져갑니다. 정점 승인 12곳을 계측한 결과 거절 **278,270건 전부가 한 검사**:

```
warp vertex : rhwrange 278270      (0.125 ≤ rhw ≤ 128)
```

그 범위의 출처는 헤더에 적혀 있습니다 — `Q_MIN/65536`, `Q_MAX/65536`, 즉
**사다리꼴 티어의 고정소수점 분모 한계**. WARP 은 f32 를 싣고, 넘칠 고정소수점이
없습니다. G400 사양서에는 역수 w 범위 제한이 없습니다.

## 2. 왜 거절되는가 (python)

Quake 투영은 `MYgluPerspective(fov, aspect, 4, 4096)` (`gl_rmain.c:904`).
`rhw = qw·tq = 1/w ∈ [1/4096, 1/4] = [0.000244, 0.25]` — 창 하한 0.125 밑으로
최대 512배. 월드 대부분이 밑으로 빠집니다.

## 3. 제안: 삼각형 단위 공통 2^n 스케일 (유저랜드, 재부팅 없음)

세 정점의 `rhw` 에 **같은** 2^n 을 곱해 창 안으로 넣는다.

### 3.1 불변성 논거

카드의 원근 보정 보간은 정점당 `(tu0·rhw, rhw)` 를 선형 보간해 나누는 비율이다:

```
좌표(픽셀) = Σ λᵢ·tu0ᵢ·rhwᵢ / Σ λᵢ·rhwᵢ
```

세 `rhwᵢ` 에 공통 c 를 곱하면 분자·분모가 함께 c 배 — **상쇄된다.** z 는 화면
선형(정점 주석: "엔진이 65536 을 곱해 포화", rhw 무관), 색은 Gouraud 화면 선형,
specular/fog 는 0, 밉맵 없음, w-버퍼 없음. 이 드라이버가 rhw 를 쓰는 곳은
보간 가중치뿐이다.

커널 쪽 봉쇄 논거도 그대로다: 커널 주석 — "봉쇄는 rhw 가 모든 정점에서
**양수**라는 데 기댄다"(`HW3D.c:1712`). 스케일은 부호를 보존한다. WARP 텍스처
봉쇄는 좌표 크기와 무관하게 CLAMPUV/POT 마스킹이며(`osmgaHW3DTexClampAxes`,
커널은 tu/tv 를 Finite 만 검사), 이 계획은 거기에 **아무 신뢰도 추가하지 않는다**.
(비대칭 기록: 사다리꼴 티어는 8 반복 너머의 마스킹을 신뢰하지 않기로 했지만,
WARP 티어는 처음부터 전 좌표를 마스킹에 맡겨 왔고 teapot·GLQuake 164k 삼각형이
그 경로로 실기에서 그려졌다.)

### 3.2 타당성 (python)

창 비 = 128/0.125 = **1024** = Quake 깊이 비 4096/4. 삼각형 하나의 `rhw` 비가
1024 이하이면 정수 n 이 존재한다 — 전 깊이를 한 삼각형이 걸치는 극단까지 포함:

```
w ∈ [4, 8]      비    2.0   n ∈ [0, 9]   가능
w ∈ [4, 4096]   비 1024.0   n ∈ [9, 9]   가능 (정확히 한 값)
w ∈ [4, 4100]   비 1025.0   불가 → 오늘처럼 사다리꼴로 (계수)
```

n 선택: `n = floor(log2(128/max))` 후 `min·2^n ≥ 0.125` 확인, 실패 시 거절.
frexp 지수 산술로 나눗셈 없이 구한다.

### 3.3 정밀도 (python)

2^n 곱은 f32 지수 덧셈 — **비트 정확, 손실 0**. `1/4096` 의 지수 −12 는 정규수
하한 −126 에서 멀고, 스케일 후 [0.125, 128] 은 지수 [−3, 7]. tu0/tv0 은 손대지
않는다(s/tq 그대로).

### 3.4 구현 지점

`osmgaMesaWarpTriangle` 에서 `BuildWarpVertex` 호출 전:
- `rhwᵢ = qwᵢ·tqᵢ` 셋의 min/max → n. 불가면 기존 `declineOne`(카운터 추가).
- **원본 a,b,c 를 변형하지 않는다** — WARP 이 거절하면 같은 정점이 사다리꼴로
  가므로, 지역 사본 3개를 만들어 사본의 `qw` 에만 2^n 을 곱한다.

### 3.5 예측 (python)

```
제출 ≈ bracket 6,155 + clip 12,636 + texture 24 + warp만재(333k/240) 1,388
     ≈ 20,203   (오늘 170,903 — 8.5×)
```

clip 12,636 은 T3a 의 정밀 판정 이후 값. WARP 배치는 720 정점 = 240 삼각형.

## 5. 위험 (검토받고 싶은 것)

1. 마이크로코드가 rhw 를 보간 가중치 외의 용도로 쓰는가? (사양서엔 없음, 이
   드라이버는 안 씀 — 그러나 마이크로코드 내부는 블랙박스. 화면 비교가 검증.)
2. 커널 범위를 그대로 두므로, 스케일 후에도 비 1024 초과 삼각형은 사다리꼴로
   떨어진다 — 그 수를 계수해 무시 가능함을 확인.
3. f32bits 변환 경로에서 스케일된 값의 반올림? (지수 덧셈이라 없음 — 3.3)
4. WARP 색이 사다리꼴보다 0~1 레벨 낮은 기존 측정 — 티어 이동으로 화면의
   해당 픽셀들이 1 레벨 어두워질 수 있음. 결함이 아니라 기록된 특성.

## 6. 자체 검증 (codex 회신 전)

- `osmgaHW3DF32Between` 은 **포함** 경계(`p >= lo && p <= hi`) — 스케일 결과가
  정확히 128.0 이어도 통과. (`HW3D.c`)
- 뷰 모델의 `glDepthRange(gldepthmin, +0.3·범위)` 와 `gl_ztrick` 은 **z 에만**
  작용한다 — Mesa 뷰포트 변환이 Win[2] 에 반영하고, rhw(=Win[3]) 는 건드리지
  않는다. 재스케일과 무관.
- `osmgaMesaWarpTriangle` 은 `a,b,c` 를 비-const 포인터로 받지만 현재 변형하지
  않는다. 사본 스케일은 이 함수 안에서 안전하다.
- **참조 증거**: 참조 DRI 드라이버는 `v->v.rhw = win[3]` — Mesa 의 1/w 를
  **스케일 없이 그대로** 하드웨어에 실었다(W2 문서 452, mga_vb.c 발췌). 즉
  실리콘은 Quake 범위의 rhw 를 상용 드라이버에서 늘 받아 왔다. [0.125, 128]
  창은 순수하게 우리 커널의 정책이며, 이 계획은 그 정책을 유저랜드에서
  맞춰 주는 것이다.

## 8. 수정된 계획 (확정)

**0 단계 — 실기 프로브 3종 (커널 프로브 섹션, 재부팅 1회에 묶음, M4 선례):**
1. **공통 스케일 스윕**: 같은 원근 삼각형을 `2^n` (n = −2, 0, +9 등) 만 바꿔
   그리고 픽셀·깊이 전수 비교. 마이크로코드의 절대 스케일 불변성 판정.
2. **공유 변 seam**: 한 변을 공유하는 두 삼각형에 서로 다른 n 을 강제, 변
   픽셀의 텍스처·색 exact diff.
3. **min/mag 임계**: 배율 1 경계 바로 양쪽에서 1과 같은 시험.

셋 다 통과해야 1 단계로 간다. 하나라도 실패하면 "배치 공통 n"(배치의 모든
삼각형에 같은 n — seam 원인 제거, 적용률 하락) 으로 후퇴해 재시험.

**1 단계 — 유저랜드 구현 (재부팅 없음):**
- `osmgaMesaWarpTriangle` 에서 state admission 뒤: `wa=*a; wb=*b; wc=*c`,
  prov 는 복사본에, `rhwᵢ = qwᵢ·tqᵢ` (double) 의 max 로 frexp 규칙 n,
  복사본 `qw` 에 `ldexp(1,n)` 곱, `BuildWarpVertex(복사본)` 이 최종 판정.
  실패·비 초과는 기존 decline (새 카운터 `rhwratio`).
- 원본 a,b,c 는 어떤 경로에서도 불변(flat 색 쓰기도 복사본으로 이동).

**2 단계 — 검증:**
- 자기 종료 60초 1회: `rhwrange → 0`, warp 몫, 제출 수(목표 ~20k, 산식 아님),
  100 프레임 시간.
- `glquake` 대 `glquake_sw`: 화면 exact diff(±1 코드 허용 명시), 특히 티어
  경계 표면.
- 회귀: `test-mesa-warp`, `test-hw3d-validate`, `test-hw3d-reach`.
