## 1. 저장소가 이미 갖고 있는 것 (다시 만들지 않는다)

`Hook.c` 를 **질문으로** 읽었다.  사다리꼴 경로의 누적 기계가 이미 다음을
전부 갖고 있다:

| | 어디 |
|---|---|
| 누적 상태·재진입 가드 | `pendTraps`, `pendSrcCount`, `pendInFlush` |
| **재생 기록** | `pendSrc[]` — 색인 넷 + **문맥 네 값**(오프셋·`ColorPtr`·`IndexPtr`·`Specular`) |
| 게이트 셋 | 렌더 브래킷 / 클립하는 VB / multipass (`batchable`) |
| **revoke 와 fork 구분** | `OSMGAMesaBufferBoundTo` — revoke 는 재생, fork 는 버린다.  *"measured at nine triangles in, eight out"* |
| 문맥 복원 브래킷 | 재생 둘레에서 네 값을 되돌린다 |
| 플러시 지점 | `RenderFinish`, 소프트웨어 폴백, 컨텍스트 전환 |

**WARP 는 이것을 전부 그대로 쓴다.**

## 2. 다른 점 — 모드와 거절

### 2.1 모드

한 순간의 pending 은 **사다리꼴이거나 WARP 이지 둘 다가 아니다**:

```c
pendMode  NONE | TRAP | WARP
```

모드가 바뀌면 **먼저 플러시**한다.  이것이 두 카운터가 동시에 0 이 아닌
상태를 없앤다.

### 2.2 플러시 키가 하나 줄어든다

```
사다리꼴  컨텍스트/VB, 가득 참, 텍스처 블록 ** + tmr[0..5] **
WARP      컨텍스트/VB, 가득 참, 텍스처 블록 ** (tmr 없음) **
```

`tmr` 은 텍스처 **기울기**이고 삼각형마다 다르다.  사다리꼴에서는 배치
상태라 **텍스처 장면이 삼각형마다 플러시**한다.  **WARP 는 기울기를
마이크로코드가 정점에서 계산하므로 배치 상태가 아니다.**

`dwgctl`·`alphactrl` 은 플러시가 아니라 **런을 자른다**.

### 2.3 거절은 셋으로 갈린다

```
(a) 사전 거절   정점 변환 실패 / 정책 밖
      -> 쌓인 WARP 를 플러시하고, 그 삼각형만 사다리꼴로
(b) 가득 참
      -> 플러시·리셋 후 같은 삼각형을 다시 시도
(c) 커널이 조립된 배치를 거절
      -> 누적된 소스 삼각형 ** 전부 ** 를 소프트웨어로 재생
```

**(c) 에서 좁히지 않는다.**  사다리꼴 경로는 거절된 사다리꼴의 소스를 찾아
*"서른 대신 소프트웨어 삼각형 하나"* 로 좁히지만, WARP 검증기는 `badRun` 을
돌려주지 소스를 지목하지 않고 — **정점 실패는 런조차 지목하지 않는다**(내
검증기가 정점 루프 전에 `badRun` 을 0 으로 되돌린다).

좁히기는 최적화이고 **정확성이 먼저다.**  유저랜드 빌더가 커널과 같은 규칙으로
미리 검사하므로 이 거절은 드물어야 한다.  잦으면 그때 런→소스 지도를 넣는다.

## 3. 정점을 만든다

```c
OSMGAMesaBuildWarpVertex(v, tex, ctx->PolygonZoffset, out)
```

- **오프셋을 넘긴다** — 안 넘기면 조용히 사라진다(M9 에서 잡은 구멍)
- **flat 이면 세 정점이 `prov` 의 색**을 갖는다 (사다리꼴이 그렇게 한다)
- 범위 밖이면 거절 → (a)

## 4. 기본은 꺼짐

**새 스위치 하나**, 인스턴스 표에서 기본 `No` — `WARP Depth Test` 와 같은
모양이다.  A/B 가 두 층이 같은 그림을 낸다고 말하기 전에는 켜지지 않는다.

## 7. 자체 확인 (codex 회신 전)

### 7.1 `badRun` 은 정점 실패를 지목하지 못한다 — 확인

`osmgaHW3DValidateWarp` 안의 `badRun` 대입을 전부 뽑았다:

```
*badRun = 0UL      진입에서
*badRun = r        런 루프 안에서
*badRun = 0UL      ** 런 루프를 통과한 뒤 **
```

정점 루프는 그 **뒤**에 돈다.  그러므로 `E_VTXFLOAT` 은 언제나 `badRun = 0`
을 달고 나온다 — **런 0 을 지목하는 것이 아니라 아무것도 지목하지 않는
것**이다.  §2.3 의 "좁히지 않는다" 는 그래서다.

### 7.2 flat shading 은 세 정점 같은 색이면 같다 — 확인

사다리꼴 빌더는 `flat != 0` 이면 색 시작값을 그 정점에서 가져온다
(`Triangle.c:861`):

```c
t->dr[0] = flat->r << 15;
t->dr[3] = flat->g << 15;
t->dr[6] = flat->b << 15;
```

곧 **상수 색**이다.  WARP 에 세 정점 같은 색을 주면 보간이 무엇을 하든 그
상수가 나온다 — 섞을 것이 없으므로 T8b 가 잰 반올림도 걸리지 않는다.

알파는 **훅이 이미 평평하게 만든다**(`Hook.c` 의 `a.a = b.a = c.a = prov.a`),
그러니 WARP 쪽에서 더 할 것이 없다.

### 8.1 용량 — 넓힌다

```
pendSrc 항목  색인 넷 + 포인터 넷 + firstTrap  = 약 36 바이트
180 -> 240 로 넓히는 비용  = 60 x 36 = 2,160 바이트 (유저랜드 BSS)
WARP 를 180 으로 묶는 비용 = 배치의 25%
```

넓힌다.  경계를 **명시**한다 — `max(MAX_TRI, MAX_VTX/3)`.

### 8.2 가장 중요한 정정 — 재생의 경계

```
verdict != OK   커널이 인코딩 전에 거절했다.  아무것도 안 그렸다.
                -> 누적 소스 전부를 기록 순서대로 소프트웨어 재생
verdict == OK   도어벨을 울린 뒤 실패했다.  ** 일부가 그려졌을 수 있다. **
                -> 재생하지 않는다.  revoke.  M10 의 커널 정책과 같다
```

**이 구분을 잃으면 그려진 것을 두 번 그린다** — 블렌딩과 같은 깊이에서
그림이 달라진다.
