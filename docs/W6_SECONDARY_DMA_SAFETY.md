# W6 — 2 차 DMA 의 회수·격리 설계 (2 판)

**1 판은 codex 교차검토에서 "이 설계로는 코드를 쓰지도, 실기 시험을 하지도
말라 — 금지가 풀리지 않는다" 는 판정을 받았고, 전부 확인했다.**

가장 큰 것: **1 판의 중심 사실이 거짓이었다.** "어느 참조도 리셋 레지스터를
쓰지 않는다" 고 썼는데 **X.Org 에 `MGASoftReset()` 이 있다.** 내 grep 이
`MGAREG_RST` 를 찾았고 그 헤더는 `MGAREG_Reset` 으로 쓴다 — **오늘 세 번째로
"있을 거라 생각한 이름" 을 찾고 "실재하는 이름" 을 놓쳤다.**

판정표는 §8. **결론: `SECADDRESS` 금지는 유지된다.**

W2 §7 이 금지한 것을 푸는 문서다:

> **`SECADDRESS` 를 회수 절차 없이 쓰기 — 금지.**
> *"`SECADDRESS` 를 되돌리는 절차를 먼저 정하거나, 그 대조를 하지 않는다."*

**여기에는 코드가 없고, 이 문서만으로 실기를 건드리지 않는다.**

## 0. 금지 목록 대조 — 설계 **전에** 했다

| 금지 | 이 설계와의 관계 |
| --- | --- |
| 시저 + 계측을 같은 실행에 | 이 설계는 시저를 쓰지 않는다 |
| 제출마다 `gettimeofday` | 넣지 않는다 |
| 이상 징후 후 재시도 | §5 의 실패 정책이 그대로 따른다 |
| **`SECADDRESS` 회수 절차 없이 쓰기** | **이 문서가 다루는 것** |

## 1. 리셋은 **있다.** 그리고 참조는 우리 상황에서 그것을 쓰지 않는다.

### 1.1 1 판의 정정

`xf86-video-mga-2.0.0/src/mga_driver.c:1020`:

```c
void MGASoftReset(ScrnInfoPtr pScrn)      /* "Resets drawing engine" */
{
    OUTREG(MGAREG_Reset, 1);              /* 0x1e40 */
    usleep(200);
    OUTREG(MGAREG_Reset, 0);
    OUTREG(MGAREG_MACCESS, 1 << 15);      /* reset memory */
    usleep(10);
    ...
```

**절차가 존재하고, 값과 지연까지 적혀 있다.** 정의도 두 헤더가 아니라
**셋**이다(`mga_drv.h:496`, `mga_reg.h:110`, `mgaregs.h:611`).

1 판에서 살아남는 것은 하나뿐이다: **DRM 의 `mga_do_dma_reset` 은 하드웨어를
건드리지 않는다** — 소프트웨어 카운터와 FIXME 둘. 그것은 재확인했다.

### 1.2 그런데 X.Org 는 그것을 **주 카드에 쓰지 않는다**

호출부가 둘이고 **둘 다 같은 가드 아래**에 있다:

```c
/* Reset card if it isn't primary one */
if ( (!pMga->Primary && !pMga->FBDev) )
    MGASoftReset(pScrn);
```
`mga_driver.c:2167`, `mga_merge.c:389`

**우리 카드는 콘솔을 소유한다. 즉 주 카드다.** 그리고 이 리셋은
**초기화 경로**에 있지 타임아웃 복구 경로가 아니다.

바로 뒤의 `#if 0` 이 한 줄 더 말해 준다 — *"This will hang if the PLLs aren't
on"*. 리셋 근처의 코드가 **상태에 따라 행한다는 것을 저자가 알고 꺼 두었다.**

### 1.3 그래서 위치가 바뀌었다

1 판: *"절차가 없으니 만들 수 없다."* → **틀렸다.**
2 판: **절차는 알려져 있고, 우리 상황(주 카드, 프리즈 직후)에서 그것을 쓰는
전례가 없으며, 실패하면 콘솔과 복구 채널을 함께 잃는다.**

이것은 "불가능" 이 아니라 **"검증되지 않은 것을 가장 나쁜 순간에 처음 써 보는
일"** 이다. §3-62 의 "이상 징후 후 재시도 금지" 가 겨냥한 행동과 같은 종류다.

### 1.4 더 좁은 무장 해제 후보 — WARP 만 세우기

codex 가 짚었고 확인했다. `mga-drm/mga_warp.c:177`:

```c
MGA_WRITE(MGA_WIADDR2, MGA_WMODE_SUSPEND);
```

**WARP 를 엔진 전체 리셋 없이 정지시키는 쓰기가 있고 DRM 이 초기화에서
쓴다.** 2 차 DMA 가 먹이는 대상이 WARP 이므로, **무장 해제의 후보로는 전체
리셋보다 이쪽이 훨씬 좁다.**

**다만 이것도 초기화에서 쓰인 것이지 실행 중 중단으로 검증된 적은 없다.**
다음 설계가 조사할 것으로 남긴다.

## 2. W2-1 음성 대조 — 하지 않는다. 다만 이유를 정정한다.

**결정은 유지한다**: `SECADDRESS` 만 쓰고 `SECEND` 를 쓰지 않는 대조는 하지
않는다. 가설이 틀리면 범위도 회수도 없다.

**그러나 1 판이 그것을 "기능이 아니라 가설의 확인일 뿐" 이라고 격하한 것은
틀렸다.** 그 사실은 실제 경로가 안전한지를 결정한다:

- `SECEND` 만 전송을 시작한다면 → `SECADDRESS` 를 먼저 쓰는 것은 무해하다
- `SECADDRESS` 가 **이전 `SECEND` 값에 대해** 시작할 수 있다면 →
  **모든 실제 제출에 stale-end 창이 있다**

**옳은 표현은 "무관" 이 아니라 "미지이며 현재로서는 시험 불가" 다.**
매뉴얼·더 강한 참조 증거·완료 판정과 회수가 생긴 뒤의 유계 실험 중 하나로만
메울 수 있다.

---

## 3. 실제 경로 — 1 판의 원자성 주장은 자기 검토로 이미 철회했다

DMA 블록은 인덱스 1 + 값 4 dword 이고 카드는 **순서대로** 적용한다. 그러므로
`SECADDRESS` 만 설정된 순간은 **존재한다.** (1 판 §3.0 에서 스스로 잡았고
codex 도 같은 결론이다.)

참조 코드 자신이 블록 내 **순서에 의존한다**: WARP 를 셋업 전에 세우고
나중에 출발시키며(`mga_state.c:282`, `:343`), 같은 블록 안에서 `EXEC` 가
뒤의 쓰기보다 앞설 수 있다(`:305`). 우리 드라이버도 SGN·Z 시작이 실행보다
앞서야 한다고 적는다(`:931`).

### 3.1 1 차의 관측은 유추의 근거는 되지만 증명은 아니다

`PRIMADDRESS` 를 먼저 쓰고 `PRIMEND` 로 출발시키는 것은 이 기계에서 프레임당
33 회, A0 만 세어도 86,554 회 관측됐다. DRM 의 IRQ 도 `PRIMEND` 재기록으로
DMA 를 재출발시킨다(`mga_irq.c:81`).

**그러나 그것은 1 차의 사실이지 2 차의 사실이 아니다.** 레지스터 쌍이 대칭인
것은 이름과 인코딩이지 트리거 의미론이 아니다. **codex 의 표현이 정확하다:
"같은 블록" 은 CPU 스케줄링 틈을 없앨 뿐 장치가 보는 레지스터 순서 틈을
없애지 못한다.**

**따라서 실제 경로의 안전 논증은 성립하지 않는다.** 트리거·래치 의미론을
독립적으로 확보하기 전에는.

## 4. 봉쇄 — 클립은 **측정된 것까지만** 경계다

측정 자체는 유효하고 값어치가 있다:

| 무엇 | 어디 | 결과 |
| --- | --- | --- |
| 클립이 기울어진 스팬에 유효한가 | `D3_2` §6 | 가드 열·행 **0 px** |
| 기울어진 변의 깊이 쓰기 | `D3_4` V4b-D | 확인 |
| 시저 경계 아홉 점·빈 상자·표면 밖 | `REMAINING_WORK:32` | 소프트웨어와 화소 일치 |

**그러나 1 판은 이것을 WARP 까지 일반화했고, 그것이 틀렸다.**

- 이 측정들은 **우리가 만든 사다리꼴을 직접 그린 경로**를 쟀다. **WARP 가
  만들어 내는 셋업, 잘못된 정점 레코드, NaN/무한대, 셋업 오버플로, 레코드
  크기와 마이크로코드의 불일치는 하나도 안 쟀다.**
- 클립은 **목적지 래스터 쓰기**를 묶는다. **2 차 DMA 의 시스템 메모리 읽기,
  WARP 마이크로코드 읽기, 텍스처 읽기는 안 묶는다.** 텍스처 봉쇄는
  `TEXORG`·크기·피치·클램프로 따로 논증해야 한다.
- **"읽기니까 나쁜 기하일 뿐" 도 과했다.** 할당 밖을 읽으면 무관한 메모리가
  장치에 노출되고, PCI 오류가 나거나 버스 중재가 막힐 수 있다 — 후자는
  §3-62 가 못 닫은 후보 그 자체다.

**정정**: 클립은 **측정된 직접 경로에 대한** 하드웨어 경계다. §12 의 "증명이
정책이 된다" 는 걱정은 **줄지 않는다.** W2 §12 가 이미 적어 둔 대로 WARP 셋업
결과는 호스트 검증이 볼 수 없고, 보수적 텍스처 도달 범위는 증명이 아니라
정책이며, 극단적 정점 텍스처 좌표는 측정된 적이 없다.

## 5. 격리 — 이 부분은 1 판이 옳다

`osmgaSubmitGaveUp(:2263)`: 래치를 호출자가 먼저 세우고, 카운터는 RAM 에서
오르고, **핸들러는 칩을 건드리지 않는다.** 세 번째 프리즈가 가르친 것이다.

**2 차 DMA 가 추가돼도 이 정책은 바뀌지 않는다.** 다만 §1.4 의 WARP 정지가
검증되면, "영구 중단" 앞에 **"WARP 만 세워 본다"** 한 단계를 넣을 여지가
생긴다 — 검증 뒤의 이야기다.

## 7. 다음 설계가 가져와야 할 것

> **2026-08-28: 이 여섯 항목의 참조 조사가 `W7_REFERENCE_EVIDENCE.md` 로
> 끝났다.** 구할 수 있는 참조를 전부 썼고(출하 Windows 드라이버 포함),
> **매뉴얼이 없어서 남는 간극은 전부 실기 실험을 요구한다.** 아래 목록은
> 그대로 유효하고, 각 항목이 지금 어디까지 왔는지는 W7 §7 을 본다.

1. **SEC 트리거 의미론** — 문서·더 강한 참조 증거·안전한 유계 실험 중 하나.
   이것 없이는 아무것도 진행되지 않는다.
2. **2 차 완료·회수 판정.** codex 의 단서: DRM 은 2 차 버퍼를 1 차 tail 로
   aging 하고 `PRIMADDRESS` 가 지나야 재사용한다 — **참조가 1 차 진행을 2 차
   회수의 충분 증거로 쓰고 있거나, 잠복 수명 버그를 갖고 있거나 둘 중
   하나다.** 어느 쪽인지 밝히는 것이 완료 판정 작업의 출발점이다.
3. **WARP 정지(`WIADDR2 = WMODE_SUSPEND`)가 실행 중에도 듣는가** (§1.4).
4. **WARP 고유의 봉쇄 논증** — 클립 밖의 읽기 경로 셋(2 차, 마이크로코드,
   텍스처)과 셋업 오버플로.
5. **수명·모드·클라이언트 규칙**: 언로드 금지의 강제, 2 차 정지까지의 불변성,
   claim 실패 후에도 진행하는 모드 변경의 금지, 저메모리 동시 할당
   (1 차 64 KiB + 마이크로코드 24 KiB + 2 차 스테이징 ≈ **112 KiB**) 을
   WARP 활성화 **전에** 한꺼번에 확보하고 실패 시 닫기.
6. **가시성 장벽** — 소유와 물리 연속성은 캐시 일관성을 뜻하지 않는다.

## 9. DRM 의 aging 은 충분 증거인가, 잠복 버그인가 — **충분하다** (2026-08-28)

§7-2 가 다음 설계의 출발점으로 지목한 질문이다. 소스 조사만 했고 하드웨어는
건드리지 않았다.

### 9.1 DRM 이 실제로 하는 것 — 전부

```c
/* Buffer aging via primary DMA stream head pointer. */   mga_drv.h:361

AGE_BUFFER(buf_priv):   entry->age.head = prim.tail + primary->offset
TEST_AGE(age, h, w):    age.head < h            (엄격 부등호)
mga_freelist_get():     head = MGA_READ(MGA_PRIMADDRESS);
                        if (TEST_AGE(...)) 재사용
```

**대기도, idle 검사도, 2 차 상태 조회도 없다.** `SECADDRESS`/`SECEND` 는 소스
전체에서 **정점 디스패치 한 곳**(`mga_state.c:679`)에만 나오고 어디서도
기다리지 않는다.

> **초판은 "디스패치 두 곳(정점, 인덱스)" 이라고 썼다. 틀렸다** — 인덱스
> 디스패치(`:728`)는 `SETUPADDRESS`/`SETUPEND` 를 쓴다. **§9 의 aging 논증은
> 정점 루프만으로 성립하므로 결론은 그대로다**(그 루프가 클립과 SEC 발사를
> 번갈아 낸다). 사실관계만 정정한다.

`SECEND` 에 실리는 `dma_access` 는 동기화 비트가 아니다 — AGP 는
`MGA_PAGPXFER`, PCI 는 **0**(`mga_dma.c:596`, `:699`)이고, **`PRIMEND` 에도
똑같이 실린다**(`:159`, `:199`). 채널 속성이지 2 차 전용 제어가 아니다.

### 9.2 결정적 증거 — 참조 자신이 그렇지 않으면 깨진다

정점 디스패치 루프가 1 차 스트림에 내는 것(`mga_state.c` 정점 디스패치):

```
clip(box0) -> SEC(buf) -> clip(box1) -> SEC(buf) -> clip(box2) -> SEC(buf)
```

**같은 정점 버퍼를 클립 사각형마다 한 번씩** 그린다. 그리고
`mga_emit_clip_rect` 는 `CXBNDRY`/`YTOP`/`YBOT` 를 **1 차 스트림으로** 쓴다.

**1 차 파서가 2 차의 배수를 기다리지 않는다고 가정해 보자.** 그러면
`clip(box1)` 이 box0 의 정점이 아직 인출·래스터화되는 중에 프로그래밍되고,
**같은 삼각형이 틀린 사각형으로 클리핑된다.**

**다중 사각형 클리핑은 X 에서 예외가 아니라 일상이다** — 일부가 가려진 창은
전부 `nbox > 1` 이다. 그러니 그 고장은 드문 것이 아니라 **상시로, 눈에 보이게**
났을 것이다.

**따라서 1 차 파서는 2 차에 대해 직렬화한다.** SEC 블록을 소비하기 전에는
그 너머로 나아갈 수 없다.

### 9.3 그래서 aging 은 무엇에 대해 충분한가

```
age = prim.tail          (SEC 블록 다음 위치)
head > age  =>  파서가 SEC 블록을 소비했다
            =>  9.2 에 의해 2 차가 배수됐다
            =>  카드가 그 버퍼 읽기를 끝냈다
```

**버퍼 재사용에 대해 충분하다. 잠복 버그가 아니다.**

**그러나 "그리기가 끝났다" 에 대해서는 충분하지 않다** — WARP 와 그 아래
래스터 단계가 아직 일하는 중일 수 있고, 그것들은 버퍼를 다시 읽지 않는다.

**DRM 은 이 둘을 혼동하지 않는다**: 버퍼 재사용은 aging, "그리기 완료" 는
`mga_irq.c:73` 의 SOFTRAP 펜스. **1 판이 §2 에서 이 둘을 섞어 본 것이 실수였고,
참조는 처음부터 나눠 놓았다.**

### 9.4 우리에게 무엇을 뜻하는가 — §6 의 blocker 가 줄어든다

§6 은 이렇게 적었다:

> **2 차 DMA 완료 판정.** 1 차가 soft trap 에 닿아 "끝났다" 고 판정하는 동안
> 2 차가 아직 메모리를 읽고 있을 수 있다.

**9.2 가 맞다면 그 문장은 성립하지 않는다.** 1 차가 SOFTRAP 에 닿으려면 그
앞의 SEC 블록을 이미 소비했어야 하고, 소비했다면 2 차는 배수된 것이다.

우리 모델에서는 더 강하다. DRM 은 움직이는 링의 head 를 보지만, 우리는 제출마다
`PRIMADDRESS`/`PRIMEND` 를 새로 쓰고 **완료 예측 전체**(`SOFTRAPEN` +
`ENDPRDMASTS` + `DWGENGSTS` 없음)를 폴링한다. 그 예측이 성립하면 **SEC 블록을
포함한 목록 전체가 소비된 것**이다.

> **즉, 지금 있는 완료 판정이 2 차까지 덮을 가능성이 높다.**

### 9.5 그러나 이것은 **추론**이지 측정이 아니다 — 경계를 긋는다

- 9.2 는 **참조가 동작한다는 사실로부터의 역추론**이다. 우리 기계에서 잰
  것이 아니고, 매뉴얼로 확인한 것도 아니다.
- 강한 추론이다 — 반례가 있으면 X 의 일상 사용에서 상시로 보였을 것이다.
  그러나 **강한 추론과 측정은 다르고, 이 프로젝트는 그 차이로 값을 치른
  적이 있다.**
- 그리고 이것은 **읽기 완료**에 대한 것이다. WARP 실행 완료, 래스터 완료,
  CPU 가시성은 각각 별개이고 §3(다섯 상태)이 이미 나눠 두었다.

**확인하는 방법**(하드웨어, 나중): 다중 클립 사각형에 해당하는 것을 만든다 —
같은 정점 버퍼를 서로 다른 클립으로 두 번 발사하고, **두 그림이 각자의 클립을
지키는지** 본다. 지키면 직렬화가 실증된다. 안 지키면 aging 은 우리 카드에서
충분하지 않고, 그때는 §6 의 원래 문장이 옳다.

**그 시험조차 `SECADDRESS` 를 쓰므로 §7 금지 아래에 있다.** 트리거 의미론
(§2)이 먼저다. 순서는 바뀌지 않는다.
