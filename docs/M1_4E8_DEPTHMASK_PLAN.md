# M1.4E8 — GL_NEVER 는 죽었고, glDepthMask 는 atype 에 걸려 있다

## 확정된 사실 (원본 근거)

`xf86-video-mga-2.0.0/util/stormdwg.c` 는 Matrox 자신의 레지스터 해독기다.

```
atype[]  011 "z1 - depth mode with gouraud"      (stormdwg.c:32)
         111 "I - Gouraud (with depth compare)"  (stormdwg.c:35)
zmode[]  001 "reserved"                          (stormdwg.c:40)
```

* **`zmode` 1 은 NEVER 가 아니라 예약값이다.** "GL 함수 여덟 개 중 하나가
  비었으니 그게 NEVER" 라는 내 추측은 원본이 부정한다. `atmode` 1 도 Xorg 플래그
  헤더가 이름 붙이지 않는다(`src/mgareg_flags.h:71-78`). 다른 필드에는 NEVER 가
  **명시적으로** 있다 — `SC_smode_snever = 1` (`mgareg_flags.h:568`). 즉 Matrox 는
  필요하면 이름을 붙인다. 안 붙였다는 건 없다는 뜻이다.
  → **`GL_NEVER` 는 깊이·알파 양쪽에서 계속 거절한다. 이제 근거가 있다.**

* **`I` 와 `ZI` 의 차이는 "비교하느냐" 가 아니라 "쓰느냐" 로 읽힌다.** ZI 는
  "depth mode", I 는 "with depth compare". 이게 사실이면
  **`glDepthMask(GL_FALSE)` = atype I + 진짜 zmode** 이고, atype I 는 검증기가
  **이미 허용하는** 인코딩이다.

* 지금 우리 무-깊이 경로가 atype I 로 멀쩡한 이유는 그때 `zmode` 가 0(NOZCMP,
  always)이기 때문이다 (`mesa/OpenStepMGAMesaTriangle.c:20`). 항상 통과하는 비교와
  비교 없음은 화면에서 구별되지 않는다. **모순 없음.**

## 왜 유저랜드에서 못 재는가

ZI 삼각형이 하나도 없으면 인코더가 `ZORG` 에 진짜 깊이가 아니라 고정 스크래치
`OSMGA_D3_ZORG` 를 넣는다(`OpenStepMGAReplacementDisplay.m:7002-7005`). 검증기도
`anyZI` 일 때만 `zorg` 를 봉쇄한다(`hw3d/OpenStepMGAHW3D.c:351-365`). 그래서 atype I
삼각형이 깊이를 비교하더라도 **내 깊이 버퍼가 아닌 곳**과 비교한다. 배치는 GL
삼각형 하나당 하나라 ZI 를 섞어 넣을 수도 없다.

→ 커널 변경이 필요하다. **재부팅 한 번의 값어치가 있는 항목.**

## 계획

1. **술어를 한 곳에** — "이 삼각형이 깊이를 주소지정하는가": `atype == ZI` 이거나
   `atype == I && zmode != NOZCMP`. 검증기와 인코더가 각자 손으로 ZI 를 적고 있는
   지금 구조가 바로 구멍이 생기는 방식이다.
2. **검증기**는 그 술어가 참인 배치마다 `zorg` 를 봉쇄한다. 비교하는 atype I 은
   깊이를 **읽는다**. 봉쇄되지 않은 읽기도 클라이언트에게 줄 것은 아니다.
3. **인코더**는 같은 술어로 진짜 `zorg` 를 넣는다.
4. ABI 버전 8. 능력 조사는 정확히 같은 값만 받는다.
5. 그 다음 **유저랜드만**: 깊이 시험이 켜진 채 `glDepthMask(GL_FALSE)` 를 atype I +
   진짜 zmode 로 내보내고, 시험이 세 가지를 묻는다 — 비교가 실제로 버리는가,
   깊이 버퍼가 그대로인가, 색이 소프트웨어와 같은가. 깊이는 공유 VRAM 매핑으로
   읽고, **공유임을 단언**하고, **엔진이 그렸음을 단언**한다.
6. 아니라고 나오면 5 만 유저랜드에서 되돌린다. 1~3 은 어느 쪽이든 남는다:
   클라이언트는 **오늘도** atype I + 0 아닌 zmode 를 보낼 수 있고 그때 스크래치
   ZORG 를 받는다.

## 재부팅 후 첫 실행

```
tdc      # atype I 가 깊이를 비교하는가, 그리고 쓰지 않는가
reach    # 검증기 단위시험 (I+ZLT+나쁜 zorg -> E_ZORG 포함)
```

`tdc` 가 "compares depth and does not write" 라고 답하면, 그 다음은 **유저랜드만**
고치면 된다 — `glDepthMask(GL_FALSE)` 를 atype I + 진짜 zmode 로 내보내고 Mesa
시험을 붙인다. 재부팅은 필요 없다.

# 측정 결과 (재부팅 후, 커널 v8)

```
atype I + ZLT: near band drew 1280 of 1280, far band drew 0 of 1280,
               depth moved in 0 pixels
ANSWER: atype I compares depth and does not write it
```

**`glDepthMask(GL_FALSE)` 는 표현 가능하다.** 같은 실행의 ZI 대조군 네 띠는
정확히 기대대로 그리고 **깊이를 썼다**(`depth!=want` 전부 0). 검증기 네 사례도
모두 옳다: ZI+나쁜 zorg→5, I+NOZCMP+나쁜 zorg→0, I+ZLT+나쁜 zorg→**5**.

### 옛 사례가 16 을 냈던 이유

`E_DSTPITCH`. 그 두 사례는 `dstWidth/dstHeight/dstPitch` 를 설정하지 않았고,
피치 검사가 깊이 원점 검사보다 **앞선다**. 세 필드를 넣자 16 이 5 와 0 으로
바뀌었다 — 주장이 아니라 측정으로 확인. (다만 "아무도 안 돌렸다" 는 것은 추론이다:
빌드 스크립트에 없었다는 사실이 증명하는 건 그 스크립트가 안 만들었다는 것뿐이다.)

### 증인 논리 (python 검산)

`glOrtho(0,W,0,H,-1,1)` 이므로 창 깊이는 `(1-z)/2` — **z 가 클수록 가깝다**.
씨앗을 가운데 두고 탐침을 한쪽 끝, 증인을 그 사이에 둔다. 증인은 **탐침이 깊이를
쓰지 않았을 때만** 통과한다:

| 함수 | seed | probe | witness | 안 썼으면 | 썼으면 |
| --- | --- | --- | --- | --- | --- |
| LESS | 0.50 | 0.20 | 0.35 | 통과 | 거절 |
| GREATER | 0.50 | 0.80 | 0.65 | 통과 | 거절 |
| LEQUAL | 0.50 | 0.20 | 0.35 | 통과 | 거절 |

읽기로 답할 수 없는 쓰기를 이게 잡는다.

## 구현과 그 증명

**구현** — 접근 유형이 두 질문을 다 나른다: ZI 는 비교하고 쓰고, I 는 비교만 한다.

* `OSMGAMesaBuildTriangle`/`...Tex` 에 `int depthWrite` 를 **추가 매개변수**로 넣었다.
  zmode 값 안에 접어 넣지 않은 이유는, 빠뜨린 호출부가 **조용히** 깊이를 쓰기
  때문이다. 매개변수면 컴파일이 안 된다. 호출부 열 곳 + 훅 두 곳을 고쳤고,
  헬퍼 `osmgaTrapezoid` 까지 내려보냈다(dwgctl 조립은 진입점이 아니라 거기 있다).
* 훅은 `ctx->Depth.Mask == GL_TRUE` 를 넘기고, `Depth.Mask != GL_TRUE` 거절을
  없앴다.

**증명** — `tdm`, 엔진 대 소프트웨어. 세 함수 각각에 세 질문을 묻는다:

```
GL_LESS     engine probe 1 witness 1 depthmoved 0   software 1 1 0
GL_GREATER  engine probe 1 witness 1 depthmoved 0   software 1 1 0
GL_LEQUAL   engine probe 1 witness 1 depthmoved 0   software 1 1 0
GL_ALWAYS 마스크 끔:  depth 8000 -> 8000, 더 먼데도 그려짐
마스크 켬 대조군:      depth 8000 -> 3333
```

**증인**이 핵심이다. 씨앗과 탐침 사이 깊이에 세 번째 사각형을 그린다 — 탐침이
깊이를 **쓰지 않았을 때만** 통과한다. 읽기로는 못 잡는 쓰기를 이게 잡는다.
마지막 줄이 반대편 대조군이다: 마스크를 켜면 깊이는 여전히 움직인다. 없으면
"깊이를 아예 안 쓰게 된 드라이버" 도 위 표를 전부 통과한다.

`tdc` 쪽도 codex 가 지적한 혼동을 닫았다:

```
atype I + ZLT: near 1280/1280, far 0/1280, depth moved 0
control: the same rows with NOZCMP drew 1280 of 1280
guard after the atype I batches: colour 0, depth 0
```

먼 띠가 비어 있던 것은 그 **행을 못 그려서가 아니다** — 같은 행이 NOZCMP 로는
전부 그려진다. 남는 설명은 비교뿐이다.

## 아직 거절하는 것

`GL_NEVER`(깊이·알파), `GL_SRC_ALPHA_SATURATE`, 분리된 알파 블렌드 인자,
polygon smooth/stipple. `GL_NEVER` 는 이제 **원본 근거**로 거절한다: `zmode` 1 과
`atmode` 1 은 예약값이지 NEVER 가 아니다.

## 투명 패스 — 이 기능이 존재하는 이유

깊이 시험을 켜고(앞의 불투명 도형에 가려지도록) 마스크를 끈 채(반투명끼리는 서로
가리지 않도록) 겹쳐 그리는 것이 전부다. 마스크를 켜면 먼저 그린 층이 깊이를 써서
뒤 층을 **전부 거절**하고, 그림은 한 겹만 남는다.

```
벽(불투명, 가장 뒤)  z=-0.5  창 깊이 0.75
초록(반투명, 가장 앞) z= 0.6  창 깊이 0.20   ← 먼저
파랑(반투명, 중간)    z= 0.2  창 깊이 0.40   ← 나중

마스크 끔:  0.40 < 0.75  → 통과 (파랑 보임)
마스크 켬:  0.40 < 0.20  → 거절 (파랑 사라짐)

engine  : pixel 3f4080, blue layer present
software: pixel 3f3f80, blue layer present
```

색이 아니라 **어느 층이 남았는가**로 판정한다. 엔진은 한 번 반올림하고 Mesa 는
절사하므로 두 경로는 설계상 한 단계씩 다를 수 있고(여기서도 초록 채널이 `40` 대
`3f`), python 이 계산한 `3f3f80` 은 소프트웨어 값과 정확히 같다. 파랑이 그림에
있느냐 없느냐는 그 차이에 흔들리지 않는다.

자고 있다 — 커널 쪽 대기이지 프로브 계산이 아니다. 미해결로 남긴다.
