# M1-4E1 — Mesa 는 rung 을 요청해야 하는가

기구는 §84 가 실증했다.  남은 것은 **정책**이다: Mesa 가 무엇을, 언제
요청하는가.  그리고 그 앞에 먼저 답해야 할 질문이 있다 — **요청해야 하는가.**

## 1. 이음매의 실제 크기

`§82` 는 세 단 차이(rung 0 대 rung 3, 창 112)를 **일부러 만들어** 쟀다.
실제 기하에서 이웃한 두 사다리꼴의 도달범위는 가깝다.

창의 폭은 두 bias 의 차다:

```
   rung 0 대 1 ->  16      rung 3 대 4 -> 128
   rung 1 대 2 ->  32      rung 4 대 5 -> 256
   rung 2 대 3 ->  64
```

그리고 **몇 단 벌어지려면 도달범위가 몇 배 차이나야 한다**:

```
   1 단 -> 약 2 배    2 단 -> 약 4 배    3 단 -> 약 8 배
```

즉 세 단이 벌어지려면 이웃한 두 프리미티브의 좌표 최대값이 **8 배** 달라야
한다.  타일 바닥에서는 일어나지 않는다.

## 2. 그러면 몇 화소가 움직이나

움직이는 화소의 비율은 `창 / 텍셀` 이다 — 표본이 네 개든 몇 개든, 위상이
고르든 아니든.

```
   TD      텍셀    인접 단 (16)   세 단 (112)
   16     65536     0.02%          0.17%
   64     16384     0.10%          0.68%
   256     4096     0.39%          2.73%
   1024    1024     1.56%         10.94%
   2048     512     3.12%         21.88%
```

**인접 단이 실제 경우다.**  TD 2048 에서 3.1%, TD 1024 에서 1.6%.  이음매를
따라 화소의 3% 가 한 텍셀 어긋나는 것은 **눈에 띄는 톱니**다 — 작지만 없지
않다.

`§82` 의 4 표본 격자에서 "인접 단은 안 문다"고 볼 뻔했는데, 그건 그 격자의
위상 집합에서만이다.  일반적인 비율에서는 `창/텍셀` 만큼 문다 — python 이
표본 4·1·7·0.5 개/텍셀에서 전부 같은 값을 낸다.

### 2-1 그런데 하나의 이음매는 평균이 아니다

`창/텍셀` 은 **위상을 고르게 훑었을 때**의 비율이다.  하나의 이음매는 위상이
고정돼 있다.  그리고 이음매를 따라 좌표가 **변하지 않는** 경우 — 세로 이음매
에서 `u` 가 상수인 경우가 그렇다 — 그 이음매는 위상 하나만 겪는다:

```
   그 위상이 창 안이면   이음매 전체가 한 텍셀 어긋난다   100%
   창 밖이면             전혀 안 보인다                    0%
```

즉 "화소의 3.1%"가 아니라 **"이음매의 3.1% 가 통째로 보인다"** 이다.  후자가
눈에 훨씬 나쁘다 — 흩뿌려진 잡음이 아니라 한 줄의 어긋난 경계다.

## 3. 그러므로 정책이 필요하다 — 다만 대가가 있다

요청은 **자기보다 높은 rung 만** 만든다.  높은 rung 은 잔차가 크다:

```
   rung 0 -> 잔차 0        rung 3 -> 잔차 112
   rung 1 -> 잔차 16       rung 4 -> 잔차 240
   rung 2 -> 잔차 48       rung 5 -> 잔차 496
```

(좌표의 addend 가 496 일 때.)  TD 2048 에서 잔차 496 은 텍셀의 96.9% — 그림이
한 텍셀 밀린다.  **그러니 필요 이상으로 높게 요청하면 안 된다.**

## 4. 정책 후보

### A. 아무것도 요청하지 않는다 (지금)
이음매가 남는다.  TD 2048 에서 3.1%.

### B. 지난 패스의 최대 rung 을 이번 패스 내내 요청한다
`RenderStart`/`RenderFinish` 가 이미 훅에 걸려 있다.  패스 안에서는 값이
고정이므로 패스 안의 이음매가 사라진다.  첫 패스와 **장면이 바뀌는 패스**에는
남는다.  정지된 그림에서는 한 프레임 만에 수렴한다.

### C. 텍스처가 클 때만 B
이음매가 무는 정도는 `창/텍셀` 이므로 작은 텍스처에서는 요청할 이유가 없다.
`TD ≤ 256` 이면 인접 단 이음매가 0.39% 이하다.  그때는 요청하지 않아 정확도를
지킨다.

### D. 삼각형마다 자기 좌표에서 rung 을 계산해 요청한다
아무 효과가 없다 — 그건 커널이 이미 하는 `자기 rung` 이다.

## 5. 무엇이 안전한가

**어떤 요청도 안전하다.**  커널이 `max(자기, min(요청, headroom))` 을 취하므로,
틀린 추정은 정확도나 연속성을 잃을 뿐 잔차를 음수로 만들지 못한다.  그래서
정책은 "맞히면 좋고 틀려도 안 깨지는" 종류다.

## 6. 기울어진 것

**C 로 기운다.**  B 의 대가(첫 패스, 장면 전환)는 작고, C 는 그 대가를
이음매가 실제로 보이는 크기에서만 치른다.

다만 B 의 "지난 패스"에는 함정이 있다: 패스마다 최대가 크게 흔들리면 정확도가
프레임마다 달라져 **깜빡임**이 된다.  요청을 **단조 증가**로만 두면(한 번 올린
rung 은 내리지 않는다) 깜빡임은 없어지지만 한 번의 큰 프레임이 영구히 정확도를
낮춘다.

## 7. 교차검토에 물을 것

- §1 의 "실제 기하에서는 인접 단"이 정말 맞나.  이웃한 사다리꼴의 도달범위가
  8 배 벌어지는 실제 경우가 있나
- §2 의 `창/텍셀` 이 표본 위상과 무관하다는 것이 맞나
- B 의 깜빡임과 단조 증가 중 어느 쪽이 나쁜가.  세 번째 길이 있나
- C 의 문턱을 어디에 둘 것인가 — `TD` 인가 텍셀 크기인가, 축마다인가
- 이 정책이 **틀렸을 때** 무엇이 보이나.  그걸 시험으로 잡을 수 있나
- A(아무것도 안 함)를 유지하고 기구만 남기는 것이 정당한가

## 9. 그래서 쟀다 — 평범한 Mesa 기하는 이음매를 안 낸다

2048 줄 텍스처 위에 여덟 개의 사각형을 쌓아 `v` 를 `k` 에서 `k+1` 로 잇는다.
python: 각 사각형의 도달범위는 `(k+1)·2^20` 이고 rung 은 0,1,2,2,3,3,3,3 —
**세 접합에서 rung 이 바뀐다.**

```
   seam    하드웨어 대 소프트웨어  1024 화소
           행별 분포: 32, 57, 82, 107, 132, 157, 182, 207 에 각 128
           접합은 45, 70, 95, 120, 145, 170, 195 -> 그 어느 행에도 0
```

차이는 **사각형마다 같은 상대 행 하나**(각 사각형의 12 번째 행)에 몰린다.
rung 이 바뀌는 접합에는 하나도 없다.

### 9-1 시험이 이음매를 볼 수 있다는 증거 (`seamx`)

"안 보인다"가 "시험이 못 본다"가 아님을 세운다.  둘째 띠가 한 번에 네 장을
덮게 해서 도달범위를 네 단 띄운다 — 공유하는 변에서 좌표는 같은데 rung 은 0
대 3 이다:

```
   seamx   768 화소, 그 중 128 이 접합 행 45 에
```

**접합에서 보인다.**  그러니 `seam` 의 0 은 시험의 눈이 먼 것이 아니다.

### 9-2 왜 평범한 타일링은 안전한가

각 프리미티브의 좌표 구간이 자기 도달범위와 **같은 대역 안**에 있기 때문이다.
`v` 가 `k`…`k+1` 이면 비율이 `(k+1)/k ≤ 2` 이므로 한 대역을 넘지 않고, 그러면
좌표의 addend 와 그 사다리꼴의 bias 가 같은 값이라 잔차가 0 이다.  이음매는
**이웃한 두 프리미티브의 좌표 규모가 서로 크게 다를 때** 생기고, 이어붙인
타일링은 정의상 그렇지 않다.

## 10. 결론 — A 를 유지한다, 그리고 이제 근거가 있다

Mesa 는 rung 을 요청하지 않는다.  기구는 남아 있고 `§84` 가 작동을 실증한다.
바뀐 것은 근거다: "정책이 어렵다"가 아니라 **"평범한 기하에서는 고칠 것이
없고, 시험이 그걸 볼 수 있음을 대조군으로 보였다"** 이다.

A 가 정당하지 않게 되는 조건도 그대로다 — 실제 장면이 접합에서 재현 가능한
차이를 보이면 그때 다시 본다.  `seam` 과 `seamx` 가 기준값(1024, 768)으로
남으므로, 그런 일이 생기면 숫자가 움직인다.
