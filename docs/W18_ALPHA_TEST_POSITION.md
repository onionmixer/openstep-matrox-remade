# W18 — 두 알파 테스트의 **위치**를 가른다 (2026-08-28, 코딩 전)

W17 이 쟀다: **텍스처 없는 삼각형에서 `aten` 은 결과를 바꾸지 않는다**(24 행).
그러나 그것이 **텍스처 경로에서 `aten` 을 꺼도 된다**를 뜻하지 않는다 —
텍스처가 없으면 첫 테스트가 볼 것도 없기 때문이다.

**이 문서는 두 테스트가 서로 다른 알파를 보는 상황을 만든다.**

---

## 1. 무엇이 어느 알파를 정하는가

| | 무엇 | 근거 |
| --- | --- | --- |
| `TEXF_TEXALPHA` | 텍스처 **스테이지 출력** `Av` = `At`(텍스처) 또는 `Af`(보간) | 헤더 주석 |
| `alphasel<25:24>` | **픽셀** 알파 = 0 텍스처 / 1 diffused / 2 modulated | 3-34 |
| 첫 테스트 | *"right after texture filtering"* | 3-34 |
| 두 번째 테스트 | *"before alpha blending"*, *"after the texture blending stage"* | 3-34, 3-35 |

**그러므로 갈라 놓을 수 있다:**

```
  TEXALPHA 세움        -> 텍스처 스테이지가 At 를 낸다
  alphasel = 1 (diffused) -> 픽셀 알파는 Af (ALPHASTART)
  At 와 Af 를 atref 반대편에 둔다
```

이 기법은 이 저장소에 이미 있다 — blendsat 이 *"not As, on purpose:
TEXALPHA must be what decides"* 라며 텍셀 알파와 `a0` 를 다르게 둔다.

---

## 2. 판별표

`atmode = ALT`(알파 < atref 일 때 그린다), `atref = 128`.

| 경우 | `At` | `Af` | `aten=1` 예상 | `aten=0` 예상 | 뜻 |
| --- | --- | --- | --- | --- | --- |
| **A** | 200 (실패) | 64 (통과) | **폐기** | **그림** | **두 테스트가 다른 알파를 본다** |
| **B** | 64 (통과) | 200 (실패) | 폐기 | 폐기 | 두 번째가 최종 알파를 본다 |
| C | 64 | 64 | 그림 | 그림 | 대조 — 둘 다 통과 |
| D | 200 | 200 | 폐기 | 폐기 | 대조 — 둘 다 실패 |

> **정정 (§8).** *"A 가 전부"* 는 틀렸다. **B 가 필요하다** — B 는
> *"`aten=0` 에서도 비교가 산다"* 와 *"`aten=0` 이 전부를 껐다"* 를 가른다.
> A 만 보면 후자를 전자로 읽을 수 있다.
>
> 그리고 *"A 에서도 안 바뀌면 `aten` 은 아무 데서도 아무것도 안 한다"* 도
> 과하다(§8.5). 대안이 여럿 남는다.

## 3. 무엇을 결론지을 수 없는가

- **`alphasel=0` 은 이 실험에 못 쓴다** — 픽셀 알파가 텍스처에서 오면 두
  테스트가 같은 값을 보고 A 를 만들 수 없다. `1`(diffused)로 고정한다.
  이것은 W17 과 반대이지만 이유가 반대다: 거기서는 `tat` 을 설명해야 했고,
  여기서는 **갈라 놓아야** 한다.
- **`alphamode`(video alpha)는 안 쓴다** — W16 이 조합 제약을 넣었고 섞을
  이유가 없다.
- **modulated(`alphasel=2`)는 이번이 아니다** — 세 번째 알파를 들이면
  판별표가 흐려진다.

## 4. Mesa 를 아직 안 고친다

A 가 `aten` 에 반응하면 **GL 과 어느 쪽이 맞는지**가 다음 질문이 된다 —
GL 의 알파 테스트는 **최종 프래그먼트 알파**를 봐야 하므로 `aten=0`(두 번째만)
이 오히려 옳을 수 있다. **그러나 그 판단은 이 측정 다음이다.**

## 5. 위험

**하드웨어 위험은 없다** — 텍스처 있는 정상 배치 제출이고 오프스크린에 그린다.

**그러나 "위험 없음" 이라고 쓰지 않는다**(§8.6). 텍스처 업로드·주소·포맷·
필터링·`TDUALSTAGE` 프로그래밍이 붙으면 **실험이 무효가 될 경로**가 여럿
생긴다. 의도한 `At` 가 실제로 샘플되지 않았는데 그것을 `aten` 의 결과로
읽는 것이 가장 그럴듯한 실패다. **그래서 §6 의 독립 확인이 필수다.**

## 6. 검증

| # | | |
| --- | --- | --- |
| V1 | 네 경우 × `aten` 둘 = 8 제출, 판정 0 | 필수 |
| V2 | 배경 sentinel 이 남아 있으면 폐기, 그린 색이면 통과 | 필수 |
| V3 | `atmode=ALWAYS` 그리기 기준선 | 필수 |
| V4 | 여섯 비교 모드 — **모드마다 맞춘 벡터로** (§8.3) | 필수 |
| V5 | `TEXALPHA` 를 **끈** 두 번째 수준 | **가설 판별자** |

> **정정 (§8.4) — 내 기대가 거꾸로였다.** `TEXALPHA` 는 `TDUALSTAGE0` 에서
> 구현된다(`:10071`) — **필터링 이후**다. 그러므로 그것은 `Av` 를 바꾸지
> **첫 테스트의 입력을 바꾸지 않는다.** 그리고 `alphasel=1` 이 이미 두 번째
> 테스트를 `Af` 로 보내고 있다. **문서대로라면 A 는 그대로 남는다.**
>
> 그래서 V5 는 대조가 아니라 **판별자**다:
>
> | A 의 결과 | TEXALPHA 세움 | TEXALPHA 끔 | 뜻 |
> | --- | --- | --- | --- |
> | 첫 입력 = 필터된 `At` (문서) | 차이 있음 | **차이 있음** | 첫 테스트가 스테이지 **앞** |
> | 첫 입력 = 스테이지 출력 `Av` | 차이 있음 | **차이 없음** | 첫 테스트가 스테이지 **뒤** |
> | `aten` 이 무시됨 / 첫 테스트 부재 | 차이 없음 | 차이 없음 | 여전히 모호 |

## 7. codex 에 물을 것

- 첫 테스트가 보는 것이 `At` 인가 `Av` 인가 — `TEXALPHA` 가 그것도 바꾸는가
- `alphasel=1` 이 두 번째 테스트를 `Af` 로 보내는 것이 맞는가
- 판별표의 네 경우가 충분한가
- V5 대조가 옳은 모양인가
- 텍스처를 하나만 쓰는데 *"first test can be different for each texture"* 가
  이 실험에 영향을 주는가

### 8.1 파이프라인 순서 — 문서와 소스가 일치한다

```
필터된 텍스처 알파 At
      -> 첫 알파 테스트          (3-34: "right after texture filtering")
      -> TDUALSTAGE 알파 처리 -> Av   (드라이버가 TEXALPHA 를 여기서 구현)
      -> ALPHACTRL.alphasel
      -> 두 번째 알파 테스트      (3-34: "before alpha blending")
```

드라이버(`:10071`)가 `TEXALPHA` 를 `TDUALSTAGE0` 의 알파 인자 선택으로
구현한다 — **필터링 뒤**다. 그러므로 **`TEXALPHA` 는 첫 테스트의 입력이
아니다.**

부수 확인(내가 먼저 찾은 것): 4-49 가 두 번째 테스트가 쓰는 필드를 열거하는데
`alphasel`·`atref`·`atmode` 는 있고 **`aten` 은 없다.**

### 8.2 ★ V5 의 기대가 거꾸로였다

내 계획: *"`TEXALPHA` 를 끄면 A 가 사라져야 한다."*
**틀렸다.** `alphasel=1` 이 이미 두 번째를 `Af` 로 보내므로, `TEXALPHA` 를
꺼도 **문서대로라면 A 는 남는다.** 그리고 그 사실이 V5 를 **더 나은 실험**으로
만든다 — 대조가 아니라 첫 테스트의 **위치를 가르는 판별자**다.

### 8.3 ★ 모드마다 벡터를 맞춰야 한다 (python)

```
At=200, Af=64 를 여섯 모드에 재사용하면:
  AE    첫 실패 · 둘째 실패   분리 X
  ANE   첫 통과 · 둘째 통과   분리 X
  ALT   첫 실패 · 둘째 통과   분리 O
  ALTE  첫 실패 · 둘째 통과   분리 O
  AGT   첫 통과 · 둘째 실패   분리 X
  AGTE  첫 통과 · 둘째 실패   분리 X
```

**여섯 중 둘만 실험이 된다.** 나머지 넷은 `aten` 과 무관하게 같은 결과라,
거기서 "차이 없음" 을 읽으면 아무것도 아닌 것을 결론으로 삼는 것이다.

모드마다 **첫 실패 + 둘째 통과** 가 되는 벡터를 따로 만든다:

| 모드 | `At` | `Af` |
| --- | --- | --- |
| `AE` | 0 | 128 |
| `ANE` | 128 | 0 |
| `ALT` | 200 | 64 |
| `ALTE` | 200 | 64 |
| `AGT` | 0 | 200 |
| `AGTE` | 0 | 128 |

### 8.4 null 결론을 좁힌다

가장 강하게 말할 수 있는 것은:

> **"이 단일 텍스처 TW32 구성에서 `aten` 으로 보이는 조기 폐기가 관측되지
> 않았다."**

*"`aten` 은 아무 데서도 아무것도 안 한다"* 가 아니다. 남는 대안: 이 실리콘이
`aten` 을 무시한다 · 이 opcode 에서 첫 테스트가 없다 · 두 테스트가 같은 값을
본다 · 의도한 `At` 가 실제로 샘플되지 않았다.

### 8.5 그래서 독립 확인이 필수다

**`At` 가 실제로 샘플되는지를 알파 테스트와 무관하게 먼저 확인한다**:
`atmode=ALWAYS`(두 테스트 모두 off), `alphasel=0`, 알파 채널 출력으로
`TEXALPHA` 세움/끔이 각각 `At`/`Af` 를 내는지 **워드 전체를 읽어** 본다.

**이것 없이 A 를 해석하면, 텍스처가 안 붙은 것을 `aten` 의 효과로 읽을 수 있다.**

### 8.6 착수 조건

1. `TEXALPHA` 를 **두 수준의 실험 인자**로 (대조가 아니라)
2. **모드별 맞춤 벡터** (§8.3 표)
3. **B 를 유지** — A 만으로는 "전부 껐다" 와 구분 안 됨
4. `ALPHASTART = byte << 15`, 알파 기울기 0 (W17 이 한 대로)
5. **독립 스테이지 출력 확인** (§8.5), 워드 전체 읽기
6. null 어휘를 **미리 정해** "anywhere" 를 금지
7. "위험 없음" 을 **실험 유효성 위험**으로 대체

## 9. 결과 (2026-08-28 실기)

### 9.1 1 부 — 텍스처가 실제로 샘플된다

```
both alpha tests off, alphasel 0, so the pixel alpha IS Av
  TEXALPHA 0: word 40c08040, alpha  64, wanted  64 (Av = Af)
  TEXALPHA 1: word c8c08040, alpha 200, wanted 200 (Av = At)
```

**스테이지가 헤더가 말하는 대로 동작한다.** 이 확인 없이 2 부를 읽었으면
"텍스처가 안 붙은 것" 을 `aten` 의 효과로 읽을 수 있었다(§8.5).

### 9.2 ★ 2 부 — 첫 테스트는 실재하고, **필터된 `At` 를 읽는다**

```
  texa mode    At  Af  aten=1 aten=0  aten matters?
     1 AE  ==    0 128    gone   draw  YES
     1 ANE <>  128   0    gone   draw  YES
     1 ALT  <  200  64    gone   draw  YES
     1 ALTE<=  200  64    gone   draw  YES
     1 AGT  >    0 200    gone   draw  YES
     1 AGTE>=    0 128    gone   draw  YES
  -> TEXALPHA 1: aten changed the result in 6 of 6 modes

     0 (같은 여섯 줄, 전부 YES)
  -> TEXALPHA 0: aten changed the result in 6 of 6 modes
```

**미리 선언한 해독표**(§8.2)가 답을 정한다:

> **양쪽 수준에서 차이 → 첫 테스트는 필터된 `At` 를 읽는다**

`TEXALPHA` 를 끄면 스테이지 출력 `Av = Af = 통과하는 값`이 된다. 그런데도
`aten=1` 이 여전히 폐기한다 — **그러므로 첫 테스트는 스테이지 뒤가 아니라
앞에서, 필터된 텍스처 알파를 본다.** 사양서의 *"right after texture
filtering"* 그대로다.

### 9.3 ★ 이 결과가 앞선 방향을 뒤집는다

W17 뒤에 내가 향하던 결론은 *"Mesa 가 `aten=0` 을 보내도 동작 변화가 없다"*
였다. **텍스처 경로에서 그것은 거짓이다** — `aten` 이 여섯 모드 전부에서
결과를 바꾼다.

| | |
| --- | --- |
| W17 (텍스처 없음) | `aten` 은 아무것도 안 바꾼다 (24 행) |
| **W18 (텍스처 있음)** | **`aten` 이 전부 바꾼다 (12 행 중 12)** |

**`aten` 을 무조건 끄면 텍스처 알파 테스트가 깨진다.** 검토가 §8.4 에서
반례로 든 것이 실측으로 확인됐다.

### 9.4 그런데 Mesa 는 지금 옳다

이 프로브는 `alphasel=1` 을 **강제해서** 두 테스트가 다른 값을 보게 만들었다.
Mesa 는 텍스처를 쓸 때 `alphasel = TEX(0)` 을 대입하므로(`:1620`), **두
테스트가 같은 텍스처 유래 알파를 보고 일치한다.**

**즉 버그를 찾은 것이 아니라 파이프라인 사실을 확정한 것이다.** 그리고 그
사실이 *"`aten` 을 끄자"* 를 막는다.

### 9.5 결론 — 좁게

| 주장 | 판정 |
| --- | --- |
| 첫 알파 테스트가 이 실리콘에 실재한다 | ✅ **측정됨** (6/6 × 2) |
| 그것이 필터된 `At` 를 본다 (스테이지 **앞**) | ✅ **측정됨** — `TEXALPHA=0` 에서도 차이 |
| 두 번째는 `alphasel` 이 고른 값을 본다 | ✅ 1 부 + 2 부와 일관 |
| Mesa 가 `aten` 을 꺼도 된다 | ❌ **반증됨** (텍스처 경로) |
| 텍스처 **없는** 경로는 W17 대로 | ✅ 변함없음 |

**이중 텍스처·변조·밉맵은 재지 않았다.** 단일 텍스처 TW32, 이 필터, 이 환경.
