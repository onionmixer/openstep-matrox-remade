# M1-4DC — 텍스처 + 블렌딩 관문을 연다

## 1. 조건은 채워졌다

관문(`OpenStepMGAMesaHook.c`, `TEXTURE_BIT` 가지 안의 `BLEND_BIT` 거절)이
남아 있던 이유는 **구조**였고, 그건 사라졌다.

| 조건 | 상태 |
|---|---|
| 쪼개진 삼각형이 한 배치로 나간다 | ✅ 앵커가 사다리꼴 것이 됐다 |
| 거절이 아무것도 안 그린다 | ✅ §79 — 색도 깊이도, **양성 대조 포함** |
| 배치가 그림을 안 움직인다 | ✅ 기준 열 개 전부 유지, §80 이 사다리꼴별 bias 확인 |
| 알파 선택자가 GL 환경을 따른다 | ✅ §77 열두 읽기가 python 과 일치, Mesa 구현 완료 |

## 3. 그런데 열면 무엇이 처음으로 실행되나

지금까지 한 번도 함께 돈 적이 없는 조합들이다:

1. `ALPHASTART`(`a0/adx/ady`)와 텍스처가 같은 프리미티브에.  블렌딩이 켜지면
   빌더가 알파 평면을 푼다 — 텍스처와 같이 푼 적은 없다
2. `AC_alphasel` 이 `diffused` 가 아닌 값으로 **Mesa 를 통해** 나간다.  §77 은
   프로브가 직접 레지스터를 쓴 것이고, 빌더가 고른 것을 쓴 적은 없다
3. 텍스처 + 블렌딩 + **깊이**.  셋이 같이 도는 것도 처음이다

## 4. 그러므로 무엇을 재나

### 4-1 관문이 실제로 열렸는지 (공허하지 않게)

`texdraw` 의 거절 목록에 `k == 3`(`glEnable(GL_BLEND)`)이 있고 지금은
`Drawn == before` 를 단언한다.  이걸 **뒤집는다** — 그리고 뒤집는 것만으로는
부족하다: 그려졌다는 것과 **맞게** 그려졌다는 것은 다르다.

### 4-2 세 환경을 Mesa 를 통해 가른다

§77 이 레지스터 수준에서 가른 셋을, 이번엔 GL 상태로 만든다:

| GL 상태 | 선택자 | 알파 |
|---|---|---|
| RGB 텍스처 + `GL_REPLACE` | `diffused` | 프래그먼트의 |
| RGBA 텍스처 + `GL_REPLACE` | `fromtex` | 텍셀의 |
| `GL_MODULATE` | `modulated` | 둘의 곱 |

세 장면 각각 하드웨어와 소프트웨어를 비교하고, **차이를 python 으로 설명**한다.
엔진의 곱은 Mesa 의 곱이 아니므로(엔진 `(a·b·257+32768)>>16`, Mesa
`(a·(b+1))>>8`) 0 이 나올 이유가 없다 — 나오면 그게 의심스럽다.

### 4-3 기준 열 개 재확인

블렌딩이 꺼진 장면은 하나도 움직이면 안 된다.  움직이면 관문이 아니라 선택자
코드가 무언가를 건드린 것이다.

## 5. 위험, 그리고 되돌리는 법

가장 큰 위험은 **관문을 연 뒤에야 드러나는 조합**이다.  Mesa 만 바뀌므로
되돌리는 것은 한 줄과 `build-matrox-mesa.csh` 한 번이고, 재부팅은 필요 없다.

### 7-1 기준 러너에서 제가 낸 버그

`tilelin` 이 16384 → 24 로 "움직였다".  실제로는 **장면 이름이 인식되지
않았다** — `strcmp(argv[2], "tile")` 는 정확히 일치해야 하고 `tilelin` 은
`tile` 에 세 번째 인자를 붙인 것이다.  인식 못 한 이름은 기본 장면을 그리므로,
24 는 `tilelin` 의 수가 아니라 **`near` 의 수**였다.  둘이 정확히 같다는 것이
단서였다.  러너에 라벨과 인자를 나눠 적고, 그 함정을 주석으로 남겼다.

### 8-1 분할 시험은 이제 원자성의 Mesa 쪽 증거다

```
   ok  a split triangle goes out as ONE batch
   ok  carrying both its trapezoids
```

배치 하나만으로는 약하다 — 쪼개지지 않은 삼각형도 배치 하나다.  그래서
사다리꼴 계수기(`OSMGAMesaHookTraps`)를 더해 **하나의 배치가 둘을 실었다**를
같이 단언한다.

## 9. 남은 미측정 — `modulated` 는 무엇의 알파를 읽나

`AC_alphasel` 의 `fromtex`·`modulated` 가 **텍셀의** 알파를 읽는지 **결합기
출력**을 읽는지 갈리지 않았다.  RGBA + `GL_MODULATE` 에서 둘은 다르다:

```
   텍셀을 읽으면      Af · At
   결합기를 읽으면    Af · (Af · At)
```

§77 은 프로브가 레지스터를 직접 쓴 것이라 결합기 상태가 이 질문을 겨냥해
설정돼 있지 않았다.  **RGBA + MODULATE 장면이 이걸 가른다** — 두 가설을 python
으로 각각 계산해 어느 쪽이 맞는지 본다.

고친 선택자는 **두 가설 모두에서** RGB 쪽이 옳다(`diffused` = `Af`), 그러니
이 질문은 RGBA + MODULATE 하나만 막고 있다.
