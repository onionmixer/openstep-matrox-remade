# M5 — 버전 10 WARP ABI 와 남은 자격검증 (2026-08-29, 코딩 전)

## 0. 무엇이 확정됐고 무엇이 남았나

M2 §11 이 개정한 순서에서 **3(자격검증)이 진짜 blocker** 였다.  M3·M4 가
그 중 다섯을 실기로 닫았다:

| M2 §11 항목 | 상태 | 근거 |
|---|---|---|
| 3a 무텍스처 + 16 비트 깊이, 비교모드·쓰기 | ✅ | M3 T1·T2, M4 T4a·T4c |
| 3b nearest clamp 텍스처 | ✅ | M3 T3 (네 위상), M4 T5 |
| 3c bilinear min/mag | ✅ | M4 T5a·T5b |
| **3d repeat U/V** | ❌ **미측정** | — |
| 3e 정점마다 다른 양의 `rhw` 로 원근 | ✅ | M4 T4a·T4b |
| **3f 블렌딩 + 텍스처 알파** | ❌ **미측정** | — |
| 3g 층 전환, 펜스 명시 | ✅ | M3 T6 |

그리고 M4 가 **변환 상수를 확정**했다 — 이것이 ABI 의 핵심 입력이다:

```
code   = min( floor(z * 65536), 65535 )      <- T2 + T4c
z      = code / 65536.0                       <- 전 코드 왕복 정확
깊이는 화면공간 평면이다 (rhw 무관)            <- T4a, worst 0 codes
텍스처는 원근 나눗셈을 한다                    <- T4b, 1176/1176 exact
CLAMPUV 는 확대·축소 양쪽에서 민다             <- T5a/T5b
텍셀 경계에 정확히 얹어 샘플링하지 않는다       <- T3 위상 0
```

**참조 DRI 의 `1.0/0xffff` 를 쓰면 안 된다** (`mga_xmesa.c:362`).

## 1. 이번 증분의 경계

재부팅 하나에 둘을 넣는다:

```
(a) T7 repeat, T8 블렌딩 — 남은 자격검증 둘 (드라이버 .m, 기존 하네스에 밴드 추가)
(b) 버전 10 계약 + 검증기 — 호스트에서 시험 가능, 하드웨어 불필요
```

**훅 분기(M2 §11 의 5)와 A/B(6)는 이번에 하지 않는다.** (a) 의 답이
검증기의 허용 정책을 바꾸고, 그 정책이 정해지기 전에 훅을 쓰면 두 번 쓴다.

## 2. T7 — `GL_REPEAT` 를 WARP 가 몰아도 같은가

사다리꼴 경로의 repeat 은 이미 있다(`M1_4CB_REPEAT.md`).  WARP 질문은 하나다:
**좌표를 WARP 가 만들어도 텍스처 유닛이 같게 감는가.**

```
맵       64 x 64, pitch 64 (2 의 거듭제곱, repeat 이 요구)
          spec 3-211: repeat 모드에서 tpitchext 는 2 의 거듭제곱이어야 한다
위치      OSMGA_M4_TEX + 40960   (40960 % 32 = 0),  16,384 바이트
TEXCTL   CLAMPUV 를 **끈다**
좌표      u,v 를 −1 .. +2 (세 주기)로 걷는다, nearest, 반 텍셀 편향 유지
판정      읽어온 물리 텍셀 x 가 `floor(u·64) mod 64` 와 같은가 — 전 화소
대조군    같은 배치를 CLAMPUV 켜고 한 번 더: 그때는 양 끝이 0 과 63 으로 포화
```

대조군이 있어야 "감았다" 와 "클램프가 켜져 있었다" 가 갈린다.

## 3. T8 — 블렌딩과 텍스처 알파

**A/B 로 한다.  블렌딩 산술의 오라클을 새로 쓰지 않는다.**

같은 삼각형, 같은 `ALPHACTRL`, **미리 칠해 둔 같은 대상**을 두 경로로 그린다:

```
1  대상 두 블록(oracle, warp)을 같은 값으로 채운다  (섞일 바탕이 있어야 한다)
2  사다리꼴 경로로 oracle 에 그린다   — ALPHACTRL 을 명시적으로 같게 쓴다
3  WARP 로 warp 에 그린다
4  osmgaM3CompareSurfaces 로 전 화소 비교
```

두 밴드:

```
T8a  무텍스처, 정점 알파, src=SRCALPHA dst=INVSRCALPHA
T8b  텍스처 알파(TW32 의 상위 바이트), 같은 블렌드
```

**이 형태의 값어치**: 블렌딩 결과가 맞는지는 이미 사다리꼴 경로에서
검증됐다(`tools/score-matrox-blend-scenes.sh`).  남은 질문은 **두 경로가 같은
그림을 내는가** 뿐이고, A/B 가 정확히 그것만 묻는다.  M3 T0 이 같은 구조로
커버리지를 닫았다.

⚠ `osmgaM3OracleTri` 는 지금 `ALPHACTRL` 을 쓰지 않는다.  T8 을 위해 인자로
받게 고쳐야 하고, 기존 호출자는 지금 값(Mesa 초기값 `1`)을 넘긴다.

## 4. 버전 10 계약

정점 형태를 **나란히** 더한다.  `OSMGAHW3DTri` 는 그대로 남는다 — 사다리꼴
경로는 계속 쓴다.

```c
/* 정확히 WARP 정점 하나, 8 dword.  전부 IEEE-754 비트 패턴이거나 팩된 색. */
typedef struct {
    unsigned int x, y;        /* 화면 좌표, float 비트 */
    unsigned int z;           /* [0,1] 정규화, float 비트  -- code/65536.0 */
    unsigned int rhw;         /* qw*tq, 강한 양수, float 비트 */
    unsigned int diffuse;     /* BGRA 팩 */
    unsigned int specular;    /* BGR + fog 팩 */
    unsigned int tu0, tv0;    /* s/tq, t/tq, float 비트 */
} OSMGAHW3DVertex;

typedef struct {
    unsigned int dwgctl;      /* 이 런 전체가 공유한다 */
    unsigned int alphactrl;   /* 이 런 전체가 공유한다 */
    unsigned int first;       /* vtx[] 안의 첫 정점 색인 */
    unsigned int count;       /* 정점 수, 3 의 배수 */
} OSMGAHW3DRun;
```

**`unsigned int` 를 쓴다, `unsigned long` 이 아니라.**  codex 가 M2 에서
지적했고 채택했다 — 계약이 i386 32 비트를 암묵으로 담으면 안 된다.

배치에 더한다:

```c
    unsigned long runCount;
    unsigned long vtxCount;
    OSMGAHW3DRun    run[OSMGA_HW3D_MAX_RUN];
    OSMGAHW3DVertex vtx[OSMGA_HW3D_MAX_VTX];
```

`OSMGA_HW3D_VERSION` 9 → 10.  **버전 9 배치는 계속 받는다** — 사다리꼴
클라이언트가 그대로 돌아야 한다(정확히는, 훅이 두 형태를 다 낼 수 있어야
전환이 점진적이다).

### 4.1 왜 런인가

사다리꼴 계약은 삼각형마다 `dwgctl`·`alphactrl` 을 담는다.  **WARP 는 그럴 수
없다** — 한 제출 안의 프리미티브는 상태를 공유한다.

실측이 이것을 값싸게 만든다: 109,803 사다리꼴에서 **`dwgctl` 변경 1.8%,
`ALPHACTRL` 변경 1.8%**(`REMAINING_WORK.md:2763`).  곧 **호환 상태 런의 평균
길이가 50 을 넘는다.**  런 경계에서만 GENERAL 목록을 다시 내면 된다.

D2-2f 가 **같은 컨텍스트는 재발행 없이 산다**는 것을 실기로 보였으므로,
런 안에서는 정점 제출만 한다.

## 5. 커널 검증 — FPU 없이

커널은 부동소수를 만질 수 없다.  전부 정수 비트 검사로 한다.

```
유한   (p & 0x7F800000) != 0x7F800000            <- NaN·±Inf 를 함께 거절
강한 양수 정규수  (p >> 31) == 0 && 0 < ((p >> 23) & 0xFF) < 0xFF
```

python 으로 확인했다: `0.0`·`-0.0`·비정규수·음수·`±Inf`·`NaN` 이 전부
떨어지고 `1e-30` 은 통과한다.

**범위 검사도 정수 비교로 한다.**  IEEE-754 는 음이 아닌 값에서 비트
패턴이 값과 **같은 순서**다(python 으로 확인).  그래서

```
0 <= v <= LIMIT   ⟺   (p >> 31) == 0 && p <= bits(LIMIT)
```

음수가 허용되는 값(화면 좌표 x,y)은 부호를 먼저 갈라 크기를 비교한다.

검사 목록:

| 항목 | 규칙 |
|---|---|
| `x`, `y` | 유한.  값은 클립이 묶는다 — 하드웨어 비교이고 W9 가 확인했다 |
| `z` | 유한, `0 <= z <= 1`.  상한 포화는 T4c 가 쟀지만 **계약은 넘기지 않는다** |
| `rhw` | **강한 양수 정규수**, 그리고 검증된 구간 안 |
| `tu0`, `tv0` | 유한.  봉쇄는 §6 |
| `count` | 3 의 배수, `first + count <= vtxCount` |
| `dwgctl`/`alphactrl` | 지금 검증기가 사다리꼴에 하는 것과 **같은 마스크** |

## 6. 봉쇄 — 이미 증명돼 있다

M2 §10 이 정정했다.  `q_i > 0` 이면 원근 보정 보간도 **볼록결합**이다:

```
u = Σλᵢqᵢuᵢ / Σλⱼqⱼ = Σμᵢuᵢ,   μᵢ = λᵢqᵢ/Σλⱼqⱼ ≥ 0,  Σμᵢ = 1
```

`HW3D.h:411` 이 이미 그렇게 적어 놨다.  그러므로 **세 정점의 `tu0/tv0` 가
범위 안이면 모든 화소가 범위 안이다** — 단 `rhw > 0` 이 정점마다 성립할 때.
§5 가 그것을 강제한다.

그 위에 하드웨어가 한 겹 더 있다: `CLAMPUV` 는 좌표가 아니라 **가져오는
주소**를 묶고(`HW3D.h:286`), M4 T5 가 확대·축소 양쪽에서 실측으로 확인했다.

`GL_REPEAT` 는 clamp 를 끄므로 그 겹이 사라진다.  **T7 이 통과하기 전에는
repeat 을 WARP 층에 들이지 않는다** — 거절해서 사다리꼴로 내린다.

## 7. 거절과 타임아웃

- **거절은 부작용이 없어야 한다.**  검증은 전부 제출 **전에** 끝난다.
  한 정점이라도 떨어지면 그 배치는 아무것도 그리지 않고 `UNSUPPORTED`.
- **타임아웃은 거절이 아니다** (M2 §10 채택).  도어벨을 울린 뒤의 타임아웃은
  부분 그리기와 wedge 가 가능하다.  **아래 층으로 재생하지 않는다** —
  격리하고 기존 재부팅 정책.
- 정점 버퍼 재사용은 포인터 통과로 충분하지만(D2-2f), **텍스처 덮어쓰기·
  대상/깊이 CPU 접근·present 에는 `DWGSYNC` 가 필요하다**(M2 §10 채택).

## 9. codex 에 물을 것

1. **T8 을 A/B 로 두는 것이 충분한가.**  두 경로가 같은 그림을 내면
   "WARP 로도 블렌딩이 된다"고 말해도 되나, 아니면 블렌딩 산술 자체를
   따로 확인해야 하나.
2. **T7 의 대조군이 옳은가.**  clamp 켠 밴드와 끈 밴드의 차이로 repeat 을
   판정하는데, 둘을 가르지 못하는 실패 방식이 있나.
3. **런 구조가 맞나.**  `(dwgctl, alphactrl)` 만 런 키로 삼는데, WARP
   제출 안에서 공유되는 상태 중 빠뜨린 것이 있나(텍스처 상태, 클립, `WFLAG`).
4. **버전 9 를 계속 받는 것이 맞나**, 아니면 10 으로 끊는 것이 안전한가.
5. **정수 비트 검사 목록에 빠진 것.**  특히 `rhw` 의 "검증된 구간" 을 무엇으로
   잡아야 하나 — `Q_MIN/Q_MAX` 가 사다리꼴용으로 이미 있는데 그대로 쓰나.
6. **`z` 상한.**  T4c 가 포화를 쟀는데, 계약에서 `z > 1` 을 거절해야 하나
   아니면 하드웨어 포화에 맡겨야 하나.
7. 빠진 것.

## 10. 자체 정정 (codex 회신 전, 2026-08-29)

계획의 §4 를 쓰고 나서 계약 헤더의 예산을 직접 확인했더니 **§4 가 그대로는
안 된다.**

### 10.1 배치에 배열을 "더할" 자리가 없다

`HW3D.h:68` 이 이미 계산해 놨다:

```
sizeof(OSMGAHW3DBatch) = 108 + 132 * MAX_TRI
MAX_TRI = 180  ->  23,868 바이트
OSMGA_HW3D_BATCH_BYTES = 24 KiB = 24,576   ->  남는 것 708 바이트
```

python 으로 독립 재현했다 — 헤더의 식과 바이트까지 같다.  **720 정점(23 KiB)이
들어갈 자리가 없다.**

그리고 24 KiB 는 **움직여서는 안 되는 숫자**다.  `HW3D.h:52` 가 이유를 적어
놨고 그건 실측된 보안 결함이다 — 분할이 28 KiB 였을 때 *"every accelerated
process had 4 KiB of the list mapped read-write"* 였고, 클라이언트가 목록을
읽어 배치마다 바뀌는 것을 지켜봤다.  배치는 정확히 세 페이지여야 한다.

**답은 공용체다.**  한 배치는 사다리꼴이거나 WARP 이고, 둘 다인 적이 없다:

```c
typedef struct {
    unsigned long magic;
    unsigned long version;
    unsigned long triCount;      /* 사다리꼴 팔에서만 */
    unsigned long runCount;      /* WARP 팔에서만 */
    unsigned long vtxCount;      /* WARP 팔에서만 */
    OSMGAHW3DState state;
    union {
        OSMGAHW3DTri tri[OSMGA_HW3D_MAX_TRI];
        struct {
            OSMGAHW3DRun    run[OSMGA_HW3D_MAX_RUN];
            OSMGAHW3DVertex vtx[OSMGA_HW3D_MAX_VTX];
        } warp;
    } u;
} OSMGAHW3DBatch;
```

`sizeof` 가 안 자라고, 페이지 분할이 안 움직이고, 링 오프셋이 안 움직인다.
**어느 팔이 살아 있는지는 `triCount`/`runCount` 중 하나만 0 이 아닌 것으로
말한다** — 두 개가 다 0 이 아니면 거절.

### 10.2 진짜 병목은 배치가 아니라 **명령 목록**이다

정점은 배치에서 곧바로 DMA 될 수 없다.  배치는 클라이언트가 쓰기 가능하게
매핑한 영역이라, 검증 뒤 카드가 읽기 전에 클라이언트가 바꿀 수 있다(TOCTOU).
지금 인코더가 목록 영역으로 **옮겨 쓰는** 이유가 그것이고, 정점도 같아야 한다.

그래서 한계는 두 예산을 **동시에** 만족해야 한다:

```
목록 영역        36,880 바이트   (HW3D.h:900, 64K − 24K − 4,080)
런당 상태 목록      460 바이트   (드라이버의 목록 빌더 osmgaDmaBlock 22 개 + SOFTRAP)
정점                 32 바이트
```

python 으로 후보를 전부 대조했다:

| MAX_RUN | MAX_VTX | 삼각형 | 배치 팔 | 목록 |
|---|---|---|---|---|
| 16 | **720** | **240** | 23,296 / 23,760 ✅ | 30,400 / 36,880 ✅ |
| 16 | 768 | 256 | 24,832 / 23,760 ❌ | — |
| 32 | 672 | 224 | 22,016 ✅ | 36,224 / 36,880 ⚠ 여유 656 |

→ **`MAX_RUN 16`, `MAX_VTX 720`(삼각형 240).**  사다리꼴의 180 보다 많고,
1.8% 상태 변경률이면 240 삼각형 배치의 평균 상태 전환은 **4.3 회**라 16 은
넉넉하다.

### 10.3 §4 를 이렇게 읽는다

원래 §4 의 "배치에 더한다"는 **틀렸고**, 위 공용체와 두 예산이 그것을 대신한다.
codex 에 물을 것에 하나 더한다:

8. **공용체가 옳은 선택인가.**  한 배치가 두 층을 섞어 담을 이유가 정말
   없는가 — 특히 훅이 삼각형 하나를 WARP 로 거절하고 사다리꼴로 내릴 때,
   그 하나를 같은 배치에 담고 싶어지지 않는가.

- 드라이버 `:655` 가 결과를 적어 놨다 — *"Which half of CLAMPUV is which
  axis, **measured** rather than guessed"*.
- 인코더 `:13128` 이 정책을 이미 강제한다: **`texPitch == texW` 이고 그 축이
  2 의 거듭제곱일 때만** 그 축의 clamp 비트를 끈다.
- 훅 `Hook.c:1823` 이 `WrapS == GL_REPEAT` 를 `TEXF_REPEATU` 로 옮긴다.

**즉 repeat 은 사다리꼴 경로에서 이미 종단으로 동작한다.**  그러므로 T7 이
물을 것은 **하나뿐**이다:

> 좌표를 WARP 가 만들어도 텍스처 유닛이 **같게** 감는가.

전부 같은 텍셀이어야 한다.  대조군은 여전히 필요하다(clamp 켠 밴드).

### 11.2 T8 을 둘로 가른다 — 블렌딩 산술을 시험하지 않기 위해

### 15.1 §13.3 을 고쳤다 — 공용체가 아니라 **두 번째 모양**이다

공용체로 하면 기존 코드의 `b->tri[i]` 를 전부 `b->u.tri[i]` 로 고쳐야 하고,

```c
typedef struct {
    unsigned long magic, version, triCount;   /* v9 와 같은 자리 */
    OSMGAHW3DState state;                     /* v9 와 같은 자리 */
    osmga_u32 runCount, vtxCount;
    OSMGAHW3DRun    run[16];
    OSMGAHW3DVertex vtx[720];
} OSMGAHW3DWarpBatch;      /* 23,412 바이트 -- v9 의 23,868 보다 작다 */
```

**v9 레이아웃은 한 바이트도 안 움직인다.**  기존 Mesa 라이브러리는 재빌드 없이
계속 그린다.  커널은 `magic`·`version` 을 읽고 어느 모양인지 정한다 — 그 두
필드가 양쪽에서 같은 자리라는 것이 성립 조건이고, C89 는 무관한 두 구조체에
그걸 보장하지 않으므로 **`offsetof` 가 있는 호스트 스위트에서 단언**한다.

이건 codex 의 권고("페이로드 형을 헤더 버전으로 고르라")를 구체화한 것이고,
공용체보다 낫다.

### 15.2 정책은 함수 하나다

```c
int osmgaHW3DWarpAdmits(const OSMGAHW3DState *st, const OSMGAHW3DRun *run);
```

지금은 **repeat 과 블렌딩을 거절**한다 — 둘 다 사다리꼴에서는 자격검증됐지만
(`M1_4CB`, `M1_4E3`) WARP 가 좌표와 셋업을 만들 때도 같은지는 T7·T8 이 아직
답하지 않았다.  거절은 사다리꼴로 내려가므로 **속도를 잃지 그림을 잃지 않는다.**

T7·T8 이 보고하면 **이 함수만** 바뀐다.

### 15.3 봉쇄는 `rhw` 위에 선다

원근 보정 보간이 볼록결합인 것은 **모든 정점 가중치가 강한 양수일 때뿐**이다.
그래서 `rhw` 는 유한·양수·정규수이고 **`0.125 ~ 128.0`**(`Q_MIN/Q_MAX` 를
65536 으로 나눈 값) 안이어야 한다.  비정규수는 일부러 뺐다 — `1e-40` 은 아무도
보내려 한 좌표가 아니고, 엔진이 0 으로 flush 할 수 있는 값 위에 봉쇄를 세울
수 없다.

### 15.4 스위트 아홉

```
배치 검증기 + 2 차 범위 + 필드 부호화 + 알파 조합 + WARP texdim
+ T3 리포터 + T7/T4b 검증기 + FPU 없는 부동소수 + WARP 배치
```

전부 타깃 `cc 2.7.2.1` 통과.  드라이버도 다시 빌드·설치했다(설치본 = HEAD).

### 15.5 유저랜드 절반 — 산술은 전부 여기 있다

`mesa/OpenStepMGAMesaWarp.{c,h}` 가 `OSMGAMesaVertex` 를 `OSMGAHW3DVertex` 로
바꾼다.  커널은 FPU 가 없으니 **변환은 전부 여기서** 일어나고 커널은 비트만
판정한다.

```
x, y      1/256 화소 -> 화소.  반 화소를 접지 않는다 -- T4b 가 정수 정점
          격자에서 평가한 오라클과 1176/1176 일치했다
z         code/65536.0 = vertex.z / 16777216.0        <- 실측 상수
rhw       qw * tq                                     <- 참조와 같다
tu0, tv0  s/tq, t/tq
diffuse   (a<<24)|(r<<16)|(g<<8)|b
```

**거절은 변환된 float 위에서 한다**, 그것을 만든 double 위가 아니라 —
범위 안의 double 도 무한대로 변환될 수 있고 커널은 float 만 본다.

`mesa/test-mesa-warp.c` 가 열 번째 스위트다.  기대 비트 패턴은 **python 이
낸 표**이지 빌더의 식을 다시 쓴 것이 아니고, **깊이 코드 65536 개 전부를
왕복**시킨다 — 참조 DRI 의 `1/65535` 가 다시 기어들면 맨 끝 코드가 하나
어긋나면서 이 줄이 깨진다.
