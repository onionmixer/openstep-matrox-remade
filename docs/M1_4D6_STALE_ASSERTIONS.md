# M1-4D6 — 유저랜드 검증기 시험의 낡은 단언 7 건 (계획)

## 1. 왜 지금인가

`hw3d/test-hw3d-validate.c` 는 **7 건이 실패한 채로** 돌고 있다.  이번 세션에서
나는 "HEAD 의 검증기로도 같은 7 건이므로 회귀 없음"을 **두 번** 근거로 썼다.
그건 위태롭다 — 알려진 실패가 7 개인 시험은 **8 번째를 못 잡는다.**  실제로
오늘 커널을 두 번 고쳤고, 두 번 다 이 시험은 "7"만 말했다.

## 2. 일곱 건의 정체 (전부 실측 확인)

두 종류뿐이다.

### 갑. 규칙이 **의도적으로** 바뀐 것 — 음수 허용

커널은 이제 좌표가 −4096 까지 내려가는 것을 허용한다
(docs/M1_4D2, M1_4D3).  `−1` 을 거절로 단언한 것들이 낡았다.

| 줄 | 단언 | 지금 |
|---|---|---|
| 241 | `tmr[6] = -1` → E_TEXCOORD | 통과(0) |
| 243 | `tmr[7] = -1` → E_TEXCOORD | 통과(0) |
| 513 | `tmr[6] = -1` → E_TEXCOORD, `badTri == 0` | 통과(0) |
| 800 | 모서리가 nought 아래로 1 → E_TEXCOORD | 통과(0) |

### 을. 시험이 **뒤바뀐 시절의 레지스터 이름**을 쓰는 것

헤더 455·461 줄이 못 박은 대로 `tmr[1] = ds/dy`, `tmr[2] = dt/dx` 이고,
*"검증기가 예전에 둘을 뒤바꿔 갖고 있었다"*.  시험은 그 시절에 쓰였다.

| 줄 | 단언이 말하는 것 | 실제로 쓰는 레지스터 | 결과 |
|---|---|---|---|
| 264 | "한 행짜리 삼각형의 **y 증분**은 적용되지 않는다" | `tmr[2]` = dt/**dx** — 열을 가로질러 적용된다 | 거절(13) |
| 455 | "**u 의 행 기울기**가 한 프리미티브에 맞으면 통과" | `tmr[2]` = dt/dx | 거절(13) |
| 707 | "**V 의 x 증분**은 U 와 같은 검사로 묶인다" | `tmr[1]` = ds/**dy** | 통과(0) |

707 은 두 겹으로 낡았다: 레지스터 이름이 틀렸고, 게다가 `−1` 은 이제 합법적인
기울기다(양·음 대칭 상한 안).

## 3. 고치는 원칙

**단언을 뒤집지 않는다. 의도를 복원한다.**  기대값만 바꾸면 다음에 규칙이
움직였을 때 또 같은 일이 된다.

1. **갑**: 허용 **안쪽**은 통과를 단언하고, 허용을 **한 단위 넘은 값**의 거절을
   짝으로 단언한다.  경계가 어디인지를 시험이 말하게 한다.
2. **을**: 레지스터 이름을 고친다.  `tmr[1]` 을 뜻했으면 `tmr[1]` 을 쓴다.
   707 은 이름을 고친 뒤 **실제로 상한을 넘는 값**을 준다.

## 4. 제안 (줄별)

| 줄 | 지금 | 제안 |
|---|---|---|
| 241 | `tmr[6] = -1` → 13 | `-1` → **OK**, 그리고 `-(NEG_ALLOW+1)` → 13 |
| 243 | `tmr[7] = -1` → 13 | 같은 방식 |
| 264 | `tmr[2] = full` → OK | `tmr[1] = full` → OK (한 행이면 `ey = 0`, 기울기 상한이 건너뛰고 `dy = 0` 이라 적용되지 않는다) |
| 266 | `tmr[2] = full`, h=4 → 13 | `tmr[1] = full` → 13 (`ey = 3`, `room/3 < full`) |
| 455 | `tmr[2] = MAX/8` → OK | `tmr[1] = MAX/8` → OK (`ey = 7`, `MAX/8 < MAX/7`) |
| 459 | `tmr[2] = MAX/4` → 13 | `tmr[1] = MAX/4` → 13 (`MAX/4 > MAX/7`) |
| 513 | `tmr[6] = -1` → 13/0 | `tmr[6] = -(NEG_ALLOW+1)` → 13/0 (좌표가 여전히 보이고 삼각형 0 을 지목하는지가 요지) |
| 707 | `tmr[1] = -1` → 13 | `tmr[2] = -COORD_MAX` → 13 (이름을 고치고, 상한을 실제로 넘긴다) |
| 800 | 모서리가 −1 → 13 | 모서리가 `-(NEG_ALLOW+1)` → 13 |

459 는 지금 **우연히** 통과한다(`tmr[2] = MAX/4` 는 폭 상한도 넘는다).  짝을 이루는
단언이므로 함께 고쳐야 그 쌍이 주장하는 것을 시험한다.

## 5. 확인 방법

고친 뒤 `test-hw3d-validate` 가 **0 실패**여야 한다.  그리고 그것만으로는 부족하다 —
바뀐 단언이 정말 무언가를 잡는지 보려면 **일부러 깨뜨려** 본다:

- `OSMGA_HW3D_TEX_NEG_ALLOW` 를 절반으로 줄이면 갑의 "허용 안쪽" 단언이 깨져야 한다
- 검증기의 `tmr[1]`/`tmr[2]` 를 다시 뒤바꾸면 을의 네 단언이 깨져야 한다

두 실험 다 시험 코드가 아니라 **검증기**를 임시로 건드려 확인하고 되돌린다.

## 6. 아직 모르는 것 / 물어볼 것

1. 264 를 `tmr[1]` 로 옮기면 "한 행이면 적용되지 않는다"를 시험하게 되는데,
   `tmr[2]`(= dt/dx)가 한 행 삼각형에서 **열을 가로질러** 적용된다는 사실 자체는
   지금 어디서도 시험되지 않는다.  새로 넣어야 하나?
2. 갑을 "허용 안쪽 통과 + 한 단위 밖 거절"로 짝지으면 허용 폭이 시험에 **박힌다**.
   폭이 다시 바뀌면 또 낡는다.  `OSMGA_HW3D_TEX_NEG_ALLOW` 로 **표현**하면
   상수를 따라가지만, 그러면 "폭이 얼마인지"는 더 이상 시험되지 않는다.
   어느 쪽이 옳은가?
3. 707 에 `-COORD_MAX` 를 주면 기울기 상한과 좌표 범위 **둘 다** 걸린다.
   어느 쪽이 걸려서 거절되는지 시험이 구별하지 못한다.  구별해야 하나?
4. 내가 "두 종류뿐"이라고 분류한 것이 맞는가?  일곱 중 실제로는 **살아 있는
   결함**인 것이 섞여 있지는 않은가?

## 8. 변이로 증명했다 (그리고 구멍을 찾았다)

0 실패는 필요조건이지 충분조건이 아니다.  검증기를 일부러 망가뜨려 새 단언이
알아채는지 봤다 — **시험이 아니라 검증기를** 고치고, 사본에서 하고, 버렸다.

| 변이 | 잡은 단언 |
|---|---|
| 허용을 절반(2048)으로 | **2** — `a u/v start at the allowance` |
| 기울기 상한을 다시 전치 | **2** — `a y increment on a one-row triangle`, `a u row gradient sized to one primitive` |
| 좌표 **평가**를 전치 (완전) | **4** — 위 둘 + 레지스터 대응 행렬 둘 |

### 8-1 처음엔 잡히지 않았다

평가 전치를 처음 걸었을 때 **전부 통과**했다.  두 가지 때문이었다:

1. 내 변이가 불완전했다 — 스팬 **시작**(`ux`/`vx2`)만 바꾸고 **끝**(`ly`/`ry`)을
   두었다.  행 walk 이 v=0 을 보고 통과시켰다.
2. 그리고 더 중요한 것: **상자 경로가 실패하면 행 walk 으로 떨어지고, 행 walk 이
   권한이다.**  상자만 틀리면 관측되지 않는다.

2 번은 오늘 도달범위 버그가 왜 그 자리에 숨었는지를 설명한다 — 도달범위는 상자에서
왔고, 상자는 아무도 검사하지 않는다.

### 8-2 그래서 행렬을 넣었다

기울기 상한이 가릴 수 없는 도형을 python 으로 잡았다: 각 기울기를 **자기 축이
허락하는 만큼 정확히** 주되, 다른 축이 훨씬 긴 프리미티브에 놓는다.

```
   ds/dy: h=4(ey=3), 폭 64(ex=63), tmr[1]=room/3
          제대로면 u 최대 8388606 ≤ room     승인
          전치되면 v 가 room/3 × 63 = 176160726   거절
   dt/dx: h=64(ey=63), 폭 4(ex=3),  tmr[2]=room/3
          제대로면 v 최대 8388606             승인
          전치되면 u 가 176160726            거절
```

## 9. 결과

```

   test-hw3d-reach:     40000 배치 그대로 통과
```

**앞으로 이 시험의 실패는 0 이 기준선이다.** "알려진 7 건" 면제는 없다.

## 10. 곁가지로 고친 것

`OSMGA_HW3D_TEX_NEG_ALLOW` 는 **주석에서만** 쓰이고 있었다 — 실제 규칙은
`p < -(q / 16L)` 이라 상수를 바꿔도 아무 일도 일어나지 않았다.  규칙이 상수를
읽도록 고치고(`q / (Q_ONE / NEG_ALLOW)`), 나눔수가 정수가 아니면 **빌드가 거절**하게
했다.  python 으로 두 형태가 모든 `q` 에서 같은 값을 냄을 확인했다.
